# Демонстрационные данные

Генератор детерминированный: один и тот же seed даёт одинаковый результат, что
позволяет опираться на данные в e2e-сценариях.

## Что создаётся

`pnpm db:seed` (профиль `demo`, по умолчанию):

| Сущность | Объём |
|---|---|
| Пользователи | 61 (администратор + `user001…user060`) |
| Подразделения | 22 в четырёх уровнях: комитет → управления → отделы → региональные |
| Должности | 10 (от председателя до специалиста) |
| Пространства | 3 общих (`org`, `flood-2026`, `digital-map`) + по одному на подразделение + личные |
| Разделы и файлы | «Регламенты», «Формы и шаблоны», «Сводки», «Материалы совещаний» |
| Роли | 7 системных со способностями |
| Территории | 74: страна, 5 регионов, 68 районов и городов — с границами (ADR-0067); 772 кишлака (уровень «населённый пункт»); региональные управления связаны со своими регионами, комитет — со страной |
| Поручения | по 3 от каждого руководителя сотрудникам подразделения (нет своих — руководителям вложенных): в срок, срок сегодня, просрочено, продлено, исполнено в срок и с опозданием, с частями соисполнителей; сроки — от дня загрузки (ADR-0082) |

| Брендирование | название Комитета и короткое «КЧС и ГО» — подзаголовок экрана входа под «Портал КЧС» и шапки печатных форм; только если администратор их ещё не задал |
| Номенклатура дел | Типовая по подразделениям (ADR-0135): 11 разделов, 44 дела на прошлый и текущий год — индексы вида `03-12`, сроки хранения по перечню; демо-документы нумеруются «подразделение-дело/номер» (ADR-0134) |
| Корреспонденты | 6 ведомств стартового набора с почтовыми доменами — белый список приёма из почты (`minfin.tj`, `meteo.tj`, `sughd.tj`, `khatlon.tj`, `barqitojik.tj`, `moh.tj`; ADR-0136) и заявители-физлица демо-обращений |

`pnpm db:seed --profile=minimal` создаёт только администратора, должности,
оргструктуру и справочник территорий с границами (без синтетических кишлаков) — для
чистой установки.

`pnpm db:seed --reset` предварительно удаляет данные (схему не трогает).

`pnpm db:seed --pack=emergency` ставит предметный пакет «Чрезвычайные ситуации»
(ADR-0128); демо-профиль ставит его сам, `--pack=none` — без пакета. С профилем
`minimal` пакет получает те же реестры, дашборды, формы, ленты и правила, но без
синтетических строк (ПВР, силы и средства, журнал оповещения, график дежурств) и
без людей в группах; «Общее» он заводит сам. Повторный запуск досоздаёт только
недостающее. Состав — `docs/01-product/04-domain-pack-emergency.md` §«Реализация».

`pnpm db:seed --data=small` или `--data=demo` дополнительно загружает синтетические
датасеты фазы 1 (раздел ниже) в пространство «Общее»; в образе api — `kchs seed
--data small|demo`. Для этого должны работать api, worker и engine: генерирует
движок, загружает тот же конвейер импорта, что у пользователя. По умолчанию
(`--data=none`) датасеты не грузятся — так сид работает и без запущенного стека (CI).

## Территории и геометрии

Источник и лицензия каждого набора фиксируются здесь до загрузки (риск R13
в `docs/04-delivery/05-risks-and-open-questions.md`): предпочтение отдаётся
официальным открытым данным с явно указанными условиями использования.

Справочник территорий фазы 1 — страна `TJ`, 5 регионов и 68 районов и городов
областного подчинения — создаёт генератор демо-данных движка (`territories.csv`,
см. ниже). Те же единицы API загружает из `apps/api/src/seed/territories.json`
при любом профиле `pnpm db:seed` (ADR-0057): файл получен из
`kchs_engine/demo/reference.py`, их совпадение проверяет тест движка
`tests/test_territory_seed.py`. Коды районов — собственные устойчивые коды
демо-данных, при загрузке реальных данных сопоставляются с официальным
классификатором (вопрос N5).

Границы (фаза 2, ADR-0067) — `apps/api/src/seed/territory-boundaries.json`, 68 районов
(565 КБ, 16,3 тыс. вершин на сетке 1e-4°): API загружает их при любом профиле, регионы и
страну собирает объединением районов, центроид ставит внутрь границы, площадь считает по
сфероиду; повтор с теми же границами ничего не меняет. Файл строит
`python -m kchs_engine.demo.boundaries` (нужен shapely, исходники скачиваются по
закреплённой сборке). 58 районов сопоставлены районам ADM2 по названиям; Душанбе — граница
ADM1, его четыре района — ячейки Вороного вокруг центров, а шесть городов, которых в ADM2 нет
отдельно (Худжанд, Бустон, Гулистон, Истиклол, Бохтар, Хорог), — круги по населению: это
**условные** границы, способ построения записан в атрибутах единицы (`boundary.method`).

Численность населения (вопрос N7) — `apps/api/src/seed/territory-population.json`: страна,
пять регионов и 68 районов и городов по официальной таблице на 1 января 2024 года. Единица
справочника «город» там, где ADM2 объединяет город с одноимённым районом (Вахдат, Турсунзаде,
Рогун, Куляб, Нурек, Левакант, Истаравшан, Исфара, Канибадам, Пенджикент), получает сумму обеих
строк таблицы (`method: official_sum`). Разбивки Душанбе по районам в публикации нет: итог
города распределён пропорционально оценкам районов 2019–2020 годов (Сино 326,1; Фирдавси 209,0;
Шохмансур 170,0; Исмоили Сомони 148,7 тыс.) — это **оценка** (`method: estimate_share`).
Суммы районов расходятся с итогами регионов на 100–200 человек — округление таблицы. Источник,
дата и способ записаны в атрибутах единицы (`population_source`). Замена новой публикацией —
правкой файла: повторный сид перезапишет только изменившиеся единицы.

Населённые пункты — 772 кишлака демо-мира (`apps/api/src/seed/settlements.json`, код
`<район>-NN`) из генератора движка (`python -m kchs_engine.demo.settlements`, совпадение
проверяет `tests/test_settlements.py`): только профиль `demo`, имена и места синтетические.
Точки генератора разбросаны вокруг приблизительных центров районов, поэтому около 40 %
кишлаков лежат за реальной границей своего района.

| Набор | Источник | Лицензия | Статус |
|---|---|---|---|
| Названия регионов и районов | официальное административно-территориальное деление Республики Таджикистан (состав 2020-х годов, после переименований 2016–2018 гг.) | общедоступные факты, авторским правом не охраняются | фаза 1, `kchs_engine/demo/reference.py` |
| Коды регионов | ISO 3166-2:TJ (`TJ-DU`, `TJ-GB`, `TJ-KT`, `TJ-RA`, `TJ-SU`) | коды стандарта используются как идентификаторы | фаза 1 |
| Коды районов (`TJ-SU-01`…), центроиды | собственные: коды — устойчивые коды демо-данных, центроиды — приблизительные (±20–30 км, заданы вручную); округлённые оценки населения генератора — только веса синтетических данных, в справочнике их заменяет статистика (строка ниже) | часть генератора kchs, свободны для использования | фаза 1 |
| Численность населения | Агентство по статистике при Президенте Республики Таджикистан, «Демографический ежегодник Республики Таджикистан», 2024, с. 281–283: постоянное население на конец 2023 года (на 1 января 2024 г.), тыс. человек | официальная публикация, числа — общедоступные факты | пакет ЧС, `territory-population.json`, любой профиль |
| Административные границы | geoBoundaries gbOpen TJK ADM1/ADM2, сборка `9469f09` (OpenStreetMap, выгрузка Wambacher, 2023): районы — ADM2, Душанбе — ADM1; районы Душанбе и шесть городов — условные границы, построенные из этих данных | ODbL 1.0 (© участники OpenStreetMap, geoBoundaries): атрибуция обязательна, файл сида — производная база под ODbL | фаза 2, `territory-boundaries.json`, любой профиль |
| Населённые пункты (кишлаки) | синтетические: распространённые топонимы генератора движка, приписанные районам случайно | часть генератора kchs, свободны для использования | фаза 2, `settlements.json`, профиль `demo` |
| Базовая карта (PMTiles) | OpenStreetMap и Natural Earth — раздел «Базовая карта» ниже | ODbL 1.0 / общественное достояние | фаза 2 (ADR-0066) |

## Синтетические датасеты — фаза 1

Генератор — в движке: `python -m kchs_engine.demo --out <каталог|s3://бакет/префикс>
--profile demo|small` (описание, форматы, замеры — `apps/engine/README.md`, раздел
«Демо-данные»; решение — ADR-0054). Он пишет файлы и `manifest.json` с параметрами
загрузки; в датасеты они попадают через обычный конвейер импорта (ADR-0046).

`pnpm db:seed --data=small|demo` делает это сам (ADR-0063): задание движка пишет файлы в
бакет файлов под `demo/<профиль>-<seed>/` (готовые не генерируются заново), сид создаёт
датасеты со схемой, ключом, полями времени и территории и связями со справочниками,
регистрирует файлы и запускает импорт. Поле «Территория» — поле-территория: коды районов
сопоставляются со справочником территорий (ADR-0057). Повтор с тем же профилем ничего не
грузит, другой профиль или seed заменяет строки импортом «заменить».

| Набор | Файл | small | demo |
|---|---|---|---|
| Территории (справочник) | `territories.csv` | 74 | 74 |
| Типы происшествий (справочник) | `incident_types.csv` | 22 | 22 |
| Гидропосты (справочник) | `hydro_posts.csv` | 46 | 46 |
| Происшествия (2024–2026, точки, время, территория, тип, ущерб) | `incidents.csv` | 50 тыс. | 5 млн |
| Объекты защиты (точки) | `protected_objects.geojson` | 5 тыс. | 50 тыс. |
| Зоны риска (полигоны) | `risk_zones.geojson` | 311 | 311 |
| Уровни воды (посты × сутки) | `water_levels.csv` | 13 152 | 50 416 |

Происшествия и уровни воды тянутся до 31.12.2026, то есть и в будущее от даты
загрузки: так дашборды «сегодня» не пустеют со временем. Оперативные цифры и таблицы
пакета ЧС берут только случившееся (время не позже «сейчас»). Для показа Комитету
правдоподобнее профиль `small` — около 50 происшествий в сутки против 3,5 тыс. в
`demo`, который нужен для нагрузочных проверок.

Всё, кроме названий регионов и районов, вымышлено: события, объекты, зоны,
наблюдения, имена кишлаков (распространённые топонимы, приписанные районам
случайно) и номера. Совпадения с реальными событиями и объектами случайны.

## Базовая карта — фаза 2

Векторную подложку собирает `infra/basemaps/build-pmtiles.sh` (ADR-0066, процедура —
`15-admin-operations.md` §6); загрузки лежат в `seeds/.cache/basemaps` вне git. На карте
обязательна атрибуция «© OpenMapTiles © OpenStreetMap contributors» — она приходит в стиль из
манифеста сборки, и карта показывает её стандартным элементом MapLibre.
