# 0181. Слои модулей без колец: порт онлайн-встречи, ai без зависимостей, проверка в CI

Статус: Принято
Дата: 2026-10-05

## Контекст

Граф синхронных зависимостей модулей (импорты `public.ts` и схем) был одной компонентой
сильной связности из 11 модулей: ai, calendar, data, documents, files, gis, identity,
integrations, mail, meetings, tasks (`04-delivery/07-architecture-hardening.md`,
находка 11). Кольца шли так:
- calendar → meetings → documents → calendar (календарь заводил комнату события через
  `meetings/public`);
- ai ⇄ data (ассистент в модуле ai ходил в данные и файлы, а данные звали модель);
- data ⇄ gis и gis ⇄ tasks (справочник территорий — ADR-0180);
- files ⇄ identity.

Правило `no-circular` dependency-cruiser ищет циклы между файлами, а не между модулями,
поэтому этих колец не видело.

## Решение

- **Порт «поставщик онлайн-встречи» у календаря.** `registerOnlineMeetingProvider` в
  `calendar/public` устроен как реестр проекций (ADR-0081): создание встречи события,
  состав участников, закрытие. Модуль встреч регистрирует его вместе со своими типами
  объектов — во всех ролях процесса и в тестах. Календарь встречи не импортирует; из
  публичного API встреч ушли функции, которые звал только он. Без поставщика событие с
  онлайн-встречей получает понятную ошибку, а не молчит.
- **ai — шлюз к модели.** У него провайдеры, лимиты, способность `ai.use`, аудит, перевод
  и `/ai/status`; других модулей он не импортирует. **Ассистент** — отдельный модуль
  `assistant` поверх ai, данных и файлов: диалог по объекту, таблицы `assistant_threads` и
  `assistant_messages`, маршруты `/assistant/*`. Адреса и возможность «ИИ» прежние.
- **Справочник территорий** — базовый модуль (ADR-0180).
- **Проверка колец в CI.** `apps/api/scripts/module-cycles.mjs` входит в
  `pnpm deps:check`:
  - строит граф dependency-cruiser и сворачивает его до модулей `src/modules/<имя>`;
  - ищет компоненты сильной связности алгоритмом Тарьяна;
  - падает, если в компоненте больше одного модуля, и показывает файлы, через которые идёт
    кольцо;
  - временное исключение, если понадобится, перечисляется в скрипте с частью этапа,
    которая его снимет; исключение без ребра — тоже ошибка;
  - `pnpm --filter @kchs/api deps:layers` печатает слои.

## Слои

Фактические слои после этой части этапа и переноса справочника людей и оргструктуры в ядро
(ADR-0179): L0 — модули без зависимостей от других модулей, Ln — над L(n−1).

| Слой | Модули |
|---|---|
| L0 | admin, ai, calendar, files, mail, push, telegram, territories |
| L1 | identity, integrations |
| L2 | data |
| L3 | alerts, assistant, forms, tasks |
| L4 | documents, gis |
| L5 | automation, knowledge, meetings, reports |
| L6 | chat |

Временных исключений нет. Кольцо files ↔ identity снял ADR-0179: files берёт подписи
пользователей и второй фактор у ядра. Исключение для него было в первой редакции
проверки, и проверка сама потребовала его убрать, когда ребро исчезло.

## Альтернативы

- **Правило dependency-cruiser с запретом путей по слоям.** Слои пришлось бы перечислять
  вручную и править при каждом новом модуле. Компонента сильной связности ловит именно
  кольцо и не требует списка.
- **Встречи и календарь одним модулем.** Календарь шире онлайн-встреч: события, ресурсы,
  ICS, проекции сроков. Слияние спрятало бы зависимость, а не убрало бы её.

## Последствия

- Новая зависимость модуля, замыкающая кольцо, роняет CI с указанием файлов. Разрывать её —
  портом у нижнего модуля (как проекции календаря, `DocumentsPrint`, поставщик онлайн-
  встречи) или выносом общей части вниз (как справочник территорий).
- Проверено: `calendar`, `meetings`, `meetings-room`, `meeting-protocol`,
  `calendar-push-reminder`, `assistant`, `data-ask`, `documents-assist`, `automation`.
