# 0195. Рельеф на карте: отмывка Комитета — растровый PMTiles в сборке векторной подложки

Статус: Принято
Дата: 2026-10-08

## Контекст

Владелец попросил показать рельеф на картах платформы. У Комитета есть отмывка рельефа
`Tajikistan data/растр/hill.tif`:

- GeoTIFF, UTM 42N;
- 9839 × 6907 пикселей по 70 м;
- оттенки серого, 255 — нет данных;
- вся страна.

При загрузке истории (ADR-0194) её не взяли: растровые подложки платформа берёт только по
внешнему адресу XYZ, WMS или WMTS (ADR-0108), а файла как подложки не было. Векторная
подложка OpenStreetMap (ADR-0066) рельефа не несёт: горы видны только по подписям вершин и
ледникам. Для Таджикистана, где 93 % территории — горы, это главный недостающий слой карты.

Нужно, чтобы:

- рельеф лежал под всеми картами сам, без настройки каждой карты;
- рельеф работал в закрытом контуре без интернета (A6, `01-vision.md`);
- вода, дороги, подписи и данные оставались читаемыми поверх рельефа.

## Решение

1. **Рельеф — часть сборки векторной подложки**, а не отдельная подложка. Стиль подложки сам
   рисует его под водой, дорогами и подписями. Отдельная растровая подложка вытеснила бы
   векторную: у карты одна подложка.
2. **Сборка** — `infra/basemaps/build-relief.sh <отмывка.tif>` (Python `relief.py` в образе
   движка: GDAL, numpy, Pillow). Её же вызывает `build-pmtiles.sh`, если задан
   `KCHS_BASEMAP_RELIEF`.
   - Отмывка перепроецируется в Web Mercator по сетке тайлов масштаба 11 (`gdalwarp -tap`):
     ≈ 60 м на пиксель на широте страны, исходник — 70 м.
   - **Двухцветная прозрачная отмывка** вместо серой. Тени — чёрные, освещённые склоны — белые;
     прозрачность растёт от «ровного» тона (медиана отмывки). Ровные места прозрачны: серая
     заливка не гасит цвета подложки, а долины не темнеют.
   - Мелкие масштабы до 5-го — усреднением с учётом прозрачности.
   - Тайлы PNG (яркость + прозрачность), архив PMTiles v3 пишет сам скрипт.
   - Результат для Таджикистана: 1065 тайлов, 42 МБ, сборка — 43 секунды.
3. **Манифест сборки** (`kchs-basemap/1`) получает необязательный блок `relief`: файл, размер,
   SHA-256, масштабы, охват, тайлы, атрибуция.
   - Файл называется `relief-<версия>-<sha8>.pmtiles`. Архив отдаётся с `immutable`, поэтому
     новое содержимое получает новый адрес.
   - Формат манифеста не меняется: без блока манифест читается как раньше. Контракт API
     расширяется полем `build.relief` (`{bytes, tiles}` или null).
4. **Загрузка** — тем же `kchs basemaps upload`. Архив рельефа проверяется так же, как
   векторный (заголовок, размер, SHA-256) и загружается до манифеста. `sync` обновляет
   подложку, если сменился рельеф, даже при том же векторном архиве. Прошлые архивы рельефа
   удаляются.
5. **Отдача** — тот же маршрут `GET /gis/basemaps/{id}/pmtiles/{файл}` с проверкой прав и
   Range. Он отдаёт только файлы текущей сборки — векторный и рельеф.
6. **Стиль.** Если в сборке есть рельеф, стиль получает растровый источник
   `pmtiles://…/relief-….pmtiles` и слой `relief`. Слой стоит над землёй и растительностью и под
   водой, дорогами, границами и подписями. Непрозрачность задаёт палитра темы:
   - светлая — 0,4;
   - тёмная — 0,5: на тёмном фоне видны только освещённые склоны;
   - «приглушённая» (под хороплеты) — 0,3.

   Значения подобраны по снимкам карты: при 0,6 тени в Памире сливаются в сплошные пятна и
   спорят с дорогами и границами.

   Клиенту ничего не нужно: протокол `pmtiles://` уже читает и растровые архивы.
7. **Консоль** «Базовые карты» показывает размер рельефа рядом со сведениями сборки. На стенде
   показа подложку с рельефом загружает `demo-stand.sh basemap`, без сброса данных.

## Альтернативы

- **Растровая подложка «Рельеф» из файла** — новый вид подложки с загрузкой GeoTIFF через
  консоль.
  - У карты одна подложка: рельеф вытеснил бы векторную с дорогами и подписями.
  - Это заметная доработка: загрузка, нарезка движком, хранение.
- **Рельеф слоем на каждой карте** (растровый слой ГИС). Его пришлось бы добавлять на каждую
  карту, а стиля подложки и её тем он не знает.
- **`hillshade` MapLibre из DEM** (terrain-RGB). Исходной DEM у Комитета нет, только готовая
  отмывка. Глобальная DEM (Copernicus, SRTM) — это загрузка из интернета и сотни мегабайт для
  страны. Можно будет вернуться к этому, когда понадобится 3D или профиль рельефа.
- **Серая отмывка как есть** с умножением. Растровые слои MapLibre не умеют режим смешивания:
  серая заливка гасит цвета подложки и затемняет долины.

## Последствия

- **Рельеф есть только у сборки, в которую его добавили.** Пересборка подложки без
  `KCHS_BASEMAP_RELIEF` даёт подложку без рельефа: манифест пишется заново.
- Отмывка Комитета охватывает только Таджикистан. Соседние страны на мелких масштабах — без
  рельефа.
- Масштабы крупнее 11-го растягивают тайлы 11-го: точнее исходник не позволяет.
- Тесты:
  - стиль — `basemap-style.test.ts`: место слоя, источник, все темы, валидатор MapLibre;
  - загрузка, `sync`, отдача диапазонами, удаление рельефа и чужая контрольная сумма —
    `gis-basemaps.test.ts`.
- Запрет из ADR-0194 («рельеф не загружается») снят.
