# 0212. Донесение без сети: ключ идемпотентности создания документа, фото черновика, очередь устройства

Статус: Принято
Дата: 2026-10-13

## Контекст

ADR-0204 отложил донесение без сети. Очередь устройства умела одну отправку — сдачу сводки,
у которой был ключ идемпотентности. У создания документа его не было. Если ответ
`POST /documents` теряется, повтор из очереди создаёт второй черновик.

Донесение в kchs — документ типа «Донесение» (`situation_report`) из стартового набора.
Пакет ЧС добавляет ему реквизиты ЧС: вид, масштаб, район, время, пострадавшие, погибшие,
эвакуированные, ущерб, меры (`04-domain-pack-emergency.md`). Заводят донесение двумя путями.
Канцелярия и дежурная смена регистрируют его экраном регистрации, а общий «Создать» входящие
типы не предлагает. Быстрой формы для сотрудника в поле, где связь пропадает, не было.
Концепт-нота (§4.2) требует отложенной отправки и фото.

## Решение

1. **Ключ идемпотентности создания.** У `DocumentCreateInput` появился `clientKey` (uuid
   устройства), у `documents` — колонка `client_key` с уникальностью по автору и ключу.
   - Повтор с тем же ключом от того же автора возвращает уже созданный документ. Событие
     `document.created` и аудит пишутся один раз.
   - Гонку одновременных повторов снимает блокировка `pg_advisory_xact_lock` по автору и
     ключу. Уникальный индекс страхует от ошибки в коде.
   - Ключ, занятый документом другого типа, даёт 409.
   - Без ключа создание работает как раньше.
2. **Фото черновика** — `POST /documents/{id}/photos` `{clientKey, data}`.
   - Принимается JPEG до 3 МБ, не больше 30 снимков у документа.
   - Сервер выбрасывает метаданные: очистка `shared/jpeg.ts` общая с фото сводки
     (ADR-0208).
   - Снимок становится файлом реестра в пространстве документооборота, прикреплённым к
     документу (`attachment`). Видит его тот, кто видит документ.
   - Повтор с тем же ключом снимка возвращает тот же файл: учёт в `document_photos`.
   - Добавлять фото можно только в черновик. Дальше файлы идут версиями документа
     (ADR-0197): из прикреплённого снимка автор делает приложение версии.
3. **Диалог «Донесение»** на экране «Документы». В нём тема, реквизиты типа (те же
   контролы, что в карточке) и снимки, сжатые на устройстве как в ADR-0208. Ключ создания
   выдаётся при открытии диалога.
   - При связи документ создаётся сразу, снимки загружаются, черновик открывается во вкладке.
   - Без сети донесение ложится в очередь устройства как запись `document.create` и уходит
     само тем же ключом.
   - Отказ по существу при связи показывает сам диалог.
4. **Очередь** (ADR-0204) получила второй вид записи.
   - Досылка: создание с ключом, затем каждый снимок под своим ключом. Загруженный снимок
     помечается на устройстве, следующий проход его пропускает.
   - Отказ по существу оставляет запись «не отправлено» с причиной и «Убрать из очереди».
     Снимки стираются вместе с записью.
   - Уведомление «Донесение из очереди отправлено» показывает строка состояния, потому что
     диалог к этому времени закрыт.
   - Очередь ведётся по сотруднику: записи других людей на общем устройстве не досылаются.
5. **Справочники на устройстве.** Типы документов и территории запоминаются по сотруднику
   (`cachedFetch`) и запрашиваются в режиме `offlineFirst`. Без этого донесение без сети не
   заполнить: район в нём обязателен. Код экрана документов и диалога модуль документов
   объявляет для работы без сети (`offline`, ADR-0207).

6. **Доставка дежурной смене** (N129). Донесение из поля не остаётся черновиком автора — оно
   уходит на регистрацию.
   - `POST /documents/{id}/intake` отправляет входящий документ, заведённый сотрудником, на
     регистрацию маршрутом типа по умолчанию (`defaultRouteKey`). Запрос повторяемый: строка
     документа блокируется, маршрут уже идёт — ответ `sent` с тем же экземпляром,
     документ зарегистрирован — `registered`, у типа нет маршрута — `draft` (донесение остаётся
     черновиком). Исходящий и внутренний так не отправляются (409).
   - Реквизиты входящего заполняются сами, без ручного ввода дежурным. Корреспондент —
     подразделение автора: корреспондент-организация с внешним кодом `unit:<id>`, один на
     подразделение, заводится системой при первом донесении. Сотрудник без подразделения
     становится корреспондентом-лицом (`user:<id>`). Дата поступления — день отправки.
   - Пакет ЧС ставит маршрут «Донесение: регистрация дежурной сменой»
     (`situation_report_intake`). В нём один шаг регистрации: группа «Дежурная смена», срок 1
     час, просрочка — руководителю дежурного и автору, как у остальных экстренных маршрутов.
     Маршрут становится маршрутом «Донесения» по умолчанию, только если администратор не выбрал
     другой (N90). После регистрации тип направляет донесение на резолюцию, как раньше.
   - **Маршрут без согласования и подписи идёт без файла.** Правило «по маршруту идёт версия»
     (ADR-0197) нужно для шагов над содержимым. Маршрут, где есть только регистрация,
     регистрирует карточку, как экран регистрации входящего. Карточка без файла предлагает
     только такие маршруты.
   - **Регистратор шага маршрута — по праву на журнал.** Назначение на шаг проверил движок,
     поэтому способность «Регистрация» не нужна, достаточно права правки журнала (действие
     `register_by_route`). Пакет давал дежурной смене правку журнала донесений, но без роли
     делопроизводителя она не могла их регистрировать. Теперь может, по маршруту.
   - Очередь устройства и диалог отправляют донесение после снимков: пока документ черновик,
     снимки к нему ещё ложатся. Если регистрация отказала по существу (пустая дежурная смена,
     допуск), донесение остаётся черновиком автора, а не «не отправлено»: документ уже на
     сервере, и уведомление объясняет причину.

## Чего нет и почему

- **Точка на карте в донесении.** Поля-точки у реквизитов донесения нет: место — район и
  населённый пункт. Точку на карте обстановки ставит регистрирующий, как раньше.

## Альтернативы

- **Общий `Idempotency-Key` с таблицей ответов.** Отклонено, как в ADR-0204: у документа есть
  строка, к которой ключ привязывается естественно.
- **Снимки — приложениями версии сразу.** Отклонено: у версии обязателен основной файл, а
  донесение из поля — карточка и снимки. Версию с приложениями автор делает из черновика.
- **Отдельная форма сбора «Донесение».** Отклонено: донесение — документ с журналом, номером
  и правилами (поручения по регламенту), а сводка пишет строку датасета.
- **Запуск маршрута флагом создания** (`POST /documents` с `submit: true`). Отклонено: снимки
  грузятся после создания и ложатся только в черновик. Отдельный повторяемый запрос после
  снимков проще и так же надёжен в очереди.
- **Уведомление дежурной смене о новом черновике.** Отклонено: без шага маршрута нет срока,
  напоминания о просрочке и записи о том, кто зарегистрировал.
- **Отдельный внутренний тип «Донесение с места».** Отклонено: донесение одно, с одним
  журналом и правилами. Регистрирует его дежурная смена независимо от того, пришло оно по
  телефону или из поля.
- **Роль делопроизводителя всей дежурной смене.** Отклонено: роль — способность регистрировать
  в любом допущенном журнале и с экрана регистрации. Новый член группы получал бы её только
  через администратора ролей, а группа пакета наполняется оргструктурой.

## Последствия

- Миграция `document-client-key-photos`: `documents.client_key` с уникальным индексом по
  автору и ключу, таблица `document_photos`.
- Контракты: `DocumentCreateInput.clientKey`, `DocumentPhotoUploadInput`, `DocumentPhoto`,
  маршрут `POST /documents/{id}/photos`. Белый список DMZ получил этот маршрут для токенов.
- `cleanJpeg` переехал из модуля форм в `shared/jpeg.ts`.
- Доставка (п. 6): контракт `DocumentIntakeResult`, маршрут `POST /documents/{id}/intake`;
  действие журнала `register_by_route`; маршрут пакета `situation_report_intake` и маршрут
  «Донесения» по умолчанию; `DocumentRoutes.options` и `start` пропускают маршрут без
  согласования и подписи у документа без файла. Миграции нет.
- Тесты:
  - интеграционный `document-offline-report.test.ts`: повтор, гонка (проверена поломкой),
    ключ по автору, фото с повтором и гонкой;
  - интеграционный `document-report-intake.test.ts`: без маршрута — черновик; повтор и гонка
    трёх запросов — один маршрут; корреспондент — подразделение, один на подразделение;
    регистрирует член дежурной смены без роли делопроизводителя (проверено поломкой); исходящий
    — 409. `emergency-pack.test.ts` проверяет маршрут пакета и маршрут типа по умолчанию;
  - unit очереди `queue-documents.test.ts` и `queue-intake.test.tsx` (отправка на регистрацию
    настоящим клиентом API; отказ по существу — черновик, проверено поломкой);
  - компонент `report-dialog.test.tsx`;
  - сквозной сценарий `documents-report-offline.spec.ts`: донесение из очереди ушло на маршрут
    приёма, корреспондент и дата поступления заполнены.
