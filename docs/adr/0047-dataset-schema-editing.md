# 0047. Правка схемы датасета: неизменный ключ поля, смена типа одной перезаписью с отчётом

Статус: Принято
Дата: 2026-09-18

## Контекст

`05-data-model.md` (Решено) инкапсулирует DDL таблиц датасетов в `modules/data/infra/physical.ts`
и описывает смену типа «через временный столбец и приведение с отчётом об ошибках»;
переименование физики не требует — имя столбца `c_<n>` стабильно. Бэклог P1-E01 S02
требует смену типа с отчётом ошибок и переименование без изменения физики; экран датасета
(`06-analytics-engine.md` §3) — редактор полей с предпросмотром ошибок приведения.

Открытыми оставались: что считать «переименованием», когда правка схемы даёт версию
датасета (кэш результатов запросов инвалидируется по версиям), как правка схемы уживается
с идущим импортом и где хранить ссылку поля на справочник.

## Решение

1. **Ключ поля неизменен.** На него ссылаются QuerySpec, графики, показатели, политики
   строк и сопоставления импорта. «Переименование» поля — правка подписи (`label`);
   физический столбец не меняется.
2. **Смена типа** (`POST /datasets/{id}/fields/{key}/convert`): по умолчанию пробный прогон —
   число непустых значений, число неприводимых и до 20 примеров. Применение —
   `ALTER TABLE … ALTER COLUMN … TYPE … USING <выражение>`: значение приводится через текст и
   `pg_input_is_valid`, неприводимое становится `NULL`. Одна перезапись таблицы в транзакции
   даёт тот же результат, что и временный столбец, но атомарно и без переименований.
   Потеря значений допускается только с `allowLoss`; совпадение значений ключа строки после
   приведения — 409. Индексы столбца строятся заново под новый тип (trigram-индекс текста к
   числу не подходит). Геометрия в другие типы не приводится и из них не получается.
3. **Версии.** Структурная правка (поле добавлено или удалено, сменился тип или ключ строки)
   даёт версию датасета с происхождением `schema` — меняется ключ кэша результатов. Правка
   описания (подпись, семантика, формат, единица, справочник, индекс) только увеличивает
   `schema_version`; он тоже входит в ключ кэша запросов (подписи есть в результатах).
4. **Очерёдность.** Правка схемы блокирует строку датасета (`FOR UPDATE`). Правки с DDL во
   время идущего импорта (queued, normalizing, loading) отклоняются с 409: загрузка опирается
   на типы столбцов на момент запуска. Описание поля можно менять и во время импорта.
5. **Индексы ищутся по каталогу** (`pg_index`), а не по именам: подмена таблиц при полной
   замене (ADR-0046) меняет имена индексов.
6. **Удаление поля** удаляет столбец вместе с данными; запрещено для полей ключа строки и
   для полей, которые служат ключом или подписью справочника другого датасета. Поле времени
   или территории, если удаляется оно, сбрасывается.
7. **Справочник** — свойство `lookup` поля (`datasetId`, `keyField`, `labelField`); при
   установке проверяются доступ пользователя к справочнику и наличие обоих полей.
8. Правка схемы — действие `manage` на датасете.

## Альтернативы

- Временный столбец и переименование — как в `05-data-model.md`: больше шагов DDL, тот же
  результат; `ALTER … TYPE … USING` сохраняет порядок столбцов и перестраивает индексы сам.
- Версия на каждую правку описания — засоряет список версий и сбрасывает кэш без изменения
  данных.
- Изменяемый ключ поля с каскадной правкой ссылок — ссылки есть в спецификациях запросов,
  графиков и политик разных модулей; каскад по ним хрупок.

## Последствия

- Смена типа выполняется синхронно в запросе. Для таблиц в миллионы строк её нужно перенести
  в задание с ходом выполнения — отложено до экрана «Схема» с крупными датасетами.
- Уникальность `unique` поля вне ключа строки на уровне базы не обеспечивается.
