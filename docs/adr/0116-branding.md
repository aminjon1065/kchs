# ADR-0116. Брендирование: логотип настройкой, акцент — токеном дизайн-системы

Статус: **Принято** · Дата: 2026-09-20 · Фаза 5 (P5-E06)

## Контекст

`15-admin-operations.md` §1 требует брендирования: логотип, название, акцентный
цвет. Название и логотип нужны на экране входа — то есть **до** сессии, когда
файлы платформы недоступны по правам. Правило 6 CLAUDE.md запрещает цвета вне
токенов дизайн-системы, а произвольный цвет из консоли — это ровно цвет вне
токенов, которому никто не проверял контраст.

## Решение

1. **Логотип хранится значением настройки** `brand.logo` как `data:`-URI (png,
   jpeg, webp, svg, до 256 КБ). Публичный `GET /branding` отдаёт его без входа.
   Файл объектом реестра не годится: у гостя нет прав ни на один объект, а
   отдельный публичный путь к файлам — новая поверхность атаки.
2. **Акцент — выбор из палитры дизайн-системы**: `blue` (по умолчанию), `green`,
   `violet`, `teal`, `maroon`. Каждый описан в `tokens.json` для светлой и тёмной
   темы, попадает в `tokens.css` как `[data-accent="…"]` и проверяется тем же
   `pnpm --filter @kchs/ui contrast`, что и акцент по умолчанию. Оболочка ставит
   атрибут на корень — компоненты не меняются вовсе.
3. **Название живёт в тех же ключах**, что уже читают печатные формы
   (`brand.name`), плюс короткое название для рейки и заголовка вкладки.
4. **Приписка на экране входа** (`brand.loginNote`) — для «Система для служебного
   пользования» и подобного; текст показывается как текст, разметка не
   допускается.
5. Изменение — в аудит с состоянием до и после, но **логотип в журнал не
   попадает**: вместо картинки пишется её размер.

## Альтернативы

- **Произвольный цвет (`#RRGGBB`).** Ломает контрастные гарантии: белый текст на
  жёлтой кнопке нечитаем, а проверить каждый цвет установки нечем. Если владелец
  потребует точный цвет бренда — он добавляется в палитру как новый токен с
  проверкой контраста, а не вводится в поле.
- **Логотип файлом в S3 с публичной ссылкой.** Требует публичного маршрута к
  хранилищу и его кэширования; `data:` в настройке проще и резервируется вместе
  с базой.
- **Своя тема целиком (CSS-переменные из консоли).** Дизайн-система перестала бы
  быть источником правды.

## Последствия

- Логотип ограничен 256 КБ — для растрового логотипа это много, для векторного с
  двух сторон хватает.
- Страница входа делает один публичный запрос `GET /branding`; он не раскрывает
  ничего, кроме названия организации, которое и так на виду.
- Печатные формы берут название из той же настройки; логотип в шапках форм —
  следующей историей.
