# 0148. Стенд демонстрации: одна команда, хранилище по HTTPS на отдельном порту, сброс без потери сертификата

Статус: Принято
Дата: 2026-09-25

## Контекст

Владелец решил (§5 «Направление работ», 25.09.2026): сначала демонстрация Комитету на
демо-данных, стенд — ноутбук владельца или арендованный VPS, «запуск должен подходить для
обоих». По N90: до пилота стенд не обновляется, а переустанавливается.

Путь установки уже был (`20-admin-install.md`): `generate-secrets --mode app`, `compose
--profile app up`, `kchs init`, `kchs seed`. Для показа ему не хватало четырёх вещей.

- **Одной команды.** Шагов пять, а подложку карты нужно загружать отдельно.
- **Хранилища по HTTPS.** Браузер ходит в хранилище напрямую по подписанным ссылкам
  (ADR-0044). Сайт по HTTPS требует хранилища по HTTPS, а готового способа не было:
  только совет в руководстве.
- **Своих паролей демо-учёток.** `kchs seed` брал встроенные пароли — их знает каждый, кто
  видел код. На VPS с публичным адресом это вход для всех.
- **Сброса перед показом.** `kchs seed --reset` чистит таблицы, но оставляет файлы в
  хранилище и поисковый индекс. Полное удаление томов стёрло бы и сертификат Let's
  Encrypt, а одинаковых сертификатов выдают не больше пяти в неделю.

## Решение

1. **`infra/scripts/demo-stand.sh`** — команды `up`, `reset`, `status`, `kchs`, `logs`,
   `down`.
   - `up` создаёт окружение, собирает образы, поднимает профиль `app`, выполняет
     `kchs init` и `kchs seed --data small` с пакетом ЧС, загружает подложку из
     `seeds/.cache/basemaps/out`.
   - Временный пароль администратора печатается сразу после `init`: упади следующий шаг,
     одноразовый пароль не пропадёт.
   - Скрипт работает в bash 3.2 (macOS) и отказывается трогать `.env` стенда разработки.
2. **Режим домена** (`--domain`, `--email`).
   - Caddy получает сертификат Let's Encrypt.
   - Надстройка `infra/compose/storage-https.yml` добавляет сайт хранилища: то же имя,
     порт 9443, тот же сертификат. Основной Caddyfile подключает дополнительные сайты
     (`import /etc/caddy/sites/*.caddy`); без файлов импорт пуст.
   - S3 по HTTP привязывается к `127.0.0.1` (`ports: !override`).
   - Заголовок Host доходит до MinIO как есть, поэтому подпись ссылок, выданных для
     `https://имя:9443`, сходится.
3. **Пароли демо-учёток.** Скрипт кладёт в окружение стенда случайный
   `SEED_USER_PASSWORD`. Compose передаёт `SEED_ADMIN_PASSWORD` и `SEED_USER_PASSWORD` в
   api, пустое значение означает встроенный пароль (`||` вместо `??`).
4. **Сброс** стирает тома данных (postgres, redis, minio, meilisearch) и оставляет тома
   Caddy, окружение и пароли, затем повторяет `up` на собранных образах.
   `reset --build` пересобирает образы после `git pull`.
5. **Проверка.** `stack-check.mjs` получил `STACK_IGNORE_TLS=1`: режим HTTPS проверяется
   локально с доменом `localhost` и внутренним центром сертификатов Caddy. Проверено на
   стенде:
   - вход и «Мой день»;
   - загрузка напрямую в хранилище по HTTPS;
   - превью от движка;
   - нарушений CSP нет.

## Альтернативы

- **Отдельное имя для хранилища** (`files.example.org`) — вторая запись DNS и второй
  сертификат ради одного показа. Порт на том же имени проще, если сетевой экран его
  пропускает.
- **Хранилище по пути** (`/s3/…`) за тем же сайтом. Подпись SigV4 покрывает путь, и
  префикс её ломает — это уже разбирали в ADR-0044.
- **`kchs seed --reset` вместо удаления томов.** В хранилище и поисковом индексе остались
  бы следы прошлого показа.
- **Ansible или cloud-init для VPS.** Лишний инструмент для одной машины: скрипт тот же для
  ноутбука и сервера.

## Последствия

- Новые файлы:
  - `infra/scripts/demo-stand.sh`;
  - `infra/compose/storage-https.yml`;
  - `infra/compose/caddy/sites-available/storage-https.caddy`;
  - руководство `30-demo-stand.md` со сценарием показа и таблицей «кто есть кто» демо-мира.
- Та же надстройка подходит рабочей установке с доменом (`20-admin-install.md`, «Домен и
  HTTPS»).
- Скрипт не поднимает медиасервер и сервер документов: встреч с видео и офисного редактора
  на стенде нет.
