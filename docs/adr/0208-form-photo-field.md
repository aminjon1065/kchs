# 0208. Поле «Фото» в формах сбора: снимок — файл реестра у формы, сжатие на устройстве, без EXIF

Статус: Принято
Дата: 2026-10-13

## Контекст

Концепт-нота (§4.2) просит снимки с места происшествия в донесениях с выезда: мост,
оползень, дом. ADR-0204 отложил поле «Фото». Нужно было решить, куда ложится файл и кто его
видит: у сдающих сводку нет права на пространство датасета формы. Без сети снимок должен
ждать вместе со сдачей.

Ограничения:

- правило 1 CLAUDE.md: файл — объект реестра, создаётся через `ObjectService`;
- правило 2: доступ — через `authorize()` и политику типа, без особых проверок в модуле;
- сводку (`GET /forms/submissions/{id}`) видит тот, кто видит форму: назначенные,
  ответственные за приёмку и те, кто ведёт форму;
- строку сдачи видят по правам датасета;
- тип поля датасета `file` уже есть (значение — идентификатор файла реестра), но форма
  его не спрашивала.

## Решение

1. **Поле датасета `file` форма спрашивает фотографией.** На экране заполнения это
   «Добавить фото»: камера или галерея телефона, без `capture`, чтобы был выбор.
   Миниатюра видна сразу. Подпись по-прежнему не спрашивается.
2. **Сжатие на устройстве.** Длинная сторона — до 1600 px, JPEG с качеством 0,82 (при
   превышении — 0,7 и 0,55). Перекодировка через canvas выбрасывает EXIF. Поворот по EXIF
   браузер применяет до этого (`imageOrientation: 'from-image'`).
3. **Координаты съёмки не храним.** Место происшествия форма спрашивает своим полем-точкой
   (ADR-0157) — явно, с картой и правкой. GPS из снимка — персональные данные о
   перемещениях сотрудника: он мог снимать дома, в дороге или с чужого телефона. Сервер не
   верит клиенту и сам выбрасывает из JPEG блоки APP1–APP15 и COM (EXIF, XMP, ICC, IPTC,
   комментарии), оставляя JFIF и данные изображения (`forms/domain/jpeg.ts`). Пиксели не
   декодируются: снимок рисует браузер, превью строит движок.
4. **Куда ложится файл.** Снимок загружается в сводку:
   `POST /forms/submissions/{sid}/photos` — `clientKey`, `fieldKey`, JPEG в base64.
   - загружает только назначенный, пока сводка открыта (черновик или возвращена);
   - принимается только JPEG до 3 МБ со стороной до 8192 px;
   - в одну сводку — не больше 30 загрузок, считая заменённые в черновике;
   - файл — объект реестра в системной папке «Вложения» пространства формы (закрытая,
     09-files.md §1), прикреплённый к форме связью `attachment`. Создаёт его модуль
     файлов (`storeFileBytes`), владелец — сфотографировавший.

   Строка `form_submission_photos` связывает файл со сводкой и ключом устройства.
   Повтор загрузки с тем же ключом возвращает уже записанный файл.
5. **Кто видит.** Вложение видно тому, кто видит объект-хозяин (03-access-model.md, шаг
   «вложение»):
   - снимок у формы видит тот, кто видит сводку, то есть форму. Ведущие форму и
     ответственные за приёмку его правят, но не выше `edit`;
   - при сдаче снимок прикрепляется и к датасету: строку с фото видят по правам датасета;
   - посторонний не видит ни сводки, ни снимка.

   Особых проверок в модуле нет: решает `authorize()`.
6. **Значение поля — только снимок этой сводки.** При сохранении черновика и при сдаче
   каждое значение фото-поля должно быть файлом, загруженным в эту сводку. Чужой файл
   реестра значением не станет: ответ 400.
7. **Сданный снимок заморожен.** Политика содержимого `forms.photos` (порт ADR-0197)
   запрещает снимку, вошедшему в сдачу, новую версию, восстановление старой и корзину —
   даже администратору (409 `file_frozen`, своё сообщение политики). Снимки черновика, не
   вошедшие ни в одну сдачу, при сдаче удаляются насовсем (`destroyFiles`), поэтому замена
   фото не копит файлы. Снимки прежней сдачи после возврата и пересдачи остаются: на них
   ссылается история строк датасета.
8. **Без сети** (ADR-0204, ADR-0207):
   - снимок ложится в IndexedDB (`photos`, по сотруднику), значение поля — ключ снимка;
   - перед сохранением черновика и перед сдачей каждый ещё не загруженный снимок уходит на
     сервер, а значение становится идентификатором файла;
   - без сети сдача ложится в очередь с ключами, досылка грузит снимки перед сдачей. Ключ
     загрузки тот же, поэтому повтор не плодит файлов;
   - после дошедшей сдачи снимки с устройства стираются, неотправленные — через 30 дней.
9. **Просмотр.** В панели сводки и в таблице строк снимок показывается миниатюрой по
   подписанной ссылке (`GET /files/{id}/download?inline=true`), в датасете — как файл.

## Альтернативы

- **Файл в пространстве датасета.** Отклонено: у сдающих нет права туда писать, а давать
  его ради фото — значит открыть им весь датасет.
- **Свой тип объекта «фото сводки» с политикой по сводке.** Отклонено пока: сводка не
  объект реестра. Её видимость сейчас равна видимости формы, поэтому вложение к форме даёт
  ту же картину без нового типа. Если сводки станут видны только своему подразделению,
  снимки последуют за ними: политика вложения не меняется.
- **Загрузка через общие сессии загрузки файлов** (ADR-0123). Отклонено. Сессии требуют
  права создавать в пространстве и рассчитаны на большие файлы с докачкой. Снимок после
  сжатия — сотни килобайт, и один запрос с ключом устройства проще для очереди без сети.
- **Перекодировать снимок на сервере.** Отклонено: нужна библиотека изображений в api или
  задание движку ради картинки. Выбрасывание блоков метаданных закрывает утечку данных, а
  декодирование делает браузер.
- **Сохранять GPS снимка отдельным полем.** Отклонено по п. 3. Если владелец захочет
  координаты съёмки как доказательство, это будет явное поле с согласием, а не тихое
  извлечение (вопрос N122).

## Последствия

- Миграция `form-submission-photos`: таблица `form_submission_photos`.
- Контракты: `FormPhotoUploadInput`, `FormPhoto`, маршрут
  `POST /forms/submissions/{sid}/photos`; константы `FORM_PHOTO_MAX_BYTES`,
  `FORM_PHOTO_MAX_PER_SUBMISSION`, `FORM_PHOTO_MAX_SIDE`.
- Модуль файлов: `storeFileBytes` в публичном API. Политика содержимого получила своё
  сообщение (`FrozenFile.message`).
- Тесты:
  - интеграционный `form-photos.test.ts`: EXIF выброшен, повтор с тем же ключом, чужой
    файл, сдача, удаление заменённого, заморозка;
  - unit `jpeg.test.ts`;
  - очередь `queue.test.ts`: сводка, открытая без сети, со снимком;
  - сценарий `forms-offline.spec.ts`.
- Подпись (`signature`) форма по-прежнему не спрашивает.
