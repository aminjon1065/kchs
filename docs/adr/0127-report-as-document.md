# ADR-0127. Отчёт исходящим документом: файл прогона — первой версией

Статус: **Принято** · Дата: 2026-09-20 · Фаза 5 (P5-E09)

## Контекст

Сценарий C (`01-product/02-users-and-scenarios.md`) требует пути «отчёт →
согласование → подпись → рассылка», а `04-domain-model.md` держит у отчёта поле
`register_as_document_type_id`. До фазы 5 такого пути не было: отчёт жил
объектом со своими прогонами, а согласование, подпись, регистрация и рассылка
есть только у документов.

Отдельный маршрут согласования для отчётов означал бы вторую реализацию
подписей, журналов регистрации и дел — то, чего проект избегает.

## Решение

1. **Отчёт становится документом, а не обзаводится своим маршрутом.**
   `POST /reports/{id}/document` заводит черновик документа выбранного
   исходящего вида; дальше работает обычная карточка со всем, что у неё есть.
2. **Первой версией кладётся файл последнего удачного прогона** (PDF, иначе
   DOCX). Второго рендера не делаем: подписывают ровно то, что человек видел,
   и числа не разъезжаются между тем, что смотрели, и тем, что подписали.
3. **Файл копируется в бакет файлов**, а не берётся ссылкой на выгрузку:
   выгрузки живут 30 дней по правилу хранения, документ — сколько положено делу.
4. **Версия добавляется отдельной транзакцией** после заведения документа:
   проверка прав читает базу, и права черновика видны только после фиксации.
5. **Связь модулей — через публичный API**: `DocumentsPublic.create` и новый
   `DocumentsPublic.addVersion`; модуль отчётов не трогает таблицы документов.

## Альтернативы

- **Рендерить заново при создании документа**: подписант получил бы другой файл,
  чем тот, что смотрел, — данные могли измениться между прогонами.
- **Ссылка на выгрузку вместо копии**: через месяц у зарегистрированного
  документа исчез бы файл.
- **Свой маршрут согласования у отчёта**: вторая реализация подписи и
  регистрации, а номер в журнале всё равно понадобился бы документу.

## Последствия

- Отчёт и документ дальше живут своей жизнью: перестроенный отчёт не меняет уже
  подписанный документ — это осознанно.
- Связь «документ ← отчёт» пока видна только по названию и примечанию версии;
  явная связь объектов — следующей историей.
- Публикация отчёта страницей базы знаний (последний шаг сценария C) делается
  из документа его файлом — отдельная история, вопрос N89.
