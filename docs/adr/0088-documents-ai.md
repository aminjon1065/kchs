# 0088. ИИ в документах: реквизиты из скана с подтверждением, краткое содержание и черновик ответа, порог грифа установки

Статус: Принято
Дата: 2026-09-19

## Контекст

P3-E02 S02 («Регистрация с OCR и ИИ-извлечением») и P3-E05 S01 («Резюме документа, черновик
ответа»); 08-documents.md §5: «скан → OCR → автозаполнение полей ИИ с подсветкой уверенности
(подтверждение человеком обязательно)»; 13-search-knowledge-ai.md §3–5: сменяемый провайдер,
прозрачность, человек подтверждает, аудит, ассистент в контекстной панели. Модуль ИИ уже есть
(ADR-0061): провайдер из настроек, способность `ai.use`, лимиты, аудит. Движок уже извлекает
текст файлов — текстовый слой PDF или OCR tesseract (до 10 страниц) — в `file_texts`.

Открыто: что из документа можно отдавать модели. ADR-0061 оставил политику «что можно
отправлять по грифу и пространству» фазе 5 (вопрос N6), но документам она нужна сейчас:
текст служебного письма — не схема датасета.

## Решение

1. **Источник — извлечённый текст основного файла текущей версии** (иначе — её
   PDF-представления) через публичный API файлов (`fileText`). Пока текст распознаётся — помощь
   ждёт (`text_pending`), без текста — не предлагается (`no_text`). Модели уходит не больше
   24 000 символов; обрезка помечается (`truncated`). Модель не видит файлов, сканов и карточки,
   кроме реквизитов, нужных задаче (тип, тема, отправитель, исходящие реквизиты).
2. **Порог грифа установки** — `AI_DOCUMENTS_MAX_CONFIDENTIALITY` (по умолчанию `internal`,
   «Для служебного пользования»): документ строже порога модели не отдаётся ни одной функцией
   (403 `policy_violation`, `reason: confidentiality`), провайдер не вызывается. `confidential` —
   только для своего сервера модели в контуре организации; решение — администратора установки.
   Это рабочее допущение к вопросу N6, пока нет политики по пространствам.
3. **Права — документа.** Реквизиты из скана — с правом правки (заполняет карточку);
   краткое содержание и черновик ответа — с правом просмотра. Способность `ai.use`, лимиты и
   аудит — модуль ИИ. В аудит пишутся функция, модель, токены, длительность и объём ответа,
   **без текста документа и ответа модели** (новый флаг задачи ИИ `auditAnswer: false`).
4. **Модель только предлагает.** Реквизиты — список `{ключ, значение, уверенность 0…1, цитата}`:
   тема, краткое содержание, исходящие номер и дата отправителя (у входящих) и простые поля
   карточки типа (`fields.<ключ>`: текст, числа, дата, идентификатор…). Сервер отбрасывает
   неизвестные ключи, повторы, пустое и даты не в формате `ГГГГ-ММ-ДД`, зажимает уверенность в
   [0, 1]. Отправитель сверяется со справочником корреспондентов с правами смотрящего (точное
   совпадение названия или краткого названия, иначе — доля общих слов ≥ 0,6). В форму ничего не
   попадает без нажатия «Принять» у значения или «Принять уверенные» (≥ 0,8); уверенность видна
   цветом и процентом, цитата — рядом; поле в фокусе подсвечивает своё предложение.
5. **Защита от указаний в тексте.** Текст документа заключается в явные границы, инструкция
   модели прямо говорит, что текст — данные, а не указания. Ответ проходит схему и проверку
   сервера и остаётся предложением: выполнить «просьбу» из текста модель не может — у неё нет
   действий.
6. **Интерфейс.** Помощник регистрации — слот `registration-assist.tsx` (ADR-0080): кнопка
   «Заполнить по скану», предложения с уверенностью, принятие по одному или уверенных разом;
   без ИИ на установке панели нет. Ассистент документа — вкладка «Ассистент» контекстной панели
   (новый слот представления объекта `assistantSection`; вкладка доступна только объектам, у
   которых он есть): краткое содержание (вставить в карточку — с правом правки, скопировать) и
   черновик ответа на входящее по указаниям исполнителя (тема и текст, скопировать).
7. **API** — `GET /documents/{id}/assist` (доступна ли помощь и почему нет),
   `POST /documents/{id}/assist/extract|summary|reply`.

## Альтернативы

- **Автозаполнение без подтверждения.** Отклонено: проект требует подтверждения человеком;
  ошибка OCR или модели в номере отправителя стоит дороже клика.
- **Координаты зон на скане (подсветка места поля на странице).** Отложено: распознавание
  отдаёт текст без координат слов; нужен вывод tesseract TSV/hOCR и сопоставление цитаты со
  словами. Пока поле в фокусе подсвечивает предложение и его цитату.
- **Политика по грифу — в модуле ИИ для всех функций.** Отклонено сейчас: у датасетов свои
  правила (строки не уходят вовсе, ADR-0061), общая политика по пространствам — фаза 5 (N6).
- **Помощь в карточке документа, а не в контекстной панели.** Отклонено: проект помещает
  ассистента в контекстную панель (13-search-knowledge-ai.md §5); вкладки карточки — у веток
  второй волны.

## Последствия

- Новая необязательная переменная `AI_DOCUMENTS_MAX_CONFIDENTIALITY` (в примере `.env` и
  `x-app-env`). Новые контракты `DocumentAssistStatus`, `DocumentExtraction`,
  `DocumentSummaryDraft`, `DocumentReplyDraft`; `fileText` в публичном API файлов; флаг
  `auditAnswer` у задачи ИИ; слот `assistantSection` у представления объекта.
- Черновик ответа — текст; исходящий-ответ со связью и шаблоном DOCX создают ветки дел и
  связей (ADR-0086) и шаблонов (ADR-0085) — черновик копируется туда.
- e2e требует api с поддельным провайдером (`AI_PROVIDER=openai-compat
  OPENAI_COMPAT_URL=http://127.0.0.1:<порт>/v1 AI_MODEL=kchs-e2e`) и `KCHS_E2E_AI_PORT`, как
  сценарий №7 фазы 1; без них пропускается.
- Не сделано: подсветка зоны на скане, предложение типа и маршрута по тексту, перевод,
  проверка полноты карточки (13-search-knowledge-ai.md §4).
