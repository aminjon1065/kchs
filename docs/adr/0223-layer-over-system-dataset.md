# 0223. Слой карты над системным датасетом с правами смотрящего; «Донесения» на «Обстановке ЧС»

Статус: Принято
Дата: 2026-10-14

## Контекст

ADR-0221 дал донесению точку «Место на карте», но слой «Донесения» не сделал (N161). Строки
датасета видны по правам пространства, а документ — по своим правам и грифу. Слой из копии
строк показал бы место и тему конфиденциального донесения тем, кому документ не открыт.

Слой (ADR-0064) стоял только на датасете реестра: `layers.dataset_id NOT NULL`, тайлы,
объекты, статистика стиля и рамка шли через компилятор с источником `dataset`, кэш тайлов —
в Redis по версии данных. Системные датасеты (ADR-0060, ADR-0082, «Подключения» ADR-0206)
компилятор уже принимал с политикой смотрящего, но версии данных у них нет. Слои их не
поддерживали.

## Решение

1. **Системный датасет `document_places` («Документы на карте»).** Модуль документов,
   представление `ds.sys_document_places`. Строки — документы с точкой в реквизитах:
   первое поле карточки вида `geometry` и строго GeoJSON Point. Поля:
   - `id`, `type_key`, `type_name`, `reg_number`, `reg_date`, `subject`, `status`;
   - `territory` — первое поле карточки вида `territory`, то есть район;
   - `location` — точка;
   - `created_at`, `confidentiality`;
   - служебные: `_id` — устойчивый 52-битный номер из `id` для объектов тайла, `viewers`,
     `grif_rank`.

   Политика строк та же, что у системного датасета «Документы» (ADR-0080), общая функция
   `documentViewerPolicy`: принципалы смотрящего пересекаются с `viewers`, гриф не строже
   допуска. Тип донесения в представление не зашит: слой отбирает его фильтром.
2. **Слой над системным датасетом.** Новый столбец `layers.system_source`; `dataset_id`
   стал необязательным. Проверка `layers_source_check` требует ровно один источник. Контракт:
   - `LayerRecord.datasetId` может быть `null`;
   - новое поле `systemSource`;
   - `LayerCreateInput` принимает `datasetId` или `systemSource`;
   - источник слоя — только системный датасет с объявленной геометрией
     (`SystemDatasetDefinition.geometry`, `LAYER_SYSTEM_SOURCES`).
3. **Права смотрящего.** Тайлы, объекты, карточка объекта, статистика стиля и рамка с
   числом объектов строятся через компилятор с источником `system`. Каждый раз политика —
   того, кто смотрит. Пространственное окно работает и здесь: ключ `system:<имя>`. Права
   на сам слой данных не открывают. Сам системный источник виден каждому (`dataAccess`),
   а строки ограничивает политика.
4. **Без кэша между пользователями.**
   - Тайл, статистика и рамка системного слоя не кладутся в Redis и не берутся оттуда.
   - Ответ тайла — `cache-control: private, no-cache`.
   - Метка `etag` считается по ключу компиляции и содержимому тайла: версии данных у
     источника нет, а 304 должен значить «тот же тайл».
5. **Правки нет.** Создать системный слой с `editable` или `moderated` нельзя (400).
   `GET …/editing` отвечает `mode: 'none'`, `reason: 'layer_readonly'`. Запись объектов —
   403.
6. **Пакет ЧС.** Слой «Донесения» (`layer.situation_reports`) над `document_places` с
   фильтром `type_key = situation_report`, значок «мегафон», подпись — номер. Карточка:
   тема, тип, номер, дата, район, документ. Новая установка кладёт его на «Обстановку ЧС».
   На установленном пакете слой досоздаётся, а карта не меняется (N90, N109): на карту его
   добавляет администратор.
7. **Веб.** Поля слоя берутся из `layerDatasetQuery`: датасет реестра или схема системного
   датасета в виде датасета. Карточка объекта системного слоя открывает документ («Открыть
   документ»). У системного слоя нет таблицы атрибутов, выгрузки, поиска по строкам,
   правки и связанных представлений.
8. **Контракт.** Событие `layer.published` — версия 2: `datasetId` может быть `null`,
   добавлено `systemSource`. Расширение `datasetId` в ответах `GET` и `PATCH
   /gis/layers/{id}` записано в `allowed-breaking.json` со ссылкой на этот ADR.

## Альтернативы

- **Копия донесений в датасет пакета подписчиком событий.** Отклонено. Права документа
  (участники, наследование, гриф) пришлось бы повторять в строках и пересчитывать при
  каждой смене доступа. Ошибка в копии раскрыла бы место документа.
- **Датасет реестра, читающий представление.** Отклонено. Запись строк, импорт, колоночная
  копия и версии датасета пришлось бы запрещать в десятке мест; ошибка открывала бы правку.
- **Слой GeoJSON отдельным маршрутом документов.** Отклонено: в карте нужны стиль, легенда,
  кластеры, подписи и фильтры, то есть второй путь отрисовки рядом с уже имеющимся.

## Последствия

- Миграции `20261014065438_document_places` (представление и право чтения `kchs_query`) и
  `20261014065722_layer_system_source`.
- Тайлы системного слоя считаются на каждый запрос. Строк немного (документы с точкой),
  окно режет по рамке, тайм-аут тайла прежний.
- Тесты:
  - интеграционный `document-places-layer.test.ts`: посторонний не видит донесение ни в
    запросе, ни в объектах, ни в тайле, ни в карточке; тайл не переходит от автора к
    постороннему; конфиденциальное видно только с допуском; правки нет;
  - `emergency-pack.test.ts` — слой в пакете.
- e2e `emergency-pack.spec.ts`, сценарий «Донесения на карте обстановки». Слой пакета
  стоит над `document_places`. Черновик донесения с местом виден автору в объектах слоя, а
  тайл приходит с `private, no-cache`. Другой сотрудник место черновика не видит.
