# 0050. DataGrid: строки окнами через getRow, правка пакетами с откатом
Статус: Принято
Дата: 2026-09-18

## Контекст
ADR-0008 выбрал собственный `DataGrid` на TanStack Table + TanStack Virtual. Для
реализации (P1-E03 S01) нужно было решить, как таблица получает данные, как
отдаёт правки и где держит состояние, чтобы один компонент служил экрану
датасета (QuerySpec, режим таблицы с `_id`/`_ver`), Explore и системным
датасетам — без знания об API. Бюджет из 04-interaction-patterns.md §1:
60 fps на 100 столбцах × 100 000 строк.

## Решение
- **Данные — у родителя.** Таблица получает `rowCount` (и `totalCount` для
  «N из M»), `getRow(index) → { id, values } | undefined` и сообщает видимое
  окно `onVisibleRangeChange(start, end)`; незагруженная строка — скелет.
  Новая ссылка `getRow` означает «данные обновились». Сортировка — серверная
  (`sort`/`onSortChange`), фильтры ведёт экран (`onColumnFilter` из меню столбца).
- **TanStack Table — только модель столбцов** (порядок, видимость, закрепление,
  ширины с перетаскиванием края); строк в нём нет, row model на 100 000 строк не
  строится. Раскладка столбцов управляемая (`columnState`) или внутренняя.
- **Правка — пакетами через `onEdit(changes) → Promise<{ rejected? }>`.** Ячейка,
  вставка, очистка, отмена и повтор дают пакет `CellChange { rowId, rowIndex,
  key, previous, value }`. Таблица сразу показывает новые значения (слой правок
  поверх данных) и держит их, пока родитель не передаст обновлённые данные.
  Отказ по ячейкам (проверка, конфликт версии строки `_ver`) или отклонённый
  промис — откат, красная рамка и причина в подвале; отклонённое уходит из
  истории отмены. Версию строки родитель берёт из своего кэша по `rowId`.
- **Разбор ввода — `@kchs/fields` (`parseValue`)**: числа и даты в локали, да/нет,
  варианты по подписи; тот же разбор пригоден мастеру импорта и формам.
- **Фокус держит сама таблица** (`role="grid"`, `aria-activedescendant` на
  активную ячейку). Поле правки и скрытое поле буфера обмена лежат вне сетки:
  в `grid` допустимы только строки и ячейки. ⌘C/⌘X/⌘V на мгновение переводят
  фокус в скрытое поле — браузер выполняет команду буфера только в поле ввода.

## Альтернативы
- Строки массивом в пропсах (как `DataTable`) — родитель держал бы все
  загруженные строки в одном массиве, а таблица не знала бы о незагруженных.
- Row model TanStack Table на загруженных строках — лишняя работа на каждый
  рендер при 100 000 строк и расхождение индексов с серверной сортировкой.
- Правка по ячейке без пакетов — вставка 1 000 значений дала бы 1 000 запросов
  и отмену по одной ячейке.

## Последствия
- Замер (`KCHS_PERF=1 pnpm --filter @kchs/ui test:visual grid-perf`, Chromium
  в образе Playwright, без наблюдателя подсветки Storybook): 60 fps без
  пропусков во всех сценариях прокрутки 100 × 100 000 (обработка события
  прокрутки — 0,7–1,8 мс); при замедлении процессора ×4 — 60 fps при обычной
  вертикальной и горизонтальной прокрутке, 52–59 fps при быстрой (600 px за
  кадр), диагональной и прыжках по таблице. Запасной путь ADR-0008 не нужен.
- Экрану датасета остаётся кэш окон (страницы по курсору), обновление кэша
  после `onEdit` и передача `_ver` в запрос правки.
- Больше ~900 000 строк при высоте строки 36 px упираются в предел высоты
  элемента браузера — для таких наборов нужна масштабируемая прокрутка (не сделано).
