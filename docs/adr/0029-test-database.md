# 0029. Отдельная база `kchs_test` для интеграционных тестов

Статус: Принято

Контекст: `04-verification.md` требует интеграционных тестов маршрутов с реальными
PostgreSQL/Redis/Meilisearch/MinIO. Testcontainers поднимает свои контейнеры на
каждый прогон (десятки секунд старта и сборка образа PostGIS), что делает
локальный цикл медленным.

Решение: init-скрипт кластера создаёт две базы с одинаковыми схемами, ролями и
привилегиями: `kchs` и `kchs_test`. Тесты подменяют `DATABASE_URL` на тестовую
базу, выполняют миграции и очистку данных перед каждым набором. В CI те же
контейнеры поднимаются как services — код тестов не меняется.

Альтернативы: testcontainers (медленно локально, но остаётся вариантом для
ночного прогона); транзакции с откатом (невозможно: сервисы ядра сами открывают
транзакции); отдельная схема вместо базы (миграции жёстко адресуют `public`,
`ops`, `yjs`).

Последствия: интеграционный набор стартует за ~2 с. Тесты обязаны очищать
данные (`resetData`), а не полагаться на пустую базу. Требуется, чтобы
инфраструктура была поднята — это же условие для `pnpm dev`.
