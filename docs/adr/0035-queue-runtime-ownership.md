# 0035. У каждой очереди заданий один исполнитель

Статус: Принято
Дата: 2026-09-18

Контекст: `02-platform-kernel.md` §9 говорит, что Python-движок «потребляет те же
очереди», что и TypeScript-воркер. BullMQ не маршрутизирует задания по имени:
любой воркер очереди забирает любое её задание. Если обе стороны слушают одну
очередь (например, `exports`), задание движка достаётся воркеру TypeScript, падает
с «нет обработчика» и тратит попытки — или наоборот. В фазе 0 очереди случайно не
пересекались (`transform` — только движок, `index`/`maintenance` — только воркер),
но в фазе 1 импорт, экспорт и обработка файлов заняли бы общие очереди.

Решение: у очереди ровно один исполнитель. Соответствие задаёт
`QUEUE_RUNTIME` в `packages/contracts/src/jobs/job.ts`:

| Очередь | Исполнитель |
|---|---|
| `imports`, `transform`, `render`, `media`, `ai` | движок (`engine`) |
| `exports`, `index`, `notify`, `automation`, `process-timers`, `maintenance` | воркер (`worker`) |

`registerJobHandler` в TypeScript и декоратор `@handler` в Python отказываются
регистрировать обработчик в чужой очереди — ошибка на старте, а не потерянные
задания в работе. Python получает соответствие из сгенерированного
`apps/engine/kchs_engine/contracts/queues.json` (`pnpm --filter @kchs/contracts gen:engine`),
CI проверяет, что файл совпадает со схемой TypeScript.

Экспорт отдан воркеру: запросы к датасетам компилирует `packages/query` в TypeScript,
результат пишется потоком CSV/XLSX/JSON/GeoJSON без передачи SQL в движок.
Превью и извлечение текста файлов — задание `render:file.process` (09-files.md §3;
движок: poppler, LibreOffice, tesseract, Pillow).

Альтернативы:
- маршрутизация по префиксу имени задания внутри общей очереди — BullMQ так не умеет,
  пришлось бы возвращать чужие задания в очередь, теряя порядок и попытки;
- отдельная очередь на каждое задание — десятки очередей и воркеров без выгоды.

Последствия: новая очередь или смена исполнителя — правка `QUEUE_RUNTIME`
и перегенерация контракта движка. Если одной области нужны оба исполнителя
(например, ИИ: вызовы LLM в TypeScript, эмбеддинги в движке), TypeScript-часть
работает синхронно или через свою очередь.
