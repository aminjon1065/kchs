# 0170. Сводные поля объекта — через `ObjectService.patchMeta`, без события

Статус: Принято
Дата: 2026-10-05

## Контекст

Модуль «Данные» менял запись `objects` напрямую, мимо `ObjectService`
(`dataset-service.ts`, `schema-service.ts`):
- число строк и полей в `meta` — при каждом импорте, правке строк, обновлении ленты и правке
  схемы;
- подзаголовок (описание датасета) — при правке настроек.

Описание при этом не доходило до поиска. Индекс переиндексирует объект только по событиям
`object.*` (`kernel/subscribers.ts`), а их у прямой записи нет. Открытые вкладки других
людей тоже его не видели. Правило 1 CLAUDE.md требует, чтобы запись реестра шла через ядро.

Счётчики по смыслу отличаются от описания. Это денормализация для карточек и списков, а не
правка пользователя. `bumpVersion` вызывается на каждую правку строк в таблице и на каждое
обновление ленты. Событие `object.updated` на каждый такой вызов засорило бы ленту
активности записями «изменил», переиндексацию и рассылку realtime.

## Решение

- В ядре появляется `ObjectService.patchMeta(tx, id, patch, {touch?})`. Метод сливает
  сводные поля в `meta` без события и без новой версии объекта, а `touch` обновляет
  `updated_at`. Это осознанное исключение из правила 3 и только для сводных полей, которые
  модуль пересчитывает сам. Состояние, на которое должны реагировать подписчики, хранится в
  таблице модуля и сопровождается своим событием (`dataset.version_created`,
  `dataset.schema_changed`).
- Описание датасета — подзаголовок объекта, поэтому оно меняется через
  `ObjectService.update`. Событие `object.updated` доводит его до поиска, открытых вкладок и
  ленты.
- Счётчики строк и полей пишутся через `patchMeta`.

## Альтернативы

- **`ObjectService.update` с `silent` для счётчиков.** Каждая правка строки увеличивала бы
  `version` объекта, а это ложные конфликты `If-Match` у того, кто в это время
  переименовывает датасет.
- **Событие на каждое изменение счётчика.** Это шум в ленте и в поиске, описанный выше.

## Последствия

- Прямой записи в `objects` в модуле «Данные» больше нет. Запретить её проверкой сборки
  (`.insert/.update(objects)` вне `kernel/objects`) — задача этапа 2 укрепления архитектуры.
- Подписи полей датасета тоже входят в поисковый документ, но правка схемы публикует только
  `dataset.schema_changed`, и его поиск не слушает. Переиндексацию по событиям модуля через
  реестр типов (без знания ядром имён событий модулей) делает этап 2.
- Тест `data-schema.test.ts`: смена описания доходит до подзаголовка объекта и публикует
  `object.updated` с полем `subtitle`.
