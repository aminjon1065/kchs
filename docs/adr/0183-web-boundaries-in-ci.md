# 0183. Границы клиента под контролем CI: слои, публичные входы модулей, registerModule

Статус: Принято
Дата: 2026-10-05

## Контекст

Разбор архитектуры (`04-delivery/07-architecture-hardening.md`, находка 14) показал, что в
web правила `01-project-structure.md` держатся на соглашениях, а dependency-cruiser для
клиента не запускается.

Если применить к коду 7884c5b5 те границы, что описаны в документах, нарушений 1081:

| Нарушение | Сколько |
|---|---|
| фичи импортируют оболочку `app/` | 592: перевод 309, оформление 180, состояние вкладок 94 и др. |
| импорты внутренностей чужой фичи | 237, в 81 паре фич, 7 взаимных пар |
| модули, которые зовут клиент API мимо слоя запросов | 221 |
| оболочка знает фичи по именам вне точки сборки | 27: рейка, нижняя навигация, палитра, shell, контекст-панель, экраны входа |
| `shared` импортирует `app` | 4 |

Циклов не было. Каталог `entities/` был пуст. Модуль описывал себя в 6–8 файлах оболочки.

## Решение

### Слои и правила

`apps/web/.dependency-cruiser.cjs`, запуск — `pnpm deps:check` (корень) вместе с api.

Слои снизу вверх:

- `shared/` — клиент API, перевод (`useT`, `useLocale`), оформление, realtime, состояние рабочего пространства и реестр модулей. Ничего выше не знает.
- `entities/` — сквозные компоненты сущностей. Знают только `shared`.
- `features/<m>/` — экраны и компоненты модуля. Чужая фича доступна только через её `index.ts`.
- `app/` — оболочка. Фичи знает только точка сборки `app/modules.tsx`.

Правила: нет циклов; клиент API — в слое запросов фичи (`api/`, `queries.ts`), в `entities` и `shared`.

### База известных нарушений

То, что осталось к моменту включения правил, лежит в `apps/web/.dependency-cruiser-known-violations.json`. Пересоздаётся командой `pnpm --filter @kchs/web deps:baseline`. CI падает на каждом новом нарушении. Базу пересоздают после того, как нарушение исправлено, но не чтобы спрятать новое.

### Что перенесено

- **В `shared/`:**
  - `shared/i18n.ts` (`useT`, `t`);
  - `shared/appearance.ts` (`useAppearance`, новый `useLocale` вместо 256 повторов `useAppearance((s) => s.locale)`);
  - `shared/workspace/{store,types,view-context,object-actions,registry,open-workspace}`. Это состояние вкладок и реестр, а не интерфейс оболочки.
- **В `entities/`:**
  - `access`: диалог доступа, ссылки, выбор принципалов, значок сервисной учётной записи;
  - `objects`: присутствие, выбор объекта;
  - `people`: выбор пользователя;
  - `files`: загрузка, превью с водяным знаком, офисный редактор;
  - `collab`: документ Yjs и клиент совместной правки;
  - `data`: формат показателей;
  - `discussion`: редактор и элемент сообщения, упоминания.
- **Публичные входы `features/<m>/index.ts`** — в 12 модулях. Через `export *` они отдают только лёгкие модули: запросы, ключи кэша, подписи, форматы, статусы. Компоненты туда не попадают: реэкспорт потянул бы их, вместе с MapLibre и тяжёлыми диалогами, в чанк любого лёгкого потребителя этого входа.

### `registerModule` (`shared/workspace/registry.tsx`)

Модуль описывает в `features/<m>/module.ts(x)`, что он даёт оболочке (`ModuleDefinition`):

- пункты навигации с хуком значка (непрочитанное в «Чатах»);
- возможности оболочки: справку, проверку консоли, быстрое действие и команды палитры;
- слои: баннеры, оверлеи, диалоги, секции контекст-панели.

Точка сборки вызывает `registerModule`. Рейка, нижняя навигация, палитра, shell и контекст-панель читают реестр. Экраны вне оболочки (вход, гость, печать) объявлены в точке сборки. Модули с вкладом в оболочку: admin, assistant, automation, calendar, chat, delegation, knowledge, meetings, spaces. Пункты рейки модулей без своих возможностей объявлены в точке сборки.

Хуки модулей (значок, справка, палитра) оболочка вызывает без условий. Если модуля нет в сборке, работает запасной хук. Реестр заполняется до первой отрисовки и дальше не меняется, поэтому порядок хуков стабилен.

## Альтернативы

- **Только правила с базой, без переносов.** Тогда в базе осталось бы 1081 нарушение. Правило ловило бы новые, но перевод, оформление и вкладки так и жили бы «в оболочке», и каждая новая фича нарушала бы слои с первой строки.
- **Публичный вход со всеми компонентами модуля.** Он ломает ленивую загрузку: проверено бюджетом оболочки, реэкспорт тяжёлых модулей в общий вход недопустим.
- **Реестр модулей в `app/`.** Тогда фичи не смогли бы регистрироваться сами, не нарушив слой.

## Последствия

- **Итог.** Нарушений 1081 → 275, все в базе:
  - 63 импорта компонентов чужих фич;
  - 212 модулей с вызовами API вне слоя запросов.

  Импортов `app/` снизу, обратных зависимостей `shared` и знания фич оболочкой — 0.
- **Бюджет оболочки:** 385,7 → 386,5 КБ (описания модулей в основном чанке).
- **Что осталось на потом:**
  - компоненты чужих фич отдавать ленивыми слотами реестра или переносить в `entities`: карта для данных и отчётов, ячейка запроса тетради, диалоги задач;
  - вызовы API выносить в слой запросов фич по мере правки модулей;
  - экраны и представления объектов перенести из точки сборки в `features/<m>/module.tsx` — `ModuleDefinition` их уже принимает;
  - вывести `ScreenKey` из реестра: сейчас это перечисление экранов в `shared/workspace/types.ts`.
