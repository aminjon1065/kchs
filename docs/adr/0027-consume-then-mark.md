# 0027. Отметка обработки события после успешного вызова подписчика

Статус: Принято

Контекст: подписчики событий должны быть идемпотентными и не терять события.
Первая реализация писала строку в `ops.event_consumptions` до вызова
обработчика: падение процесса между записью и обработкой навсегда «съедало»
событие (наблюдалось на практике — часть объектов seed не попала в поисковый
индекс).

Решение: порядок «проверить → обработать → отметить → ack». Падение между
обработкой и отметкой приводит к повторной обработке, а не к потере.
Обработчики ядра идемпотентны (upsert в индекс, `onConflictDoNothing` в ленте
активности, дедупликация уведомлений по `aggregate_key`).

Альтернативы: двухфазная фиксация с блокировкой строки (сложнее, тот же риск);
хранение позиции потока вместо идентификаторов событий (теряет защиту от
повторной доставки внутри группы).

Последствия: гарантия «как минимум один раз» вместо «ровно один раз».
Требование идемпотентности подписчика зафиксировано в `Subscriber` и проверяется
в обзоре кода. Добавлено задание `search.reindex` для восстановления индекса.
