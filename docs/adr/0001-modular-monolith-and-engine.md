# 0001. Модульный монолит на TypeScript + вычислительный движок на Python
Статус: Принято. Дата: 2026-09-17

## Контекст
Тринадцать функциональных областей с сильными связями (объекты, права, события) должны работать как один продукт и разворачиваться on-premise малой командой. Часть операций (геоформаты, большие файлы, OCR, расшифровка, рендеринг) требует библиотек, недоступных или слабых в Node.js.

## Решение
Один развёртываемый код `api` (роли `api`/`worker`) с модулями и ядром; отдельный сервис `engine` на Python, исполняющий задания из очереди без доменной логики. Границы модулей проверяются линтером.

## Альтернативы
Микросервисы (распределённые транзакции для объект+ACL+событие, эксплуатационная сложность); чистый монолит (клубок); всё на Python (слабее для realtime и общих типов с клиентом); всё на Node (GDAL/whisper/LibreOffice-интеграции хуже).

## Последствия
Одна транзакция на бизнес-операцию; простая поставка; горизонтальное масштабирование репликами; дисциплина границ обязательна; два языка — только в engine.
