# 0150. Почта в составе установки: docker-mailserver и Roundcube, ящики из платформы, пароль для почты отдельно

Статус: Принято
Дата: 2026-09-25

## Контекст

Владелец решил (05-risks §5, Q9/N41/N56): нужна полноценная почта Комитета — почтовый
сервер в составе установки, ящики сотрудников и канцелярии, веб-почта, домен Комитета с
записями MX, SPF и DKIM. Каталога LDAP/AD нет: сотрудников ведёт платформа. Установка S1 —
один сервер, закрытый контур, исходящий интернет через прокси. Домена пока нет.

## Решение

1. **Сервер и веб-почта** — профиль compose `mail`:
   - `docker-mailserver` 16 — Postfix, Dovecot, OpenDKIM, OpenDMARC, без антивируса и
     спам-фильтра по умолчанию;
   - `Roundcube` 1.7.

   Выбран за предсказуемость: учётки — один файл, который сервер подхватывает без
   перезапуска; DKIM — одной командой; всё документировано и проверено годами. Stalwart
   сильнее (JMAP, API учёток), но веб-почты у него нет, а его конфигурация меняется от
   версии к версии.
2. **Ящики ведёт платформа** (модуль `mail`, таблица `mail_mailboxes`):
   - у каждого действующего сотрудника — `логин@домен`, у канцелярии — общий ящик
     (`MAIL_REGISTRY_LOCAL`);
   - платформа переписывает файл учёток `postfix-accounts.cf` целиком, заменой, при
     создании, блокировке и правке сотрудника и при смене пароля для почты;
   - заблокированный сотрудник из файла пропадает: вход закрыт сразу, письма ему не
     принимаются, содержимое ящика остаётся;
   - `kchs mail sync` делает то же вручную.
3. **Пароль для почты — отдельный от пароля платформы.**
   - Второй фактор к IMAP и SMTP почтовых программ не применим. Пароль платформы в почте
     обходил бы MFA, а утечка из почтовой программы открывала бы всю платформу.
   - Сотрудник получает пароль для почты в профиле: четыре группы по пять знаков, около
     115 бит. Он показывается один раз и заменяет прежний; отзыв оставляет ящик
     принимающим.
   - Хранится только хеш `{SSHA512}` — его проверяет Dovecot. Схема быстрая, но пароль
     случайный и длинный, подбирать его по хешу бесполезно.
   - До первого пароля ящик принимает письма со случайным невыдаваемым паролем.
4. **Ящик канцелярии — служебный:**
   - его пароль знает только платформа — зашифрован мастер-ключом, входит в
     `kchs secrets rotate`;
   - исходящие документы уходят из него (`MAIL_SUBMISSION_URL`, ADR-0149);
   - приём в очередь «Из почты» идёт из него же: `kchs mail sync` заводит интеграцию
     `imap` «Ящик канцелярии» с делопроизводителем;
   - делопроизводители работают с почтой канцелярии в очереди «Из почты», а не в
     веб-почте.
5. **TLS.**
   - В закрытом контуре и на тестовом домене `mail-init` выпускает самоподписанный
     сертификат на `MAIL_HOSTNAME`. Платформа и Roundcube ходят к серверу внутри сети
     развёртывания без проверки имени (`MAIL_TLS_VERIFY=false`).
   - С доменом Комитета сертификат заменяется настоящим и проверка включается
     (`31-admin-mail.md`).
6. **Наружу:**
   - порт 25 — для приёма из интернета, когда будет домен и MX;
   - 587 и 993 — почтовые программы сотрудников;
   - веб-почта — на `KCHS_BIND`;
   - если прямой порт 25 из контура закрыт, исходящие идут через ретранслятор
     провайдера (`MAIL_RELAY_HOST`).

## Альтернативы

- **Пароль платформы для почты** (Dovecot проверяет хеш из базы) — одна учётка, но
  второй фактор обходился бы почтовой программой.
- **Своя SSO для веб-почты.** Платформа — не поставщик OIDC. Появится поставщик —
  Roundcube подключится к нему плагином, почтовые программы останутся на пароле для почты.
- **Внешний почтовый сервис.** Закрытый контур и требование «почта в составе установки».
- **mailcow.** Десяток контейнеров ради того же для одной организации S1.

## Последствия

- Службы `mail-init`, `mailserver`, `webmail`; тома `mailconfig`, `maildata`, `mailstate`,
  `webmaildata`.
- Переменные: `MAIL_DOMAIN`, `MAIL_CONFIG_DIR`, `MAIL_SUBMISSION_URL`, `MAIL_IMAP_HOST`,
  `MAIL_IMAP_PORT`, `MAIL_TLS_VERIFY`, `MAIL_WEBMAIL_URL`, `MAIL_REGISTRY_LOCAL`;
  `MAIL_HOSTNAME`, `MAIL_RELAY_HOST` — у сервера.
- Миграция `mail-mailboxes`; события `mail.password_changed`, `mail.mailboxes_synced`;
  действие аудита `user.mail_password_changed`.
- Проверено на живом сервере (`mail-provisioning.test.ts` при `KCHS_MAIL_E2E=1`):
  - вход по IMAP паролем из профиля;
  - письмо канцелярии доходит сотруднику;
  - письмо сотрудника в канцелярию попадает в очередь «Из почты».
- Резервная копия тома `maildata` в ночную копию установки пока не входит (ADR-0117) —
  это в руководстве.
