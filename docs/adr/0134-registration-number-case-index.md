# 0134. Номер «подразделение-дело/номер»: индекс дела по номенклатуре в номере, дело при регистрации отдельно от подшивки

Статус: Принято
Дата: 2026-09-25

## Контекст

Владелец 24.09.2026 решил (N12, `05-risks-and-open-questions.md` §5): номер по умолчанию —
«подразделение-дело/номер», например `03-12/145`. Это код подразделения, индекс дела по
номенклатуре и порядковый номер.

До этого решения было так:

- стартовые журналы нумеровали документы шаблоном `{prefix}-{seq:04}/{yy}` (`ВХ-0001/26`);
- формат знал подстановку `{unit.code}` — код подразделения из оргструктуры (`UO`, `UD-CANC`);
- о деле номенклатуры документ узнавал только при подшивке после исполнения (ADR-0086).

В делопроизводстве стран СНГ индекс дела уже содержит индекс подразделения: `03-12` —
подразделение 03, дело 12 в его разделе номенклатуры. Коды оргструктуры для номера не
годятся: они мнемонические и нужны другим частям системы, например правилам пакета ЧС
(`unit_head('UO')`).

Решение должно было ответить на три вопроса:

- откуда брать индекс дела в момент регистрации;
- что делать, если дело не выбрано или номенклатуры ещё нет;
- как не сломать форматы, которые администратор уже задал.

## Решение

1. **Подстановка `{case.index}`** — индекс дела по номенклатуре, выбранного при регистрации.
   Формат по умолчанию (`DEFAULT_NUMBER_FORMAT`) — `{case.index}/{seq}`, отсюда `03-12/145`.
   Порядковый номер общий для журнала в году, как и раньше.
2. **Дело при регистрации подбирается само.** Это открытое дело года регистрации, совпавшее с
   документом по типу и подразделению. Если лучшее совпадение единственное, оно выбирается.
   Правило ранжирования то же, что у подшивки (ADR-0086).

   В диалоге «Регистрация документа» поле «Дело по номенклатуре» уже заполнено, и номер виден
   сразу: «Номер будет: 03-12/146». Делопроизводителю обычно остаётся нажать
   «Зарегистрировать». Можно выбрать другое дело или «Без дела».

   Регистрация по маршруту (шаг `register`) и через API без `caseId` подбирает дело так же;
   `caseId: null` означает «без дела».
3. **Без дела номер не рвётся.** Если дело не выбрано или подобрать его нельзя (два равных
   совпадения, номенклатуры нет), `{case.index}` берёт префикс журнала (`ВХ/146`), а без
   префикса — код подразделения. Регистрацию это не блокирует: чистая установка без
   номенклатуры работает с первого дня.
4. **Какое дело годится.** Выбранное дело должно быть открытым, года регистрации и с правом
   подшивать в него (`file_in`). Иначе — 400 с объяснением: «Дело закрыто…», «Дело 03-21 —
   номенклатуры 2025 года».
5. **Дело регистрации хранится отдельно от дела подшивки** — в `documents.reg_case_id`
   (`registrationCase` в карточке). У `case_id` прежний смысл: «подшит». Счётчики дела, опись,
   закрытие, передача в архив и акт об уничтожении не видят документов в работе. Подшивка
   предлагает дело из номера первым и выбирает его, если оно открыто. Карточка показывает
   «Дело по номенклатуре» до подшивки.
6. **Стартовые журналы переходят на новый формат**: «Входящие», «Исходящие», «Внутренние»,
   «Договоры», «Обращения граждан». Приказы и распоряжения по традиции нумеруются по порядку в
   году (`001-ПР/26`). Журналы пакета ЧС сохраняют свои форматы.

   Миграция `documents-reg-case` меняет формат только у стартовых журналов, чей формат равен
   прежнему умолчанию; изменённые администратором форматы не трогаются.
7. **Предпросмотр номера** — `GET /documents/{id}/number-preview?journalId=&caseId=`. Номер не
   выдаётся и не резервируется: параллельная регистрация может занять его раньше. Подсказка
   дел для регистрации — `GET /documents/{id}/cases?purpose=registration`.

## Альтернативы

- **`{unit.code}-{case.index}` с индексом дела без подразделения.** Для этого понадобился бы
  отдельный числовой индекс подразделения: коды оргструктуры мнемонические. Кроме того,
  индекс в номенклатуре обычно записывается целиком (`03-12`).
- **Держать дело регистрации в `case_id`.** Документ в работе числился бы в деле: опись,
  счётчики и передача в архив пришлось бы учить различать «подшит» и «отнесён».
- **Требовать дело при регистрации.** Чистая установка без номенклатуры не могла бы
  зарегистрировать ни одного документа — это против «не трудно пользователям».
- **Сразу менять формат всех журналов.** Сломало бы форматы, которые администратор уже задал.
  Приказы по традиции нумеруются по порядку.

## Последствия

- В контракте нумерации (`numbering.ts`) новая подстановка, а формат по умолчанию для новых
  журналов — `{case.index}/{seq}`. У `DocumentRegisterInput` появилось поле `caseId`, у
  `DocumentRecord` — поле `registrationCase`.
- Номер из резерва выдан заранее, поэтому индекса дела не содержит: диалог об этом
  предупреждает.
- Смена формата в середине года на рабочей установке даст номера двух видов в одном журнале.
  Если это нежелательно, администратор меняет формат с нового года; миграция трогает только
  нетронутые стартовые журналы.
- Типовая номенклатура по подразделениям в демо и импорт номенклатуры из Excel — ADR-0135.
