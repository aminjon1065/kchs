# 0031. Порт справочника вместо обращения ядра к модулю идентификации

Статус: Принято

Контекст: ядру нужны имена авторов (лента активности, уведомления, обсуждения)
и оргструктура (политики типов: «руководитель видит поручения подчинённых»).
Прямой импорт `modules/identity` нарушает правило границ «kernel/* не
импортирует modules/*» (01-overview.md) — это подтвердил `dependency-cruiser`.

Решение: ядро объявляет порт `kernel/directory/port.ts`
(`refs`, `displayName`, `manager`, `subordinates`, `unitHead`); модуль
`identity` регистрирует реализацию при старте — тем же приёмом, что и реестр
типов объектов. Разрешение сессии для WebSocket-шлюза передаётся как зависимость
из композиционного корня (`main.ts`).

Альтернативы:
- Разрешить `kernel → modules/*/public.ts`: ослабляет правило, которое иначе
  проверяется автоматически.
- Перенести таблицы пользователей в ядро: противоречит модели данных
  (05-data-model.md относит их к идентификации) и раздувает ядро.

Последствия: ядро тестируется без модулей (пустая реализация по умолчанию),
границы проверяются в CI, замена источника людей (LDAP, внешний каталог)
сводится к другой реализации порта.
