# 0164. Отчёты: библиотека шаблонов, версии с возвратом через документ, оглавление и нумерация, A3, новые блоки, группы и внешние адреса рассылки

Статус: Принято
Дата: 2026-09-25

## Контекст

«Отчёты» вошли в «закончить разработку» (05-risks §5). В руководстве 12 «Чего пока нет»:
- нет библиотеки шаблонов (старт — только «В отчёт» из тетради);
- нет версий и отката;
- страница всегда A4;
- нет оглавления и нумерации разделов;
- нет блоков «изображение», «файл», «дашборд»;
- получатели рассылки — только сотрудники;
- нет своих параметров, кроме «Периода» и «Территории»;
- нет согласования и подписи отчёта отдельным маршрутом.

Шаблон отчёта — совместный документ Yjs (ADR-0078): правки идут через сервер совместного
редактирования, а таблица `reports` хранит его JSON-снимок.

## Решение

1. **Библиотека шаблонов** — `GET /reports/templates`.
   - Встроенные шаблоны КЧС — в коде модуля: «Ежедневная оперативная сводка», «Итоги
     паводкового сезона», «Исполнение поручений». Это каркас разделов с подсказками и
     относительным периодом, источники блоков выбирает автор. Подписи в выборе — словари
     интерфейса (`data.report.templates.builtin.<ключ>`); тексты блоков — на основном языке.
   - Отчёт организации становится шаблоном отметкой `meta.template` в сводке объекта реестра
     (`POST /reports/{id}/template`, право `manage`, событие `report.updated` с
     `changed: ['template']`). В библиотеке его видят те, кто видит сам отчёт.
   - Новый отчёт копирует блоки, параметры и печать шаблона через обычный
     `POST /reports`: ссылки блоков проверяются правами автора, как всегда.
2. **Версии — таблица `report_versions`** (блоки, параметры, печать, повод, подпись, автор).
   - Поводы: «Вручную» (с подписью), «При формировании» — только если шаблон изменился с
     последней версии, «Перед возвратом».
   - Каждая запись публикует `report.version_saved`.
   - Перед снимком открытый документ сбрасывается в базу (`CollabService.change` без правки,
     как у страниц базы знаний): версия берёт то, что видят соавторы.
   - **Возврат пишет снимок версии в документ Yjs сервером** (`CollabService.change`):
     соавторы видят его сразу, JSON-снимок обновляет обычный путь сохранения документа.
     Текущее состояние перед этим — версией «Перед возвратом», поэтому возврат обратим.
3. **Печать.**
   - `ReportSettings.pageSize` — A4 или A3. Движок печатает PDF нужного формата, а шаблон DOCX
     получает размер страницы; ширина окна страницы печати — ширина поля печати формата.
   - `toc` и `numbering`. Разделы — подписи блоков и заголовки текста: подпись и заголовок
     первого-второго уровня — раздел, третьего и глубже — подраздел.
   - Страница печати пишет номера прямо в подписи и заголовки блоков и строит оглавление;
     модель DOCX получает те же подписи и оглавление текстовым блоком с разрывом страницы.
     Движку для этого ничего не нужно.
   - Номеров страниц в оглавлении нет: Chromium не отдаёт разбиение по страницам, а поле TOC
     Word без обновления при открытии пустое.
4. **Новые блоки** (`image`, `file`, `dashboard`; зависимости — в `reportBlockReferences`).
   - **Изображение** — файл-картинка до 8 МБ отдаётся data URL (`GET
     /reports/{id}/images/{fileId}`: `view` отчёта и `download` файла). Так картинка доходит
     до браузера движка, которому хранилище файлов недоступно. Файл с грифом не отдаётся:
     копия с водяным знаком — свой путь (ADR-0085). В DOCX — снимком, как графики.
   - **Файлы** — названия видимых смотрящему файлов списком (`GET /reports/{id}/files`);
     в DOCX — маркированный список.
   - **Дашборд** — графики и показатели дашборда с фильтрами по умолчанию сеткой; в DOCX —
     снимком всей сетки. Маршрут данных дашборда помечен `readOnly`: страница печати с токеном
     печати ходит только в чтение. Параметры отчёта к дашборду не применяются: соответствие
     фильтров дашборда периоду и территории отчёта — отдельная работа.
5. **Получатели рассылки** (`ReportScheduleInput`: `groups`, `roles`, `emails`).
   - Группы и роли разворачиваются в действующих сотрудников на момент каждой рассылки.
     Каждый получает свой рендер под своими правами, как раньше.
   - Внешние адреса — один запуск под правами автора рассылки (того, кто сохранил
     расписание); письмо с файлами уходит им (`report_runs.external_emails`), без ссылки в
     систему.
   - Отчёт с грифом «Конфиденциально» наружу не уходит: запуск «Пропущен» с причиной, в
     диалоге — предупреждение. Та же граница, что у исходящего письмом (ADR-0149).
   - Проверка «указан хоть один получатель» перенесена из схемы в сервис: получателем может
     быть только роль или только адрес.
6. **Не делается:**
   - **Свои параметры отчёта.** Параметр должен доходить до каждого блока: привязки полей
     запросов, графиков и показателей, параметры рассылки, страница печати, «В отчёт» из
     тетради. Это переработка параметров тетради (ADR-0071), а не отчёта.
   - **Согласование и подпись отчёта маршрутом.** Они уже есть через документооборот:
     «Исходящим документом» (ADR-0127) заводит черновик с файлом прогона, дальше маршрут,
     подпись и регистрация. Второй путь согласования разошёлся бы с первым.

## Альтернативы

- **Версии — история обновлений Yjs.** Отвергнуто: полная история документа растёт без
  границ и не даёт «версию» в понятном пользователю смысле. Снимок JSON с поводом и подписью
  проще показать и вернуть.
- **Внешним адресам — рендер «под правами получателя».** У внешнего адресата прав в системе
  нет. Рендер под правами автора рассылки честно показывает, чьи данные уходят, а гриф
  ограничивает, что может уйти.
- **Картинка по подписанной ссылке хранилища.** Отвергнуто: из контейнера движка адрес
  хранилища для браузера пользователя недоступен.

## Последствия

- Контракт отчёта: блоки `image`, `file`, `dashboard`; настройки `pageSize`, `toc`,
  `numbering`; `ReportRecord.template`; получатели `groups`, `roles`, `emails`;
  `ReportRenderStart.pageSize`; фигура модели печати `image` и `dashboard`. Старые отчёты
  читаются со значениями по умолчанию, миграции данных не нужно.
- События: `report.version_saved`; у `report.updated` — `changed: template`.
- Миграции: `report_versions`, `report_runs.external_emails`.
