# 0005. REST + OpenAPI из zod-контрактов
Статус: Принято. Дата: 2026-09-17

## Контекст
Клиенты: web (TS), Python-движок, интеграции, ИИ-инструменты, Telegram-бот. Нужна одна поверхность API с типами и документацией.

## Решение
REST `/api/v1`, схемы zod → типы TS + OpenAPI + типизированный клиент; problem+json; курсорная пагинация; действия через `:verb`.

## Альтернативы
tRPC (только TS, нет OpenAPI без надстроек); GraphQL (сложность авторизации на полях, N+1, лишняя гибкость при одном клиенте).

## Последствия
Единый API для всех потребителей; генерация клиента в CI; контракты как источник истины.
