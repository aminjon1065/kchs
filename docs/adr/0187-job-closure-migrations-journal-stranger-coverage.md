# 0187. Хвосты этапов 1–2: закрытие записей по сбою и отмене заданий, журнал миграций, покрытие теста «посторонний»

Статус: Принято
Дата: 2026-10-05

## Контекст

Разбор этапов 1–2 укрепления (`04-delivery/07-architecture-hardening.md` §5.1 и открытые
вопросы частей 2В) оставил пять хвостов.

1. **Отмена закрывала только импорт.** По `job.cancelled` (ADR-0172) закрывался лишь импорт
   датасета. Обработка файла, рендер документа, анализ, колоночная копия, пайплайн,
   источник и запуск отчёта слушали только `job.failed`, и после отмены их записи
   оставались «в работе». У PDF-представления версии документа, расшифровки встречи и
   запуска правила не было подписчика и на окончательный сбой: если движок падал или
   задание не укладывалось в предел времени, они навсегда оставались «готовится».
   Восемь подписчиков повторяли один и тот же код: найти задание, сверить очередь и имя,
   достать данные, закрыть запись.
2. **Ключ прогресса.** `kchs:job:<id>` в кэше только писался, читателя не было (ADR-0175).
3. **Журнал миграций.** `GRANT … ON ALL TABLES` давал `kchs_app` правку и удаление строк
   `public.__migrations`, то есть возможность скрыть или подделать применённую миграцию,
   в обход сверки хэшей (ADR-0173).
4. **Покрытие теста «посторонний не видит»** (ADR-0186).
   - Маршруты `{ capability }` с параметром пути тест не обходил.
   - Вложенный параметр делегированного маршрута (пункт, строка, версия) подставлялся
     случайным UUID. Сервис, который ищет вложенный ресурс раньше проверки прав, отвечал
     404, и тест проходил вхолостую.
5. **Отзыв чужого замещения** отвечал 403 и тем подтверждал, что замещение с таким id есть.

## Решение

1. **Закрытие записей по заданию — общей фабрикой `jobClosedSubscriber`**
   (`kernel/jobs/outcomes.ts`).
   - Модуль называет свои виды заданий и функцию закрытия записи. Подписчик слушает
     `job.failed` и `job.cancelled`, находит задание, сверяет вид и передаёт причину: текст
     сбоя или «Задание отменено».
   - Отдельного статуса отмены у этих записей нет: отмена закрывает их, как сбой, с этой
     причиной. Так уже было у импорта, контракты статусов не меняются.
   - Переведены прежние подписчики: файлы, рендер документа, анализ, импорт, источник,
     пайплайн, отчёт. Колоночная копия слушает отмену в своём подписчике.
   - Добавлены подписчики для PDF версии (`applyPdfResult` со статусом «сбой»), расшифровки
     (`TranscriptService.failPending`) и запуска правила (`RuleRuns.failOpen`).
   - Закрытие защищённое: завершённую запись (готовую расшифровку, выполненный запуск,
     готовый PDF) поздний сбой не перезаписывает.
   - Имена прежних подписчиков не меняются — это их группы событий (ADR-0171).
2. **Ключ прогресса удалён.** Прогресс и сообщение задания хранит его запись
   (`jobs.progress`, `jobs.message`), открытым экранам их доставляет канал `rt:job`.
3. **Журнал миграций пишет только мигратор.**
   - Запись в `public.__migrations` отозвана у ролей приложения. Чтение оставлено: его
     просит `pg_dump` резервной копии ролью `kchs_app`.
   - Если миграции идут ролью `kchs_app` (нет `DATABASE_MIGRATOR_URL`), отзыв пропускается:
     приложение не отнимает права у самого себя.
   - Тест правки хэша идёт соединением мигратора.
4. **Тест «посторонний не видит» шире.**
   - Он обходит маршруты `{ capability }` с параметром пути (34): способность проверяется
     до обработчика, и посторонний без неё получает 403 при любых значениях в пути.
   - Вложенные параметры делегированных маршрутов объектов матрицы подставляются
     настоящими: пункт чек-листа задачи, строка датасета, резерв номера журнала, версия
     страницы.
   - Где вложенный ресурс без движка, почты или регистрации документа не создать
     (сегмент расшифровки, письмо исходящего, направление на резолюцию), постороннего
     проверяет профильный тест на настоящем ресурсе. Это список `NESTED_ELSEWHERE` со
     ссылками; для письма и направления проверки дописаны.
   - Новый делегированный маршрут с вложенным параметром без значения или строки списка
     роняет тест.
5. **Посторонний при отзыве замещения получает 404**, как с недоступным объектом.
   Заместитель (вторая сторона) по-прежнему получает понятный отказ «завершить может
   только назначивший».

## Альтернативы

- **Статус `cancelled` у каждой записи** (рендер, запуск отчёта, пайплайн…). Он честнее
  в интерфейсе, но меняет контракты статусов и экраны в шести модулях. Отказались: причина
  «Задание отменено» в тексте ошибки различает отмену и сбой.
- **Один подписчик ядра на все закрытия** вместо подписчиков модулей. Новая группа событий
  после обновления начала бы с новых событий (ADR-0171), а прежние группы модулей стали бы
  лишними. Фабрика сохраняет группы.
- **Читатель ключа прогресса** — экран заданий мог бы брать прогресс из кэша. Но запись
  задания уже его хранит, и второй источник только расходился бы с ней.

## Последствия

- Новое задание с записью модуля закрывается одной строкой `jobClosedSubscriber`, без
  повторения поиска задания и сверки вида.
- Тесты:
  - `kernel/jobs/outcomes.test.ts`;
  - `job-closed.test.ts` — механизм, обработка файла и то, что каждый подписчик закрытия
    слушает и отмену;
  - `db-maintenance.test.ts` — журнал миграций только на чтение;
  - `kernel.test.ts` — 404 постороннему при отзыве замещения;
  - `access-matrix.test.ts` — способности и вложенные ресурсы;
  - `documents-email.test.ts`, `document-resolutions.test.ts` — посторонний на настоящих
    вложенных ресурсах.
