# 0204. Офлайн-очередь веба: отправки в IndexedDB, ключ идемпотентности сдачи, справочники на устройстве

Статус: Принято
Дата: 2026-10-12

## Контекст

Концепт-нота КЧСиГО (ред. 2.0), §4.2: неустойчивая связь в горных районах и сезонные
отключения электричества; «мобильное приложение с отложенной отправкой». Разбор
`docs/04-delivery/08-architecture-concept-note-and-signatures.md` §7: очередь отправок форм
сбора и донесений в IndexedDB, сжатие фото на устройстве, отправка при появлении сети,
ключ идемпотентности у сдачи формы, кэш справочников и подложки района.

Ограничения:

- сдача сводки (ADR-0103, ADR-0129) — `POST /forms/submissions/{id}/submit` — защищена
  статусом: повтор после успешной сдачи отвечал 409 «Сводка уже сдана»; очередь, потерявшая
  ответ, не отличила бы успех от отказа;
- приложение — SPA с CSP-nonce на каждую выдачу `index.html` (ADR-0043): страница не
  кэшируется, холодный старт без сети невозможен без пересмотра CSP и служебного потока;
- бюджет оболочки — 400 КБ (ADR-0166).

## Решение

1. **Ключ идемпотентности сдачи.** `FormSubmissionSubmitInput.clientKey` (uuid устройства);
   сервер хранит ключ последней сдачи (`form_submissions.submit_key`). Повтор с тем же
   ключом возвращает уже записанную сдачу — в любом статусе: если сводку успели вернуть,
   старый повтор не пересдаёт её прежними значениями. Другой ключ после сдачи — по-прежнему
   409. Веб шлёт ключ всегда, и с сетью тоже.
2. **Очередь `apps/web/src/shared/offline/`**: IndexedDB `kchs-offline` (без неё — память
   вкладки). Сдача с сетевой ошибкой (нет соединения, 408, 429, 502–504) ложится в очередь;
   ключ записи — ключ идемпотентности на всю её жизнь; новая правка той же сводки заменяет
   значения, ключ оставляет. Досылка — при входе, при событии `online` и раз в 30 секунд, пока
   очередь не пуста; по порядку, до первой сетевой ошибки; один проход за раз (две вкладки
   защищает ключ). Отказ по существу (400, 403, 409) — запись «не сдана» с причиной и кнопкой
   «Убрать из очереди»: решает человек.
3. **Очередь — по сотруднику.** Запись помечена сотрудником; досылаются только записи
   вошедшего: на общем устройстве чужие сдачи не уходят от вашего имени и не видны вам.
4. **Видно, что ждёт.** Экран сводки — «Ждёт отправки» с пояснением; строка состояния —
   «N отправок ждут сети»; когда отправка дошла — уведомление «Сводка из очереди сдана» и
   перечитанная сводка.
5. **Справочники на устройстве.** Назначения сводок и схема формы запоминаются при
   успешном ответе и отдаются при сетевой ошибке (`cachedFetch`) — тоже по сотруднику.
   Пока страница открыта, этого хватает, чтобы открыть и заполнить сводку без сети.

## Чего нет и почему

- ~~**Холодный старт без сети.**~~ Сделано в ADR-0207 (13.10.2026): служебный поток держит
  оболочку, ответ из кэша несёт свой CSP и тот же nonce; профиль вошедшего на устройстве;
  сводку можно открыть без сети местным черновиком.
- ~~**Сжатие фото.**~~ Сделано в ADR-0208 (13.10.2026): поле датасета `file` форма
  спрашивает снимком, сжатие на устройстве, файл у формы, без сети снимок ждёт в очереди.
- **Донесение без сети.** Донесение — документ модуля документооборота; очередь умеет одну
  отправку — сдачу сводки — и расширяется видом записи, когда у создания документа будет
  ключ идемпотентности.
- **Подложка района (PMTiles) на устройстве.** Выгрузка района — серверная обрезка архива
  подложки и десятки мегабайт в хранилище браузера; на бюджет оболочки не влияет, но это
  отдельная работа (выбор района, обновление, место на телефоне).

## Альтернативы

- **Идемпотентность заголовком `Idempotency-Key` и общей таблицей ответов.** Отклонено пока:
  у сдачи уже есть строка, к которой ключ привязывается естественно; общий механизм
  понадобится, когда в очереди появятся другие виды отправок.
- **Background Sync служебного потока.** Отклонено: есть не во всех браузерах (Safari), а
  служебный поток регистрируется только с push-уведомлениями.
- **Хранение очереди в `localStorage`.** Отклонено: синхронный, 5 МБ и строки — а в очереди
  будут фото.

## Последствия

- Миграция: `form_submissions.submit_key`; контракт `FormSubmissionSubmitInput`.
- Тест повтора сдачи (`forms.test.ts`) и тесты очереди (`shared/offline/queue.test.ts`).
