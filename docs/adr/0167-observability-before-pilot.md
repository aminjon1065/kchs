# 0167. Наблюдаемость до пилота: «Здоровье системы» из метрик, оповещения в чарте, трассы движка, предел памяти Redis

Статус: Принято
Дата: 2026-09-25

## Контекст

ADR-0147 поставил экспортёры служб данных и Alertmanager и перечислил, чего не хватает:

- трасс движка;
- метрик диска сервера;
- предела памяти Redis;
- экрана «Здоровье системы» из метрик;
- оповещений в чарте S2.

Администратор Комитета смотрит в консоль, а не в Grafana. Экран опрашивал только
компоненты и не показывал ни нагрузку, ни уже сработавшие оповещения. Без `maxmemory`
оповещение `KchsRedisMemory` в S1 не могло сработать. В кластере правила приходилось
переносить вручную, а имя задания в Prometheus зависело от имени релиза. Задание в
движке обрывало трассу, начатую запросом в api.

## Решение

1. **«Здоровье системы» из Prometheus и Alertmanager.** Ответ `/admin/health` получил
   два блока.
   - `metrics` — мгновенные запросы к Prometheus за 5 минут:
     - запросы в секунду, доля 5xx и p95 ответа api (задания `kchs-api` и `kchs-dev`,
       без `/health`);
     - наибольший RSS api и worker;
     - размер базы приложения (имя — из `DATABASE_URL`) и число подключений;
     - занятая и предельная память Redis.
   - `alerts` — действующие оповещения Alertmanager (`/api/v2/alerts` без заглушённых и
     подавленных), критичные сверху, не больше 50.

   У каждого блока три состояния:

   | Состояние | Когда |
   |---|---|
   | `off` | адрес не задан |
   | `unavailable` | служба не ответила за 2 с |
   | `ok` | ответ есть; `null` у значения — нет данных за окно |

   Ответ кэшируется на 15 с. Адреса — `PROMETHEUS_URL` и `ALERTMANAGER_URL`: в `x-app-env`
   по умолчанию службы профиля observability, в чарте — `observability.prometheusUrl` и
   `observability.alertmanagerUrl`. Заодно экран проверяет движок (по
   `ENGINE_INTERNAL_URL`) и показывает версию установки `KCHS_VERSION`: в compose и в
   чарте это тег образов, при разработке — «разработка».
2. **Предел памяти Redis:** `--maxmemory` при прежнем `noeviction`. В S1 предел задаёт
   `REDIS_MAXMEMORY`, по умолчанию 1 ГБ. Во встроенном Redis чарта —
   `redis.embedded.maxmemory`, 768 МБ при лимите контейнера 1 ГиБ: запас на буферы
   клиентов и перезапись AOF. У предела Redis отказывает в записи и не вытесняет задания
   очередей. Оповещение `KchsRedisMemory` на 90 % теперь срабатывает и в S1.
3. **Оповещения в чарте S2.** При `observability.prometheusRule.enabled` чарт ставит
   `PrometheusRule` с теми же правилами. `files/alerts.yml` — копия
   `infra/observability/prometheus/alerts.yml`, совпадение сверяет задание CI «Правила
   оповещений». `ServiceMonitor` чарта ставит имя задания `kchs-api` / `kchs-worker`
   relabeling'ом, а не берёт его из имени сервиса. Правила и экран работают с теми же
   метками, что в S1.
4. **Трассы движка.** Необязательная группа зависимостей `otel` входит в образ. Трассы
   включает `OTEL_EXPORTER_OTLP_ENDPOINT` — тот же коллектор, что у api и worker. Без
   адреса пакеты OpenTelemetry не импортируются. Спаны:
   - входящие запросы FastAPI, кроме `/health`;
   - исходящие запросы httpx: обратные вызовы в api уносят `traceparent`;
   - задания очередей.

   Спан задания продолжает трассу запроса api, который его поставил: контекст лежит в
   опциях задания BullMQ под ключом `tm`. Имя и атрибуты спана — как у TypeScript-воркера
   (`job <очередь> <имя>`, `messaging.*`), так что задание видно в одной трассе с
   запросом, где бы оно ни выполнялось.

## Альтернативы

- **Экран читает `/metrics` самого api.** Это только текущий процесс: ни worker, ни база,
  ни Redis туда не попадают, а Prometheus уже всё собирает.
- **Grafana во фрейме консоли.** Второй вход, CSP и права Grafana ради нескольких чисел.
  Grafana остаётся для разбора.
- **Правила в чарт через символьную ссылку или шаблон из-за пределов чарта.** Helm не
  читает файлы вне чарта, а ссылки ломаются при упаковке. Копия со сверкой в CI проще.
- **`opentelemetry-instrument` для движка.** Обёртка грузит SDK и все инструментовки даже
  при выключенных трассах. Явная настройка оставляет правило «выключено — не загружено»,
  как у api (ADR-0045).

## Последствия

- Из списка ADR-0147 остаются метрики диска сервера: нужен node-exporter. Место видно по
  MinIO: в S1 тома всех служб обычно на одном диске.
- Запросы экрана опираются на имена заданий `kchs-api`, `kchs-worker`, `kchs-dev` и на
  имена метрик экспортёров. При их смене экран покажет «нет данных», а не ошибку.
- Образ движка нужно пересобрать, чтобы появилась группа `otel`. Тесты движка в CI ставят
  её (`--extra otel`).
- Новый предел Redis применяется при пересоздании контейнера `redis`.
