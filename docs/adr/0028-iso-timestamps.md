# 0028. ISO 8601 для `timestamptz` на уровне типа колонки

Статус: Принято

Контекст: контракты API описывают время как `z.iso.datetime({offset: true})`.
Драйвер `postgres.js` в связке с `timestamp(..., { mode: 'string' })` отдаёт
формат PostgreSQL (`2026-09-17 18:48:34.534+00`), который не проходит валидацию
ответа: каждый маршрут, возвращающий время из БД, падал с 500.

Решение: собственный тип колонки Drizzle `timestamptz` с `fromDriver`,
приводящим значение к ISO 8601. Все временные поля объявляются через `tsCol()`,
`createdAt()`, `updatedAt()` из `schema/_shared.ts`. Тип в SQL не изменился
(`timestamp with time zone`), миграции не затронуты — проверено
`drizzle-kit generate` (изменений нет).

Альтернативы: переопределение парсера типа 1184 в `postgres.js` (не сработало
через drizzle); `mode: 'date'` + ручное `toISOString()` в каждом отображении
(шум в коде и риск пропустить поле); ослабление контракта (недопустимо —
контракт описывает внешнее API).

Последствия: время из БД везде ISO 8601, клиент разбирает его `Date`/`Intl` без
предобработки. Локальные даты (`date`) остались строками `YYYY-MM-DD`.
