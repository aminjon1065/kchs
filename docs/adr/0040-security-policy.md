# 0040. Политика безопасности: системные настройки, кэш процесса, шлюз незавершённой настройки входа

Статус: Принято
Дата: 2026-09-18

Контекст: `17-security.md` §2 требует обязательности MFA по роли, отключения гостевых
ссылок политикой (P0-E06 S04) и настраиваемого простоя сессии. Ключи
`security.requireMfaRoles`, `security.allowShareLinks`, `security.sessionIdleHours`
были объявлены, но не применялись. Вопрос N3 (обязательна ли MFA для администраторов
с первого дня) открыт; рабочее допущение — MFA доступна всем, обязательность включает
администратор.

Решение:
- Политика — системные настройки `security.*`, контракт `SecurityPolicy`
  (`packages/contracts/admin/security.ts`). Читает `SecurityPolicyService` ядра;
  процесс держит значение в памяти 10 секунд: изменение применяется сразу в процессе,
  где его сделали, и не позже чем через 10 с в остальных. Испорченное значение
  настройки заменяется умолчанием — сбой данных не запирает вход.
- Меняет политику администратор системы (`admin.system`):
  `GET/PATCH /admin/security-policy` в модуле идентификации (он проверяет, что роли
  существуют). Каждое изменение — запись аудита `security.policy_changed` (notice)
  с состоянием до и после.
- Обязательная MFA: при разрешении сессии модуль идентификации сообщает, подключён ли
  второй фактор; ядро выставляет `ctx.mfaEnrollmentRequired`. Пока он не подключён,
  сервер отвечает `403 mfa_enrollment_required` на всё, кроме `GET /me`, подключения
  TOTP и выхода (флаг маршрута `allowPendingMfaEnrollment`). Сначала проверяется
  временный пароль, затем MFA — смена пароля не требует второго фактора. Realtime-шлюз
  не принимает подключение, пока настройка входа не завершена. Отключить второй
  фактор, обязательный для роли, нельзя (`422 policy_violation`).
- Гостевые ссылки при запрете политикой не создаются (`422 policy_violation`),
  выданные ссылки и токены доступа не действуют — приостанавливаются, а не
  отзываются: включение политики возвращает их действие. Список ссылок объекта
  сообщает `allowed`, чтобы интерфейс не предлагал недоступное.
- Простой сессии: `security.sessionIdleHours`, иначе `SESSION_IDLE_HOURS` из конфигурации.

Альтернативы: политика в переменных окружения — меняется только перезапуском и не
попадает в аудит; чтение настроек из БД на каждом запросе без кэша — лишний запрос
на каждый вызов API; инвалидация кэша по событию `settings.changed` — события
разбираются группой потребителей, и сигнал получает только один процесс.

Последствия: администратор включает обязательную MFA в консоли («Безопасность»), и
сотрудники с ролью видят только экран подключения TOTP; политика, включённая во
время работы, применяется к открытой вкладке при следующем запросе — клиент по коду
`mfa_enrollment_required` перечитывает профиль. Новый код ошибки
`mfa_enrollment_required` добавлен в `ERROR_CODES`.
