# 0057. Территории и справочники: модуль GIS, территории ответственности, подстановки в запросах

Статус: Принято
Дата: 2026-09-19

## Контекст

P1-E07 требует справочник территорий («модель, загрузка из seed, дерево, пикер, семантика в
запросах», КП: агрегация по уровню через `territory_level()`), подписи справочников в таблице
(сценарий приёмки фазы 1 №2) и политику «только своя область» (сценарий №5).
`05-data-model.md` описывает `territories` и `territory_closure`, `07-gis-engine.md` §11 —
иерархию и использование, `contracts/query-spec.md` — функции `lookup_label`,
`territory_level`, `territory_name`. Открытыми оставались: где живёт справочник и откуда он
загружается, откуда берутся территории пользователя (`@my_territories`) и как функции
справочников выполняются, если роль `kchs_query` читает только таблицы строк `ds.t_*`
(ADR-0048).

## Решение

1. **Модуль `gis`** владеет таблицами `territories` (объект реестра типа `territory`: код,
   родитель, уровень, названия ru/tg/en, центроид; граница `geom` — с данными фазы 2) и
   `territory_closure` (строка «сам себе» и все предки). Уровни — `country`, `region`,
   `district`, `jamoat`, `settlement`. Справочник открыт всем сотрудникам выдачей ACL
   `everyone:*` на уровень `view`: права дальше работают через `authorize()`, поиск находит
   единицу по коду и названиям на всех языках. Публичный API модуля — `TerritoryService`
   (загрузка, список, карточка) и `territoryIndex()` — справочник в памяти процесса
   (иерархия, коды, названия), который перечитывается, когда меняется метка версии в Redis.
2. **Загрузка.** `pnpm db:seed` (оба профиля) загружает 74 единицы — страну, 5 регионов
   (ISO 3166-2:TJ) и 68 районов — из статического `apps/api/src/seed/territories.json`.
   Файл получен из `kchs_engine/demo/reference.py`: API не зависит от движка при установке,
   а совпадение с демо-данными (коды `territory_code` в наборах) проверяет тест движка
   `tests/test_territory_seed.py`. Загрузка повторяема: существующие коды не меняются.
3. **Территории ответственности.** У подразделения появилась территория (`org_units.territory_id`,
   правка — `PATCH /org/units/{id}`). `PrincipalSet.territoryIds` — у каждого своего
   подразделения территория его самого или ближайшего предка, где она задана; макрос
   `@my_territories` — эти территории и явный атрибут пользователя `territoryIds`. Политика
   «только своя область» — политика строк `{field, op: 'within', value: '@my_territories'}`:
   `within` раскрывает вложенные территории по замыканию. Смена территории подразделения
   сбрасывает кэш множеств принципалов.
4. **Функции справочников — подстановками.** Компилятор не соединяет запрос с таблицами
   `public` (роль `kchs_query` их не читает, ADR-0048): `territory_level(x, 'region')`,
   `territory_name(x)` и `lookup_label(поле)` компилируются в `($n::jsonb ->> значение)` с
   одной подстановкой «значение → результат» на запрос. Подстановки передаёт вызывающий в
   `CompileContext.references`; если нужной нет, `compileQuery` бросает
   `MissingReferencesError` со списком запросов, `QueryService` загружает их и компилирует
   заново. Версии подстановок входят в ключ кэша результата. Аргумент территориальных функций —
   поле-территория (результат `territory_level` — тоже территория, с подписями и фильтрами)
   или код территории текстом (результат — код). Подписи `lookup_label` строятся запросом к
   справочнику **с правами пользователя** (его политики строк и столбцов действуют); справочник
   недоступен — подписей нет, ошибки и чужих значений тоже; справочник больше 10 000 строк —
   ошибка запроса.
5. **Значения поля-территории** при вводе и импорте: идентификатор справочника, код или
   название на любом языке (без учёта регистра, «ё» = «е»). Неизвестное значение — ошибка
   поля «Нет территории…», неоднозначное название — просьба указать код. Импорт: тип
   `territory` в сопоставлении, API передаёт движку в задании таблицу сопоставления
   «ключ → идентификатор» (движок справочник не читает), ошибки строк —
   `unknown_territory` и `ambiguous_territory`.
6. **Интерфейс.** Грид и фильтры получают у поля-территории и поля со справочником «варианты»
   (значение → подпись): подпись вместо значения, правка выбором, вставка по подписи;
   подписи справочника загружаются с правами пользователя (до 2000 строк). Фильтр
   «в пределах» — дерево справочника с поиском. Экран «Территории» — дерево и карточка.

## Альтернативы

- **Соединение с `public.territories` в SQL** — короче, но роль `kchs_query` получила бы право
  читать таблицу приложения; при ошибке переписывателя сырого SQL это путь к чужим данным.
- **Территории как справочный датасет в `ds`** (зеркало из `07-gis-engine.md` §11) — даёт
  соединения в компиляторе, но иерархию и названия всё равно нужно держать рядом с запросом;
  зеркало остаётся задачей фазы 2 (`dataset_row_id` в таблице уже есть).
- **Территории пользователя только атрибутом учётной записи** — пришлось бы вести их у каждого
  сотрудника вручную; подразделение уже отвечает за территорию, атрибут остаётся для исключений.

## Последствия

- Руководитель регионального управления получает «свою область» без ручной настройки: политика
  `within @my_territories` действует во всех путях к данным (таблица, графики, дашборды, экспорт).
- Подстановка территорий невелика (сотни единиц); для населённых пунктов (десятки тысяч) при
  загрузке полного классификатора понадобится подстановка только по значениям запроса —
  пересмотреть вместе с зеркалом справочника в фазе 2.
- Смена справочника территорий меняет метку версии и ключи кэша запросов, которые его используют.
