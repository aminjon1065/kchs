# 0184. Таблицы ядра — только через его сервисы; запись в них и сырой SQL — под проверкой CI

Статус: Принято
Дата: 2026-10-05

## Контекст

Часть 2В-1 этапа 2 укрепления архитектуры (`04-delivery/07-architecture-hardening.md`,
§5.0 и §6). После переноса схемы к владельцам (ADR-0178) правило dependency-cruiser
`kernel-tables-via-services` пускает модуль к таблицам ядра только на чтение реестра
объектов. Но в базе известных нарушений api было 15 записей, и правило не видит две вещи:
запись модуля в таблицу ядра и таблицу, названную в тексте SQL по имени.

| Где | Что |
|---|---|
| chat, 7 файлов | сам писал `conversations`, `conversation_members`, `messages` — 15 мест записи мимо `DiscussionService` |
| documents, 5 файлов | читал `acl_entries`, `acknowledgment_requests`, `process_instances`, `links` |
| data, automation, identity | `dependencies`; `spaces`; `spaces` и профиль в `users` |

Попутно нашлись записи без события (правило 3):

- `PATCH /me` правил профиль в `users` без `user.updated` и без сброса кэша принципалов;
- синхронизация каталога LDAP/AD заводила должности без события и аудита и писала `org_units.external_id` напрямую.

Непрочитанное считалось двумя способами:

- список бесед чата: чужие неудалённые сообщения после отметки прочтения, без неё — после вступления в беседу или собственного последнего сообщения;
- обсуждение объекта (`DiscussionService.unreadCount`): все сообщения после отметки, включая удалённые; системные (без автора) не считались; без отметки — вся беседа.

Сырой SQL — `sql.raw` Drizzle и `.unsafe` postgres.js — встречался в 55 местах в 16 файлах вне
`modules/data/infra`, `shared/db` и `packages/query`:

- сервисы данных — 40 мест;
- тайлы, экстент и статистика слоя — 3;
- реестр объектов и поиск по смыслу — 4. Вектор запроса вставлялся литералом из ответа движка без проверки;
- адаптер внешней СУБД — 3;
- сид — 5.

Имена экранировались восемью способами: `ident` физических таблиц (кавычки без удвоения),
`alias` строк датасета, `quote` тайлов, экстента, детализации и диалектов компилятора,
`quoteIdent` SQL-лаборатории и адаптера внешней базы, ссылки выражений статистики слоя (без
удвоения кавычек) и пайплайнов (кавычки из имени выбрасывались), имена столбцов в сиде.

## Решение

### Таблицы ядра — только через его сервисы

Модуль читает таблицы ядра только через сервисы, порты и фрагменты SQL ядра. Напрямую — только
реестр объектов `objects`, на чтение. Новые API ядра:

- **Обсуждения** (`kernel/discussions`):
  - `DiscussionService.createConversation` — беседа-объект: личная, группа, канал;
  - `DiscussionService.post` с `meta` — след быстрого действия: задача, встреча, пересылка — пишется вместе с сообщением, а не правкой после;
  - `DiscussionMembers` — состав: `add`, `remove`, `ids`, `list`, `audience` (кому слать, без заглушивших), `setSettings` (закреп, звук, архив);
  - `DiscussionQueries` — чтения:
    - `inbox` — список бесед с непрочитанным и последним сообщением, видимость — `visibleObjectsSql`;
    - `unreadCount`, `conversation`, `briefs`, `involving`;
    - `message`, `messages` — по идентификаторам, `live` — без удалённых;
    - `search` — по тексту беседы.

  Модуль чатов хранит своё (системный ключ канала, закрепы, индекс поиска), а беседы, состав и
  сообщения пишет только ядро.
- **Связи** (`kernel/links`):
  - `LinkService.dependencyTargets` — цели зависимостей вида;
  - `LinkSql.firstTarget` и `LinkSql.sources` — фрагменты для списков модуля: «ответ на», «о территории», «есть ли ответ».
- **Пространства:** `SpaceService.personalOf`, `keyOf`, `titles`.
- **Доступ, ознакомление, процессы:**
  - `explicitUserEntries` — явные записи ACL людей на объект;
  - `Acknowledgments.hasRequests`;
  - `ProcessView.hasAny`.
- **Справочник:**
  - `UserService.updateProfile` — профиль с событием `user.updated` и сбросом кэша принципалов после фиксации;
  - `OrgService.setExternalId` — связь подразделения с каталогом;
  - синхронизация каталога заводит должности через `PositionService.create`.

Осознанное исключение одно: identity пишет в учётную запись `users` столбцы входа и связи с
каталогом (ADR-0179):

- отметку входа и смены пароля;
- источник входа;
- идентификатор и DN каталога, время синхронизации;
- статус учётной записи, только что созданной из каталога, — в той же транзакции.

Остальное о людях identity пишет через сервисы справочника.

### Одно определение непрочитанного

`DiscussionQueries` считает непрочитанное одним выражением и для списка бесед, и для обсуждения
объекта. Считаются чужие неудалённые сообщения, системные тоже:

- после отметки прочтения;
- без неё — после вступления в беседу;
- иначе — после своего последнего сообщения (обсуждение объекта, где отметок ещё нет);
- иначе — все.

Для чата ничего не меняется. Обсуждение объекта перестаёт считать удалённые и начинает считать
системные сообщения.

### Сырой SQL — только в слоях, устроенных для него

`sql.raw` и `.unsafe` допустимы:

| Где | Зачем |
|---|---|
| `apps/api/src/modules/data/infra/**` | физическое хранение датасетов: DDL схемы `ds`, COPY импорта, имена из `ident` |
| `apps/api/src/shared/db/**` | миграции, права ролей, секции аудита; чтение текста компилятора под `kchs_query` |
| `packages/query/src/**` | компилятор QuerySpec и сырого SQL лаборатории |
| `apps/api/src/modules/integrations/infra/database-source.ts` | внешняя СУБД источника (ADR-0107): SQL к чужой базе под учётной записью интеграции, значение курсора — параметром |

Остальной код строит SQL шаблоном `sql` с параметрами и фрагментами этих слоёв:

- **Сервисы модуля данных** берут имена хранения фрагментами `physical.ts`: `tableSql`, `historySql`, `columnSql`, `typeSql`, `aliasSql`. Постоянные куски пишутся шаблоном `sql` без подстановок.
- **Текст компилятора `@kchs/query` выполняет только `readAsQueryRole`** (`shared/db/query-role.ts`): транзакция только для чтения под `kchs_query`, тайм-аут оператора и пояс — настройки транзакции. Через него читают:
  - запросы QuerySpec, SQL-лаборатория и её пробный разбор столбцов;
  - потоковая выгрузка;
  - тайлы, экстент и статистика слоя.
- **Обёртки тайла MVT и экстента** вокруг SQL компилятора — `gis/infra/layer-sql.ts`. В текст попадают SQL компилятора и имена полей через `quoteIdent`, координаты и размеры ячеек — параметрами.
- **Вектор поиска по смыслу** — параметр: ровно 1024 конечных числа после проверки zod. Вектор, не прошедший проверку, даёт пустую выдачу.
- **Связки и порядок фильтра реестра** — фрагменты `sql`.
- **Адаптер внешней базы** переехал из `integrations/domain` в `integrations/infra`.

### Один помощник экранирования

`quoteIdent` из `@kchs/query` (`packages/query/src/ident.ts`) берёт имя в двойные кавычки и
удваивает кавычки внутри. Так имена читают Postgres, DuckDB и язык выражений. Им пользуются:

- диалекты компилятора, SQL-лаборатория и проверка выражений;
- `ident` и `aliasSql` физических таблиц;
- тайлы и экстент слоя;
- адаптер внешней базы (ветка PostgreSQL; у MySQL — обратные кавычки);
- выражения детализации, пайплайнов и статистики слоя.

Проверка имени по своим правилам (сгенерированное `t_…`/`c_…`, ключ поля snake_case,
имя внешней базы) остаётся у вызывающего. Кавычки — защита в глубину.

### Проверки в `pnpm deps:check`

- **dependency-cruiser api — без базы известных нарушений.** `.dependency-cruiser-known-violations.json` и `deps:baseline` у api удалены, любое нарушение роняет CI. У web база своя (ADR-0183).
- **`scripts/table-owners.mjs`** ловит:
  - запись модуля в таблицу ядра: `.insert/.update/.delete(t)` Drizzle и `INSERT INTO`/`UPDATE`/`DELETE FROM ${t}`, где `t` — таблица из `kernel/<область>/schema.ts`;
  - чужую таблицу по имени в тексте SQL (`FROM`, `JOIN`, DML): у модуля — таблицу ядра или другого модуля, у ядра — таблицу модуля.

  Свои таблицы подставляются `${таблица}`. Исключение — identity и `users`.
- **`scripts/raw-sql.mjs`** ловит `*.raw(` и `.unsafe(` в исходниках `apps/api/src` и `packages/*/src` вне списка выше; тесты не проверяются. Исключение-файл без сырого SQL тоже роняет проверку: список не устаревает молча.

Обе проверки опробованы подложенными нарушениями.

## Альтернативы

- **Оставить базу нарушений и исправлять по мере правки.** База dependency-cruiser помнит пару «файл → модуль». Новый импорт той же таблицы в том же файле она не замечает, а запись по импорту, разрешённому на чтение, не видит вовсе.
- **Правило линта (плагин Biome на GritQL) вместо скриптов.** Ему нужно знать, какие таблицы чьи. Скрипт читает это из `schema.ts`, как `module-cycles.mjs` читает граф импортов.
- **Выполнение текста компилятора — публичным API модуля данных.** Тогда gis ходил бы в data за чужим SQL, а «выполни любой текст» стал бы публичным API модуля. Помощник `shared/db` ничего не знает о домене и пускает только под `kchs_query`.
- **Помощник экранирования в `shared` api.** Пакет `@kchs/query` не может импортировать api, поэтому общий помощник — в пакете.
- **Разрешить `modules/*/infra/**` целиком.** Тогда новое место сырого SQL появлялось бы без решения. Исключение должно быть отдельной строкой списка с причиной.

## Последствия

- **Итоги:**
  - база нарушений api: 15 → 0;
  - запись модулей в таблицы ядра: 19 мест вне входа identity → 0;
  - сырой SQL вне слоёв: 16 файлов и 55 мест → 1 файл-исключение (адаптер внешней базы, 3 места);
  - экранирование имён: 8 способов → `quoteIdent`.
- **Поведение:**
  - `PATCH /me` публикует `user.updated` и сбрасывает кэш принципалов;
  - синхронизация каталога заводит должности с событием и аудитом;
  - непрочитанное обсуждения объекта считается как в чате (см. выше);
  - имя поля с кавычкой в выражении пайплайна экранируется, а не теряет кавычку.
- **Новый код:**
  - таблица ядра, которой модулю не хватает, — новый метод сервиса или фрагмент SQL ядра, а не импорт схемы;
  - новый текст SQL как есть — в слой из списка или новой строкой исключения с причиной в `scripts/raw-sql.mjs` и здесь.
- **Не сделано в этой части:** тип `publishEvent(tx: Tx)` и остальное из §5.1 плана — другие части 2В.
- **Предел проверки:** `raw-sql.mjs` видит вызовы `sql.raw` и `.unsafe`, но не то, из чего собран текст внутри разрешённых слоёв, — это остаётся на ревью.
