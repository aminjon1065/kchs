# 0189. Каталог событий по владельцам; снимки событий и OpenAPI в git; проверка ломающих изменений

Статус: Принято
Дата: 2026-10-05

## Контекст

Часть 3Б этапа 3 плана укрепления (`07-architecture-hardening.md` §5.0а).

- **Каталог событий — один файл.** В `packages/contracts/src/events/catalog.ts` лежали
  288 событий 59 доменов потоков. Каждый модуль правил этот общий файл, и параллельные ветки
  конфликтовали в нём. Кто владеет событием, из файла не было видно.
- **Версия в конверте всегда 1.** Конверт события несёт `version` (`contracts/events.md`),
  вебхук получает конверт целиком. Правила повышения версии не было, и публикация всегда
  ставила 1.
- **OpenAPI в git нет.** Спецификацию собирает `pnpm openapi:gen`, CI публикует её
  артефактом (ADR-0030). В git файла нет: в нём около 12 МБ, схемы zod развёрнуты в каждом
  ответе. Поэтому изменение контракта API не видно на ревью. Удалённый маршрут или поле
  первым замечает внешний потребитель.

## Решение

### 1. Каталог по владельцам

- **Файлы.** Событиям ядра отведено 9 файлов в `packages/contracts/src/events/`: `object`,
  `space`, `discussion`, `notification`, `job`, `process`, `acknowledgment`, `directory`,
  `settings`. Событиям модулей — 16: `files`, `data`, `reports`, `forms`, `alerts`, `gis`,
  `territories`, `tasks`, `calendar`, `meetings`, `chat`, `knowledge`, `documents`, `mail`,
  `automation`, `integrations`. Схемы, общие для нескольких файлов, лежат в `shared.ts`.
- **Владение доменом.** Файл владеет доменами потоков (`events:<домен>`, префикс типа)
  целиком. Тест каталога проверяет три вещи:
  - тип события есть ровно в одном файле — сборка распространением молча перезаписала бы
    дубликат;
  - домен есть ровно в одном файле;
  - каталог — объединение файлов.
- **Сборка.** `catalog.ts` собирает `EVENT_PAYLOADS`, `EVENT_TYPES`, `EVENT_DOMAINS` и
  `EVENT_CATALOG_PARTS`. Тип и поведение `publishEvent` не изменились. Схемы совпадают с
  прежним каталогом: 288 типов, без различий.
- **Отступление от «по доменам».** У одного модуля несколько доменов: у `data` это `source`,
  `dataset`, `query`, `chart` и другие. Файл на домен дал бы 59 файлов и раздробил бы
  модуль. Файл на владельца совпадает с владением кодом.

### 2. Версия нагрузки

- **Где задаётся.** Версия — `EVENT_VERSIONS` в `catalog.ts`, по умолчанию 1.
  `eventVersion(type)` возвращает версию события, и публикация ставит её в конверт.
- **Когда меняется.** Версия повышается на 1 при ломающем изменении нагрузки и никогда не
  понижается. Тест проверяет, что в `EVENT_VERSIONS` только известные типы и целые числа от 2.
- **Правила для получателей** — в `contracts/events.md`, раздел «Версия нагрузки».

### 3. Снимки в git

- **События.** Снимок — `packages/contracts/snapshots/events.json`, вида
  `{ "<тип>": { "version", "schema" } }`. Схема строится через
  `z.toJSONSchema(…, { io: 'output' })`. В файле 288 строк, около 80 КБ.
- **OpenAPI.** Снимок — `apps/api/openapi.snapshot.json`. Он хранит структуру операций
  `"<МЕТОД> <путь>"`: параметры (`in`, `name`, `required`, схема), тело (обязательность,
  схемы по типам содержимого) и ответы по кодам.
  - Поддерево-объект, которое встречается больше одного раза, хранится в `defs` один раз,
    под ключом sha256 содержимого (12 знаков). На его месте стоит `{ "$ref": "<ключ>" }`.
  - Итог: 689 операций и 916 общих схем, около 0,7 МБ вместо 12.
  - Серверы, схемы безопасности, описания и теги в снимок не входят. Они зависят от окружения
    или не входят в контракт.
- **Нормализация.** Из схем удаляются `description`, `title`, `summary`, `tags`, `examples`,
  `example`, `default`, `deprecated`, `$schema`, `$id`. При `format` удаляется и `pattern`:
  выражение zod для uuid — шум. Ключи, `required` и перечисления упорядочены, на запись
  отводится одна строка. Так diff на ревью построчный и не зависит от формулировок.
- **Команды.**

  | Команда | Что делает |
  |---|---|
  | `pnpm contracts:snapshot` | пересобирает оба снимка: снимок событий, `openapi:gen` и снимок OpenAPI. После части 3А-1 (ADR-0188) OpenAPI пересобирается этой же командой |
  | `pnpm --filter @kchs/contracts snapshot:events --check` | проверяет, что снимок событий не отстал от кода |
  | `pnpm --filter @kchs/api openapi:snapshot --check` | проверяет, что снимок OpenAPI не отстал от `openapi.json` |

- **CI.** Проверка пересобирает снимок и требует пустой `git diff`:
  - события — в статическом задании, вместе с проверкой совместимости `--events`;
  - OpenAPI — в интеграционном задании, после `pnpm openapi:gen`, вместе с `--api`. Сборке
    приложения нужны Redis и база.

  Обоим заданиям нужна вся история: `fetch-depth: 0`.

### 4. Проверка совместимости — `pnpm contracts:compat [--events] [--api]`

- **Сравнение.** Проверка сравнивает снимки рабочего дерева со снимками в базе:
  `git show <база>:<путь>`. Правила — чистые функции `packages/contracts/scripts/compat-core.mjs`
  с unit-тестами. Сторона схемы определяет правило:
  - тело и параметры запроса шлёт клиент — пишущая сторона;
  - ответ получает клиент — читающая сторона;
  - нагрузка события — обе стороны. Новый код подписчиков читает события, записанные прежним
    кодом: outbox, потоки, повтор из DLQ, сохранённые условия правил автоматизации. А новые
    события получают прежние приёмники вебхуков.

| Изменение | Событие | Запрос | Ответ |
|---|---|---|---|
| Удалены событие, операция, параметр, тело, успешный код ответа, тип содержимого | ломает | ломает | ломает |
| Поле удалено (переименование = удаление + новое поле) | ломает | ломает | ломает |
| Новое обязательное поле, необязательное поле стало обязательным | ломает | ломает | — |
| Обязательное поле стало необязательным | ломает | — | ломает |
| Тип сузился: перестал принимать тип или `null`; убрано значение перечисления; строка стала перечислением; добавлен формат; ужесточено ограничение (`minLength`, `maxLength`, `minimum`, `maximum`, `pattern`…); убран вариант объединения | ломает | ломает | — |
| Тип расширился: стал nullable, другой тип, формат убран | ломает | — | ломает |
| Формат сменился (`uuid` → `email`) | ломает | ломает | ломает |
| Новые событие, операция, необязательное поле; новое значение перечисления или вариант объединения; ослабленное ограничение | проходит | проходит | проходит |

Новое значение перечисления не ломает: получатель обязан терпеть незнакомые значения, как
незнакомые поля.

- **Нулевые схемы.** Обёртка «или null» (`anyOf: [X, null]`) снимается, и поля внутри неё
  сравниваются. Ссылки `defs` разворачиваются: одинаковая схема, вынесенная в `defs` и
  записанная на месте, различий не даёт.
- **Ломать можно только явно.**
  - **Событие.** Повысить версию в `EVENT_VERSIONS`: тогда схема события с новой версией не
    сравнивается, а в выводе появляется заметка `версия 1 → 2`. Уменьшение версии — ошибка.
  - **Операция API.** Лучше добавить новую операцию или необязательное поле, чем менять
    прежнее. Если поломка неизбежна, её разрешает запись в
    `packages/contracts/snapshots/allowed-breaking.json`:
    `{ "events": { "<тип>": "ADR-NNNN: причина" }, "api": { "<МЕТОД> <путь>": "ADR-NNNN: причина" } }`.
    Причина без номера ADR в начале — ошибка проверки. Исключение, которое не понадобилось,
    выводится заметкой «уберите»: исключение снимают следующим изменением, чтобы оно не
    пропустило чужую поломку той же операции.
- **База.** Проверка сравнивает с `git merge-base HEAD <ссылка>`, а не с вершиной ссылки.
  Иначе событие, добавленное в main после ответвления, выглядело бы в ветке удалённым.
  - **Ссылка.** Ссылку задаёт `KCHS_CONTRACTS_BASE`, по умолчанию `origin/main`, затем `main`.
  - **Ссылка в CI.** Для PR — `origin/<целевая ветка>`. Для пуша в `main` —
    `github.event.before`, прежнее состояние main. Для пуша в `phase/**` — `origin/main`.
  - **Нулевой хэш.** Нулевой хэш означает, что базы нет.
  - **Ненайденная ссылка.** Явно заданная, но не найденная ссылка — ошибка с кодом 2. Иначе
    клон без истории молча выключил бы проверку.
  - **База без снимка.** Если в базе снимка нет, сравнивать не с чем. Так проходит первое
    слияние, которое вводит снимки.

## Альтернативы

- **Полный `openapi.json` в git.** Это 12 МБ, diff нечитаем, общие схемы повторяются в каждом
  ответе.
- **oasdiff, openapi-diff.** Это Go- или Java-бинарь вне стека (`18-tech-stack.md`). Он не
  покрывает события, и правило «обе стороны» для них всё равно пришлось бы писать. Своя
  проверка — около 450 строк вместе с оболочкой, правила закреплены тестами.
- **Версия в имени события (`task.created.v2`).** Новый тип означает новые подписки, правила
  автоматизации и фильтры вебхуков по типу. Конверт уже несёт `version`.
- **Сравнение с вершиной main.** Даёт ложные «удаления» для того, что появилось в main после
  ответвления ветки.

## Последствия

- **Ревью.** Изменение схемы события или маршрута меняет снимок и видно на ревью. Забытая
  пересборка снимка роняет CI.
- **Ломающие изменения.** Ломающее изменение события требует новой версии, ломающее
  изменение API — ADR и записи в списке исключений.
- **После 3А-1.** Если таблица маршрутов (ADR-0188) поменяет схемы структурно, проверка
  покажет каждое место. Его либо возвращают к прежней форме, либо разрешают со ссылкой на
  ADR-0188.
- **Ограничения.**
  - **Рекурсивные схемы.** Это дерево фильтра (запросы, графики, метрики, слои карты,
    политики строк), условия определения процесса и рекурсивное значение JSON в параметрах.
    fastify-type-provider-zod 5 выносит их в ссылки `#/components/schemas/schema0`, а
    `components.schemas` в спецификации пуст. Эти ссылки — 161 место в 62 операциях — снимок
    не раскрывает, и изменения внутри них проверка не видит. Это вопрос части 3А-1: регистрация
    схем с `id` и `jsonSchemaTransformObject`.
  - **Варианты объединения.** Они сопоставляются по порядку. Перестановка вариантов даёт
    ложную тревогу — для неё есть исключение с ADR.
  - **Смысл поля.** Смысл поля и единицы измерения проверка не видит.
  - **Обновление zod.** Оно может поменять форму JSON Schema. Тогда снимки пересобираются, а
    сравнение остаётся структурным.
