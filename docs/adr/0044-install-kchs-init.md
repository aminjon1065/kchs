# 0044. Установка: `kchs init`, образ api одним бандлом, web — единственная точка входа

Статус: Принято
Дата: 2026-09-18

## Контекст

Критерий готовности фазы 0 (`02-roadmap.md`): «`docker compose up` + `kchs init` дают рабочую
систему за ≤ 10 минут». `15-admin-operations.md` §2 (Решено) описывает установку: `.env` из
скрипта, `docker compose up -d`, `kchs init` — миграции, первый администратор, базовые
справочники. На момент решения:

- команды `kchs` не было; первого администратора создавал только `db:seed` с паролем из `.env`;
- образ api не запускался: `tsc` оставлял в `dist` импорты `~/…`, а пакеты монорепо
  (`@kchs/contracts` и др.) экспортируют исходники TypeScript — Node не мог загрузить ни то,
  ни другое; каталог миграций задавался фиксированным путём от исходного файла, а ошибка его
  чтения молча превращалась в «миграций нет»;
- в профиле `app` worker наследовал из образа проверку HTTP `/health`, а HTTP-сервера у него
  нет — контейнер всегда был `unhealthy`; web по умолчанию брал `KCHS_DOMAIN=localhost`
  (HTTPS с внутренним CA и перенаправлением на неопубликованный 443) и проверки не имел;
  значения `.env` разработки для хоста (`TRUST_PROXY=loopback`) попадали в контейнеры, порты
  postgres/redis/meilisearch/mailpit публиковались на всех интерфейсах;
- подписанные ссылки S3 подписывались внутренним адресом (`minio:9000`), после чего адрес
  заменялся публичным. SigV4 подписывает заголовок `Host`, поэтому MinIO отвечал
  `SignatureDoesNotMatch`: в контейнерах браузер не мог ни загрузить файл, ни показать превью.
  При разработке оба адреса совпадают (`localhost:9000`), и ошибка не проявлялась;
- сервис `caddy` профиля `proxy` использовал тот же Caddyfile, что и web, но без собранного
  SPA в `/srv/web`: на страницы отвечал 404 и дублировал web (порты 80/443, тома `caddydata`).

## Решение

1. **CLI `kchs`** в `apps/api` (`src/cli/kchs.ts`): `init`, `migrate`, `seed`, `help`. В образе —
   `/usr/local/bin/kchs` (`docker compose exec api kchs init`), локально — `pnpm kchs init`.
   `kchs init` по шагам: миграции → системные роли и индекс поиска (`bootstrapPlatform`) →
   производственный календарь РТ на текущий и следующий год (праздники с постоянной датой;
   существующие дни не перезаписываются; это начальные данные, как системные роли в
   `bootstrapPlatform`, поэтому без доменных событий — событие будут публиковать правки
   календаря из консоли) → первый администратор с ролью `system_admin`, если
   активного `system_admin` ещё нет. Логин и почта — из `--admin-login`/`--admin-email` или
   `KCHS_ADMIN_LOGIN`/`KCHS_ADMIN_EMAIL`. Пароль генерирует `UserService` (как при создании
   пользователя в консоли) с `mustChangePassword`: он печатается один раз, при первом входе
   администратор задаёт свой. Повторный запуск ничего не ломает и администратора не создаёт —
   в сводке «уже есть». Сводка заканчивается адресом входа (`KCHS_BASE_URL`).
   `kchs seed` (то же, что `pnpm db:seed`) после `init` переиспользует администратора с тем же
   логином, не меняя пароль; признак «демо-данные уже загружены» — корень оргструктуры `HQ`,
   а не «в базе есть пользователи».
   Базовая карта PMTiles из `15-admin-operations.md` — фаза 2 (S04): шаг добавится в
   `kchs init` вместе с реестром базовых карт.
2. **Образ api — бандл esbuild** (`apps/api/scripts/build.mjs`): `dist/main.js` и `dist/kchs.js`
   с общими чанками. Пакеты монорепо и алиас `~/` входят в бандл, npm-зависимости остаются
   внешними; в образе — только prod-зависимости. Типы проверяет `tsc --noEmit`,
   `tsconfig.build.json` удалён. Каталог миграций — `KCHS_MIGRATIONS_DIR` или поиск
   `drizzle/meta` вверх от модуля. Код в образе принадлежит root и процессу доступен только
   на чтение.
3. **Подписанные ссылки** подписывает клиент S3 с `S3_PUBLIC_ENDPOINT` (подпись вычисляется
   локально, обращения к этому адресу нет); сам сервер ходит в хранилище по `S3_ENDPOINT`.
4. **Compose**: общее окружение api и worker (`x-app-env`); у worker — проверка живости по
   файлу, который он обновляет раз в 10 с; у web — `KCHS_DOMAIN=:80` по умолчанию (HTTP, домен
   включает автоматический HTTPS) и проверка на внутреннем `:2020/healthz`; api ждёт
   `minio-init`, worker и web — здорового api; теги образов — `KCHS_IMAGE_TAG`; порты данных и
   служебных интерфейсов — на `KCHS_BIND` (по умолчанию 127.0.0.1), наружу — web и S3;
   доверие прокси в контейнерах — `TRUST_PROXY_APP`.
5. **Профиль `proxy` и сервис `caddy` удалены.** Единственная точка входа — web (Caddy со
   сборкой SPA): TLS, статика, `/api`, `/ws`, `/collab`, CSP (ADR-0043). Маршрут LiveKit
   появится в том же Caddyfile с фазой 4. `15-admin-operations.md` §2 обновлён.
6. **`generate-secrets.sh --mode dev|app --env-file ПУТЬ`**: режим `app` записывает адреса полного
   развёртывания (`NODE_ENV=production`, `KCHS_BASE_URL` на `WEB_PORT`,
   `ENGINE_API_URL=http://api:3000`); порты берутся из окружения, так что второй стенд можно
   поднять рядом с первым.
7. **Проверка**: `infra/scripts/verify-stack.sh` — отдельный проект compose на чистых томах,
   `kchs init`, `kchs seed`, дымовой прогон API через web, браузер (CSP, вход, «Мой день»,
   загрузка в S3, превью движка) и время каждого шага. В CI — workflow `stack.yml`: каждую ночь,
   на PR с меткой `stack` и вручную.
   Замер 2026-09-18 (Apple Silicon, Docker Desktop): с готовыми образами `up` до здоровых
   контейнеров — 23 с, `kchs init` — 1 с, демо-данные — 5 с. Сборка без кэша слоёв (базовые
   образы уже скачаны): api ≈ 3 мин, web ≈ 40 с, движок ≈ 4 мин.

## Альтернативы

- `tsc` + `tsc-alias` и сборка каждого пакета монорепо в JS: пакеты экспортируют исходники
  TypeScript (так удобнее разработке и vitest), понадобились бы сборка каждого пакета и условия
  `exports`. Бандл проще и собирается за доли секунды.
- Запуск в образе через `tsx`: dev-зависимость в продакшене, транспиляция на лету при старте.
- Постоянный пароль первого администратора из `.env`, как в seed: пароль остаётся в файле и в
  истории оболочки. Временный пароль с обязательной сменой — как у пользователей, созданных
  администратором.
- Оставить `caddy` внешним прокси перед web: второй Caddy на S1 без выгоды. Внешний
  балансировщик — предмет S2 (Ingress в Helm-чарте).
- Подменять `Host` в запросах к MinIO промежуточным прокси: лишний компонент, когда подпись
  нужным адресом — штатный путь SDK.

## Последствия

- При обновлении нужно пересобрать образ api (`docker compose --profile app build api`).
- `S3_PUBLIC_ENDPOINT` и `KCHS_STORAGE_ORIGIN` должны указывать адрес, по которому браузер
  видит MinIO. Если web работает по HTTPS, S3 тоже должен быть доступен по HTTPS (иначе браузер
  заблокирует смешанное содержимое) — например, отдельный домен за TLS.
- Праздники с плавающей датой (Иди Рамазон, Иди Қурбон) и переносы выходных `kchs init` не
  заносит: их вносит администратор, когда появится раздел календаря в консоли («Система»,
  `15-admin-operations.md` §1). Пока у календаря нет потребителей (сроки по рабочим дням
  появятся с задачами и документами). Допущение — `05-risks-and-open-questions.md`, N4.
- Новая обязательная переменная окружения api должна попасть в `x-app-env` compose, иначе
  ночная проверка установки упадёт.
