# 0065. Компилятор стилей карт `@kchs/map-style`, шкалы карт в токенах, легенда

Статус: Принято
Дата: 2026-09-19

## Контекст

P2-E01 S01: `LayerStyle` (контракт `layer-style.md`, **Решено**) нужно превращать в слои
MapLibre и легенду — одинаково для студии карт, плиток дашбордов и печати
(07-gis-engine.md §4). Открытыми оставались:

- откуда компилятор берёт цвета: палитры и токены живут в `@kchs/ui` (CSS-переменные и
  `tokens.json`), а `@kchs/ui` сам будет зависеть от компилятора (легенда);
- шкалы карт. `02-design-system.md` (**Рекомендовано**) называет `viridis` и `brown-teal`, в
  токенах их не было; `--seq-*`/`--div-*` были одни на обе темы. Расчёт (светлота OKLab,
  как в ADR-0049) показал брак: у `teal` шаги `#2BA6B6`→`#0EA5B7` отличаются на 0,006, у
  `blue` `#4573DD`→`#2F62E6` — на 0,036: при 7 классах соседние неразличимы. На тёмной
  подложке светлая шкала «от светлого к тёмному» прячет большие значения;
- соглашения с тайлами сервера (S02): как приходят числа, даты, кластеры, фильтр слоя;
- как считать классы (методы контракта: equal, quantile, jenks, log, stddev, manual).

## Решение

1. **Пакет `packages/map-style`** — ESM TypeScript без MapLibre в рантайме: типы
   `@maplibre/maplibre-gl-style-spec`, зависимости `@kchs/contracts`, `@kchs/fields`,
   `@kchs/i18n`. API:
   - `compileLayerStyle(style, ctx)` → `{ layers, legend, images, warnings }`;
   - `classify(values, method, classes, { breaks })` → края классов;
   - `paletteColors(theme, palette, n)`, `resolveColor(token, theme)`, `deriveOutline`;
   - `styleTileFields(style)` — поля, которые стиль читает из тайла.

   `ctx`: `id` (префикс слоёв), `source`, `sourceLayer` (`layer` по умолчанию — имя
   слоя `ST_AsMVT`; `null` — GeoJSON), `geometry` данных, `fields` (FieldDef подходит как
   есть), `theme`, `locale`, `name`, `breaks` (от `classify`), `domains` (min/max/nulls
   полей), `time` (кадр, мс), `clientFilter`, `territoryDescendants`, `now`, `timezone`,
   `fonts`.
2. **Тема приходит снаружи** (`MapTheme`, как `ChartTheme` в ADR-0049). В браузере —
   `readMapTheme`/`useMapTheme` из `@kchs/ui`: CSS-переменные `--seq-*`, `--div-*`,
   `--viz-cat-*`, `--viz-other`, семантика, `--text`, `--bg-surface`; короткая запись
   минифицированного CSS (`#fff`) и `rgb()` приводятся к `#RRGGBB`; тема — по яркости
   поверхности, поэтому работает и системная. Хук пересчитывает тему при смене
   `data-theme` и `prefers-color-scheme` — карта перекомпилирует стиль. В тестах пакета —
   значения `tokens.json`; тест `@kchs/ui` сверяет чтение `tokens.css` с `tokens.json`.
   `map-style` от `@kchs/ui` не зависит (иначе цикл: легенда живёт в `@kchs/ui`).
3. **Шкалы карт в токенах.** `color.sequential` (`blue`, `teal`, `orange`, `viridis`) и
   `color.diverging` (`red-blue`, `brown-teal`) — по 7 шагов **для каждой темы**
   (`{light, dark}`), CSS `--seq-<шкала>-1…7`, `--div-<шкала>-1…7`. Шаг 1 — малое
   значение: в светлой теме светлое, в тёмной тёмное — большее значение всегда
   контрастнее подложки. `viridis` светлой темы — канонический в обратном порядке.
   Нейтраль расходящихся — `surface-2` светлой и `surface-3` тёмной темы (как у
   `--viz-div`); `red-blue` совпадает с `--viz-div`. Шаги `blue`/`teal`/`orange` светлой
   темы пересчитаны в OKLab с ровной светлотой (края `blue` — прежние `#E9EFFF…`).
   `pnpm --filter @kchs/ui contrast` проверяет шкалы карт в обеих темах: шаг светлоты
   последовательной ≥ 0,06 в сторону «большего», у расходящейся — ≥ 0,08 от нейтрали к
   каждому полюсу, полюса при протанопии и дейтеранопии — ΔE ≥ 12, симметричные шаги
   плеч — ΔE ≥ 8 (худшие: `brown-teal` 14,4 и 10,0 в светлой теме).
4. **Палитры на классы.** Классы 3–9 — равномерно по 7 опорным шагам с интерполяцией в
   OKLab (7 классов — ровно токены, края шкалы всегда сохраняются, у нечётного числа
   классов расходящейся средний — ровно нейтраль); `reverse` переворачивает порядок.
   `categorical` — палитра графиков по порядку (девятый класс — «прочее»), `status` —
   success → warning → danger. Цвета стиля: `categorical.N` (по кругу из 8), `<шкала>.N`
   (1…7, без номера — пятый), `status.N`, семантические (`accent`, `success`, `warning`,
   `danger`, `info`, `neutral`, `purple`), `other`, `#rrggbb` — как есть в обеих темах.
   Неизвестный токен — первый цвет палитры и замечание `color-unknown`. `auto` — тот же
   оттенок со сдвигом светлоты OKLab: −0,16 в светлой теме, +0,14 в тёмной (обводка
   полигонов, кольцо точек и значков).
5. **Классификация.** Результат — края `[min, b1…b(k−1), max]`: класс — `[e(i), e(i+1))`,
   ровно как выражение `step`. Внутренние границы строго возрастают (повторы
   схлопываются — классов бывает меньше), последняя может совпасть с максимумом (верхний
   класс из одного значения; подпись — одно число). `quantile` — линейная интерполяция
   рангов (R-7); `jenks` — точный алгоритм Фишера — Дженкса O(k·n²) по равномерной по рангу
   выборке не больше 2000 значений (оптимальность проверена перебором в тестах); `log` —
   равные интервалы log10 положительных значений; `stddev` — шаг σ от среднего (нечётное
   число классов — средний класс «среднее ± 0,5σ»); `manual` — `renderer.breaks`.
   Компилятор берёт `ctx.breaks` (вычисленные вызывающим по статистике слоя), затем кэш
   `renderer.breaks`; без границ — один цвет палитры, замечание `breaks-missing` и
   пояснение в легенде. Пустое значение и деление на ноль при `normalizeBy` — цвет
   «прочее», в легенде «Нет данных», если `domains[field].nulls > 0`.
6. **Соглашения с тайлами и источниками** (реализует S02):
   - числа — числами (`numeric` — `double precision`); выражения всё равно читают поля
     через `to-number`, пустое проверяется до него (`to-number` пустого — 0);
   - дата и дата-время — **миллисекунды эпохи**: `date` — полночь UTC календарной даты,
     `datetime` — момент (MapLibre не разбирает строки дат);
   - кластеры сервера — объекты с `point_count > 1` без остальных полей (как у GeoJSON с
     `cluster: true`, поэтому оба пути рисуются одинаково); обычные точки — без
     `point_count` или с 1;
   - **фильтр слоя применяет сервер** (в тайле нет полей фильтра, `styleTileFields`);
     на клиенте — только по `ctx.clientFilter` (GeoJSON со всеми полями, предпросмотр);
   - время: без кадра фильтрует сервер (`t`); с `ctx.time` — на клиенте: `instant` —
     `[from, to)`, `range` — `[from, to]`, `cumulative` — до `to`.
7. **Слои.** Снизу вверх: `fill` и `outline` (полигоны), `line`, `heatmap`, `point` (`circle`;
   фигуры и значки — `symbol` с SDF-изображениями), `cluster` и `cluster-count`, `label`.
   id — `<ctx.id>:<роль>`, роль — ещё в `metadata['kchs:role']` (MapView выбирает по ней
   объекты для щелчка). Изображения из `images` (`kchs-shape-<форма>`, `kchs-icon-<имя>`,
   SDF, сторона 32 логических px: `icon-size` = диаметр / 32) MapView регистрирует до
   слоёв. `maxZoom` стиля включительно: `maxzoom` MapLibre = maxZoom + 1, от 22 — без
   ограничения. Рендереры:
   - `categorized` — `match` по строке или целому числу, «да/нет» и дробные — `case`;
     `other: null` — объекты вне категорий не рисуются; повтор значения — замечание;
   - `graduated` — `step`, `visual.target` `size`/`both` у точек (диаметр 6…24) и линий
     (ширина ×1…×4); у полигонов размер — замечание;
   - `proportional` — `interpolate` по линейной, корневой (площадь пропорциональна
     значению) или логарифмической шкале между min и max диапазона поля; пустые не
     рисуются; у полигонов — простой стиль и замечание; `point.sizeBy` — та же шкала,
     если рендерер сам не задаёт размер;
   - `heatmap` — только точки: вес — доля диапазона поля, у кластера сервера умножается
     на `point_count`; цвет плотности — 7 шагов палитры, у нуля прозрачный;
   - `rule` — `case` в порядке правил (первое подходящее);
   - кластеры — кружок по log10 числа точек (`cluster.style` min/max — диаметры), число
     внутри сокращается по языку («1,2 тыс.», «2,5 млн», «1.2K»), цвет — основной у
     простого стиля и размера по значению, иначе «прочее»;
   - подписи — поле или шаблон `{{field}}`: числа `number-format` с языком и точностью
     поля (ноль знаков — выражением: MapLibre пропускает ложные опции), варианты выбора —
     их подписи, «да/нет» — словами, дата — замечание `label-format`; гало — цвет
     поверхности; у точек — `text-variable-anchor` со сдвигом на радиус, у линий — вдоль
     линии; приоритет `size`/`field` — `symbol-sort-key`. Шрифты по умолчанию — `Noto Sans
     Regular`/`Bold` (glyphs базовой карты S04), `ctx.fonts` их меняет.
8. **Фильтр → выражение** — смысл операторов как у SQL-компилятора `packages/query`:
   `not`, `neq`, `not_in`, `not_contains` пропускают пустые, подстроки — без учёта
   регистра, `between` — включительно, «весь день» даты-времени — в поясе
   `ctx.timezone`, `relative` и `@today`/`@now` — от `ctx.now`, `within` — по
   `territoryDescendants`. Что на клиенте не вычислить (макросы пользователя, параметры,
   `regex`, геометрия, списки `multi_select`), заменяется по полярности: в фильтре слоя —
   «может выполниться» (лишнего не прячем), в правилах — «не выполняется» (не красим
   наугад); под `not` полярность меняется. Каждый такой случай — `filter-unsupported`.
9. **Легенда** — модель из тех же классов, категорий и правил: заголовок (свой или по
   полю), части (основная, «размер» у `sizeBy`, кластеры), образцы `fill`, `line`,
   `point`, `heatmap-gradient`, `proportional-circle`, `cluster`, пояснение. Числа — формат
   легенды или поля (проценты — как проценты), без точности — подобранная по значениям и
   без лишних нулей («2,4 – 18»). Тексты — ключи `ui.map.legend.*`. Компонент `MapLegend`
   в `@kchs/ui` рисует образцы SVG-атрибутами (CSP), значки — через `renderIcon`
   (без него — кружок цвета значка).
10. **Замечания** (`warnings`: `geometry-mismatch`, `field-missing`, `breaks-missing`,
    `domain-missing`, `renderer-geometry`, `filter-unsupported`, `color-unknown`,
    `category-duplicate`, `label-placement`, `label-format`) — стиль всё равно
    компилируется; редактор стиля показывает их у полей.

## Альтернативы

- `map-style` читает `tokens.json` сам — нет смены темы без перезагрузки и второй источник
  значений рядом с CSS; зависимость от `@kchs/ui` — цикл пакетов.
- Тёмные варианты шкал «автоматически» (инверсия светлоты) — не проходят проверку
  светлоты и цветослепоты; подобранные значения проверяются `contrast`.
- Отдельный список цветов на каждое число классов (как ColorBrewer 3…9) — 7× больше
  токенов; интерполяция 7 опорных шагов в OKLab держит ровные шаги светлоты.
- Фильтр слоя всегда на клиенте — в тайле нет его полей, выражение спрятало бы всё.
- ckmeans вместо Дженкса — быстрее на больших n, но выборка 2000 значений укладывается в
  десятки миллисекунд, а точный алгоритм проще проверить.

## Последствия

- S02 (тайлы) следует соглашениям п. 6; `layer.tile_fields` берёт `styleTileFields`
  (одинаковая логика должна остаться одной — в API сейчас своя копия).
- S04 (базовые карты) отдаёт glyphs `Noto Sans Regular`/`Bold`; подписи Inter потребуют
  собрать glyphs Inter и передать `ctx.fonts`.
- MapView (P2-E02) регистрирует `images` как SDF из набора значков (Lucide), выбирает
  объекты по `metadata['kchs:role']`, перекомпилирует стиль по `useMapTheme`; границы
  классов и диапазоны полей (`breaks`, `domains`) — из статистики слоя на сервере.
- Редактор стиля (S03) показывает палитры через `paletteColors`, замечания — у полей.
- В `02-design-system.md` шкалы карт описаны по этому решению; новая шкала или шаг
  проходит `contrast` в CI.
