# 0225. Третий разбор перед пилотом: безопасность на стыках, CI и зависимости

Статус: Принято
Дата: 2026-11-03

## Контекст

Перед пилотом на VPS с реальными данными Комитета проект разобран заново: доступ, песочница SQL,
движок и УЦ, инварианты ядра, эксплуатация, web, предметная логика. Макроархитектура и проверки
этапов 0–3 держатся. Этот ADR закрывает этап А разбора: безопасность на стыках модулей и CI.

Находки этапа А:

- движок разбирал геофайл драйвером, который GDAL выбирал по содержимому, и LibreOffice при
  конвертации загружал внешние ссылки документа;
- начатый, но не подтверждённый второй фактор принимался наравне с подключённым, а подключение
  фактора не требовало ничего, кроме сессии; подключённый фактор открывает подпись и выпуск
  сертификата УЦ (ADR-0079, ADR-0218);
- блокировка входа по-прежнему проверяла пароль, счётчики попыток и погашение кода
  восстановления не были атомарны;
- исходящие запросы по адресу пользователя достигали служб самой установки: частные сети лентам
  и подложкам открыты ради серверов закрытого контура (ADR-0132);
- маршруты управления учётными записями и доступом были доступны токену API и шлюзу DMZ; гость
  по ссылке проходил на любой `GET` с проверкой права; вебхук фильтровал по полю, которое никто
  не заполнял;
- сниппет поиска базы знаний и ссылка «показать на месте» отдавали содержимое, которое браузер
  исполнил бы как разметку; рукопожатие WebSocket принималось с любого сайта;
- CI с 18.09 не выполнялся ни разу (версия pnpm, тег Trivy), поэтому в `pnpm audit` накопились
  уязвимости рантайма, а копия правил оповещений в чарте отстала.

## Решение

### Движок

- **Геоформат открывается только драйвером заявленного формата, без сети.** `OGR_SKIP` и
  `GDAL_SKIP` задаются до первой загрузки GDAL (`kchs_engine/geoguard.py`): драйвер описания
  источника (OGR VRT) и драйверы сети и баз данных не регистрируются. Определение формата
  (`data/readers.py`) отклоняет XML с расширением геоформата, у которого корень не `<kml>`/`<gpx>`.
  Тот же список задан в `Dockerfile` запасным рубежом.
- **LibreOffice без внешних ссылок.** Профиль конвертации создаётся до запуска `soffice` и
  запрещает загрузку и обновление внешних ссылок и макросы.
- Политика хранилища движка не сужена: представления и подписанные экземпляры — новые версии
  файла, `PutObject` в `spaces/*/files/*` движку нужен. От перезаписи оригиналов защищает
  версионирование бакета (этап эксплуатации).

### Вход и второй фактор

- `verifyTotp` принимает только подтверждённые факторы; начатый фактор подтверждает только
  `POST /me/mfa/enable`.
- `POST /me/mfa/enable` требует текущий пароль (локальный или каталога) и ограничен 5 попытками за
  15 минут на сотрудника. В web — поле «Пароль для подтверждения». Ломающее изменение тела —
  в `allowed-breaking.json`, клиент обновлён в том же выпуске.
- Заблокированная учётная запись пароль не проверяет: ответ тот же, что неверному паролю, время
  ответа выравнивает хеш пустышки. Блокировку снимает срок или сброс пароля по ссылке. Прежнее
  правило «о блокировке узнаёт только знающий пароль» отменено: оно позволяло перебирать пароль
  во время блокировки без счёта.
- Счётчики неудач входа и попыток второго фактора растут в самом `UPDATE`; код восстановления
  гасится условным `UPDATE … WHERE used_at IS NULL RETURNING`.

### Исходящие запросы

- Сети самой установки — подсети сетевых интерфейсов процесса api (сеть compose с почтой,
  метриками, журналами, Redis и хранилищем; сеть пода) — закрыты для всех запросов общего клиента
  `shared/net/outbound.ts` всегда, как служебные. Частные сети за их пределами по-прежнему по
  политике вызова (ADR-0132). `OUTBOUND_ALLOW_INSTALLATION_NETWORKS` — только для особой схемы,
  где внешняя для kchs служба стоит в одной сети с api.

### Доступ в api

- **Признак маршрута `sessionOnly`** (таблица маршрутов, ADR-0188): маршрут управляет учётными
  записями и доступом и вызывается только из сессии. Токену API и шлюзу DMZ он недоступен при
  любой области; белый список шлюза перегенерирован. Признак стоит у 32 маршрутов: создание и
  правка учётных записей, временный пароль, сброс второго фактора и ключей входа, допуск,
  факсимиле, служебные учётные записи, роли, группы и их состав, оргструктура и должности, права
  на объект, гостевые ссылки, участники пространства. Чтение справочников по токену с областью
  чтения остаётся.
- **Признак `guest`**: гостю по ссылке открыт белый список — `GET /objects/:id`, `/files/:id`,
  `/files/:id/download`, `/files/:id/previews`, `/files/:id/text`. Регистрация маршрута падает,
  если признак стоит не у `GET` с `auth: { action }`.
- **Вебхук проверяет видимость владельцем подписки**: перед доставкой — `authorize(view)` с
  грифом. Событие без объекта реестра уходит, только если подписка называет его тип прямо (`*` и
  `user.*` его не включают); отключённому владельцу не доставляется ничего. Поле `visibility`
  удалено из конверта события (`contracts/events.md`).
- «Объяснить доступ» — управляющим доступом объекта, аудитору безопасности и администратору
  системы. Предел открытий гостевой ссылки засчитывается условным `UPDATE`.

### Web и хранилище

- Сниппет поиска базы знаний: подсветка приходит метками, текст экранируется целиком, метки
  становятся `<mark>` (`knowledge/domain/snippet.ts`).
- «Показать на месте» — только растровые изображения, PDF, видео, звук и простой текст, с типом
  ответа из записи файла (`signedGetUrl`, `ResponseContentType`); остальное всегда скачивается.
- Рукопожатие `/ws` принимается только с Origin установки (`allowRequest`); без Origin приходят не
  браузеры.

### CI и зависимости

- `pnpm/action-setup` берёт версию из `packageManager`; `aquasecurity/trivy-action` закреплён по
  SHA коммита v0.36.0; копия правил оповещений в чарте сверена.
- undici 6.29.1, zod 4.6, fastify 5.12, nodemailer и mailparser без известных уязвимостей;
  транзитивные fast-uri, ip-address, fflate — переопределением в пределах своей ветки версий.

## Альтернативы

- **Закрыть лентам частные сети целиком.** Ломает серверы закрытого контура Комитета (ADR-0132);
  закрыта только сеть установки.
- **Второй фактор подтверждать кодом действующего фактора вместо пароля.** При первом
  подключении действующего фактора нет; пароль — единое правило для обоих случаев.
- **Перечень путей в `scopes.ts` и шлюзе вместо признака маршрута.** Расходится с таблицей
  маршрутов при первом новом маршруте.
- **`Content-Security-Policy: sandbox` на адресе хранилища.** Мешает встроенному просмотру PDF;
  тип ответа и вложение решают задачу в api.

## Последствия

- Пользователь, который подключает второй фактор, вводит пароль ещё раз.
- Заблокированный сотрудник видит «Неверный логин или пароль» до конца блокировки или до сброса
  пароля по ссылке.
- Лента, подложка или интеграция на адресе в сети самой установки больше не работает без
  `OUTBOUND_ALLOW_INSTALLATION_NETWORKS`. На машине разработки сеть установки — локальная сеть
  машины.
- Интеграция не заводит и не правит учётные записи, роли и права по токену: это консоль или
  синхронизация каталога.
- CI снова выполняется. Первый прогон на GitHub может показать то, что локальные проверки не
  ловят (визуальные снимки, установка в контейнерах).
- Осталось на следующие этапы разбора: сокет realtime при выходе и отзыве сессии, SSO без
  локального второго фактора, секрет HTTP-интеграции в предпросмотре, ссылка сброса пароля в
  журнале без SMTP, OnlyOffice в iframe с `allow-same-origin`; эксплуатация (копии, рабочая
  установка, лимиты, оповещения), фоновые задания и автоматизация, предметная логика.
