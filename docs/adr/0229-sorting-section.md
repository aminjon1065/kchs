# Черновик раздела ADR-0229 — порядок списков и повторный импорт истории

> Для вклейки в сводный ADR-0229 этапа Г.

## Контекст

- Базы созданы с `C.UTF-8` (провайдер libc), и списки шли по байтам: «Ёров» стоял перед
  «Абдуллоевым», фамилии на Ғ, Қ, Ӯ, Ҳ, Ҷ, Ӣ оказывались после «Я», номера сортировались как
  текст («№ 10» перед «№ 2»). Поиск людей для пикеров и список участников пространства
  порядка не задавали вовсе.
- Код строки разбора истории ЧС — порядковый номер в году (`H2019-0007`, акты — `D2022-012`).
  `kchs import-history` пропускал строки, чей код уже есть. Новая выгрузка с добавленной
  строкой сдвигала номера: одни события терялись (их код занят прежними), другие дублировались
  (прежние под новыми кодами), а уточнения не применялись.

## Решение

### Порядок списков

- **Коллация `kchs_natural`** (миграция `natural_collation`): ICU, `tg-u-kn` — таджикский
  алфавит и числа по значению. Проверено на базе: Ғ после Г, Ӣ после И, Қ после К, Ӯ после У,
  Ҳ после Х, Ҷ после Ч, Ё — рядом с Е (как в словарях); «1, 01-15/2, 01-15/10, 2, 10, 12/3,
  12/10, 100». Для фамилий `tg-x-icu` и `ru-x-icu` дают один порядок; числа правильно
  сортирует только вариант с `kn`.
- **Порядок задаётся в ORDER BY**, `natural()` из `shared/db/collation.ts`, а не коллацией
  столбцов. `objects.title`, `users.display_name` и `documents.reg_number` входят в
  представления системных датасетов (`ds.sys_*`), и `ALTER COLUMN … COLLATE` потребовал бы их
  пересоздать. Равенство, `ILIKE` и индексы не меняются: коллация детерминированная и
  применяется только к сортировке.
- **Где:**
  - люди — члены подразделения и группы, обладатели роли, служебные учётные записи,
    участники пространства, поиск для пикеров (раньше без порядка; результат держит порядок
    поиска);
  - подразделения, группы, должности в поиске, теги;
  - названия объектов в списках модулей (проекты, календари, страницы, устройства, паспорта,
    подложки, слои, отчёты, пространства, виды и рабочие пространства);
  - справочники документов (типы, журналы, шаблоны, корреспонденты);
  - текстовые поля сортировки общего списка объектов (`compileObjectSort`): название,
    регистрационный номер, индекс дела.
- **Новая установка** получает коллацию той же миграцией; кластер базы с ICU по умолчанию не
  нужен.

### Повторный импорт истории ЧС

- **Ключ по содержанию** (`seed/history/content-keys.ts`). Ключ происшествия: время до
  минуты, точность даты, территория, вид в источнике (без него — код вида), место. Ключ акта:
  документ, блок района, дата бедствия, территория. Число погибших и пострадавших, описание и
  ущерб в ключ не входят: их уточняет новая выгрузка. Текст нормализуется: регистр, форма
  Unicode, пробелы, крайняя пунктуация.
- **Неразличимые строки** (два схода лавин в одном районе в один день) различаются порядковым
  номером внутри группы: в порядке источника (`origin`), затем по коду.
- **Сопоставление** (`syncByContent`):
  - совпавшая строка уточняется, только если изменилось поле выгрузки, и сохраняет свой код;
  - новая строка получает код выгрузки или, если он занят, следующий номер года;
  - строка, удалённая в системе, не воскресает;
  - сопоставляются только строки истории (`source = import`); коды донесений заняты, но сами
    строки не трогаются;
  - акт ссылается на происшествие уже по коду в базе.
- **Переход без миграции данных.** Ключ уже загруженной истории (13.10) досчитывается из её же
  полей; территория из идентификатора переводится в код. Та же выгрузка повторно — ни новых
  строк, ни правок.

## Альтернативы

- **Коллация столбцов миграцией.** Мешают представления системных датасетов; порядок в ORDER
  BY — то же поведение без пересоздания представлений и без блокировки таблиц.
- **Пересоздать базу с ICU по умолчанию.** Нужен дамп и восстановление стенда с реальными
  данными, а равенство и `LIKE` у недетерминированной части ICU работают иначе.
- **Сортировка датасетов (`packages/query`) той же коллацией.** На больших таблицах `COLLATE`
  отключает сортировку по индексу. Графики уже сортируют подписи на клиенте
  (`localeCompare` с `numeric`), поэтому датасеты не тронуты.
- **Ключ — хэш строки источника (файл, лист, номер строки).** Номер строки меняется при
  правке листа; ключ по содержанию переживает вставку строк в источник.

## Последствия

- Сортировка по `natural()` не использует индекс по столбцу. Списки ограничены страницей и
  фильтрами, на объёмах пилота это незаметно.
- Нужен Postgres с ICU (образы PostGIS и управляемые Postgres 17 его имеют); без ICU миграция
  не пройдёт.
- Строку истории, у которой в системе исправили время, территорию, вид или место, новая
  выгрузка добавит рядом как другое событие. Исправления описаний и чисел, сделанные в системе,
  новая выгрузка перезапишет: источник истории — выгрузка Комитета.
- Внутри группы неразличимых строк вставка новой строки в середину источника может поменять
  местами уточнения двух соседей (у обоих одинаковые время, место и вид).
