# 0059. SQL-лаборатория в API и на экране: способность `data.sql`, имена датасетов, ошибки с позицией

Статус: Принято
Дата: 2026-09-19

## Контекст

ADR-0052 задал конвейер сырого SQL в `packages/query` (`rawSqlTables` → `compileRawSql` →
выполнение под `kchs_query`), SqlEditor в дизайн-системе дал редактор с подсказками. Оставалось
подключить их к API и экрану (P1-E05 S02, сценарий приёмки фазы 1 №5: «SQL-лаборатория тоже
[показывает только свои строки]; попытка `SELECT * FROM public.users` отклонена»). Не было
решено, кому доступна лаборатория, как имя таблицы находит датасет, откуда подсказки и что
возвращается для столбцов, которые не являются полями датасета.

## Решение

1. **Доступ — способность `data.sql`** (её уже называет `contracts/query-spec.md` для показа
   SQL). Системные роли: `system_admin`, `data_steward`, `gis_admin`. Лаборатория не расширяет
   доступ к данным — политики те же, — но свободный SQL нагружает базу сильнее конструктора.
2. **API.** `POST /sql/run {sql, params}` → обычный `QueryResult`; `GET /sql/schema` —
   подсказки редактора. Выполнение — `QueryService.runSql`: `rawSqlTables` называет таблицы,
   датасеты ищутся по названию без учёта регистра среди **видимых пользователю**
   (`visibleObjectsSql`), для найденных — политики строк и столбцов через `DatasetAccess`. Два
   доступных датасета с одним названием — понятная ошибка «переименуйте один из них»; скрытая
   таблица и несуществующая неразличимы. Транзакция только для чтения под `kchs_query`,
   `statement_timeout` и пояс пользователя (`set_config('TimeZone', …)`), предел 50 000 строк
   (`truncated`), кэш Redis — только для детерминированных запросов (`compiled.cacheable`),
   журнал запусков — как у QuerySpec.
3. **Столбцы результата.** Прямая ссылка на поле датасета — тип, подпись и формат поля;
   вычисляемые столбцы — тип по OID Postgres (числа, даты, логические, JSON, массивы текста),
   прочее — текст. Геометрия без `ST_AsGeoJSON` приходит как EWKB и показывается текстом.
   Значения строками массивов (`.values()`), поэтому одинаковые имена столбцов не теряются.
4. **Ошибки.** Разбор и проверки — 400 с `data.issues[{path, message, position, hint}]`
   (позиция в тексте пользователя). Ошибки выполнения Postgres переводятся по SQLSTATE
   («Деление на ноль», «Поле должно быть в GROUP BY…») с позицией через `rawSqlErrorPosition`;
   исходное сообщение Postgres — в `hint`. Тайм-аут — `query_timeout`.
5. **Подсказки** (`GET /sql/schema`): до 200 самых свежих видимых датасетов с полями; поля,
   скрытые политикой столбцов для пользователя, не показываются никому из их адресатов — даже
   управляющему, который их видит (подсказки не должны раскрывать больше, чем запрос).
6. **Экран** «SQL-лаборатория» (`/sql`, кнопка в каталоге данных при способности): дерево
   датасетов и полей со вставкой имён, SqlEditor с ⌘Enter и выполнением выделенного, поля
   значений `{{параметров}}` (пусто — NULL), ошибки подчёркиваются в тексте, результат — в
   DataGrid. История запросов — в браузере пользователя (30 последних); серверная история и
   сохранение как `query` — вместе с сохранёнными запросами.

## Альтернативы

- **Лаборатория всем сотрудникам** — безопасно по данным, но без контроля нагрузки; способность
  назначается ролью и её легко выдать шире.
- **Разрешение имён по всем датасетам с отказом по правам** — раскрывало бы существование
  чужих датасетов через разные ошибки.

## Последствия

- Руководитель с политикой строк видит в лаборатории только свои строки; системные таблицы,
  запись, `pg_sleep` и подобное отклоняются с позицией (ADR-0052).
- Одноимённые датасеты в разных пространствах мешают друг другу в SQL — псевдонимы таблиц
  (`SqlDataset.aliases`) можно добавить без изменения контракта.
