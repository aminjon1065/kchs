# 0142. Гриф «Секретно» снят: три уровня, прежние значения — «Конфиденциально»

Статус: Принято
Дата: 2026-09-25

## Контекст

ADR-0080 ввёл четыре грифа ядра: `public < internal < confidential < secret`. Применимость
`secret` оставалась открытой (вопрос N10, `08-documents.md` §13). Владелец 24.09.2026 решил: гриф
«Секретно» убрать. Гостайна обрабатывается только в аттестованных системах, а kchs к ним не
относится. Остаются «Для служебного пользования» и «Конфиденциально» (N11: ДСП видит каждый, кому
дан доступ к документу, «Конфиденциально» — только с допуском).

Гриф — атрибут ядра, а не только документа. Его хранят несколько мест:

- `objects.confidentiality` и `documents.confidentiality` — с ограничениями `CHECK`;
- в типе документа — допустимые грифы и гриф по умолчанию;
- допуск сотрудника — атрибут `users.attributes.clearance`;
- ранг действующего грифа — в поисковом индексе.

Неизвестное значение допуска разбор приводит к допуску по умолчанию (ДСП). Значит, простое
удаление значения молча отняло бы у сотрудника с допуском «Секретно» доступ к конфиденциальным
документам.

## Решение

1. **Уровни — `public < internal < confidential`.** Список `CONFIDENTIALITY_LEVELS` в контракте
   и ограничения `CHECK` в базе больше не знают `secret`. Выбор грифа в карточке документа, в
   справочнике типов и в диалоге допуска строится из того же списка, поэтому пункт исчезает
   везде сразу.
2. **Прежние значения — «Конфиденциально»**, самый строгий из оставшихся. Доступ не
   расширяется: конфиденциальное видят только сотрудники с допуском. Миграция
   `confidentiality-no-secret` переводит:
   - объекты и документы;
   - допустимые грифы типов — `secret` в списке заменяется на `confidential`;
   - грифы типов по умолчанию;
   - допуски сотрудников.

   Затем меняются ограничения.
3. **Поиск.** Если такие объекты были, миграция ставит задание `search.reindex`: до
   переиндексации они выпадают из выдачи, а не открываются лишним.
4. **Разбор значения из хранилища.** `parseConfidentiality('secret')` отдаёт «Конфиденциально»,
   а не допуск по умолчанию. Старая резервная копия, пакет конфигурации или сторонний импорт не
   должны понижать гриф.
5. Переменная `AI_DOCUMENTS_MAX_CONFIDENTIALITY` принимает три уровня. Извлечение реквизитов ИИ
   отбрасывает «Секретно» как неизвестный гриф.

## Альтернативы

- **Оставить `secret`, но скрыть в интерфейсе.** Значение продолжало бы жить в API, в поиске и в
  пакетах конфигурации, то есть существовало бы полуофициально. Владелец просил убрать гриф
  совсем.
- **Переводить прежние значения в ДСП.** Это расширило бы доступ к материалам, которые кто-то
  счёл особо важными.
- **Отказывать в обновлении, если в базе есть `secret`.** Установки с такими данными нет, а
  отказ перенёс бы решение на администратора в момент обновления. Перевод в «Конфиденциально»
  безопасен и предсказуем.

## Последствия

- Изменения в аудит не пишутся: это системная миграция данных, а не действие человека. Их
  описывает этот ADR.
- `03-access-model.md`, `08-documents.md` §13, `05-data-model.md` и руководства 06 и 22
  перечисляют три уровня.
- Водяные знаки и сокрытие содержания в уведомлениях по-прежнему начинаются с
  «Конфиденциально» (`REDACT_FROM`).
