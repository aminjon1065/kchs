# 0004. Модель доступа: ACL + пространства + политики типов + политики строк/столбцов
Статус: Принято. Дата: 2026-09-17

## Контекст
Нужно единообразное, объяснимое управление доступом для объектов, данных (строки/столбцы), документов с грифами, с учётом оргструктуры, руководителей, замещений.

## Решение
Уровни `view<comment<edit<manage<owner`; принципалы (пользователь, группа, подразделение с вложенностью, должность, роль пространства, роль, все, ссылка); наследование по дереву объектов с возможностью разрыва; политики типов для производных прав (участник процесса, исполнитель, руководитель); атрибутные ограничения (грифы, политики строк/столбцов датасетов); делегирование; способности через роли; единый `authorize` и SQL-предикаты видимости.

## Альтернативы
Чистый RBAC (не выражает «поделиться этим документом с Ивановым»); Zanzibar-подобный сервис (избыточен для одной инсталляции); только ACL без политик (дублирование прав при каждом назначении).

## Последствия
Сложность сосредоточена в ядре; обязательные негативные тесты; «объяснить доступ» как инструмент; кэш принципалов.
