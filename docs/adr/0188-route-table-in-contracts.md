# 0188. Таблица маршрутов в контрактах: схемы маршрута описаны в одном месте

Статус: Принято
Дата: 2026-10-05

## Контекст

Находка 13 обзора архитектуры (`04-delivery/07-architecture-hardening.md` §2): клиент
`api<T>(path)` не связывает путь с типом, тело запроса — `unknown`. ADR-0030 обещал
типизированный клиент из `packages/contracts`, но связи «маршрут → схемы» в контрактах не
было. Метод, путь и схемы маршрута жили в вызове `route({ method, url, schema })` в api. В
файлах маршрутов api лежали 60 именованных схем и 346 встроенных выражений zod. Клиент
переписывал их вручную.

## Решение

**Таблица маршрутов.** Записи вида `defineRoutes({ 'GET /tasks/:id': { params, query?, body?,
response? } })` лежат в `packages/contracts/src/routes/`, по файлу на владельца:

- область ядра — `kernel/<область>.ts`, таблица `kernel<Область>Routes`;
- модуль — `modules/<модуль>.ts`, таблица `<модуль>Routes`;
- общие схемы таблиц — `params.ts`: `IdParam`, `RowParams`, `Ok`.

Ключ — метод и путь в синтаксисе Fastify без `/api/v1`. Он проверяется при загрузке модуля.
`response` — схемы по кодам, как в Fastify. `apiRoutes` из `@kchs/contracts/routes`
объединяет таблицы. Если ключ описан в двух таблицах, `mergeRouteTables` падает. Тип
`ApiRoutes` назван явно — пересечение таблиц. Выведенный тип не помещается в объявления
(TS7056).

**Маршруты процессов — в `@kchs/process`.** Схемы движка процессов стоят на
`ProcessDefinition` (ADR-0079). Пакет процессов сам зависит от контрактов, обратного импорта
быть не может. Поэтому `processRoutes` (18 маршрутов) и `documentProcessRoutes` (5) описаны
в `packages/process/src/routes.ts` тем же `defineRoutes`. Полная таблица собирается так:
`mergeRouteTables(apiRoutes, processRoutes, documentProcessRoutes)`. api собирает её в
`shared/http/route-table.ts`.

**Регистрация по ключу.** Вызов выглядит так: `route({ route: 'GET /tasks/:id', auth, tags,
summary, handler })`.

- Из записи таблицы берутся метод, путь и схемы. В api остаются политика доступа, обработчик,
  теги, описание и лимиты.
- Типы `request.params`, `request.query` и `request.body` — выход схем записи. У части без
  схемы тип `unknown`.
- Маршрут, который регистрируется в цикле по действиям, называет ключ шаблоном:
  `` `POST /cases/:id/${action}` as const ``. В таблице у каждого действия своя запись.

Служебные маршруты вне `/api/v1` в таблицу не входят: `/health`, `/api/openapi.json`,
`/api/docs`. Не входит и страница офисного редактора `/office/editor/:id`. Это не контракт
API.

**Полнота таблицы.**

- **Маршрут без записи не регистрируется.** Ключ вне таблицы не пропустит компилятор: тип
  `ApiRouteKey`. Ключ, собранный во время выполнения, отвергнет регистратор (`contractOf`).
- **Запись без регистрации не даёт запуститься.** После `registerModules` вызывается
  `assertRouteTableRegistered()`. Маршруты регистрируются безусловно: выключенный модуль
  отвечает 404 в `featureGate`. Поэтому проверка при старте не зависит от настроек
  установки.
- **Тесты.** `apps/api/src/shared/http/route.test.ts` проверяет регистратор.
  `packages/contracts/src/http/__tests__/route-contract.test.ts` проверяет ключи, объединение
  таблиц и выведенные типы. Оба теста проверяют, что схема параметров называет ровно
  параметры пути.

**Типы для клиента.** По ключу маршрута выводятся:

| Тип | Что это |
|---|---|
| `RoutePath<K>`, `RouteMethod<K>`, `PathParamNames<P>` | путь, метод и имена параметров пути |
| `RouteParams<C, K>` | вход схемы параметров; без схемы — `{ имя: string }` по сегментам `:имя` пути |
| `RouteQuery<C>`, `RouteBody<C>` | вход схем, то есть то, что передаёт клиент |
| `RouteResponse<C>` | выход схемы успешного ответа (200, 201, 202 или 204); без схемы — `unknown` |

Здесь `C` — запись таблицы, `Routes[K]`. Клиент web (этап 3А-2) строится по полной таблице:
`ApiRoutes & typeof processRoutes & typeof documentProcessRoutes`.

**Поведение не меняется.** Пути, коды и формы прежние, схемы — те же объекты zod. Спецификации
`pnpm openapi:gen` до и после переноса совпадают байт в байт: 554 пути, 689 операций.

**Рекурсивные схемы в OpenAPI.** Давний дефект нашёлся при снимках контрактов (ADR-0189).
Рекурсивную схему fastify-type-provider-zod выносит в ссылку, а схема без имени получала
ссылку на компонент `schema0` или `schema1`, которого в `components.schemas` не было. Это
161 висячая ссылка в 62 операциях: дерево фильтра, рекурсивное значение JSON, условия
правила автоматизации. Внешний потребитель получал битую спецификацию, проверка
совместимости не видела изменений внутри этих схем.

- **Имена.** `openApiComponents()` в `packages/contracts/src/http/components.ts` называет
  рекурсивные схемы: `Json`, `FilterNode`, `RuleCondition`. Реестр zod — свой, не
  глобальный: `z.toJSONSchema` в провайдере ИИ и в снимке событий он не трогает.
- **Компоненты.** api передаёт реестр в `createJsonSchemaTransform` и
  `createJsonSchemaTransformObject` (`shared/http/openapi-schemas.ts`). Схемы попадают в
  `components.schemas` в двух видах, для запроса и для ответа: `FilterNodeInput` и
  `FilterNode`. Служебные `$id` и `$schema` у компонентов убраны.
- **Охрана.** `pnpm openapi:gen` падает на ссылке на неописанную схему. Unit-тест
  `shared/http/openapi-schemas.test.ts` проверяет ссылки всех маршрутов таблицы. Новая
  рекурсивная схема без имени не пройдёт ни то, ни другое.
- **Итог.** Изменились ровно 62 операции с висячими ссылками, остальные 627 — байт в байт
  прежние. Ссылок 177 на 6 компонентов, все разрешаются.
- **Снимок и совместимость (ADR-0189).** Снимок OpenAPI хранит компоненты в `defs` под их
  ссылкой (`#/components/schemas/FilterNode`). Проверка совместимости теперь заходит внутрь:
  новое обязательное поле условия фильтра даёт находки в 27 операциях. Сравнение
  рекурсивной схемы кончается: пара ссылок сравнивается на пути один раз. Ссылка вне снимка
  внутри объединения означает «тип неизвестен», а не «любой». Иначе переход от висячей
  `schema0` к компоненту выглядел бы сужением типа: так проверка против `bf010ec9`
  показывала 19 ложных поломок. В `allowed-breaking.json` они не записаны. Запись
  исключения освобождает от проверки операцию целиком, а в CI её никто бы не использовал:
  снимка с висячими ссылками в main нет.

Схемы перенёс кодмод. В 40 таблиц легли 689 записей и 346 встроенных выражений zod. 60
локальных объявлений схем api, многие из них — копии `IdParam`, стали 35 объявлениями; 3 из
них общие, в `routes/params.ts`. Комментарии при схемах сохранены. Схемы, которые описывали
ответы вне таблицы, ушли в доменные файлы контрактов: `NormalizedReport`, `BackupRecord` и
`BackupList`, `OfficeTicketQuery`. Список токенов api заменён существующим `ApiTokenList`.

## Альтернативы

- **Схемы в `route()`, клиент из OpenAPI.** Отклонено ADR-0030: типы через JSON Schema теряют
  выразительность zod, в цикле разработки появляется шаг генерации.
- **Ключ — объект `{ method, path }`.** Строку `'GET /tasks/:id'` легче искать. Она же — ключ
  реестра маршрутов, по которому работают тесты доступа (ADR-0186). Из неё типом выводятся
  метод и параметры пути.
- **Одна таблица на всё API.** 689 записей в одном файле: правка любого модуля даёт конфликт.
  Таблицы разложены по владельцам, как схема БД (ADR-0178).
- **Схемы процессов в контрактах.** Тогда в контракты пришлось бы перенести
  `ProcessDefinition` и константы машины состояний (ADR-0079).
- **Полнота только тестом.** Регистрация безусловная, поэтому проверка при старте дешевле. И
  её нельзя пропустить, пропустив тест.

## Последствия

- **Новый маршрут.** Это запись в таблице владельца и `route({ route: … })` в api. Без записи
  код не скомпилируется, без регистрации api не запустится.
- **Схемы маршрутов в api не живут.** Схема zod в файле маршрутов — повод перенести её в
  таблицу. Внутренние схемы сервисов не трогаются: ответы движка, полезная нагрузка заданий,
  манифесты.
- **Запись таблицы — контракт HTTP.** Её изменение меняет OpenAPI, а снимок OpenAPI в git
  ловит ломающие правки (ADR-0189).
- **Ответ без схемы.** У 27 записей схемы ответа нет. Почти все из них — файлы, тайлы, потоки
  и выгрузки. Семь отвечают JSON без схемы: `GET /objects/:id/links`,
  `GET /objects/:id/activity`, `GET /admin/jobs`, `GET /gis/service-layers/:id/features`,
  `GET /me/preferences`, `GET /me/workspace-state`, `GET /me/delegations`. Для них
  `RouteResponse` — `unknown`. Со схемой ответ проверяется при сериализации, лишние поля
  отбрасываются. Поэтому схему добавляют отдельной правкой с тестом.
- **Ответ обработчика компилятор не сверяет.** Его проверяет сериализатор Fastify, как и
  раньше. Типизировать ответ обработчика по `RouteResponse` — отдельный шаг.
