# 0160. Ключ строки уникален среди живых строк; карта: файл геоданных на карту, выгрузка слоёв, группы, отмена правки геометрии

Статус: Принято
Дата: 2026-09-25

## Контекст

Известное ограничение: мягко удалённая строка датасета держала значение ключа — уникальный
индекс ключа был полным (так `upsert` импорта «воскрешал» удалённую строку через `ON CONFLICT`),
поэтому новая строка с ключом удалённой отклонялась (409), а откат, возвращающий прежнее значение
ключа, спотыкался о удалённые строки. Таблицы `ds.t_*` создаёт код (`Physical`), а не drizzle.

В разделе «Чего пока нет» руководства по картам: файл геоданных нельзя добавить прямо на карту,
карта выгружается только картинкой, нет групп слоёв и отмены правки геометрии. Поле `group`
записи слоя карты (`MapLayerEntry.group`) было в контракте, но интерфейс его не использовал.

## Решение

1. **Индекс ключа — по живым строкам**: `CREATE UNIQUE INDEX … WHERE _deleted_at IS NULL` при
   создании таблицы и смене ключа; повторы ключа при смене считаются среди живых строк.
   - `upsert` импорта сохраняет воскрешение: сначала отдельным `UPDATE` оживает последняя удалённая
     строка ключа, у которого нет живой строки (история строки не рвётся), затем
     `INSERT … ON CONFLICT (ключ) WHERE _deleted_at IS NULL DO UPDATE` — для остальных. Сводка
     изменений перед публикацией сопоставляет строку так же (живая, иначе последняя удалённая).
   - Новая строка с ключом удалённой принимается; возврат удалённой строки, ключ которой занят
     живой, — 409 (нарушение индекса, как раньше). Откат отменяет версии от новых к старым, поэтому
     ключ, который держала отменённая вставка, ему больше не мешает.
   - Прежние таблицы: `Physical.upgradeKeyIndexes()` при старте api перестраивает полные уникальные
     индексы `ds.t_*` в индексы живых строк (как `upgradeHistoryTables`, ADR-0062): таблицы строк
     создаются на лету ролью приложения, у роли миграций нет прав на их индексы, а drizzle о них не
     знает. Повторный запуск ничего не меняет.
2. **Файл геоданных прямо на карту** — кнопка в панели слоёв открывает мастер импорта (новый
   датасет в пространстве карты); итог «Добавить на карту» создаёт слой со стилем по умолчанию
   (`POST /gis/layers`, как «На карте» у датасета, ADR-0072), ставит его на карту и приближает к
   охвату. Одно действие для пользователя, но это те же импорт и слой: права, версии и движок для
   геоформатов — как у обычного импорта. Карту нужно сохранить.
3. **Выгрузка карты в геоформаты** — видимые слои с доступом к данным, по файлу на слой: задание
   экспорта датасета слоя (ADR-0056, ADR-0068) в GeoJSON, GeoPackage или KML с фильтром слоя
   (`style.filter`) и политиками пользователя; нужна способность «Выгрузка данных». Один
   многослойный файл не собирается: GeoPackage с несколькими таблицами потребовал бы нового
   задания движка, а слои карты часто ссылаются на разные датасеты с разными правами.
4. **Группы слоёв** — пункт «Группа…» меню слоя: новое название или одна из групп карты, «Убрать из
   группы». Соседние слои одной группы — один узел дерева панели со сворачиванием и общим флажком
   видимости; слой, добавленный в группу, встаёт поверх её слоёв, чтобы узел оставался цельным.
   Контракт карты не меняется — используется `MapLayerEntry.group`.
5. **Отмена и повтор правки геометрии** — история черновика в хранилище сеанса правки
   (`past`/`future`, до 50 шагов): каждая правка terra-draw, координаты вручную и местоположение —
   шаг; «Отменить»/«Повторить» на панели правки, ⌘Z/Ctrl+Z и ⇧⌘Z/Ctrl+Y (в полях формы — их
   собственная отмена). Новый объект начинает историю заново. Отмены правок состава и стиля карты
   нет — для них есть «Сохранить карту» и «Отменить» редактора стиля.

## Альтернативы

- **Не воскрешать удалённые строки при загрузке** (ключ удалённой — новая строка): проще SQL, но
  повторная загрузка того же списка плодила бы новые `_id` и рвала историю и связи строки.
- **Миграция drizzle с блоком `DO`** для прежних индексов: выполняется ролью миграций, которая не
  владеет таблицами `ds.*`; проверка при старте уже принята для таблиц истории.
- **Шторка сравнения слоёв** — отложена: нужен второй холст MapLibre или обрезка слоёв по
  `clip-path` с синхронизацией вида; это отдельная работа по студии.

## Последствия

- Строк с одним ключом в таблице может быть несколько, но живая — не больше одной; запросы
  пользователей по-прежнему видят только живые строки.
- Импорт в режиме «обновить по ключу» делает на один проход по таблице больше (воскрешение).
- Тесты: `data-rows.test.ts` (ключ удалённой строки), `data-rollback.test.ts` (отмена вставки не
  мешает откату; занятый живой строкой ключ — 409; перестройка прежнего индекса),
  `data-import-review.test.ts` (восстанавливаемые строки в сводке), модульные
  `edit-store.test.ts` и `layer-panel.test.ts`.
