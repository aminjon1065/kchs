# Черновик раздела ADR-0225: доступ в api

> Раздел для общего ADR-0225 (третий разбор). Сводится в `0225-*.md` при сведении этапа.

## Контекст

Область токена API выводится из тега маршрута (ADR-0097), а шлюз DMZ открывает
снаружи то же, что доступно токену (ADR-0200). Под тегами `org`, `access` и `spaces`
вместе со справочниками лежали маршруты, которые меняют учётные записи и доступ:
временный пароль, сброс второго фактора и ключей входа, роли, группы, допуск,
оргструктура, факсимиле, служебные учётные записи, права на объект и гостевые
ссылки. Гость по ссылке проходил на любой `GET` с проверкой права на объект, а не
только на просмотр самого объекта (ADR-0032). Вебхук фильтровал события по полю
`visibility` конверта, которое никто не заполнял. «Объяснить доступ» отвечал любому
читателю объекта. Предел открытий гостевой ссылки проверялся до засчитывания.

## Решение

- **Признак таблицы маршрутов `sessionOnly`** (`RouteContract`, ADR-0188): маршрут
  управляет учётными записями и доступом и вызывается только из сессии сотрудника.
  `requiredScope` для него возвращает «токенам недоступно» при любом теге, поэтому
  маршрут закрыт и токену API, и шлюзу DMZ (тот же расчёт, белый список
  перегенерирован). Признак стоит у 32 маршрутов:
  - учётные записи: `POST /users`, `PATCH /users/:id`, `POST /users/:id/reset-password`,
    `POST /users/:id/reset-mfa`, `GET|DELETE /users/:id/passkeys`,
    `PUT /users/:id/clearance`, `GET|PUT|DELETE /users/:id/facsimile`,
    `POST /service-accounts`, `PATCH /service-accounts/:id`;
  - роли, группы, оргструктура: `POST /roles`, `PATCH|DELETE /roles/:id`, `POST /groups`,
    `PATCH /groups/:id`, `PUT /groups/:id/members`, `POST /org/units`,
    `PATCH /org/units/:id`, `POST /org/positions`, `PATCH|DELETE /org/positions/:id`;
  - права на объект и пространство: `POST|DELETE /objects/:id/access`,
    `PUT /objects/:id/access-mode`, `POST /objects/:id/access/explain`,
    `POST /objects/:id/share-links`, `DELETE /objects/:id/share-links/:linkId`,
    `POST /spaces/:id/members`, `PUT|DELETE /spaces/:id/members/:userId`.

  Чтение справочников (`GET /users`, `/groups`, `/roles`, `/org/*`, состав доступа
  объекта) токену с областью чтения остаётся.
- **Признак `guest`**: гостю по ссылке открыт только белый список — `GET /objects/:id`,
  `GET /files/:id`, `/files/:id/download`, `/files/:id/previews`, `/files/:id/text`
  (то, что вызывает страница гостевого просмотра). Остальное, включая обсуждение,
  состав доступа, активность и ссылки, гостю отвечает 404. Регистрация падает, если
  признак стоит не у `GET` с `auth: { action }`.
- **Вебхук проверяет видимость получателем.** Перед заведением доставки — право
  владельца подписки на объект события (`authorize(view)` с грифом; удалённый в корзину
  — тоже). Событие без объекта реестра (вход в систему, окончательно удалённый объект,
  служебные ресурсы) уходит, только если подписка называет его тип прямо — `*` и
  `user.*` его не включают. Отключённой учётной записи-владельцу не доставляется ничего.
  Поле `visibility` из конверта события удалено: его никто не заполнял, а решение о
  видимости принимает получатель по текущим правам (`contracts/events.md`).
- **«Объяснить доступ»** — тем, кто управляет доступом объекта (уровень `manage` или
  `owner`), аудитору безопасности и администратору системы.
- **Предел открытий гостевой ссылки** засчитывается одним условным `UPDATE … WHERE uses
  < max_uses RETURNING`: параллельные открытия не проходят сверх предела.

## Альтернативы

- **Перечень путей в `scopes.ts` и `gateway.ts`.** Расходится с таблицей маршрутов при
  первом новом маршруте; признак рядом со схемами маршрута виден при правке контракта.
- **Сменить тег у маршрутов управления на закрытый.** Перекладывает разделы OpenAPI и
  документацию, а смысл «справочник открыт, управление — нет» прячет в имени тега.
- **Заполнять `visibility` ядром из ACL на момент события.** Дорого на каждом событии,
  устаревает к моменту доставки и не учитывает гриф и допуск получателя.

## Последствия

- Интеграция не заводит и не правит учётные записи, роли и права по токену — это
  делается в консоли или синхронизацией каталога (LDAP, ADR-0098). Если такой сценарий понадобится,
  он будет отдельным решением с узкой областью и аудитом.
- Вебхук, подписанный администратором системы, получает всё в пределах его допуска —
  по модели доступа администратор видит все объекты (03-access-model.md §1).
- Снимки контрактов: конверт события без `visibility`; OpenAPI не меняется.
