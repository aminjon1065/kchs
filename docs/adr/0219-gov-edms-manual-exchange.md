# 0219. Ручной обмен с закрытой госЭДО: очередь «Из госЭДО», пакет исходящего, отметка о передаче

Статус: Принято
Дата: 2026-10-14

## Контекст

Пункт 10 плана `08-architecture-concept-note-and-signatures.md` §11 — адаптер государственной
системы ЭДО — ждал её интерфейса. ADR-0206 оставил порт `EdmsExchange`, очередь `edms_sends`
и канал `edms` журнала подключений без реализации.

Владелец ответил 14.10.2026 (`05-risks-and-open-questions.md` §8): «не надо ничего ждать, она
закрытая, оттуда документы берутся и потом у нас работается». Интерфейса не будет. Документ
выгружается из госсистемы на рабочем месте канцелярии и дальше ведётся в платформе. Исходящий
адресату, который работает через госЭДО, канцелярия загружает туда вручную. Нужен удобный
ручной обмен: быстро завести выгрузку и быстро собрать пакет для загрузки.

## Решение

1. **Провайдер порта «ручной обмен».** `MANUAL_EDMS` (`manual: true`) — адаптер по умолчанию.
   - `EdmsSends.enqueue` теперь ставит отправку, а не отказывает 409.
   - Задание `EDMS_DISPATCH_JOB` ручные отправки не трогает. Сетевых повторов нет.
   - Отправку закрывает отметка человека: `EdmsSends.markSent` в транзакции отметки ставит
     `sent`, номер в госсистеме и событие `edms.sent`, пишет передачу в канал `edms` журнала
     подключений.
   - Автоматический адаптер, если интерфейс появится, регистрируется
     `registerEdmsExchange` как раньше.
2. **Входящие: очередь «Из госЭДО».** Навигатор «Документы» → «Канцелярия» → «Из госЭДО»
   (право `documents.register`).
   - **Загрузка пачкой.** Файлы перетаскиваются в окно. Архив ZIP — один документ: основной
     файл — первый PDF, иначе первый DOCX, иначе первый файл; остальное — приложения
     (до 100 файлов из архива). Россыпь файлов — каждый отдельным документом или одним
     документом с приложениями, как выберет делопроизводитель.
   - **Повтор по содержимому.** Клиент считает SHA-256 основного файла и спрашивает
     `POST /documents/gov-edms/check`. Повтор помечается «Уже заведён: № … — повторно не
     заводится» и не загружается. Сервер проверяет хэш ещё раз при завершении: черновик
     повтора уходит в корзину, ответ 409 с номером заведённого документа.
   - **Черновик входящего.** `POST /documents/gov-edms/intake` создаёт документ через
     `DocumentService.create`: тип «Входящее письмо», способ доставки `edms`, тема — имя
     файла. Файлы загружаются обычной сессией к черновику, `…/intake/{id}/complete`
     собирает версию (основной файл и приложения). Событие `document.edms_imported`, аудит.
   - **Реквизиты из текста.** Подписчик `file.text_extracted` разбирает текст основного
     файла (`parseRequisites`, русские и таджикские формулировки): исходящий номер и дата
     отправителя, отправитель, тема. Заполняются только пустые поля. Тема заменяется, только
     если человек её не менял (равна теме из имени файла). Корреспондент ищется по сходству
     названия (`similarity > 0,3`). Состояние разбора — «Реквизиты читаются из текста…»,
     «Реквизиты из текста», «Текста нет — реквизиты вручную». Событие
     `document.edms_prefilled`. ИИ не используется.
   - **Повтор по реквизитам.** Тот же отправитель и тот же исходящий номер у другого
     документа — предупреждение «Тот же отправитель и номер уже есть: …». Документ
     заводится: скан и PDF одного письма — разные файлы, решает человек.
   - Регистрация — обычной карточкой: номер, журнал, резолюция, поручения как у любого
     входящего. Фильтр «Ждут регистрации» показывает черновики, «Все» — и
     зарегистрированные.
3. **Исходящие: пакет и отметка.**
   - В справочнике «Корреспонденты» у адресата — переключатель **«Обмен через госЭДО»**
     (`correspondents.edms_exchange`).
   - Регистрация исходящего такому адресату (подписчик `document.registered`) ставит
     отправку в `edms_sends` и открывает регистратору дело во Входящих **«Передать в госЭДО:
     …»** (вид `edms_transfer`, срок — конец следующего дня, 36 часов).
   - В карточке исходящего — блок **«госЭДО»**: «Ждёт передачи в госЭДО», кнопки «Скачать
     пакет для госЭДО» и «Отметить: передано».
   - **Пакет** — ZIP `<рег. номер> — госЭДО.zip`:
     - основной файл назван регистрационным номером: подписанный экземпляр (ADR-0198), иначе
       готовый PDF версии, иначе основной файл;
     - `Приложения/…` — приложения версии в закреплённых версиях файлов (ADR-0197);
     - `card.json` (формат `kchs.gov-edms.package/v1`) — реквизиты, адресат с кодом
       (`externalId`), подписи с хэшами, хэш манифеста версии, список файлов.
     Пакет кладётся в корзину выгрузок (`gov-edms/<id>/…`), ссылка подписана. Предел —
     200 МБ. Событие `document.edms_package_prepared`, аудит.
   - **Отметка «передано»** — дата и номер в госЭДО, примечание. Пишется в реестр отправки
     способом `edms` (номер — в поле трека), первая отметка исполняет исходящий, как любая
     отправка. Подписчик `document.dispatched` закрывает отправку в очереди (`markSent`) и
     дело во Входящих.
   - Адресату без признака передачу можно отметить общей кнопкой «Отметить отправку»
     способом «госЭДО». Тогда блок «госЭДО» появляется и показывает передачи.
4. **Название способа доставки.** `edms` в интерфейсе — «госЭДО» (тадж. «ҲЭД-и давлатӣ»,
   англ. «Government EDMS») вместо «СЭД»: другой СЭД в платформе нет.

API: `POST /documents/gov-edms/check`, `GET|POST /documents/gov-edms/intake`,
`POST /documents/gov-edms/intake/{id}/complete`, `GET /documents/{id}/gov-edms`,
`POST /documents/{id}/gov-edms/package`, `POST /documents/{id}/gov-edms/transferred`.
Миграция `20261014031006_gov-edms.sql`: поле корреспондента и таблица `gov_edms_intakes`
(файл, хэш, состояние разбора, найденные реквизиты, повтор).

## Альтернативы

- **Ждать интерфейс госсистемы.** Отклонено владельцем: система закрыта, интерфейса не будет.
- **Регистрация выгрузки экраном «Регистрация входящего».** Отклонено: экран — по одному
  документу, без проверки повторов и без архивов; выгрузка приходит пачками.
- **Реквизиты из текста через ИИ.** Отклонено для этого шага: ИИ настроен не на каждой
  установке, а у бланков госорганов устойчивые формулировки. Разбор правилами, человек
  проверяет в карточке.
- **Запрет повтора по отправителю и номеру.** Отклонено: скан и PDF одного письма, повторная
  выгрузка с исправлением — решает делопроизводитель, система предупреждает.
- **Отдельный реестр передач в госЭДО.** Отклонено: передача — та же отметка отправки,
  реестр отправки, исполнение и отчёты уже работают.

## Последствия

- Канал `edms` журнала подключений считает реальные передачи: показатель концепт-ноты
  видит обмен с госЭДО.
- Новый вид дела во Входящих `edms_transfer` (делегирование по разделу «Документы»).
- Новые события `document.edms_imported`, `document.edms_prefilled`,
  `document.edms_package_prepared`; контракты совместимы с main.
- Зависимость `fflate` (ZIP) в api и web.
- Подписанный пакет с проверяемой подписью Комитета появится вместе с собственным
  удостоверяющим центром (ответ владельца по N91/N119): пакет берёт подписанный экземпляр,
  когда он есть.
