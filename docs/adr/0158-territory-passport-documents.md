# 0158. Документы территории в паспорте

Статус: Принято
Дата: 2026-09-25

## Контекст

Паспорт территории (ADR-0077) собирает данные, объекты, показатели и поручения единицы.
Вкладка «Документы» была заглушкой с обещанием связи «о территории» (руководство 05, «Чего
пока нет»). К этому времени территория документа хранится в трёх местах:

- реквизит документа `territory_id` — задаётся через API, карточка его не показывает;
- поле-территория карточки типа: «Район» донесения о ЧС и «Территория» распоряжения штаба
  пакета ЧС, любое поле типа `territory` в `cardSchema`;
- связь ядра `about_territory` от документа к единице справочника — её создаёт блок
  «Связи» карточки (ADR-0086).

Права на документы личные: документ видят участники карточки, получатели по ACL и
канцелярия, гриф — не выше допуска (ADR-0080).

## Решение

1. Документ относится к территории, если любое из трёх мест указывает на неё или на
   вложенную единицу: область показывает документы своих районов, как поручения
   (ADR-0077). Отдельную «территорию документа» не заводим: три источника читаются как
   есть.
2. `GET /documents/territory/:id?limit=` модуля «Документы». Ответ — `DocumentTerritoryList`:
   номер, дата регистрации, тема, вид, статус, территория-источник и способ связи (`card`,
   `field`, `link`), общее число. Порядок — по дате регистрации, без неё — по дате создания,
   новые сверху.
3. Права — предикат видимости ядра на каждую строку (`visibleObjectsSql`): ACL,
   наследование, участники карточки и гриф выше допуска. Документ без права просмотра в
   ответ не попадает и в общем числе не считается.
4. Web: вкладка «Документы» паспорта — таблица с колонкой «Как связан», число на вкладке,
   открытие документа щелчком. Пустая вкладка объясняет, как документ сюда попадает.
   Маршрут живёт в модуле «Документы»: модуль GIS от него не зависит. Документы уже
   зависят от GIS через справочник территорий, и обратная зависимость дала бы цикл.

## Альтернативы

- **Только связь «о территории».** Донесения о ЧС и распоряжения штаба пакета несут район
  реквизитом карточки. Требовать от дежурного ещё и связь — двойной ввод.
- **Территория подразделения документа.** Место регионального управления не равно
  предмету документа: письмо управления в министерство — не документ «про» его район.
- **Синхронизировать `territory_id` с полем карточки при записи.** Получились бы два
  источника одного значения и миграция уже заведённых документов. Чтение трёх источников
  дешевле при объёмах канцелярии.
- **Отбор на клиенте по общему списку объектов.** Список не знает вложенности территорий и
  полей карточек разных типов. Считать итог по видимым документам пришлось бы в браузере.

## Последствия

- Поле-территория карточки ищется по ключу из `cardSchema` каждого типа. Новое поле типа
  `territory` в карточке сразу работает для паспорта, без настройки.
- Запрос проходит документы по условию на поля карточки без индекса по вложенным
  территориям. Для объёмов канцелярии (тысячи документов) этого достаточно. При росте
  нужен индекс выражения по полю карточки.
