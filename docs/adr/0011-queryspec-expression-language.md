# 0011. QuerySpec и язык выражений с компиляцией в SQL; сырой SQL через libpg-query
Статус: Принято. Дата: 2026-09-17

## Контекст
Один и тот же запрос нужен гриду, конструктору, графикам, показателям, тайлам, экспорту, ИИ; политики доступа должны применяться в одном месте; продвинутые пользователи хотят SQL.

## Решение
Декларативный QuerySpec + собственный язык выражений (Pratt-парсер, типизация) → компилятор в SQL с диалектами (Postgres; DuckDB позже); политики строк/столбцов встраиваются компилятором. Сырой SQL парсится настоящим парсером Postgres (libpg-query), проверяется по белому списку и переписывается.

## Альтернативы
Прямой SQL от клиента (небезопасно); ORM-конструкторы (не выражают агрегации/гео/окна декларативно для UI); Cube/Metabase-встраивание (чужой продукт внутри).

## Последствия
Ядро аналитики — собственный пакет с обширными тестами; ИИ генерирует QuerySpec, а не SQL; единая точка безопасности данных.
