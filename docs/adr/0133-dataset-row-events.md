# 0133. События строк датасета для правил: по настройке датасета, со значениями, без чувствительных полей

Статус: Принято
Дата: 2026-09-24

## Контекст

Пакет ЧС (P5-E08) и приложение E концепт-ноты КЧСиГО требуют правил вида «сообщение
об опасном явлении магнитудой от 4,5 в районе ГБАО → уведомить дежурную смену» и
«донесение с погибшими → поручение руководству». Сообщения и происшествия — строки
датасетов: их пишут ленты по адресу (ADR-0132), формы сбора (ADR-0103, ADR-0129) и
дежурный на карте (ADR-0076).

Правило автоматизации (ADR-0096) видит только конверт события. Единственное событие
правки строк, `dataset.rows_changed`, несёт идентификаторы и счётчик, но не значения. Поля
объекта (`object.fields`) правилу даёт поставщик данных процесса, а он есть только у
документа. Получалось, что правило может узнать «в датасете что-то вставили», но не
может отобрать строку по значению и не может подставить значение в текст уведомления.

Открытыми были вопросы:

- публиковать ли значения в каждом событии правки строк или по выбору;
- как не превратить импорт миллионов строк и массовую правку в миллионы запусков правил;
- что делать с чувствительными полями и политиками столбцов — значения попадут в тексты
  уведомлений;
- как дать правилу территорию так, чтобы условие «в области» было простым.

## Решение

1. **Настройка датасета `rowEvents`**, по умолчанию выключена. Включает её тот, кто
   управляет датасетом (диалог «Настройки» схемы). Диалог предупреждает, что значения
   увидят в текстах правил все, кто видит датасет.
2. **Три события на строку** — `dataset.row_created`, `dataset.row_updated`,
   `dataset.row_deleted`. Объект события — датасет, поэтому получатели уведомлений правила
   ограничены теми, кто видит датасет, как у любого объекта (ADR-0096). Полезная нагрузка:
   - `rowId`;
   - `values` — значения полей по ключам;
   - `labels` — подписи вариантов выбора и названия территорий, для текстов уведомлений;
   - `territories` — у полей-территорий идентификатор, код, название и путь кодами от
     страны (`['TJ','TJ-GB','TJ-GB-04']`). Условие «в ГБАО» — это
     `contains(event.payload.territories.territory.path, 'TJ-GB')` на уже существующем языке
     выражений.

   У правки есть ещё `changed` и `previous` (прежние значения изменённых полей). Ядро
   правил отдаёт их корнем `previous.*`, и правило ловит переход «статус стал
   „рассмотрено“».
3. **Что не публикуется**:
   - чувствительные поля (`sensitive`);
   - геометрия сложнее точки (полигоны велики, правилу из них нужна разве что территория);
   - при удалении без истории — значения (строка удалена окончательно, их нечем прочитать).
4. **Предел пакета — 200 строк** (`ROW_EVENTS_LIMIT`). Правка больше предела публикует
   только сводное `dataset.rows_changed`. Импорт файла и загрузка источника через staging
   (ADR-0046, ADR-0107) событий строк не публикуют вовсе. Строковые события — для строк,
   которые пишутся по одной: лента, форма, дежурный, пакет из буфера.
5. **Публикация — в той же транзакции**, что правка строки: через outbox после истории
   строки (`row-service.ts`, `row-events.ts`). Отдельного подписчика в модуле данных нет:
   события слушают правила и исходящие вебхуки, как любые события каталога.

## Альтернативы

- **Значения в `dataset.rows_changed`.** Отклонено: событие одно на пакет до тысячи строк.
  Правилу пришлось бы перебирать массив, а условия и шаблоны языка выражений рассчитаны на
  одну запись.
- **Поставщик полей для датасета (`ProcessObjectProvider`).** Отклонено: объект события —
  датасет, а не строка. Поставщик дал бы поля схемы, но не значения конкретной строки, и
  правило не знало бы, какая строка пришла.
- **Всегда публиковать события строк.** Отклонено: значения попадают в тексты уведомлений
  всем, кто видит датасет. Решать это должен тот, кто датасетом управляет. Кроме того,
  лишние события нагружают шину.
- **Отбирать строки прямо в модуле данных** (подписка «строка удовлетворяет условию»).
  Отклонено: это второй механизм правил рядом с автоматизацией.

## Последствия

- В каталоге событий — три новых типа домена `dataset`. Конструктор правил подсказывает
  их поля автоматически.
- Правило с условием по значениям строки теперь можно проверить тестовым прогоном на
  настоящих событиях — это проверяет тест `data-row-events.test.ts`.
- Политики строк и столбцов датасета при публикации не применяются: пишущий их не имеет
  (правка строк требует доступа без ограничений, ADR-0051), а получатели видят датасет
  целиком или не видят его. Поэтому настройку не стоит включать у датасетов, строки которых
  разным людям видны по-разному. Об этом предупреждает подсказка.
- Правка больше 200 строк молча не запускает строковые правила. Если понадобится
  «правило на итог пакета», его строят на `dataset.rows_changed`.
