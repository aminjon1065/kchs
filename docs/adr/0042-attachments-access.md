# 0042. Вложения: закрытая системная папка и доступ через связь `attachment`

Статус: Принято
Дата: 2026-09-18

Контекст: `09-files.md` §1 (Решено): вложение — связь `attachment` от объекта к файлу,
один файл может быть вложен в несколько объектов, загруженные как вложения файлы лежат
в скрытой системной папке пространства «Вложения». Модель доступа не говорила, кто
видит такие файлы. Папка с доступом по роли в пространстве открыла бы вложения
закрытых объектов (конфиденциальный документ) всем участникам пространства.

Решение:
- Папка «Вложения» создаётся при первом вложении в пространстве (`meta.system =
  'attachments'`, блокировка от гонки), без владельца и в режиме `restricted`:
  роль в пространстве до её содержимого не доходит (ADR-0040 не причём — это
  общее правило границы наследования, см. `03-access-model.md`).
- Доступ к вложению выводит ядро (шаг `attachment` в `effectiveLevel`): кто видит
  объект-хост, видит вложение; кто правит хост — правит вложение (новая версия), но
  не выше `edit` — делиться и удалять может только владелец файла. Хост проверяется
  без этого шага: вложение вложения доступа не передаёт. Гость по ссылке с
  `includeAttachments` видит вложения открытого ему объекта тем же путём.
- Читатели вложения для поискового индекса — его собственные плюс читатели хостов;
  прикрепление и открепление переиндексируют файл, изменение доступа хоста —
  его вложения (вместе с поддеревом, задание `search.reindex-subtree`).
- Загрузка вложения требует `edit` на хосте и идёт в пространство хоста; права на
  создание в пространстве не нужны. Прикрепить существующий объект связью
  `attachment` может только тот, кто вправе им делиться (`share`): иначе прикрепление
  было бы выдачей доступа в обход владельца.
- Системные объекты (`meta.system`) не попадают в общие списки без `includeSystem`;
  в файловом менеджере — кнопка «Вложения объектов».

Альтернативы: доступ по роли в пространстве (просто, но вложения закрытых объектов
видны всем участникам); копирование ACL хоста на файл при загрузке (снимок устаревает
при изменении прав хоста и не работает для файла в нескольких объектах); политика
типа `file` вместо ядра (ядро уже знает о вложениях — гостевые ссылки с
`includeAttachments`, — а вложением может стать не только файл).

Последствия: одна проверка на каждый `authorize` — выборка хостов по индексу связей;
списки (`visibleObjectsSql`) пока не выводят доступ из хостов — вложения доступны через
объект (панель «Связи»), по прямой ссылке и в поиске, а в папке «Вложения объектов»
видны загрузившему и администратору.
