# Черновик раздела ADR-0227 — копии за пределы сервера и восстановление

> Для вклейки в сводный ADR-0227 этапа Б (эксплуатация к VPS).

## Контекст

На установке без резервного узла копия базы (`pg_dump` платформы, ADR-0117) лежала в бакете
`kchs-backups` того же MinIO на том же диске. Файлы сотрудников не копировались вовсе, `.env`
с мастер-ключом — «в менеджере секретов» без процедуры. Отказ диска, потеря сервера или
ошибочный `down -v` уносили данные вместе с копиями, а без мастер-ключа не расшифровать
вторые факторы, секреты интеграций и ключ удостоверяющего центра (ADR-0218). Восстановление
копии платформы до работающего приложения никто не проводил: дамп шёл с `--no-acl`.

Решение владельца (04.11.2026): копии забирает **компьютер в Комитете по SFTP**; сервер к
этой машине доступа не имеет. Оповещения о сбоях — Telegram (сторож, отдельный раздел).

## Решение

- **Ночная копия — `infra/scripts/backup.sh`**, репозиторий restic (версия репозитория 2:
  шифрование, сжатие, дедупликация) в каталоге хоста `KCHS_BACKUP_DIR`
  (`/var/lib/kchs-backup`), вне томов Docker. restic — в контейнере, закреплён по отпечатку;
  на сервере ставить его не нужно. Таймер systemd — каждую ночь в 03:30 (`install-timer`).
- **Что входит** — три снимка с метками:
  - `env` — `.env` установки потоком;
  - `db` — `pg_dump -U postgres --format=custom --compress=0 --create` потоком: владельцы,
    права ролей, права по умолчанию и настройки базы — в дампе; без сжатия, чтобы restic
    дедуплицировал соседние ночи;
  - `files` — бакеты `kchs-files`, `kchs-media`, `kchs-tiles` с тома MinIO, как их хранит
    MinIO (объект — каталог с `xl.meta`), без `.minio.sys`: пользователи, политики, версии
    и правила хранения заводит `minio-init` из `.env` при восстановлении.
  Не входят: превью (строит движок), выгрузки (временные, 30 дней), колоночные копии
  (строятся из базы), копии `pg_dump` платформы (повторяют снимок `db`), поиск
  (перестраивается из базы), Redis (очереди и кэш).
- **Снимок целиком или никакого**: снимок, при котором `pg_dump` или чтение файлов
  оборвались, удаляется (`forget`) — restic сохранил бы и неполный.
- **Хранение** 14 / 8 / 6 (дни, недели, месяцы), `forget --prune` по меткам. Каждую ночь
  `check` структуры, по воскресеньям — ещё 20 % данных.
- **Признаки для сторожа**: `last-success` (время UTC) и `last-failure` (время и причина);
  сбой вне известных шагов тоже пишет `last-failure`.
- **Пароль репозитория — отдельный файл** `/etc/kchs/backup.pass` (права 600), не в `.env`:
  копия `.env` лежит в репозитории, и пароль внутри неё ничего бы не защищал. Пароль и
  копия `.env` хранятся у ответственного офлайн.
- **Забор — `infra/scripts/backup-pull.sh`** на компьютере Комитета (Linux или WSL):
  `rsync` по SSH ключом; на сервере `backup.sh allow-pull` заводит пользователя
  `kchs-backup` с ключом `command="rrsync -ro <репозиторий>",restrict` и чтением
  репозитория группой. Прежняя копия перед забором сохраняется поколением из жёстких
  ссылок (`KCHS_PULL_KEEP`, 14): порча или удаление копий на сервере не уносит последнюю
  хорошую. `verify` сверяет файлы с их SHA-256 без пароля, `check` — полная проверка
  restic с паролем, на копии только для чтения.
- **Восстановление — `backup.sh restore --yes`**: `.env` из копии (прежний — рядом), стирание
  томов данных проекта, база и хранилище с `minio-init`, `pg_restore --create --clean
  --if-exists --exit-on-error`, файлы на остановленный MinIO, снова `minio-init`.
- **Копия платформы** (`backup.run`) — тоже с владельцами и правами: `--format=custom
  --create` вместо `--no-owner --no-acl`; восстановление — `pg_restore --create --clean
  --if-exists -d postgres`. В формате custom `--no-owner` при снятии игнорируется, а
  `--no-acl` отбрасывал права: у приложения пропадал DML до синхронизации привилегий при
  старте, у роли запросов — чтение таблиц датасетов, и терялись права по умолчанию; их
  мигратор не возвращает (он не владелец таблиц `ds.*` и не задаёт права по умолчанию
  роли `kchs_app`).
- **Версии файлов**: `minio-init` и чарт включают версионирование `kchs-files` с правилом
  «прежние версии — 30 дней, пустые отметки удаления убираются». Политика хранилища
  движка (запись производных как новых версий файла) не сужается: от перезаписи оригиналов
  защищают версии. Правила хранения добавляются один раз — повторный `mc ilm rule add`
  заводил второе правило при каждом запуске `minio-init`.

## Альтернативы

- **Сервер сам отправляет копии в Комитет или во внешнее S3.** Тогда на сервере лежит доступ
  к хранилищу копий, и захваченный сервер стирает и копии. Забор с машины Комитета этого
  доступа не даёт.
- **Копировать файлы через S3 (`mc mirror`) в промежуточный каталог.** Переносимо между
  реализациями S3, но требует ещё одной полной копии файлов на диске сервера. Снимок тома
  места не требует; переход на другую реализацию хранилища потребует `mc mirror` один раз.
- **Копировать весь том MinIO вместе с `.minio.sys`.** Вместе со служебными данными
  восстанавливалась бы чужая конфигурация; её заводит `minio-init` из `.env`.
- **`pg_dump` в сжатом формате или в виде SQL.** Сжатый дамп restic не дедуплицирует; SQL
  теряет выборочное восстановление `pg_restore`.
- **Только снимки диска у провайдера.** Не спасают при блокировке аккаунта или потере у
  провайдера — решение владельца.

## Последствия

- Администратору нужно один раз: `backup.sh init` (переписать пароль), `install-timer`,
  `allow-pull` для ключа Комитета; на компьютере Комитета — `backup-pull.sh` по расписанию.
- На сервере нужны `rsync` и `python3` (`rrsync` написан на Python); `allow-pull` проверяет
  это сам.
- Место на сервере — примерно размер базы и трёх бакетов, на компьютере Комитета — столько
  же плюс прирост поколений.
- RPO без резервного узла — сутки; RTO — время переноса репозитория на новый сервер и
  `restore` (на базе и файлах пилотного размера — минуты).
- Внешнее S3 вместо встроенного MinIO копирует его владелец: `backup.sh` снимает файлы с
  тома встроенного MinIO.

## Проверено

Временный проект compose (порты 51xxx, api на хосте), демо-учётки, файл 300 КБ, таблица
датасета ролью приложения:

- `backup.sh init`, `run`: снимки `env`, `db`, `files`; репозиторий 3,9 МиБ при дампе
  25 МиБ; `check --read-data` — без ошибок. С остановленной базой — код 1, причина в
  `last-failure`, неполного снимка базы нет, `last-success` не тронут.
- Снос: все тома проекта и `.env` удалены; репозиторий скопирован в каталог «Комитета».
  `backup-pull.sh verify` — 21 файл цел; на копии с дописанным байтом — «испорчен», код 1;
  `check` с паролем — без ошибок.
- `backup.sh restore --yes`: `.env` совпал с исходным побайтно (права 600); отпечаток прав —
  владельцы и ACL 211 отношений, схем и базы, настройки базы, права ролей, число строк —
  совпал полностью; api стартовал, синхронизация привилегий — без изменений; вход, файл
  скачан, SHA-256 совпал; версии `kchs-files` включены, пользователи движка и узла заведены.
  `restore` повторяем: проверки выше — после второго запуска поверх первого.
- Копия платформы с новыми флагами (роль `kchs_app`) → `pg_restore --create --clean
  --if-exists -d postgres`: права совпали, чтение таблицы датасета ролью запросов и 10
  записей прав по умолчанию на месте. Со старыми флагами — у приложения нет DML, у роли
  запросов нет чтения датасета, прав по умолчанию 0.
- Забор по SSH (два контейнера Ubuntu 24.04): `allow-pull` → `rrsync -ro`, `restrict`;
  `pull` ×3 — копия, поколение, обрезка по `KCHS_PULL_KEEP`; запись на сервер и команда
  оболочки отклонены, файлы на сервере не тронуты. Без `python3` `allow-pull` отказывает с
  подсказкой.
- `minio-init` дважды подряд (первая редакция проверки, та же логика `case`): одно правило
  хранения на бакет, привязка политик не задваивается; итоговая редакция отработала дважды
  за каждый `restore` без ошибок.
- shellcheck (`-S warning`) — чисто.
