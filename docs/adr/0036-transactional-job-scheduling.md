# 0036. Задание ставится в транзакции и уходит в очередь после коммита

Статус: Принято
Дата: 2026-09-18

Контекст: `JobService.enqueue` писал запись в `jobs` и сразу добавлял задание
в BullMQ, вне транзакции вызывающего кода. Для импорта (фаза 1) это означает гонку:
движок может взять задание раньше, чем закоммитится строка `imports`, а при
откате транзакции задание всё равно выполнится. Правило №3 `CLAUDE.md` требует,
чтобы изменение состояния публиковало событие через outbox в той же транзакции.

Решение: `JobService.schedule(tx, ctx, input)` в транзакции вызывающего кода
пишет запись реестра со статусом `queued`, входные данные (`jobs.payload`)
и параметры BullMQ (`jobs.options`), затем публикует событие `job.queued`.
Подписчик ядра `kernel-jobs` получает событие после коммита и вызывает
`JobService.dispatch(id)` — добавление в BullMQ с `jobId = id`, поэтому повторная
передача не создаёт дубль. Страховка — задание обслуживания `jobs.redispatch`
раз в две минуты передаёт записи `queued`, которых нет в BullMQ.
`JobService.enqueue(ctx, input)` оставлен для служебных действий без своей
транзакции и открывает её сам.

Попутно:
- повторяемые задания по расписанию приходят в воркер без записи реестра — воркер
  создаёт её и сохраняет в данных задания (раньше такие задания падали на
  `invalid input syntax for type uuid`, и дайджест почты не отправлялся);
- промежуточный сбой попытки возвращает запись в `queued`, окончательный
  фиксирует `failed` и публикует `job.failed` — инициатор получает уведомление.
  Движок передаёт признак `final` во внутреннем маршруте статуса.

Альтернативы:
- хук «после коммита» в обёртке транзакции — теряет задание, если процесс упадёт
  между коммитом и добавлением в Redis;
- периодический опрос `jobs` вместо события — задержка в секунды на каждом импорте.

Последствия: постановка задания добавляет задержку диспетчера outbox и потребителя
(обычно сотни миллисекунд). Задание, поставленное вне работающего воркера (роль `api`),
ждёт, пока воркер поднимется, — поведение не отличается от прежнего.
