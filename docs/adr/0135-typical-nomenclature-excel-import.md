# 0135. Типовая номенклатура по подразделениям в демо и импорт номенклатуры из Excel

Статус: Принято
Дата: 2026-09-25

## Контекст

Владелец 24.09.2026 решил (N20, `05-risks-and-open-questions.md` §5): в демо — типовая
номенклатура дел по подразделениям, для канцелярии — импорт номенклатуры из Excel.

До этого решения было так:

- демо-сид заводил пять дел канцелярии с индексами `01-01…01-08`;
- номенклатура велась в системе вручную, по одному делу (ADR-0086).

Утверждённая номенклатура органа — это таблица на сотни строк, её готовят в Excel. Номер
«подразделение-дело/номер» (ADR-0134) берёт индекс дела из номенклатуры, поэтому без неё
номер теряет смысл. Кроме того, номенклатура должна быть заведена к началу года.

Импорт пользователей (ADR-0041) читает Excel в движке (openpyxl) заданием очереди. Для
номенклатуры такой путь тяжёл по двум причинам:

- нужны правки в Python, пересборка образа движка и контракты движка;
- для файла на сотни строк достаточно проверки за один запрос.

## Решение

1. **Типовая номенклатура** (`typical-nomenclature.ts`) — разделы по подразделениям демо-мира.
   Индекс дела — индекс подразделения и номер дела в разделе:
   - 01 — руководство: приказы по основной деятельности — постоянно;
   - 02 — канцелярия: входящая и исходящая переписка, обращения, записки, договоры;
   - 03 — оперативное управление: сводки, распоряжения и протоколы штаба, «03-12 Донесения о
     чрезвычайных ситуациях»;
   - 04 — анализ рисков, 05 — ИТ, 06 — кадры (личный состав — 75 лет), 07 — юридический
     отдел;
   - 08–11 — региональные управления.

   Типы документов у дел подобраны так, чтобы каждый тип вёл к одному делу. Тогда дело при
   регистрации подбирается однозначно, и номер выходит `02-05/146` или `03-12/145`.
2. **Демо-сид** заводит номенклатуру на прошлый и текущий год для подразделений, которые есть
   в оргструктуре, — до демо-документов. Их дела переведены на индексы типовой номенклатуры.

   После предметного пакета сид повторяется и дописывает к делам типы, появившиеся позже:
   распоряжения и протоколы штаба, оперативные сводки. Уже заведённые дела не меняются, кроме
   дописанных типов. Дело с тем же индексом, но заведённое на другое подразделение, не
   трогается.
3. **Импорт из Excel** — «Номенклатура дел» → «Ещё» → «Импорт из Excel»:
   - образец (`GET /cases/import/template.xlsx`) — типовая номенклатура на текущий год и лист
     «Как заполнять» со списками подразделений и типов документов установки;
   - файл загружается в личное пространство;
   - «Проверить» (`POST /cases/import`, `mode: check`) ничего не создаёт;
   - «Завести N дел» (`mode: apply`) создаёт готовые строки одной транзакцией.

   Импорт доступен владельцу «вести журналы».
4. **Столбцы узнаются по началу заголовка**, без учёта регистра, «ё» и знаков препинания:
   «Индекс», «Заголовок/Наименование», «Год», «Подразделение», «Срок…», «Статья/Отметка»,
   «Типы…», «Примечание». Шапка ищется в первых десяти строках любого листа. Правила
   проверки строк:
   - подразделение — по коду или названию;
   - типы документов — по коду или названию через «;»;
   - срок хранения — число лет от 1 до 100 или «постоянно»;
   - год пустой — берётся год, выбранный при импорте.

   Ошибки строк сформулированы по-человечески: «Подразделение „…“ не найдено в оргструктуре»,
   «Индекс повторяется в файле для этого года». Дело, индекс которого в этом году уже есть,
   получает отметку «Уже есть» и пропускается. Повторный импорт того же файла ничего не
   дублирует.
5. **Excel читается в api без движка и без новых зависимостей** (`shared/xlsx.ts`). Книга — это
   ZIP с XML-частями: каталог архива разбирается вручную, распаковка — встроенным `zlib`,
   дальше читаются книга, общие строки и лист. Запись образца устроена так же: жирная
   закреплённая шапка, ширина столбцов, индексы с ведущим нулём — текстом.

   Формулы, стили и даты не разбираются: берётся записанное значение ячейки. Для справочника
   этого достаточно.

## Альтернативы

- **Разбор в движке, как у импорта пользователей.** Долгое задание здесь не нужно, а правки
  в Python, образ движка и контракты движка того не стоят.
- **Библиотека XLSX в Node.** `xlsx` (SheetJS) в npm устарел и с известными уязвимостями,
  `exceljs` тяжёл. Чтения таблицы с текстом и числами хватает на двести строк кода с тестами.
- **CSV вместо Excel.** Владелец просил Excel. К тому же CSV из Excel путает кодировку и
  разделитель.
- **Сразу обновлять уже заведённые дела из файла.** Импорт молча переписал бы дела, в которые
  уже подшиты документы; безопаснее пропускать их с отметкой.

## Последствия

- В контрактах `documents`: `CaseImportInput`, `CaseImportReport`.
- `shared/xlsx.ts` пригоден и для других справочников. Импорт пользователей остаётся в
  движке: он проверяет больше и выдаёт пароли.
- На стенде, где демо-сид уже заводил дела `01-01…01-08`, повторный сид добавит дела
  типовой номенклатуры рядом. Индексы, совпавшие со старыми (`01-01`), остаются старыми. Для
  чистого вида демо-стенд ставится заново.
- Для рабочей установки номенклатура не заводится сама: канцелярия импортирует утверждённую,
  начиная с образца.
