# ADR-0099. Поиск по смыслу: векторы объектов рядом со словесным индексом

Статус: **Принято** · Дата: 2026-09-20 · Фаза 5 (P5-E01/P5-E05, основание)

## Контекст

`13-search-knowledge-ai.md` §1 требует гибридной выдачи: словесный индекс
(Meilisearch) плюс векторная близость (`pgvector`, модель `bge-m3` в движке),
«похожие объекты» в контекстной панели и ответы по базе знаний с цитатами.
Базу знаний и ответы делают параллельно; общим для них нужен один механизм
векторов, который не ломает поиск там, где модель не установлена.

## Решение

1. **Векторы — в Postgres**, таблица `embeddings(object_id, chunk_no, text,
   embedding vector(1024), model, hash)` с индексом HNSW по косинусу. Права в
   таблице не дублируются: выдачу режет предикат видимости ядра по `object_id` —
   один источник правды о доступе.
2. **Считает движок**, синхронным маршрутом `POST /ai/embed` (fastembed, ONNX —
   без torch). Модель задаёт `ENGINE_EMBEDDING_MODEL`; пусто — движок отвечает
   503 «модель не настроена», api запоминает это на пять минут и работает
   словесным поиском. Отсутствие модели — состояние установки, а не сбой.
3. **Индексация — заданием** `index:search.embed`, которое ставит тот же
   подписчик ядра, что обновляет словесный индекс: шина событий не ждёт модель.
   Текст объекта (название, подпись, содержимое типа из `searchable`) режется на
   куски по ~900 символов с нахлёстом; кусок с прежним хэшем не пересчитывается,
   поэтому правка абзаца не гоняет модель по всему регламенту.
4. **Гибридная выдача** — ранговое слияние (RRF, k=60) словесных и смысловых
   попаданий на первой странице; режим `words` в запросе отключает смысл.
   Фильтры запроса (тип, пространство, владелец, статус, даты) применяются и к
   смысловой части — иначе выдача обошла бы фильтр.
5. **«Похожие объекты»** — `GET /objects/{id}/similar`: ближайшие к первому
   куску объекта, сам объект исключён, права проверяются как у поиска. Раздел в
   контекстной панели не показывается, если семантика выключена.

## Последствия

- Поиск работает одинаково с моделью и без неё; установка без ИИ ничего не
  теряет, кроме смысловой части выдачи.
- Размер: кусок ~900 символов → ~4 КБ вектора; тысяча длинных страниц — порядка
  сотни мегабайт с индексом. Приемлемо для S1.
- Смена модели обесценивает старые векторы: поле `model` в таблице позволяет
  переиндексировать выборочно (переиндексация — заданием, отдельной кнопки пока
  нет).
- Ответы по базе знаний (RAG) и ассистент с инструментами опираются на этот же
  механизм и добавляются следующими историями.

## Альтернативы

- **Вектора в Meilisearch** (экспериментальная поддержка) — выдача и права в
  одном месте, но версия индекса становится критичной, а политика грифов и
  предикаты видимости у нас уже в Postgres.
- **Отдельная векторная БД** (Qdrant, Weaviate) — ещё одна служба в установке
  ради задачи, которую закрывает расширение уже развёрнутого Postgres.
- **Эмбеддинги в api (onnxruntime-node)** — тяжёлая модель внутри процесса,
  который обязан отвечать быстро; в движке для этого уже есть очередь и место.
