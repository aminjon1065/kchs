# 0194. История ЧС Комитета: разбор исходников вне платформы, загрузка командой в пакет ЧС

Статус: Принято
Дата: 2026-10-08

## Контекст

Владелец передал всё, что есть у Комитета за 1988–2026 годы:

- реестр бедствий Disaster (Excel, 1992–2020, несколько версий файлов);
- акты оценки ущерба комиссий (Word, 2013–2026);
- официальную сводку «10 сола» (2013–2024);
- геобазу ArcGIS «Карта связи КЧС и ГО»;
- резервную копию старой базы ESTJ (SQL Server 2005).

Данные разнородны: двуязычные колонки, старые таджикские шрифты, переименованные районы,
347 написаний вида бедствия, суммы в рублях и сомони. Стенд показа перед загрузкой очищен до
администратора и справочников (`demo-stand.sh up --empty`, профиль `base`).

## Решение

1. **Разбор — вне платформы, повторяемо** (`infra/history`). Python в образе движка (Excel,
   Word, геоданные) превращает исходники в каталог загрузки — `manifest.json`, JSON с
   типизированными значениями, GeoPackage, архив — и файл сверки для владельца. Исходники
   только читаются. Правила сопоставления (районы, виды, дубли) — в коде, а не в ручной
   правке таблиц: при новой выгрузке Комитета разбор повторяется.
2. **Загрузка — сервисами платформы** (`kchs import-history`, `demo-stand.sh history`).
   Создание объектов, строк, слоёв и файлов идёт через `DatasetService`, `RowService`,
   `ImportService`, `LayerService`, `MapService` и `registerStoredFile` — с реестром объектов,
   аудитом и событиями (незыблемые правила 1 и 3). Объекты находятся по ключам пакета,
   строки — по первичным ключам: повторный запуск досоздаёт недостающее.
3. **История — в пакет ЧС.** События ложатся в его реестр «Происшествия», классификатор
   пакета расширяется: снегопад и мороз, засуха, подтопление, ж/д и авиация, поражение током,
   взрывоопасные предметы, противоградовые работы. У каждого вида есть категория сводки
   «10 сола». Новые и следующие события продолжают тот же реестр, дашборды пакета видят
   историю.
4. **Поля истории** в «Происшествиях»:
   - точность даты (день, месяц, год) и дата в источнике;
   - количество явлений («н. Варзоб 6 тарма» — шесть лавин);
   - вид и место в источнике, спасённые;
   - погибшие «из описания»;
   - ущерб и потребности как в источнике;
   - полный текст и откуда строка.

   Ущерб числом в сомони — с 2001 года. Раньше суммы были в рублях разного масштаба, они
   хранятся только текстом.
5. **Правила не срабатывают на историю.** На время загрузки у «Происшествий» выключены
   события строк (ADR-0133), после загрузки они снова включены. Иначе правило «Происшествие
   с погибшими» разослало бы уведомления и поручения по каждому историческому событию.
6. **Официальные цифры — из «10 сола»**, реестр — рядом (решение владельца): дашборд
   «История и статистика ЧС» показывает сводку и реестр отдельными блоками. Расхождения видны
   в сверке.
7. **ESTJ** не восстанавливается: SQL Server 2005, записей о событиях почти нет. Из неё —
   образец классификатора и бланков донесений, сама копия — в архиве файлов.

## Альтернативы

- **Импорт файлов мастером в интерфейсе.**
  - Таблицы Disaster не ложатся мастером без предварительной правки.
  - Акты Word — не таблицы.
  - Результат не повторить на другом стенде (VPS).
- **Разбор на TypeScript в api.** В api нет библиотек для xls, docx и FileGDB. В образе
  движка они есть, и он уже читает эти форматы при импорте.
- **Отдельный реестр «Архив ЧС» вне пакета.** Его пришлось бы связывать с реестром пакета, а
  дашборды строить дважды. Владелец выбрал пакет.

## Последствия

- **Новая выгрузка Комитета:** `build-bundle.sh`, сверка, затем `demo-stand.sh history`.
  Исправленные строки повторный запуск не перезаписывает: правка — в платформе.
- **Рельеф (отмывка `hill.tif`)** историей не загружается: он вошёл в сборку векторной подложки
  (ADR-0195, `infra/basemaps/build-relief.sh`).
- Тест загрузчика — `apps/api/test/history-import.test.ts`.
