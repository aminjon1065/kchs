# 0176. Минимальные права движка и токен задания для его обратных вызовов

Статус: Принято
Дата: 2026-10-05

## Контекст

Движок разбирает недоверенные файлы: GDAL, LibreOffice, poppler, tesseract, ffmpeg и Chromium
получают на вход то, что загрузил любой сотрудник. Это самая большая поверхность атаки
установки. При этом у движка было больше прав, чем нужно (находка 7 разбора,
`04-delivery/07-architecture-hardening.md`):

- **База.** Полная роль `kchs_app`: `DATABASE_URL` в compose и чарте, запасной путь в
  `columnar.py`. Хотя движок в базу не пишет: строки датасетов загружает TS-воркер (ADR-0046),
  итоги заданий принимает api.
- **Хранилище.** Ключ администратора MinIO: чтение, запись и удаление во всех бакетах, включая
  резервные копии.
- **Redis.** Общий пароль: все ключи, потоки событий `events:*` (событие можно подделать —
  подписчики ему доверяют), сессии и доступы гостей.
- **Сервисный токен.** Общий `INTERNAL_SERVICE_TOKEN` открывал все внутренние маршруты api:
  захваченный движок мог сообщить «итог» любого задания — превью чужого файла, расшифровку
  чужой записи, строки импорта пользователей.
- **Окружение.** Внешние программы наследовали всё окружение движка — все секреты выше.
- **DuckDB.** Колоночный tier выполнял скомпилированный api запрос без песочницы: функции
  чтения файлов и расширения были доступны.

## Решение

**База.** Единственная роль движка — `kchs_query` (`DATABASE_QUERY_URL`): чтение таблиц строк
для колоночных копий (ADR-0048, ADR-0109). `DATABASE_URL` из compose и чарта убран, запасного
пути в коде нет.

**Хранилище.** Свой пользователь MinIO с политикой `infra/compose/minio/engine-policy.json` (в
чарте — `kchs.engineS3Policy` с бакетами из `s3.buckets`). Права выведены из ключей, которые
модули api дают заданиям:

| Действие | Что |
|---|---|
| чтение | исходники: `files/spaces/*` (файлы и шаблоны), `files/meetings/*` (записи встреч), `files/demo/*`; выгрузка слоя `exports/datasets/*`; копии `columnar/columnar/*` |
| запись | `files/imports/*` (нормализация импорта), `files/demo/*`, `files/spaces/*/files/*` (PDF версии документа), `previews/spaces/*`, `exports/datasets|reports|documents/*`, `columnar/columnar/*` |
| список | бакет файлов — чтобы отсутствующий объект давал «не найдено», а не «доступ запрещён» (проверка манифеста демо-данных) |

Удалять движку нечего: удаляют api и worker. Бакетов резервных копий, медиа и тайлов он не
видит. Пользователя заводит `minio-init` (идемпотентно), движок ждёт его завершения. Для
внешнего S3 политику задаёт администратор хранилища (`infra/helm/README.md`,
`06-guides/20-admin-install.md`).

**Redis.** Пользователь ACL `kchs-engine` (`infra/compose/redis/start.sh`, тот же файл в
чарте):

- ключи `bull:<очередь>:*` очередей с исполнителем `engine` в `QUEUE_RUNTIME`;
- чтение флагов отмены `kchs:job:cancel:*` (ADR-0172).

Потоки событий, кэш, сессии и доступы ему не видны; `SCAN`, `KEYS`, `RANDOMKEY` и pub/sub
закрыты, опасные команды тоже, кроме `INFO` — его спрашивает BullMQ. Кэш ADR-0175 движку не
передаётся. Тест `packages/contracts/src/jobs/__tests__/engine-access.test.ts` сверяет список
очередей в ACL с `QUEUE_RUNTIME` и копии скрипта для compose и чарта.

**Токен задания.** Обратные вызовы движка несут заголовок `x-kchs-job-token`.

- Токен выдаётся при передаче задания очереди движка в BullMQ (`JobService.dispatch`) и лежит
  в данных задания (`callbackToken`). Это HMAC-SHA256 над id записи задания, ресурсом и сроком
  (72 ч; повторная передача из реестра выдаёт новый). Ключ выведен из `KCHS_MASTER_KEY`, а
  мастер-ключа у движка нет: токен не подделать и не переписать на другое задание.
- Ресурс модуль указывает при постановке (`callbackScope`): `file:<id>`,
  `document-version:<id>`, `document-render:<id>`, `recording:<id>`, `import:<id>`,
  `report-run:<id>`.
- Маршрут объявляет `auth: { engineJob: { jobParam } }` (статус задания, импорт пользователей —
  его id и есть id задания) или `{ engineJob: { scope } }`. Проверка — в плагине
  аутентификации, сравнение подписи за постоянное время; при смене мастер-ключа принимается и
  прежний (ADR-0143). Без токена — 401, токен чужого задания или ресурса — 403.
- Общий сервисный токен внутренние маршруты api больше не принимает. Им движок проверяет только
  вызовы api в движок (`/data/analyze`, `/ai/embed` и другие).

Движок и api выкатываются одним выпуском, поэтому обратной совместимости для старого
заголовка нет: задания, поставленные до обновления, получат токен при повторной передаче
(сверка ADR-0172).

**Окружение внешних программ.** `kchs_engine/tools.py`: `subprocess` (LibreOffice, poppler,
tesseract, ffmpeg) и Chromium получают окружение по белому списку — путь, профиль, язык, пояс,
временные каталоги, шрифты, данные tesseract. Новая переменная окружения движка к ним сама не
попадёт.

**DuckDB.** Соединение колоночного tier после загрузки пояса читает только файлы копий этого
запроса (`allowed_paths`) и сбрасывает промежуточное только в каталог кэша
(`allowed_directories`, `temp_directory`). `enable_external_access = false` закрывает сеть,
чтение других файлов и установку расширений, `lock_configuration = true` не даёт вернуть
настройки текстом запроса.

**Обновление прежних установок.**

- `generate-secrets.sh` генерирует `REDIS_ENGINE_PASSWORD`, `S3_ENGINE_ACCESS_KEY` и
  `S3_ENGINE_SECRET_KEY`.
- `--add-missing` дописывает их в существующий `.env`, не трогая остального; `demo-stand.sh`
  делает это сам.
- Без них compose оставляет движку прежний пароль Redis и ключ администратора хранилища, а
  движок при старте пишет предупреждение `engine.broad_access` — установка не ломается до
  перехода.
- В чарте ключи обязательны.

## Альтернативы

- **Режим `auth: 'service'` с общим токеном вместо токена задания.** Убирает ручные проверки, но
  оставляет главное: любой обладатель общего токена сообщает итоги любых заданий. Маршрутов,
  которым нужен именно общий токен, не осталось — все внутренние маршруты относятся к
  конкретному заданию.
- **Токен случайный, в реестре заданий.** Проверка стоила бы запроса к базе на каждый отчёт о
  прогрессе. Подпись проверяется без базы, а срок и привязка лежат в самом токене.
- **Отдельный ключ подписи в окружении.** Ещё один секрет для установки и ротации. Ключ из
  мастер-ключа уже есть у api и worker, ротация идёт тем же порядком (ADR-0143).
- **Движок — без Redis, задания через HTTP api.** Это переписывание очередей (ADR-0015,
  ADR-0035). ACL даёт ту же изоляцию малой ценой.

## Последствия

- Захваченный движок не читает и не меняет базу, не видит событий, сессий и кэша, не удаляет
  файлы и не трогает резервные копии. Итоги он может сообщить только по заданиям, которые сейчас
  у него в очереди, — с данными из их же входа.
- Новая очередь с исполнителем `engine` требует строки в ACL. Тест contracts упадёт, пока её
  нет.
- Новый префикс ключа, который движок читает или пишет, требует правки политики хранилища:
  иначе задание получит `AccessDenied`. Это проверяет `verify-stack.sh` (превью файла движком).
- Внешний S3 и внешний Redis: пользователя и политику администратор заводит сам; чарт этого не
  делает.
- Тесты:
  - api: `shared/crypto/__tests__/job-token.test.ts`, `test/engine-callbacks.test.ts` и
    внутренние маршруты в тестах модулей (`engineJobHeaders`, `engineHeadersFor` в
    `test/helpers.ts`);
  - движок: `test_tools.py`, `test_columnar.py::test_sandbox_reads_only_copies_of_the_query`,
    `test_job_reliability.py`.
