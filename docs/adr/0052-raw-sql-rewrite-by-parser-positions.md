# 0052. Сырой SQL: переписывание текста по позициям разборщика, служебные имена CTE и повторный разбор

Статус: Принято
Дата: 2026-09-19

## Контекст

ADR-0011 и `06-analytics-engine.md` §6 (Решено) задают конвейер SQL-лаборатории: разбор
`libpg-query` → белый список → переписывание ссылок на датасеты в подзапросы с политиками →
выполнение под `kchs_query`. `05-data-model.md` уточняет: политики — подзапросом в тексте
запроса, без DDL; `17-security.md` — только `ds.*` с проверкой прав. Открытыми остались:
как получить итоговый текст из дерева, как не ошибиться с областями видимости CTE (CTE с
именем таблицы, CTE внутри подзапроса) и что означают незаданные `{{параметры}}`.

npm-пакет `libpg-query` 17 (WASM, грамматика Postgres 17 — как у образа базы) отдаёт дерево
с байтовыми позициями узлов, но без обратного преобразования дерева в текст (deparse есть в
отдельных пакетах `@libpg-query/parser` и `pgsql-deparser`).

## Решение

1. **Итоговый текст — правки исходного по позициям узлов**, а не deparse дерева. Меняются
   только отдельные лексемы: имя таблицы → `(подзапрос с политиками) AS "имя"`, подпись
   поля → ключ (голое поле выборки — ещё `AS "подпись"`), имя CTE → служебное,
   `{{параметр}}` → `($n::тип)`. Каждая заменяемая лексема перечитывается из текста и
   сверяется со значением в дереве; расхождение — отказ. Остальной текст пользователя
   выполняется как есть — ровно то, что разобрал и проверил разборщик той же версии, что и
   сервер.
2. **Каждая ссылка на таблицу переписывается**: на датасет из контекста пользователя или на
   служебное имя CTE `__kchs_cte_N` (все CTE запроса переименовываются). Если анализ областей
   видимости ошибётся, Postgres не найдёт служебное имя и запрос упадёт, но имя пользователя
   не разрешится в физическую таблицу через `search_path`.
3. **Повторный разбор итогового SQL**: один SELECT, таблицы — только `ds.t_…` датасетов
   запроса и служебные CTE, номера параметров — в пределах значений, нет `INTO` и
   блокировок. Иначе — исключение (ошибка программиста), запрос не выполняется.
4. **Белые списки по дереву**: для каждого допустимого типа узла — перечень полей;
   неизвестный узел или поле (например, из новой версии разборщика) — отказ. Функции и типы
   приведений — белые списки, чёрный список функций — для понятной причины.
5. **Параметры `{{имя}}`** на время разбора заменяются маркерами `$n` той же длины (позиции
   ошибок совпадают с текстом пользователя); каждый маркер обязан стать параметром в дереве.
   Незаданный необязательный параметр — `NULL` (условие не снимается, в отличие от QuerySpec:
   снять условие в произвольном SQL нельзя), обязательный — ошибка. Тип — из объявления
   (`QuerySpec.params`), без объявления его выводит Postgres по месту.
6. Подзапрос датасета строит тот же код, что и CTE QuerySpec (`datasetRelation`); системные
   столбцы строк попадают в него, только если упомянуты, — `SELECT *` отдаёт поля датасета.
7. Разборщик загружается динамическим импортом при первом сыром SQL; для бандла API пакет
   `libpg-query` остаётся внешним (WASM ищется рядом с модулем).

## Альтернативы

- Deparse изменённого дерева (`pgsql-deparser`): ещё одна зависимость, а итоговый текст —
  пересериализация, в которой ошибка сериализатора меняет смысл запроса незаметно для
  проверок; правки по позициям меняют только заменяемые лексемы.
- Представления `ds_names` с «человеческими» именами в базе: DDL на каждый набор политик и
  пользователей, противоречит решению «подзапрос, без DDL» (`05-data-model.md`).
- Вернуть имя CTE как есть и довериться анализу областей видимости: ошибка анализа открыла бы
  путь к физической таблице через `search_path`.
- Незаданный параметр снимает условие, как в QuerySpec: требует разметки необязательных частей
  (`[[ … ]]`) — отложено до редактора SQL-лаборатории (P1-E05 S02).

## Последствия

- Вызывающий ставит сеансу пояс (`compiled.timezone`) и выполняет запрос в транзакции только
  для чтения под `kchs_query` с тайм-аутом — как QuerySpec.
- Позиции ошибок Postgres при выполнении относятся к переписанному тексту; `sourceMap` и
  `rawSqlErrorPosition` возвращают их к тексту пользователя.
- Память тяжёлых выражений (`lpad` на миллиард символов, `string_agg` по `generate_series`)
  ограничивают только тайм-аут и ресурсы сервера.
- Имя столбца выражения от подписи — по ключу (правило имён Postgres), голое поле сохраняет
  подпись; USING по подписи не поддерживается.
