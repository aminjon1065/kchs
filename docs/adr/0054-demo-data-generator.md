# 0054. Демо-данные фазы 1: генератор файлов в движке и манифест загрузки

Статус: Принято
Дата: 2026-09-19

## Контекст

`04-verification.md` §7 требует демонстрационные датасеты — «Происшествия» (5 млн строк: точки,
время, территория, тип, ущерб), «Объекты защиты» (50 тыс. точек), «Зоны риска» (полигоны),
«Уровни воды» (временной ряд), справочники и территории — от детерминированного генератора в
движке, запускаемого `pnpm db:seed --profile demo`. По ADR-0046 у движка нет подключения к
базе: таблицы датасетов, версии и события создаёт TypeScript, а файл попадает в датасет
конвейером «файл в S3 → анализ → нормализация в движке → загрузка воркером». Источник и коды
территорий открыты (вопрос N5): рабочее допущение — регионы по ISO 3166-2:TJ, районы со своими
устойчивыми кодами, без границ до фазы 2.

## Решение

1. **Генератор пишет файлы, а не строки в базу.** Пакет `kchs_engine/demo`, CLI
   `python -m kchs_engine.demo --out <каталог|s3://бакет/префикс> --profile demo|small`:
   CSV (UTF-8, «,», десятичная точка, даты ISO) и GeoJSON FeatureCollection, которые анализ
   импорта распознаёт без предупреждений. Сид регистрирует файлы и загружает их тем же
   конвейером, что и пользователь: демо-данные заодно проверяют импорт на 5 млн строк, а
   версии, события и права датасетов создаются как обычно.
2. **Манифест `manifest.json` (`kchs-demo/1`)** пишется последним — его появление значит, что
   файлы готовы. Для каждого набора: название, вид (`table`/`reference`), описание, файл,
   формат, число строк, размер, SHA-256, ключ, поля времени и территории, предлагаемые связи со
   справочниками и `import` — `ImportRunInput` контракта без `fileId` и `target` (параметры
   чтения, сопоставление столбцов с полями, геометрия, ключ, `onError: stop`). Порядок наборов —
   порядок загрузки: справочники раньше таблиц. Там, где анализ не может знать больше, манифест
   уточняет его предложение: код района — семантика `territory`, ущерб — `money` в сомони.
3. **Детерминированность без зависимостей.** Только стандартная библиотека: случайные числа —
   из `random.random()` (последовательность для одного seed Python гарантирует между
   версиями), распределения построены поверх него; у каждого набора свой поток, строковый
   seed которого включает имя набора. Один seed и одна версия генератора — побайтно те же
   файлы (совпадают на macOS и Linux arm64/x86_64; хэши малого профиля закреплены в тестах);
   файлы пишутся потоком, в памяти — только один день происшествий.
4. **Территории.** Официальные названия регионов и районов (русские, таджикские, английские),
   коды регионов ISO 3166-2:TJ, коды районов `TJ-XX-NN` — собственные, приблизительные центроиды
   и оценка населения для демонстрации. События, объекты, зоны и наблюдения «привязаны» к
   синтетическим населённым пунктам района: точки сгущаются у кишлаков, описание называет пункт.
5. **Профили:** `small` (50 тыс. происшествий, 5 тыс. объектов, 12 гидропостов в ряду — для
   тестов и быстрых стендов) и `demo` (5 млн, 50 тыс., 46).

## Альтернативы

- Генератор пишет строки прямо в `ds.*`: движку понадобились бы роль с DML и знание физических
  таблиц, а версии, события и счётчики пришлось бы воспроизводить в обход `physical.ts`
  (ADR-0046).
- Генератор в TypeScript-сиде: `04-verification.md` относит его к движку, а потоковая запись и
  проверка распознавания анализом естественнее рядом с кодом анализа и нормализации.
- Parquet или сжатые CSV: меньше места, но конвейер импорта фазы 1 их не читает.
- `numpy` для скорости: нет гарантии неизменности потоков между версиями и лишняя зависимость
  базовой установки; чистый Python даёт 5 млн строк за ~15 с.

## Последствия

- Сиду нужно положить файлы в хранилище (или сгенерировать их сразу в S3), зарегистрировать как
  файлы, создать датасеты по `import` манифеста и дождаться загрузки; повторный запуск с тем же
  seed даёт те же файлы и хэши.
- «Происшествия» профиля `demo` — ~1,1 ГБ (предел импорта — 2 ГБ); место в S3 нужно учитывать.
- Изменение формата манифеста — новая версия `kchs-demo/N` и правка сида.
- Названия и коды районов живут в `kchs_engine/demo/reference.py` до решения по N5; при загрузке
  реальных данных коды сопоставляются с официальным классификатором.
- Анализ импорта исправлен попутно: счётчик из нулей и единиц с редкими 2–3 («Погибшие») —
  целое, а не «да/нет» с ошибками.
