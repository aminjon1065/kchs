# 0002. PostgreSQL + PostGIS как единая система записи
Статус: Принято. Дата: 2026-09-17

## Контекст
Нужны транзакционные данные платформы, таблицы датасетов пользователей, пространственные операции, полнотекст и векторы, при этом — простое резервирование и эксплуатация.

## Решение
Всё хранится в одном PostgreSQL 17 с PostGIS, pgvector, pg_trgm. Датасеты — физические таблицы в схеме `ds`. Для сценариев S2+ добавляется колоночный tier (Parquet в S3 + DuckDB в engine) за интерфейсом диалекта компилятора запросов.

## Альтернативы
ClickHouse для аналитики (нет полноценного гео, join слабее, ещё один сервис); отдельная гео-БД (разрыв прав и связей); DuckDB как основной (нет многопользовательской записи).

## Последствия
Единая модель прав на строки; одно резервное копирование; необходимость партиционирования и индексов для больших датасетов; переход к DuckDB для холодных больших данных без изменения контрактов.
