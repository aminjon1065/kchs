# ADR-0101. Качество данных: правила на датасете, проверка по версии

Статус: **Принято** · Дата: 2026-09-20 · Фаза 5 (P5-E03)

## Контекст

`06-analytics-engine.md` §15 требует правил качества (`not_null`, `unique`,
`range`, `regex`, `in_set`, `referential`, `geometry_valid`, `freshness`,
`row_count_delta`), выполняемых при новой версии датасета, с результатом в
карточке, бейджем в каталоге и флагами на строках.

Датасеты хранятся физическими таблицами `ds.t_*` со сгенерированными именами
столбцов; правило 5 CLAUDE.md запрещает собирать SQL из пользовательского
ввода.

## Решение

1. **Правило — строка метаданных**, а не код: вид, поле, параметры, важность
   (`error` / `warning`). Набор правил датасета заменяется целиком (`PUT`),
   ключи уникальны, поле проверяется по реестру полей при сохранении — правило
   на несуществующее поле не сохранится.
2. **SQL собирается из реестра**: имя столбца берётся из `dataset_fields`
   (физическое имя сгенерировано платформой), значения и шаблоны уходят
   параметрами запроса. Пользовательский текст в SQL не попадает никогда.
3. **Проверка идёт на текущей версии** и запускается двумя путями: заданием по
   событию `dataset.version_created` и кнопкой «Проверить сейчас». Итог —
   строка `dataset_quality_runs` (версия, статус, результаты правил с примерами
   нарушивших строк) и событие `dataset.quality_checked`.
4. **Сводка** — `failed`, если не выполнилось правило важности `error`;
   `warning`, если только предупреждения; `unknown`, если правил нет. Правило,
   которое само не выполнилось (поле удалили, справочник недоступен), получает
   статус `error` с причиной — проверка не падает целиком.
5. **Права обычные**: читать правила и отчёт может тот, кто видит датасет;
   менять — уровень `manage`. Отдельных прав у качества нет.

## Последствия

- Проверка идёт по всей таблице: на миллионах строк это несколько секунд, и
  поэтому она выполняется заданием, а не в транзакции импорта.
- Примеры нарушивших строк — идентификаторы `_id`: карточка открывает их в
  таблице, не дублируя данные в отчёте (и не обходя политики строк).
- Алерт при ухудшении качества и флаги прямо в таблице строк — следующая
  история: событие `dataset.quality_checked` для этого уже публикуется.
- `custom_expr` (произвольное выражение) не реализован осознанно: он открывает
  путь пользовательскому SQL, а язык выражений платформы к датасетам пока не
  применяется.

## Альтернативы

- **Проверки в момент записи строки** — дорого на импорте и не ловит правила
  уровня таблицы (уникальность, число строк).
- **Отдельный инструмент качества** (Great Expectations в движке) — лишняя
  служба и второй язык правил ради набора проверок, которые выражаются SQL.
