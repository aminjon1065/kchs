# 0056. Экспорт датасета: задание очереди `exports`, права на момент выполнения, XLSX без библиотек

Статус: Принято
Дата: 2026-09-19

## Контекст

P1-E03 S04 требует экспорт в CSV/XLSX/JSON/GeoJSON «с политиками» и выгрузку миллиона строк
заданием с файлом; сценарий приёмки фазы 1 №5 — «экспорт CSV содержит только его строки».
`06-analytics-engine.md` §5 даёт экспорту тайм-аут 10 минут и форматы-задания, `09-files.md` —
бакет `kchs-exports` со сроком хранения 30 дней, контракт `QUEUE_RUNTIME` (ADR-0035) — очередь
`exports` с исполнителем-воркером TypeScript. Не описано, кому принадлежит файл, чьи права
действуют и как писать XLSX в воркере (openpyxl есть только в движке).

## Решение

1. **API.** `POST /datasets/{id}/exports {format, where?, search?, sort?, fields?, ids?}`
   проверяет действие `export` (уровень `view` и способность `data.export`), строит QuerySpec
   «как в таблице» (фильтр и быстрый поиск — общий `tableFilter`, выделенные строки — `_id in`,
   сортировка с `_id` в конце), компилирует его с правами запросившего — ошибки сразу 400 — и
   ставит задание `exports:dataset.export`; ответ — `{jobId}`. Состояние — общий `GET /jobs/{id}`.
2. **Права — на момент выполнения.** Воркер строит контекст инициатора (`buildUserCtxFor`),
   заново проверяет `export` и компилирует спецификацию с его текущими политиками строк и
   столбцов. Отозванные права или несовместимая спецификация — `UnrecoverableError`: задание не
   повторяется.
3. **Чтение и запись.** `QueryService.stream`: транзакция только для чтения под `kchs_query`,
   тайм-аут 10 минут, сначала число строк (прогресс), затем курсор пачками по 2000. Не больше
   1 000 000 строк: компилятор читает на строку больше, лишнее отрезается, результат помечается
   `truncated`. Файл пишется потоком во временный каталог и загружается в `kchs-exports` по ключу
   `datasets/{id}/{jobId}/{имя}`; итог задания — `{fileName, format, rows, size, truncated, key}`,
   запись аудита `dataset.exported` (notice).
4. **Форматы.** CSV — UTF-8 с BOM, подписи полей на языке пользователя, RFC 4180, числа как в
   базе (без потери точности), дата-время — ISO 8601 со смещением пояса пользователя. JSON —
   массив записей по ключам полей, GeoJSON — `FeatureCollection` по полю геометрии (без него —
   400). XLSX пишет собственный потоковый писатель: ZIP с deflate из `node:zlib` (`crc32`
   Node 22, дескрипторы данных), лист с `inlineStr`, типизированные числа, логические, даты и
   время по поясу пользователя со встроенными форматами Excel, закреплённая строка заголовков.
   Лишняя зависимость (exceljs) и переход в движок ради записи не нужны; совместимость проверена
   чтением через openpyxl.
5. **Защита от формул.** В CSV значения, которые начинаются с `=`, `@`, табуляции, перевода
   строки, а также с `+`/`-`, если это не число или телефон, получают ведущий апостроф. Выгрузка
   журнала аудита остаётся строже (`shared/csv.ts`): там апостроф получает любой `+`/`-`.
6. **Скачивание.** `GET /datasets/exports/{jobId}/download` — только инициатору, только готовому
   заданию и пока у него есть `export` на датасет; ответ — подписанная ссылка (15 минут) с
   `Content-Disposition: attachment`. Файл, удалённый по сроку хранения, — 404 с объяснением.
7. **Интерфейс.** Кнопка «Экспорт» в тулбаре таблицы (при способности `data.export`): формат,
   охват «как в таблице» (поиск, сортировка, видимые столбцы в их порядке) или «всё», прогресс
   задания и «Скачать».

## Альтернативы

- **Файл экспорта — объект реестра** в личном пространстве: делился бы и искался как обычный
  файл, но жил бы бессрочно и копировал данные в обход политик датасета; экспорт — временный
  результат задания, как и задумано бакетом с TTL.
- **XLSX в движке** (openpyxl write-only): лишний круг через S3 и обратный вызов, а очередь
  `exports` по контракту исполняет воркер.
- **Права на момент постановки**: проще, но задание в очереди выгрузило бы данные человеку,
  у которого доступ уже отозван.

## Последствия

- Руководитель с политикой строк выгружает только свои строки; маскированные поля выгружаются
  маской, скрытых нет.
- Выгрузка больше миллиона строк обрезается с предупреждением; разбиение на части и Parquet —
  при появлении колоночного tier (S2+).
- Экспорт выделения (`ids`) готов в API; кнопка в панели выделения таблицы появится вместе с
  панелью действий над выделением.
