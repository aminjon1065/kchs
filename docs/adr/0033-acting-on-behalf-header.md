# 0033. Режим «от имени» — заголовок запроса, а не состояние сессии

Статус: Принято

Контекст: `03-access-model.md` §Делегирование требует, чтобы действия
заместителя записывались с `actor.onBehalfOf`, а интерфейс показывал баннер
«Вы замещаете …». В схеме есть колонка `sessions.on_behalf_of`, но переключение
режима внутри сессии означает скрытое состояние: другая вкладка того же
пользователя получила бы чужой режим, а после перезагрузки режим сохранялся бы
незаметно для пользователя.

Решение: режим передаётся заголовком `x-kchs-on-behalf-of` на каждом запросе.
`buildUserCtx` принимает его только если в `PrincipalSet.actingFor` есть активное
замещение от этого пользователя, иначе — `403`. Веб-клиент хранит выбор в
`sessionStorage`, не отправляет заголовок на личные маршруты (`/me`, `/auth`),
чтобы выход из режима был всегда возможен, и снимает режим, когда замещение
исчезло из `/me`.

Альтернативы: колонка в сессии (скрытое состояние, общее для вкладок);
отдельная «сессия замещения» (лишний вход и путаница в списке устройств).

Последствия: режим виден в каждом запросе и в ответе `/me`
(`session.onBehalfOf`), аудит получает обе стороны без дополнительной логики,
замещение по-прежнему не даёт прав само по себе — только `acting_as:<user>`
в множестве принципалов, как описано в модели доступа.
