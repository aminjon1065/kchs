# 0014. Transactional outbox + Redis Streams
Статус: Принято. Дата: 2026-09-17

## Контекст
Уведомления, индексация, автоматизация, realtime и вебхуки должны надёжно реагировать на изменения без потери событий и без распределённых транзакций.

## Решение
Событие пишется в `ops.outbox` в транзакции с данными; диспетчер публикует в Redis Streams; потребители — consumer groups с ack, повторами и DLQ.

## Альтернативы
Kafka (эксплуатация избыточна для объёмов); публикация напрямую из кода (потеря при сбое); только Postgres LISTEN/NOTIFY (нет гарантий доставки).

## Последствия
Гарантия «хотя бы один раз» — потребители идемпотентны; один Redis для очередей, pub/sub и кэша.
