# 0032. Гостевая ссылка: открытие по токену доступа, а не по сырому токену ссылки

Статус: Принято

Контекст: `03-access-model.md` требует гостевые ссылки с необязательным паролем,
ограничением по сроку и числу открытий, водяным знаком и аудитом открытий.
Сырой токен из URL не может служить единственным ключом: для ссылки с паролем
его предъявление не доказывает знание пароля, а счётчик `uses` при проверке на
каждом запросе считал бы не открытия, а обращения к API.

Решение: публичный маршрут `POST /share/{token}/open` принимает пароль и в
обмен выдаёт короткоживущий токен доступа (`g_…`, TTL 12 часов или до истечения
ссылки), который хранится в Redis и предъявляется в заголовке
`x-kchs-share-token`. Открытие увеличивает `uses` и пишется в аудит
(`share_link.opened`). Сырой токен продолжает работать для ссылок без пароля —
прямая ссылка из письма открывается одним переходом.

Последствия: пароль передаётся один раз и не хранится в браузере; отзыв ссылки
и истечение срока прекращают доступ немедленно (токен доступа проверяется по
строке `share_links` при каждом запросе); `uses` отражает число открытий.
Гостевой контекст не имеет личного состояния: избранное, недавние, подписки и
прочитанность для него не ведутся (`isGuest()` в ядре).
