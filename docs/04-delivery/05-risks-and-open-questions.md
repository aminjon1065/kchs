# Риски и открытые решения

## 1. Архитектурные и технические риски

| # | Риск | Влияние | Митигация |
|---|---|---|---|
| R1 | Широта продукта → незавершённые модули | потеря целостности | ядро первым; фазы с DoD; вертикальные срезы; никаких параллельных «полустроек» |
| R2 | Компилятор запросов: ошибки типизации/SQL, обход политик строк | безопасность, доверие | golden-тесты; единственный путь к данным; libpg-query для SQL; роль `kchs_query`; негативные тесты по всем путям |
| R3 | Производительность собственного DataGrid | UX аналитика | ранние бенчмарки (P1-E03); запасной путь — AG Grid Community за тем же интерфейсом (ADR-0008) |
| R4 | Тайлы «на лету» на больших слоях | медленные карты | генерализация, кластеризация, кэш, Martin в S2, deck.gl |
| R5 | Совместное редактирование (Yjs) и права | конфликты, утечки | ограниченный набор объектов; права на уровне Hocuspocus; тесты |
| R6 | LiveKit: сеть/NAT/TURN, запись | звонки не работают в части сетей | TURN/TLS на 443; предварительная проверка сети в клиенте; документ по портам для ИТ-службы |
| R7 | Качество расшифровки таджикской речи | протоколы неточны | ручной режим; выбор модели; оценка на пилоте; возможна дообученная модель |
| R8 | LLM-провайдер: стоимость, недоступность, приватность | функции ИИ | сменяемый провайдер; on-prem вариант; кэш; лимиты; всё ИИ — опционально |
| R9 | Один Postgres для всего | узкое место при росте | партиционирование, реплика чтения, колоночный tier; мониторинг с ранними порогами |
| R10 | Движок процессов: сложные маршруты, долгие ожидания | баги оркестрации | событийная модель шагов, идемпотентность, тесты восстановления; Temporal как план Б |
| R11 | Модель доступа с политиками типов — сложность | ошибки прав | таблицы истинности, генерируемые негативные тесты, «объяснить доступ» как инструмент отладки |
| R12 | Локализация таджикского (терминология, ИИ, OCR) | принятие пользователями | словарь терминов в глоссарии с ранней проверкой носителем; ключи с fallback на ru |
| R13 | Геометрии административных границ: источник и лицензия | юридический | зафиксировать источник в seeds/README, предпочесть официальные данные |
| R14 | Электронная подпись: юридическая сила | документооборот «не считается» | порт `SignatureProvider`; простая ЭП как внутренний инструмент; уточнить требования |
| R15 | Объём фронтенда (десятки экранов) | производительность, время | ленивые модули, единые компоненты, бюджеты бандла |
| R16 | Python-движок: тяжёлый образ, модели | развёртывание | образ с моделями отдельным слоем; профили compose; документ по ресурсам |

## 3. Открытые технические решения (исполнитель решает, фиксирует ADR)

- Точный формат состояния вкладок и стратегия keep-alive тяжёлых панелей.
- Библиотека drag-and-drop и виртуализации в списках (рекомендованы `@dnd-kit`, TanStack Virtual).
- Хранение результатов профилирования столбцов (таблица vs jsonb в датасете).
- Способ материализации `event_instances` календаря.
- Диаризация спикеров (pyannote — лицензия/ресурсы) — включать ли.
- Кэш тайлов: только Redis или диск/nginx с первого дня.
- Генерация OpenAPI-клиента: `openapi-fetch` vs `orval`.
