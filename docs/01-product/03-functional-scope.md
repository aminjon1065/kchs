# Функциональный состав и связи

Перечень возможностей организован по модулям продукта. Модули **не** совпадают один в один с техническими границами (см. `02-architecture/01-overview.md`): часть возможностей реализуется ядром платформы и работает для всех модулей.

Приоритеты: **P0** — ядро, без которого модули не связаны; **P1** — первая ценность; **P2** — полнота; **P3** — расширение. Фазы — в `04-delivery/02-roadmap.md`.

## 1. Идентификация и доступ

Учётные записи (пароль Argon2id, политика паролей), вход, MFA (TOTP, коды восстановления, passkeys), сессии и устройства, восстановление доступа, SSO (OIDC), синхронизация LDAP/AD, организационная структура (подразделения-дерево, должности, назначения, руководители), группы, системные роли и способности, делегирование/замещение, аудит входов, принудительное завершение сессий. Приоритет P0 (базово), P2 (SSO/LDAP/passkeys).

## 4. Документооборот

Типы документов с картами полей, журналы регистрации и нумерация, регистрация (в т.ч. из почты и скана с ИИ-распознаванием), версии файлов, шаблоны (DOCX с плейсхолдерами), маршруты (последовательные/параллельные согласования, подпись, регистрация, ознакомление), резолюции → поручения, контроль исполнения (сроки по бизнес-календарю, эскалация), связи документов (в ответ на, во исполнение, отменяет), номенклатура дел и архив (сроки хранения, акты), печатные формы, простая электронная подпись с листом подписи и порт для квалифицированной, корреспонденты, отчёты по документообороту. Приоритет P1 (регистрация, маршруты, резолюции, контроль), P2 (архив, шаблоны, почта-в-документ), P3 (квалифицированная подпись).

## 5. Файлы

Папки и файлы в пространствах, загрузка (drag-and-drop, папками, докачка), скачивание, версии, предпросмотр (изображения, PDF, офисные документы, видео, геоданные, таблицы), извлечение текста и OCR для поиска, блокировка, общий доступ и ссылки с паролем/сроком, использование файла как вложения в любом объекте, корзина, квоты, совместное редактирование офисных документов (интеграция ONLYOFFICE/Collabora). Приоритет P0 (базово), P1 (предпросмотр, версии), P3 (офис-редактор).

## 6. Задачи и проекты

Задачи и **поручения** (единая сущность с разными правилами), подзадачи, чек-листы, исполнители/соисполнители/контролёр, приоритеты, сроки (по бизнес-календарю), зависимости, проекты с ключами, доски/списки/таймлайн/календарь, спринты-итерации (опционально), пользовательские поля, шаблоны задач, приёмка результата, повторяющиеся задачи, нагрузка по людям, обсуждения и вложения, отчёт по контролю. Приоритет P1 (задачи, поручения, доска), P2 (таймлайн, нагрузка, зависимости).

## 7. Коммуникации

Личные сообщения, групповые чаты, каналы (открытые/закрытые), треды, обсуждения объектов (единый механизм), упоминания, реакции, вложения, поиск, закрепления, черновики, статусы присутствия, «не беспокоить», интеграция с уведомлениями, быстрые действия из сообщения (создать задачу, привязать к документу). Приоритет P0 (обсуждения объектов), P2 (полный мессенджер).

## 8. Аудио- и видеосвязь

Звонки из чата (личные/групповые), встречи по расписанию, комнаты, демонстрация экрана (в т.ч. дашборда/карты одной кнопкой), приглашения внешних по ссылке, запись, расшифровка, черновик протокола (ИИ), решения и поручения из протокола, регистрация протокола как документа, ознакомление. Приоритет P2.

## 9. Календарь

Личные, командные и ресурсные календари, события с повторами и напоминаниями, приглашения и ответы, поиск времени, проекции сроков задач и документов, связь со встречами, ICS-экспорт/подписки, интеграции с внешними календарями позже. Приоритет P1 (базово), P2 (полнота).

## 10. Уведомления и «Мой день»

«Мой день»: Входящие (что требует действия), сегодня (встречи, сроки), мои задачи и поручения, выданные поручения (контроль), недавние и закреплённые, «Продолжить» (восстановление контекста), сводки для руководителей, настраиваемые виджеты. Уведомления: центр, каналы, тонкие настройки, тихие часы, дайджесты. Приоритет P0 (базово), P1 (полнота).

## 11. Поиск и знания

Палитра команд (Cmd+K): объекты, команды, навигация, недавние; страница поиска с фасетами; семантический поиск; база знаний: страницы-дерево с версиями, шаблоны (инструкция, регламент, справочник), ознакомление под подпись, сроки пересмотра, ИИ-ответы с цитатами. Приоритет P0 (палитра, поиск), P2 (знания, семантика).

## 12. Автоматизация, интеграции, ИИ

Правила «если-то» (события, условия, действия) с конструктором и шаблонами; расписания; вебхуки; API-токены и публичное REST API; интеграции: SMTP/IMAP, Telegram-бот (уведомления, согласования, запросы), LDAP/AD, OIDC, S3, внешние БД, WMS/WFS/ArcGIS, календари, SMS-шлюз, ONLYOFFICE; ИИ-ассистент в контексте (запрос к данным, объяснение графика, резюме документа, черновик ответа, извлечение полей из скана, перевод ru↔tg↔en, протокол встречи, ответы по базе знаний) с прозрачностью и правами. Приоритет P1 (Telegram, SMTP, базовые правила), P2 (ИИ-ассистент), P3 (остальное).

## 13. Администрирование

Пользователи, структура, роли, пространства, типы документов и журналы, маршруты, шаблоны, справочники, интеграции, правила, мониторинг заданий, аудит, здоровье системы, резервирование и восстановление, политики безопасности, брендирование, объявления, флаги функций, лимиты и квоты. Приоритет P0 (пользователи/роли/структура), P1 (остальное поэтапно).

## Предложенные дополнения к исходному видению

Каждое дополнение решает конкретную проблему целостности или реальной работы.

| Дополнение | Проблема, которую решает |
|---|---|
| **Реестр объектов и универсальные связи** | Без него модули остаются отдельными приложениями; ссылки в тексте не дают навигации, прав и истории |
| **Входящие (actionable inbox) отдельно от уведомлений** | Уведомления теряются в потоке; элементы, требующие действия, должны иметь состояние «сделано» |
| **Территории как первоклассный справочник и паспорт территории** | Для организации, работающей по регионам, территория — главный разрез анализа и хаб всех объектов |
| **Каталог показателей** | Один и тот же KPI, посчитанный по-разному в разных дашбордах, разрушает доверие к системе |
| **Тетради** | Аналитику нужен холст для исследования, а не только «сохранить график» |
| **Отчёты из шаблонов с регистрацией как документ** | Замыкает цикл «данные → официальный документ» |
| **Формы сбора данных** | Сбор сведений от подразделений/регионов — постоянная работа; без форм он остаётся в Excel и почте |
| **Бизнес-календарь и делегирование** | Сроки поручений считаются по рабочим дням; отпуск не должен останавливать согласования |
| **Единые обсуждения (комментарии = чат)** | Две системы сообщений — дублирование и потеря контекста |
| **Регистрация из почты и извлечение полей из сканов** | Главная трудозатрата канцелярии |
| **Telegram-бот** | Самый распространённый канал в регионе; согласование и уведомления вне рабочего места |
