### Что работает сейчас

```
bash infra/scripts/generate-secrets.sh
pnpm install && docker compose up -d --wait
pnpm db:migrate && pnpm db:seed && pnpm dev
```

- демо-организация: 61 пользователь, 22 подразделения, 10 должностей, 3 общих пространства,
  21 пространство подразделений и личные пространства;
- вход по паролю с CSRF-защитой, MFA TOTP, восстановление пароля, управление сессиями и устройствами;
- реестр объектов: создание/перенос/архив/корзина/восстановление с пересчётом предков и событиями;
- доступ: владелец, ACL с наследованием, роли пространств, разрыв наследования с копированием прав,
  «Объяснить доступ», гостевые ссылки;
- файлы: загрузка в MinIO, версии, папки, скачивание; обсуждения с упоминаниями; лента активности;
  поиск с учётом прав; Входящие и уведомления; аудит; задания (TS-воркер и Python-движок); realtime;
- гостевые ссылки: открытие объекта без входа по `/s/<токен>`, пароль, срок, счётчик открытий,
  водяной знак, аудит открытий, отзыв;
- замещение: баннер «Вы замещаете» с переключателем режима «от имени», дублирование Входящих
  заместителю, аудит с обеими сторонами;
- почта: письма о упоминаниях уходят сразу, остальное — дайджестом раз в 15 минут
  (в разработке принимает mailpit на <http://localhost:8025>);
- интерфейс: оболочка рабочего пространства с вкладками и сплит-панелями, светлая и тёмная темы,
  три плотности, полная навигация с клавиатуры, палитра команд, мобильная раскладка.

### Найдено и исправлено сценариями приёмки

- `GET /objects/{id}` падал с 500 для гостя по ссылке: личное состояние
  (избранное, недавние, подписки) запрашивалось с `user_id = link:<…>`.
- Список Входящих падал с 500 на сортировке: `nulls last asc` вместо `asc nulls last`.
- Ссылка с паролем не открывалась вовсе — не было маршрута обмена пароля на доступ.
- Канал `email` записывался в уведомление, но письма не отправлялись.
- Дымовой прогон отправлял сломанный JSON в одной проверке (экранирование в bash).
- ICU-плюрализация ломалась на шаблонах с несколькими ветвями: в строке состояния
  вместо «1 задание» выводился кусок шаблона. Разбор переписан со счётчиком скобок,
  добавлены unit-тесты `packages/i18n`.

### Принятые решения (ADR)

- ADR-0025 — расширения PostgreSQL в схеме `extensions` вместо `public`.
- ADR-0026 — собственный образ PostgreSQL вместо `postgis/postgis`.
- ADR-0027 — отметка обработки события после успешного вызова подписчика.
- ADR-0028 — ISO 8601 для `timestamptz` на уровне типа колонки.
- ADR-0029 — отдельная база `kchs_test` для интеграционных тестов.
- ADR-0030 — типизированный клиент из `packages/contracts`, OpenAPI — для внешних потребителей.
- ADR-0031 — порт справочника вместо обращения ядра к модулю идентификации.
- ADR-0032 — гостевая ссылка открывается по короткоживущему токену доступа.
- ADR-0033 — режим «от имени» передаётся заголовком запроса, а не хранится в сессии.
- ADR-0034 — доставка уведомлений почтой: немедленно и дайджестом.

## Открытые вопросы к владельцу продукта

Сформулированы в `04-delivery/05-risks-and-open-questions.md`, раздел «Новые вопросы»;
работа продолжается с разумным допущением:

- **N1** — git недоступен: не приняты лицензионные соглашения Xcode Command Line Tools
  (`sudo xcodebuild -license`). История коммитов не ведётся.
- **N2** — учётные данные демо-стенда: сейчас пароли задаются переменными
  `SEED_ADMIN_PASSWORD` / `SEED_USER_PASSWORD`, значения по умолчанию пригодны только для разработки.
- **N3** — обязательность MFA: сейчас MFA доступна, но не принудительна ни для одной роли.

## Известные ограничения

- Партиционирование `activities`, `notifications`, `query_runs` отложено до появления объёмов
  (задание обслуживания, фаза 5).
- Таджикская локаль покрыта на 36 % ключей, английская — на 90 %; недостающие ключи наследуются
  из русской (допустимо до фазы 5).
- Превью файлов и извлечение текста — в фазе 1 вместе с движком обработки.
