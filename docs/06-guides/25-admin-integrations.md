# Интеграции, вебхуки, токены API

## Интеграции

**«Администрирование» → «Интеграции»** (способность «Автоматизация»). Раздел
содержит два блока: интеграции и исходящие вебхуки.

«Внешние службы установки и исходящие вебхуки. Секреты хранятся зашифрованными и
наружу не отдаются».

### Завести интеграцию

**«Новая интеграция»**:

- **«Ключ»** — «Стабильный ключ для переноса между контурами»;
- **«Название»**;
- **«Вид»**: **«Почта (SMTP)»**, **«Telegram»**, **«Почтовый ящик (IMAP)»**,
  **«LDAP / Active Directory»**, **«OIDC SSO»**, **«HTTP-сервис»**,
  **«Хранилище S3»**, **«SFTP»**, **«База PostgreSQL»**, **«База MySQL /
  MariaDB»**, **«Своя»**;
- **«Конфигурация»** — JSON без секретов: адреса, имена, расписание;
- **«Секреты»** — JSON с секретами: «значения сохраняются зашифрованными и
  обратно не отдаются. Пусто — прежние секреты остаются».

В строке видно состояние («Работает», «Ошибка», «Не проверялась», «Выключена»),
перечень имён секретов и дата последней проверки. Действия: **«Проверить
связь»**, **«Настроить»** (там же переключатель **«Включена»** и **«Журнал
синхронизаций»**), **«Входящий вебхук»**.

**«Входящий вебхук»** выдаёт адрес с секретом: «Скопируйте адрес сейчас: секрет в
нём больше не показывается. Запрос по этому адресу публикует событие, но прав ни
на что не даёт».

Встроенные SMTP и Telegram настраиваются переменными окружения и показываются в
списке с бейджем **«Встроенная»** только для чтения — так весь учёт внешних служб
собран в одном месте.

### Для чего нужны отдельные виды

- **«Почтовый ящик (IMAP)»** — очередь «Из почты» в документообороте: платформа
  забирает письма и заводит по ним черновики входящих. Опрос идёт по расписанию,
  интервал задаётся в конфигурации ящика. Корреспондента письму подставляют по адресу
  или по «Почтовым доменам» ведомства из справочника корреспондентов; отклонённые и
  неразобранные письма очищаются через 180 дней (расписание «Документы: очистка очереди
  «Из почты» по сроку хранения»).
- **«База PostgreSQL»** и **«База MySQL / MariaDB»** — подключения для раздела
  **«Источники данных»**; без интеграции этот раздел скажет: «Подключений к
  внешним базам нет».
- **«HTTP»** — хранилище ключа API для ленты по адресу: секрет интеграции
  (например, `mapKey`) лента подставляет в адрес или заголовок записью
  `{secret:mapKey}`, сам ключ в настройке ленты не виден.
- **«LDAP / Active Directory»** и **«OIDC SSO»** — реестровая запись рядом с
  настройкой в разделах «Каталог» и «Единый вход».

## Источники данных

**«Администрирование» → «Источники данных»** (способность «Источники данных»).
«Датасеты из внешних баз и ленты по адресу: подключение и секреты — в
интеграциях, здесь — что читать, как раскладывать и когда обновлять».

### Подключение к базе данных

Порядок: заведите интеграцию вида PostgreSQL или MySQL → **«Добавить источник»**
→ **«Подключение к базе данных»** → **«Подключение»**, **«Пространство»**, **«Название источника»**, **«Что
читаем»** («Таблица» или «Запрос SQL»), схема и таблица либо текст запроса
(«Запрос выполняется во внешней базе под её учётной записью») → **«Прочитать
столбцы»** → отметьте нужные → **«Режим»** («снимок» или «инкремент»),
**«Расписание (cron)»** («Пять полей, например `0 * * * *`. Пусто — только
вручную»), **«Поле-курсор»**, **«Ключевые поля»** → сохраните и нажмите
**«Синхронизировать сейчас»**.

Каждый запрос к внешней базе ограничен по времени: предпросмотр, чтение столбцов и
проверка соединения — 30 секунд (`EXTERNAL_DB_TIMEOUT_MS`), загрузка в задании —
10 минут. Не уложилась — «Внешняя база не ответила вовремя: сузьте выборку,
добавьте условие или индекс»; сама база продолжать запрос не будет.

Есть **«Проверить соединение»** и **«Журнал синхронизаций»**. Датасет создаётся
автоматически и помечается как не редактируемый; при удалении источника «Датасет
останется, но перестанет обновляться из внешней базы».

### Лента по адресу

Лента — GeoJSON, CSV или JSON, который служба публикует по адресу: землетрясения
USGS и EMSC, мировые предупреждения GDACS, термоточки NASA FIRMS. Сервер забирает
её по расписанию и пишет записи строками датасета: новые добавляет, знакомые по
ключу обновляет — только поля ленты и только если они изменились. Поля, которые
правит дежурный (статус, решение), лента не трогает, а строку, удалённую
вручную, заново не заводит.

**«Добавить источник» → «Лента по адресу»**, три шага:

1. **«Адрес»** — **«Адрес ленты»**, **«Формат»**, для JSON — **«Путь к массиву
   записей»**; если лента требует ключ API — **«Секреты»**: интеграция HTTP с
   этим ключом, а в адресе вместо ключа — `{secret:имя}`. **«Проверить ленту»**
   показывает, сколько записей и полей нашлось, и первые записи таблицей.
2. **«Датасет и поля»** — **«В существующий датасет»** (несколько лент можно
   писать в один датасет: у каждой — своя константа в поле «Источник») или
   **«В новый датасет»**. Для каждого поля — откуда значение: **«Поле записи»**
   (путь, например `properties.mag`, и приведение — по умолчанию «по типу поля»),
   **«Постоянное»**, **«Шаблон»** (`{latitude}_{longitude}_{acq_date}` — ключ
   ленты без идентификатора), **«Дата + время»** (у FIRMS они в двух столбцах).
   Отметьте **ключ**. Ниже — **«Геометрия записи»** («Объект GeoJSON» или
   «Широта и долгота»), поле геометрии и **«Поле района»** — район, в границах
   которого лежит запись; **«Только записи внутри территорий страны»** отбросит
   события соседних стран, **«Область отбора»** с кнопкой **«Таджикистан»** —
   записи вне прямоугольника.
3. **«Расписание»** — название и cron (по умолчанию каждые 15 минут).

Потом — **«Синхронизировать сейчас»** или ждать расписания; в
**«Журнале синхронизаций»** у каждого опроса видно, сколько записей пришло,
добавлено и обновлено, и почему часть пропущена. Не отвечает, отвечает ошибкой
или не тем форматом — источник получает статус «ошибка» с причиной.

**Предупреждения в стандарте CAP 1.2** — формат **«CAP 1.2 (предупреждения)»** (ADR-0201).
Адрес — сообщение `<alert>` или индекс Atom/RSS. Сообщения внутри индекса читаются сразу,
ссылки — по одной (до 50 за опрос). Ключ доступа ленты уходит только на её собственный адрес,
на чужие ссылки — нет. Для сопоставления полей:

| Путь | Что это |
|---|---|
| `key` | ключ нити: уточнение и отмена обновляют строку первичного сообщения — выберите его ключевым полем |
| `sent`, `msgType`, `status` | время отправки, вид (`Alert`, `Update`, `Cancel`), статус (`Actual`, `Exercise`) |
| `info.headline`, `info.description`, `info.instruction` | заголовок, описание, указания населению |
| `info.event`, `info.severity`, `info.urgency`, `info.certainty` | явление и оценки |
| `info.parameter.<имя>`, `area.desc` | параметры службы (`alertlevel` у GDACS) и описание области |
| `lang.tg.headline` и подобные | блоки на других языках; основной выбран по порядку: русский, таджикский, английский |
| геометрия «из записи» | области сообщения; для набора с точкой — широта `center.lat`, долгота `center.lon` |

Тестовые, черновые и служебные сообщения строк не создают.

### Исходящий прокси

Если серверы выходят в интернет только через прокси, задайте в `.env`
`HTTP_PROXY` (и при своём прокси для https — `HTTPS_PROXY`) и перезапустите api и
worker. Через прокси пойдут ленты, растровые подложки, внешние ГИС-службы,
ICS-подписки, вебхуки и провайдеры ИИ; службы самой установки — напрямую.
Внутренние серверы, которые прокси не видит (служба закрытого контура, свой
сервер модели), перечислите в `NO_PROXY` через запятую: имя точно или
`.домен` для всех поддоменов. Подробнее — `02-architecture/15-admin-operations.md` §2.

## Исходящие вебхуки

Второй блок раздела «Интеграции».

**«Новый вебхук»**: **«Название»**, **«Адрес»** («Только внешний адрес: адреса
внутренней сети запрещены»), **«События»** («Типы событий через запятую:
`document.*`, `task.created`»).

После создания показывается **«Секрет подписи»**: «Скопируйте секрет сейчас:
больше он не показывается. Им проверяется подпись HMAC-SHA256 в заголовке
`x-kchs-signature`».

В строке — состояние («Работает», «На паузе», «Отключён»), дата последней
доставки, число отказов подряд и, при отключении, «Отключён после серии
отказов». Действия: **«Доставки»** (журнал с кнопкой **«Повторить»**), **«На
паузу»** / **«Включить»**, удаление.

Наружу уходит только то, что видит владелец подписки; домены заданий, вебхуков и
токенов не отправляются никогда. Повторы идут от 30 секунд до 6 часов в течение
суток, серия отказов отключает подписку.

Перевыпуск секрета подписи в интерфейсе не предусмотрен (маршрут API есть) —
создайте новый вебхук.

## Токены API

**«Администрирование» → «Токены API»**: «Все токены установки: чьи они, кем
выпущены и когда использовались. **Выпускаются токены в профиле владельца**».

В строке — название, статус («Действует», «Отозван», «Просрочен»), префикс
`kchs_…`, владелец, кто выпустил, области доступа, дата последнего использования и
срок. Кнопка отзыва: «Запросы с этим токеном перестанут работать сразу. Владелец
увидит отзыв в своём профиле».

Как устроен токен:

- формат `kchs_<префикс>_<секрет>`; в базе хранится только хэш;
- токен строит контекст своего владельца и дальше проходит обычную проверку прав
  — **прав он не расширяет**, области доступа только сужают их;
- область выводится из тега маршрута: `GET` и «читающие» `POST` — чтение,
  остальное — запись;
- безусловно закрыты пути `/me`, `/auth`, `/internal`, `/admin`, `/share`,
  `/hooks` и теги аутентификации, администрирования и ИИ;
- режим администратора и работа «от имени» токену не достаются;
- незавершённая настройка входа владельца (временный пароль, обязательный второй
  фактор) закрывает токен целиком;
- у токена свой лимит запросов.

Чтобы сотрудник мог выпустить токен, дайте ему способность **«API-токены»**
(через роль). Выпуск происходит в профиле: **«Мои токены API»** → **«Выпустить
токен»**.

Документация API собирается самой установкой и доступна по адресу `/api/docs`.

## Приём координат техники и групп

Канал для поставщика услуг GPS-мониторинга (ADR-0203):

1. Заведите служебную учётную запись поставщика (**«Администрирование» →
   «Пользователи»**, вид «служебная»). Членство в пространствах ей не нужно.
2. Выпустите на неё токен с областью **`write:positions`**.
3. В **«Устройства слежения»** (палитра команд) заведите устройства: номер у поставщика
   (IMEI, логин трекера), вид, код в «Силах и средствах»; в поле «**Кто передаёт
   координаты**» выберите служебную запись поставщика.
4. Поставщик отправляет `POST /api/v1/public/positions` с заголовком
   `Authorization: Bearer kchs_…` и телом `{"positions": [{"deviceId": "IMEI-…",
   "at": "2026-10-12T08:00:00+05:00", "lat": 38.56, "lon": 68.78, "speed": 40}]}` — до
   500 точек за раз. В ответе — сколько принято, сколько повторов и какие точки
   отбракованы с причиной.

Телефон оперативной группы передаёт координаты в сессии сотрудника — его назначают
«передающим» в карточке устройства.

**Настройки** (кнопка на экране «Устройства слежения», только администратору системы):
срок хранения точек в месяцах (по умолчанию 12; старые месяцы удаляются целиком ночью),
порог «нет связи» в минутах (15), датасет слоя карты (пакет ЧС ставит «Техника и группы
на карте»).
## Кто и сколько передаёт: журнал подключений

Платформа считает каждое подключение по суткам: запросы, записанные строки и ошибки.
Подключение — это токен API, входящий вебхук или почтовый ящик интеграции, лента,
источник из внешней базы, форма сбора, исходящий вебхук.

- **Дашборд «Интеграции»** в пространстве «Общее»: активные подключения за 30 дней,
  запросы и строки за сутки, сколько подключений молчит дольше суток, полнота передач.
  Ниже — передачи по дням и каналам и таблица «Состояние подключений».
- **Датасет «Подключения»** — источник дашборда. Его можно взять в запрос, график или
  свой показатель: в редакторе выберите системный источник «Подключения».
- Строки видят те, у кого есть право управлять интеграциями. Сотрудник видит только
  свои токены.
- Запросы по токенам появляются в данных примерно через минуту.
- Выпущенный, но ни разу не использованный токен тоже виден: у него ноль запросов и
  отметка «Молчит дольше суток».

Что смотреть в первую очередь:

1. **«Молчат дольше суток»** — партнёр перестал передавать или у ленты сбой. Причина
   ошибки — в столбце «Последняя ошибка».
2. **«Полнота за 30 дней»** — доля дней с передачами. У суточной сводки она должна быть
   близка к 100 %.
3. **«Активные подключения»** — сколько партнёров реально обмениваются данными. Это
   показатель концепт-ноты «не менее двух партнёров».

## Каталог каналов обмена

Раздел базы знаний **«Каналы обмена»** в пространстве «Общее» описывает 16 каналов, по
которым платформа обменивается данными. Каждый канал описан паспортом: назначение,
состояние, формат, пример, порядок доступа, ответственный, описание API. Раздел ставит
пакет ЧС (`kchs seed --pack emergency`).

- Паспорта правятся как обычные страницы. Впишите ответственных и опубликуйте новую
  редакцию.
- Каналы с пометкой «создаётся проектом» в платформе ещё не работают.
- Новый паспорт создаётся шаблоном **«Паспорт канала»** в диалоге «Создать страницу».

Песочница для партнёров — отдельная установка демо-профиля
(`bash infra/scripts/demo-stand.sh up`, руководство `30-demo-stand.md`). Тестовые
токены выдаются только в ней. Проверенную настройку переносите в рабочий контур
пакетом конфигурации.

## Перенос конфигурации между контурами

**«Администрирование» → «Конфигурация»**: «Перенос настройки между контурами:
выгрузка в JSON-пакет по стабильным ключам и импорт с предпросмотром различий.
Секреты в пакет не попадают».

1. **«Выгрузка»**: отметьте разделы — **«Интеграции»**, **«Вебхуки»**,
   **«Маршруты»**, **«Журналы регистрации»**, **«Типы документов»**,
   **«Шаблоны документов»** — и нажмите **«Выгрузить пакет»**.
   Сохраните полученный JSON.
2. На другом контуре: **«Импорт»** → вставьте пакет в поле **«Пакет (JSON)»** →
   **«Показать различия»**.
3. Изучите карточку **«Различия»**: строки помечаются «Новая», «Изменится»,
   «Совпадает», **«Конфликт»** (запись правили здесь после выгрузки пакета),
   «Не поддержана».
4. При необходимости включите **«Перезаписывать записи, изменённые здесь»** и
   нажмите **«Применить»** — «Применено записей: {N}, пропущено: {M}».

Записи узнаются по ключу, а не по названию. У журнала ключ виден и правится в
справочнике журналов: поле **«Ключ»**, латиница, цифры и `_`. Переименование журнала
ключ не меняет. Если ключ не задать, он получится из названия.

Как переносятся справочники документооборота:

- тип ссылается на журнал нумерации и маршрут по ключу, журнал на типы — тоже по ключу;
- подразделения узнаются по коду;
- файл шаблона DOCX до 2 МБ едет в пакете, больший файл загрузите вручную;
- сотрудники не переносятся: получателя резолюций «конкретный сотрудник» выберите на
  новом контуре сами;
- разделы применяются в порядке «маршруты → журналы → типы → шаблоны», порядок в
  файле не важен.

Секреты интеграций в пакет не попадают и заводятся на новом контуре заново.

## Частые вопросы

**Вебхук не доходит.** Проверьте журнал **«Доставки»**: там видны попытки и
причина. Частые причины — адрес внутренней сети (запрещён), перенаправление
(не поддерживается) и серия отказов, после которой подписка отключается.

**Почему в вебхук не приходят события заданий?** Домены `job`, `webhook` и
`token` наружу не отправляются никогда.

**Токен работал, а теперь отвечает отказом.** Проверьте: не отозван ли он, не
истёк ли срок и не оказался ли владелец с незавершённой настройкой входа — в
последнем случае токен закрывается целиком.

**Как подключить почтовый ящик канцелярии?** Заведите интеграцию вида «Почтовый
ящик (IMAP)»; экран «Из почты» в документах сам об этом пишет: «Ящик канцелярии
настраивается интеграцией „imap“ в администрировании».
