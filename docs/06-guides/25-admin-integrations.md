# Интеграции, вебхуки, токены API

## Интеграции

**«Администрирование» → «Интеграции»** (способность «Автоматизация»). Раздел
содержит два блока: интеграции и исходящие вебхуки.

«Внешние службы установки и исходящие вебхуки. Секреты хранятся зашифрованными и
наружу не отдаются».

### Завести интеграцию

**«Новая интеграция»**:

- **«Ключ»** — «Стабильный ключ для переноса между контурами»;
- **«Название»**;
- **«Вид»**: **«Почта (SMTP)»**, **«Telegram»**, **«Почтовый ящик (IMAP)»**,
  **«LDAP / Active Directory»**, **«OIDC SSO»**, **«HTTP-сервис»**,
  **«Хранилище S3»**, **«SFTP»**, **«База PostgreSQL»**, **«База MySQL /
  MariaDB»**, **«Своя»**;
- **«Конфигурация»** — JSON без секретов: адреса, имена, расписание;
- **«Секреты»** — JSON с секретами: «значения сохраняются зашифрованными и
  обратно не отдаются. Пусто — прежние секреты остаются».

В строке видно состояние («Работает», «Ошибка», «Не проверялась», «Выключена»),
перечень имён секретов и дата последней проверки. Действия: **«Проверить
связь»**, **«Настроить»** (там же переключатель **«Включена»** и **«Журнал
синхронизаций»**), **«Входящий вебхук»**.

**«Входящий вебхук»** выдаёт адрес с секретом: «Скопируйте адрес сейчас: секрет в
нём больше не показывается. Запрос по этому адресу публикует событие, но прав ни
на что не даёт».

Встроенные SMTP и Telegram настраиваются переменными окружения и показываются в
списке с бейджем **«Встроенная»** только для чтения — так весь учёт внешних служб
собран в одном месте.

### Для чего нужны отдельные виды

- **«Почтовый ящик (IMAP)»** — очередь «Из почты» в документообороте: платформа
  забирает письма и заводит по ним черновики входящих. Опрос идёт по расписанию,
  интервал задаётся в конфигурации ящика.
- **«База PostgreSQL»** и **«База MySQL / MariaDB»** — подключения для раздела
  **«Источники данных»**; без интеграции этот раздел скажет: «Подключений к
  внешним базам нет».
- **«LDAP / Active Directory»** и **«OIDC SSO»** — реестровая запись рядом с
  настройкой в разделах «Каталог» и «Единый вход».

## Источники данных

**«Администрирование» → «Источники данных»** (способность «Источники данных»).
«Датасеты из внешних баз: подключение берётся из интеграции, здесь — выборка,
режим и расписание».

Порядок: заведите интеграцию вида PostgreSQL или MySQL → **«Добавить источник»**
→ **«Подключение»**, **«Пространство»**, **«Название источника»**, **«Что
читаем»** («Таблица» или «Запрос SQL»), схема и таблица либо текст запроса
(«Запрос выполняется во внешней базе под её учётной записью») → **«Прочитать
столбцы»** → отметьте нужные → **«Режим»** («снимок» или «инкремент»),
**«Расписание (cron)»** («Пять полей, например `0 * * * *`. Пусто — только
вручную»), **«Поле-курсор»**, **«Ключевые поля»** → сохраните и нажмите
**«Синхронизировать сейчас»**.

Есть **«Проверить соединение»** и **«Журнал синхронизаций»**. Датасет создаётся
автоматически и помечается как не редактируемый; при удалении источника «Датасет
останется, но перестанет обновляться из внешней базы».

## Исходящие вебхуки

Второй блок раздела «Интеграции».

**«Новый вебхук»**: **«Название»**, **«Адрес»** («Только внешний адрес: адреса
внутренней сети запрещены»), **«События»** («Типы событий через запятую:
`document.*`, `task.created`»).

После создания показывается **«Секрет подписи»**: «Скопируйте секрет сейчас:
больше он не показывается. Им проверяется подпись HMAC-SHA256 в заголовке
`x-kchs-signature`».

В строке — состояние («Работает», «На паузе», «Отключён»), дата последней
доставки, число отказов подряд и, при отключении, «Отключён после серии
отказов». Действия: **«Доставки»** (журнал с кнопкой **«Повторить»**), **«На
паузу»** / **«Включить»**, удаление.

Наружу уходит только то, что видит владелец подписки; домены заданий, вебхуков и
токенов не отправляются никогда. Повторы идут от 30 секунд до 6 часов в течение
суток, серия отказов отключает подписку.

Перевыпуск секрета подписи в интерфейсе не предусмотрен (маршрут API есть) —
создайте новый вебхук.

## Токены API

**«Администрирование» → «Токены API»**: «Все токены установки: чьи они, кем
выпущены и когда использовались. **Выпускаются токены в профиле владельца**».

В строке — название, статус («Действует», «Отозван», «Просрочен»), префикс
`kchs_…`, владелец, кто выпустил, области доступа, дата последнего использования и
срок. Кнопка отзыва: «Запросы с этим токеном перестанут работать сразу. Владелец
увидит отзыв в своём профиле».

Как устроен токен:

- формат `kchs_<префикс>_<секрет>`; в базе хранится только хэш;
- токен строит контекст своего владельца и дальше проходит обычную проверку прав
  — **прав он не расширяет**, области доступа только сужают их;
- область выводится из тега маршрута: `GET` и «читающие» `POST` — чтение,
  остальное — запись;
- безусловно закрыты пути `/me`, `/auth`, `/internal`, `/admin`, `/share`,
  `/hooks` и теги аутентификации, администрирования и ИИ;
- режим администратора и работа «от имени» токену не достаются;
- незавершённая настройка входа владельца (временный пароль, обязательный второй
  фактор) закрывает токен целиком;
- у токена свой лимит запросов.

Чтобы сотрудник мог выпустить токен, дайте ему способность **«API-токены»**
(через роль). Выпуск происходит в профиле: **«Мои токены API»** → **«Выпустить
токен»**.

Документация API собирается самой установкой и доступна по адресу `/api/docs`.

## Перенос конфигурации между контурами

**«Администрирование» → «Конфигурация»**: «Перенос настройки между контурами:
выгрузка в JSON-пакет по стабильным ключам и импорт с предпросмотром различий.
Секреты в пакет не попадают».

1. **«Выгрузка»**: отметьте разделы — **«Интеграции»**, **«Вебхуки»**,
   **«Типы документов»**, **«Маршруты»** — и нажмите **«Выгрузить пакет»**.
   Сохраните полученный JSON.
2. На другом контуре: **«Импорт»** → вставьте пакет в поле **«Пакет (JSON)»** →
   **«Показать различия»**.
3. Изучите карточку **«Различия»**: строки помечаются «Новая», «Изменится»,
   «Совпадает», **«Конфликт»** (запись правили здесь после выгрузки пакета),
   «Не поддержана».
4. При необходимости включите **«Перезаписывать записи, изменённые здесь»** и
   нажмите **«Применить»** — «Применено записей: {N}, пропущено: {M}».

Раздел «Типы документов» объявлен, но пока не поддержан: журналам регистрации
нужен стабильный ключ — это открытый вопрос к владельцу продукта. Секреты
интеграций в пакет не попадают и заводятся на новом контуре заново.

## Частые вопросы

**Вебхук не доходит.** Проверьте журнал **«Доставки»**: там видны попытки и
причина. Частые причины — адрес внутренней сети (запрещён), перенаправление
(не поддерживается) и серия отказов, после которой подписка отключается.

**Почему в вебхук не приходят события заданий?** Домены `job`, `webhook` и
`token` наружу не отправляются никогда.

**Токен работал, а теперь отвечает отказом.** Проверьте: не отозван ли он, не
истёк ли срок и не оказался ли владелец с незавершённой настройкой входа — в
последнем случае токен закрывается целиком.

**Как подключить почтовый ящик канцелярии?** Заведите интеграцию вида «Почтовый
ящик (IMAP)»; экран «Из почты» в документах сам об этом пишет: «Ящик канцелярии
настраивается интеграцией „imap“ в администрировании».
