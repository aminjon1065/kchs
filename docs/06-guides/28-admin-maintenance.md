# Обслуживание, здоровье, наблюдаемость

## Здоровье системы

**«Администрирование» → «Здоровье системы»** — первый раздел консоли.

- Плитки компонентов: `postgres`, `redis`, `meilisearch`, `storage` и `engine` с
  бейджем **«Работает»**, **«С замечаниями»** или **«Недоступен»** и задержкой в
  миллисекундах. Движок проверяется, когда задан его адрес (`ENGINE_INTERNAL_URL`), —
  в установке целиком в контейнерах он задан всегда.
- Четыре счётчика: **«Неопубликованных событий»**, **«Заданий в очереди»**,
  **«Выполняется»**, **«Ошибок за сутки»**.
- Карточка **«Действующие оповещения»** — то, что Alertmanager сейчас рассылает, без
  заглушённых: важность, правило, суть и время начала, критичные сверху.
- Карточка **«Нагрузка и ресурсы»** — из Prometheus за последние 5 минут:
  - запросов в секунду, доля ответов с ошибкой 5xx, p95 ответа API;
  - память api и worker;
  - размер базы данных и число подключений;
  - память Redis из предела.
- Карточка **«Инсталляция»**: **«Версия»**, **«Время работы»**, **«Состояние»**.

Метрики и оповещения берутся из профиля `observability` (раздел «Наблюдаемость»
ниже). Адреса — `PROMETHEUS_URL` и `ALERTMANAGER_URL`, в установке в контейнерах по
умолчанию `http://prometheus:9090` и `http://alertmanager:9093`. Если профиль не
запущен, карточки пишут, что служба не отвечает; если адрес пуст — что сбор не
настроен. Остальной экран работает и без них.

Раздел только читает: кнопки «Обновить» нет, данные перечитываются при
переоткрытии вкладки (метрики и оповещения — не чаще раза в 15 секунд). «Версия» —
тег образов установки (`KCHS_IMAGE_TAG`), на стенде разработчика — «разработка».

На что смотреть каждый день:

- «Неопубликованных событий» должно быть около нуля; растущее число означает, что
  стоит `worker` или не справляются подписчики;
- «Ошибок за сутки» — повод заглянуть в журналы;
- любой компонент не «Работает» — см. `infra/runbooks/incident.md`.

## Регулярные работы

Все регулярные задания платформы видны на экране **«Расписания»** (см.
«Расписания и правила автоматизации»): очистка корзины через 30 дней, обрезка
«недавних», повтор брошенных заданий, дайджест писем, напоминания об
ознакомлении, сроки поручений, опрос почтовых ящиков, очистка очереди «Из почты»
(отклонённые и неразобранные письма старше 180 дней), напоминания календаря,
синхронизация подписок ICS, периоды форм сбора, проверка алертов, очистка
журналов и ночная резервная копия.

По требованию из консоли запускается одно: **«Переиндексировать поиск»** в
карточке **«Обслуживание»** раздела «Резервные копии».

## Наблюдаемость

Отдельного раздела в консоли нет. Метрики, трассы и журналы собираются отдельным
профилем compose:

```bash
docker compose --profile observability up -d
```

Поднимаются:

- Alloy — агент: приём OTLP и журналы контейнеров;
- Tempo, Loki, Prometheus;
- экспортёры метрик Postgres и Redis;
- Alertmanager — доставка оповещений, интерфейс `http://127.0.0.1:9093`;
- Grafana — `http://127.0.0.1:3001`, пароль в `GRAFANA_ADMIN_PASSWORD` из `.env`.

Интерфейсы публикуются только на самом сервере.

- **Метрики** api и worker включены в контейнерах всегда (`METRICS_PORT=9464`,
  только внутренняя сеть). Что снимается: длительность HTTP-запросов по маршруту
  и коду, память и процессорное время, задержка цикла событий, размер и возраст
  outbox, задания по очередям и состояниям, длительность заданий и обработки
  событий, число realtime-подключений.
- **Трассы** включаются адресом коллектора: `OTEL_EXPORTER_OTLP_ENDPOINT_INTERNAL=http://alloy:4318`
  в `.env` для профиля `app` — у api, worker и движка сразу. Без адреса SDK трасс не
  загружается вовсе. Доля трасс — `OTEL_TRACES_SAMPLER` и `OTEL_TRACES_SAMPLER_ARG`.
  Задание движка продолжает трассу запроса, который его поставил: импорт файла,
  печать отчёта или превью видны одной трассой с запросом в api.
- **Журналы** несут `trace_id` и `span_id`: в Grafana из строки журнала
  открывается трасса и наоборот.
- **Метрики служб данных** собираются учётными записями только для чтения метрик.
  При каждом запуске профиля их заводят одноразовые контейнеры `metrics-init-*`:
  - Postgres — роль `kchs_monitor` (только `pg_monitor`, пароль
    `KCHS_MONITOR_PASSWORD`). Снимаются соединения по состояниям, старейшая
    транзакция, размер баз, взаимные блокировки, возраст транзакций, WAL и
    контрольные точки. Потабличных метрик нет: таблиц датасетов в схеме `ds`
    становится всё больше;
  - Redis — память, клиенты, команды, ошибки ответов, сохранение на диск;
  - MinIO — собственные метрики по токену пользователя `kchs-prometheus` только с
    правом `admin:Prometheus`. Метрики не открыты публично: порт S3 смотрит наружу;
  - Meilisearch — собственные метрики по ключу только с действием `metrics.get`:
    очередь задач, задержка индексирования, размер базы, время ответа.
- Дашборды:
  - `infra/observability/dashboards/kchs-overview.json` («kchs — обзор»): запросы,
    p95 по маршрутам с линией бюджета, ошибки, память, процессор, цикл событий,
    outbox, очереди, задания, события, предупреждения;
  - `kchs-infrastructure.json` («kchs — инфраструктура»): Postgres, Redis, MinIO,
    Meilisearch и доставка оповещений.
- Правила оповещений — `infra/observability/prometheus/alerts.yml`, по группам:
  - приложение: экземпляр не отвечает, 5xx выше 1 %, p95 выше бюджета, outbox
    старше минуты, очередь растёт, RSS выше 1 ГБ;
  - Postgres: база не отвечает, соединений больше 80 % от `max_connections`,
    транзакция дольше 30 минут, «idle in transaction» дольше 5 минут, взаимные
    блокировки, возраст транзакций выше миллиарда, отставание реплики — если она
    есть;
  - Redis: не отвечает, память у предела `maxmemory` (или больше 2 ГБ, если предела
    нет), отказ соединений, отказ записи (OOM, MISCONF), сбой сохранения на диск.
    Предел задаёт `REDIS_MAXMEMORY` (по умолчанию `1gb`); у предела Redis отказывает в
    записи и не вытесняет задания очередей. Новый предел применяется при
    пересоздании контейнера: `docker compose up -d redis`;
  - хранилище: MinIO не отвечает, узлы или диски вне сети, свободно меньше 10 %
    (предупреждение) и 5 % (критично) диска;
  - поиск: Meilisearch не отвечает, индексирование отстаёт больше 15 минут,
    очередь задач почти заполнена;
  - сама наблюдаемость: метрики службы не собираются, Alertmanager не доставил
    оповещение.

  Что делать по каждому оповещению — `infra/runbooks/incident.md`, раздел
  «Оповещения наблюдаемости».

### Куда приходят оповещения

Prometheus передаёт сработавшие правила в Alertmanager. Тот рассылает их письмом и,
если задан чат, в Telegram. Настройка — переменные `.env`, затем
`docker compose --profile observability up -d`: конфигурация собирается заново при
каждом старте контейнера.

- **Получатели письма** — `ALERTMANAGER_EMAIL_TO`, адреса через запятую. Пусто —
  писем нет, оповещения видны только в интерфейсе Alertmanager и в Prometheus.
- **Почтовый сервер** — тот же, что у api и worker в контейнерах
  (`SMTP_URL_INTERNAL`, в разработке — mailpit). Отдельный задаётся в
  `ALERTMANAGER_SMTP_URL`:
  - `smtp://логин:пароль@узел:587` — со STARTTLS: с логином он обязателен, пароль
    открытым не уходит;
  - `smtps://логин:пароль@узел:465` — TLS сразу.

  Отправитель — `SMTP_FROM` или `ALERTMANAGER_SMTP_FROM`.
- **Telegram** — `ALERTMANAGER_TELEGRAM_CHAT_ID`, чат дежурных; у группы число
  отрицательное. Бот — тот же, что у платформы (`TELEGRAM_BOT_TOKEN`): добавьте его
  в группу. Свой бот задаётся в `ALERTMANAGER_TELEGRAM_BOT_TOKEN`. Из закрытого
  контура запросы к Telegram идут через исходящий прокси (`HTTPS_PROXY`) или адрес
  своего Bot API (`TELEGRAM_API_URL`).
- **Тема письма** — «[Портал КЧС] ТРЕВОГА: имя правила — суть». Название установки
  задаётся в `ALERTMANAGER_INSTALLATION`, например «КЧС — рабочий контур». Когда
  правило перестаёт срабатывать, приходит письмо «Восстановлено».
- **Ритм.** Оповещения группируются по правилу и заданию: первое письмо — через
  30 секунд, новые в той же группе — не чаще раза в 5 минут, напоминание о
  несрабатывающем — раз в 4 часа. Пока экземпляр в критическом состоянии, его же
  предупреждения (задержки, память) отдельно не шлются.
- **Проверить доставку** можно тестовым оповещением. Письмо придёт через полминуты:

  ```bash
  docker compose exec alertmanager amtool alert add KchsDeliveryTest \
    severity=warning job=test instance=manual \
    --annotation=summary="Проверка доставки оповещений" \
    --alertmanager.url=http://127.0.0.1:9093
  ```

- **Тишина на время работ** — «Silences» в интерфейсе Alertmanager, или
  `amtool silence add alertname=… --duration=2h`.

**Чего в наблюдаемости пока нет:** метрик диска сервера. Место видно по MinIO: в S1
тома всех служб обычно лежат на одном диске.

В кластере S2 те же правила оповещений ставит чарт (`PrometheusRule`,
`observability.prometheusRule.enabled`), а экран «Здоровье системы» читает Prometheus
и Alertmanager кластера по `observability.prometheusUrl` и
`observability.alertmanagerUrl` — `infra/helm/README.md`.

Бюджеты отклика проверяются профилем k6: `bash infra/perf/run-k6.sh` на стенде с
демо-данными.

## Переменные окружения

Источник истины — схема конфигурации `api`; что попадает в контейнеры — блок
`x-app-env` в `infra/compose/docker-compose.yml`; образец — `.env.example`.

### Обязательные

`DATABASE_URL`, `REDIS_URL`, `S3_ENDPOINT`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`,
`MEILI_HOST`, `MEILI_MASTER_KEY`. В производственном режиме обязателен ещё
`DATABASE_QUERY_URL` — под этой ролью выполняются запросы к данным.

### Адреса и режим

`NODE_ENV`, `ROLE` (`api` / `worker` / `all`), `PORT`, `HOST`, `TRUST_PROXY`,
`LOG_LEVEL`, `TZ` (по умолчанию `Asia/Dushanbe`), `KCHS_BASE_URL`,
`KCHS_API_URL`, `WEB_PORT`, `WEB_HTTPS_PORT`, `KCHS_BIND`, `KCHS_DOMAIN`,
`CADDY_EMAIL`, `KCHS_IMAGE_TAG`, `KCHS_ADMIN_LOGIN`, `KCHS_ADMIN_EMAIL`.

### Хранилище

`S3_PUBLIC_ENDPOINT` и `KCHS_STORAGE_ORIGIN` — адрес хранилища, видимый браузеру;
бакеты `S3_BUCKET_FILES`, `S3_BUCKET_PREVIEWS`, `S3_BUCKET_MEDIA`,
`S3_BUCKET_EXPORTS`, `S3_BUCKET_TILES`, `S3_BUCKET_BACKUPS`,
`S3_BUCKET_COLUMNAR`; `BASEMAPS_PREFIX`, `S3_FORCE_PATH_STYLE`, `S3_REGION`.

### Безопасность и лимиты

`KCHS_MASTER_KEY` (шифрование секретов интеграций и TOTP), `KCHS_MASTER_KEY_PREVIOUS`
(прежний ключ на время смены, потом убрать), `SESSION_COOKIE_NAME`,
`SESSION_IDLE_HOURS`, `SESSION_ABSOLUTE_DAYS`, `INTERNAL_SERVICE_TOKEN`,
`RATE_LIMIT_PER_MINUTE`, `LOGIN_RATE_LIMIT_PER_IP_PER_MINUTE`,
`API_TOKEN_RATE_LIMIT_PER_MINUTE`, `WEBHOOKS_ALLOW_PRIVATE_ADDRESSES`,
`WEBHOOK_RETRY_WINDOW_HOURS`, `EXTERNAL_DB_TIMEOUT_MS` (потолок запроса к внешней
базе при предпросмотре и проверке, по умолчанию 30 000 мс; загрузка в задании —
до 10 минут).

### Почта, Telegram, движок

`SMTP_URL`, `SMTP_FROM`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_API_URL`,
`TELEGRAM_POLLING`, `ENGINE_INTERNAL_URL`, `ENGINE_API_URL`, `ENGINE_WEB_URL`.

### Интеллектуальные функции

`AI_PROVIDER` (пусто — функции скрыты; `anthropic` или `openai-compat`),
`AI_MODEL`, `ANTHROPIC_API_KEY`, `ANTHROPIC_BASE_URL`, `OPENAI_COMPAT_URL`,
`OPENAI_COMPAT_API_KEY`, `AI_DAILY_REQUESTS` (50), `AI_DAILY_TOKENS` (300 000),
`AI_TIMEOUT_MS`, `AI_DOCUMENTS_MAX_CONFIDENTIALITY` (по умолчанию «Для служебного
пользования»). Сервер проверяет связку на старте: `anthropic` без ключа или
`openai-compat` без адреса и модели не запустится.

У движка: `ENGINE_EMBEDDING_MODEL` — модель векторов для смыслового поиска и
раздела «Похожие» (пусто — поиск остаётся словесным); `ENGINE_TRANSCRIBE_MODEL` —
модель распознавания речи для расшифровки встреч (пусто — расшифровка выключена),
плюс `ENGINE_TRANSCRIBE_DEVICE`, `_COMPUTE`, `_LANGUAGE`, `_TIMEOUT_S`.

### Встречи, офисный редактор, push, календарь

`LIVEKIT_URL`, `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`, `LIVEKIT_NODE_IP`,
`KCHS_MEDIA_ORIGIN`, `S3_EGRESS_ENDPOINT`, `LIVEKIT_WEBHOOK_URL`;
`ONLYOFFICE_URL`, `ONLYOFFICE_INTERNAL_URL`, `ONLYOFFICE_CALLBACK_URL`,
`ONLYOFFICE_JWT_SECRET`; `PUSH_VAPID_PUBLIC_KEY`, `PUSH_VAPID_PRIVATE_KEY`,
`PUSH_CONTACT`; `CALENDAR_FEEDS_ALLOW_PRIVATE`.

### Наблюдаемость

`METRICS_PORT`, `METRICS_HOST`, `OTEL_EXPORTER_OTLP_ENDPOINT`,
`OTEL_EXPORTER_OTLP_ENDPOINT_INTERNAL`, `OTEL_TRACES_SAMPLER`,
`OTEL_TRACES_SAMPLER_ARG`, `GRAFANA_PORT`, `GRAFANA_ADMIN_PASSWORD`,
`OTLP_HTTP_PORT`, `KCHS_MONITOR_PASSWORD`, `ALERTMANAGER_PORT`,
`ALERTMANAGER_EMAIL_TO`, `ALERTMANAGER_SMTP_URL`, `ALERTMANAGER_SMTP_FROM`,
`ALERTMANAGER_SMTP_REQUIRE_TLS`, `ALERTMANAGER_TELEGRAM_CHAT_ID`,
`ALERTMANAGER_TELEGRAM_BOT_TOKEN`, `ALERTMANAGER_TELEGRAM_API_URL`,
`ALERTMANAGER_INSTALLATION`, `ALERTMANAGER_EXTERNAL_URL`.

### Демонстрационные данные (только стенд)

`SEED_ADMIN_LOGIN`, `SEED_ADMIN_PASSWORD`, `SEED_USER_PASSWORD` — читаются
командой `kchs seed`. В `.env.example` их нет; при отсутствии применяются
значения по умолчанию, поэтому на любом доступном извне контуре демо-данные
загружать нельзя.

## Включение интеллектуальных функций «под ключ»

1. В `.env`: `AI_PROVIDER` и ключ или адрес модели; при необходимости поправьте
   `AI_DAILY_REQUESTS`, `AI_DAILY_TOKENS`, `AI_DOCUMENTS_MAX_CONFIDENTIALITY`.
2. Для смыслового поиска задайте `ENGINE_EMBEDDING_MODEL` **в окружении
   контейнера движка** и поднимите движок:
   `docker compose up -d --wait engine`.
3. Перезапустите `api` и `worker`.
4. Проверьте: **«Возможности»** → **«Интеллектуальные функции»** включена; роль
   сотрудника содержит способность «ИИ-ассистент».
5. Откройте любой объект → вкладка **«Ассистент»**: вместо «Ассистент выключен»
   должны появиться подсказка и поле вопроса. У датасета — «Спросить данные» со
   счётчиком вопросов.
6. Смысловой поиск: откройте объект с длинным текстом, подождите индексацию и
   проверьте раздел **«Похожие»** во вкладке «Инфо».

Если модель векторов не отвечает, поиск молча остаётся словесным — установка от
этого не ломается.

## Чего в консоли нет

- Экрана очередей с повтором и отменой заданий (их счётчики видны в «Здоровье
  системы»).
- Размеров базы и хранилища, лицензий и лимитов.
- Шаблонов писем, правил уведомлений по умолчанию и тестовой отправки.
- Очистки корзины и пересчёта кэшей по требованию (идут по расписанию).
- Раздела наблюдаемости: Grafana и Alertmanager открываются отдельно.

## Частые вопросы

**Поиск отстаёт, уведомления не приходят.** Почти всегда это остановленный
`worker` или зависшие подписчики: посмотрите «Неопубликованных событий» в
«Здоровье системы» и журналы `worker`.

**Объекты не находятся поиском.** Проверьте `meilisearch` в «Здоровье системы» и
нажмите **«Переиндексировать поиск»**.

**Расшифровка встреч не работает.** Не задана модель распознавания речи
(`ENGINE_TRANSCRIBE_MODEL`) — интерфейс честно пишет «Модель распознавания речи
не настроена в этой установке».

**Где посмотреть медленные запросы?** В Grafana, дашборд «kchs — обзор»: p95 по
маршрутам с линией бюджета. Бюджеты проверяются профилем k6.
