# Рабочая установка: пилот на одном сервере

Рабочая установка — это «Портал КЧС» с настоящими данными Комитета на одном сервере (VPS).
Её ставит и обновляет скрипт `infra/scripts/pilot.sh` (ADR-0227). Он никогда не стирает
данные и не загружает демо-мир. Стенд показа (`demo-stand.sh`, [30](30-demo-stand.md)) —
другая вещь: его сбрасывают перед каждым показом, у него общие учётки, и рабочие данные на
него не заносят. На рабочей установке `demo-stand.sh` отказывается что-либо делать.

## Что понадобится

**Сервер** — Ubuntu 24.04 на одном из двух профилей. Профиль задаёт пределы памяти и
процессора служб, чтобы одна тяжёлая служба не уронила остальные.

| Профиль | Процессор | Память | Диск | Что работает |
|---|---|---|---|---|
| `16` | 4 vCPU | 16 ГБ | 150 ГБ SSD | портал, движок (два задания разом), поиск; редактор документов — по желанию |
| `32` | 8 vCPU | 32 ГБ | 200 ГБ SSD | всё, включая редактор документов и наблюдаемость, движок — четыре задания разом |

Сервер ещё не выбран — берите `32`, если бюджет позволяет: импорт больших таблиц и
печать отчётов идут заметно быстрее. Профиль можно сменить позже одной командой.

На обоих профилях заведите своп-файл 4–8 ГБ: он не даёт системе убить службу при
кратком пике памяти.

```bash
sudo fallocate -l 8G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile
sudo swapon /swapfile && echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
```

**Два имени в DNS**, обе записи A — на адрес сервера:

- имя портала, например `portal.kchs.tj`;
- имя хранилища файлов: `files.` перед именем портала, например `files.portal.kchs.tj`.

Файлы, превью и фото донесений браузер берёт из хранилища напрямую, по своему имени и порту
443. Прокси Комитета обычно пускает HTTPS только на порт 443 — поэтому у хранилища своё имя,
а не свой порт.

**Открытые порты:** 80 и 443. Больше ничего наружу не нужно: базы, очереди и движок
слушают только сам сервер.

**Docker:** `curl -fsSL https://get.docker.com | sh`.

**Telegram для оповещений** (по желанию, но очень советую): бот платформы
(`TELEGRAM_BOT_TOKEN`, [29](29-admin-emergency-pack.md)) и номер чата, куда писать о
сбоях, — личного чата администратора или группы дежурных ИТ. Номер чата — у бота
@userinfobot или в адресе группы в веб-версии Telegram.

## Установка

```bash
git clone https://github.com/aminjon1065/kchs.git && cd kchs
sudo bash infra/scripts/pilot.sh install --domain portal.kchs.tj --email it@kchs.tj \
  --profile 32 --telegram-chat <номер чата>
```

Ключи:

- `--domain` — имя портала; `--storage-domain` — имя хранилища, если не `files.<портал>`;
- `--email` — почта администратора: на неё выпускаются сертификаты HTTPS и заводится первая
  учётная запись;
- `--profile 16|32` — профиль сервера (по умолчанию `16`);
- `--telegram-chat` — куда сторож пишет о сбоях;
- `--office` — поднять ещё сервер документов (совместная правка Word и Excel);
- `--basemap <каталог>` — подложка карты района, собранная `infra/basemaps/build-pmtiles.sh`.

Что делает скрипт:

1. Создаёт `.env` со случайными паролями и ключами (права 600).
2. Собирает образы (10–20 минут в первый раз) и запускает службы.
3. Заводит администратора `admin` и печатает **временный пароль — один раз**. Запишите его.
   При первом входе система попросит свой пароль и второй фактор.
4. Один раз, в пустую базу, ставит справочники: территории с границами, базовые карты и
   предметный пакет ЧС. Демо-сотрудников и демо-документов нет.
5. Ставит сторожа — таймер systemd, который каждые 5 минут проверяет сервер.

**Сразу после установки:**

- Сохраните копию `.env` **вне сервера** — на флешку или в сейф ИТ, в двух экземплярах. В
  нём мастер-ключ: без него не расшифровать второй фактор сотрудников, секреты интеграций и
  ключи удостоверяющего центра Комитета. Потеря `.env` при потере сервера — это потеря
  подписей и новый УЦ.
- Настройте резервные копии: [27](27-admin-backup.md).
- Историю ЧС Комитета загружает `pilot.sh history <каталог>` ([29](29-admin-emergency-pack.md)).

## Обновление

```bash
cd kchs && git pull
sudo bash infra/scripts/pilot.sh update
```

Порядок: свежая резервная копия (без неё обновление не начнётся), новые секреты к прежним
(старые не меняются), сборка, перезапуск. Миграции базы `api` применяет сам при старте.
Затем проверка `/health` и уборка кэша сборки старше недели. Данные остаются на месте.

Без скрипта копий обновление отказывается работать. Ключ `--skip-backup` его обходит, но
пользоваться им можно, только если копия только что сделана вручную.

Закрытый контур без интернета: образы собираются на машине с интернетом
(`docker save kchs/api kchs/web kchs/engine kchs/postgres …`), переносятся и загружаются
`docker load`. Затем `pilot.sh install|update --no-build`.

## Каждый день

```bash
bash infra/scripts/pilot.sh status    # службы, последняя копия, диск, сторож
bash infra/scripts/pilot.sh logs api  # последние строки журнала службы
bash infra/scripts/pilot.sh profile 32   # перейти на другой профиль (после смены сервера)
```

## Сторож и оповещения

Сторож проверяет раз в 5 минут и пишет в Telegram. Одно и то же сообщение приходит не чаще
раза в час. Когда беда прошла, приходит «снова в порядке».

| Сообщение | Что делать |
|---|---|
| **диск … занят на N %** | Освободить место: старые выгрузки и журналы. `docker system df` покажет, что занимает Docker. Перед заполнением диска база останавливается — не доводите до 100 %. |
| **служба … не отвечала на проверку здоровья — перезапущена** | Сторож уже перезапустил службу. Если повторяется — `pilot.sh logs <служба>` и обратиться к разработчику. |
| **служба … падает и перезапускается по кругу** | `pilot.sh logs <служба>`; частая причина — нехватка памяти: перейти на профиль 32 или сервер побольше. |
| **служба … остановлена** | `pilot.sh update --skip-backup --no-build` поднимет службы. |
| **последняя удачная копия — N ч назад** или **копий ещё не было** | Копия не сделана: см. [27](27-admin-backup.md). Без свежей копии не обновляйтесь. |
| **api не отвечает на /health** | Портал недоступен: `pilot.sh status`, `pilot.sh logs api`. |

Порог диска — `KCHS_WATCHDOG_DISK_PCT` в `.env` (85 %), возраст копии —
`KCHS_WATCHDOG_BACKUP_HOURS` (26 ч). Журнал сторожа — `journalctl -u kchs-watchdog`.
Пробный прогон без отправки — `bash infra/scripts/watchdog.sh --dry-run`.

## Частые вопросы

**Портал открывается, а файлы и превью — нет.** Нет DNS-записи имени хранилища
(`files.<портал>`), или она указывает не на сервер. Проверка: `nslookup files.portal.kchs.tj`.

**Сертификат HTTPS не выпустился.** Порты 80 и 443 должны быть открыты из интернета, а DNS —
указывать на сервер до установки. `pilot.sh logs web` покажет ответ Let's Encrypt.

**Можно ли поставить рабочую установку на ноутбук рядом со стендом показа?** Нет: рабочей
установке нужен сервер с постоянным адресом и резервными копиями.

**Забыли пароль администратора.** Если есть второй администратор — он задаёт временный
пароль в консоли. Если нет — к разработчику: стирать установку ради нового пароля нельзя.

## Чего пока нет

- Встреч с видео и записью: медиасервер (профиль `media`) скрипт не поднимает.
- Почты на домене Комитета: [31](31-admin-mail.md).
- Распределённой установки на несколько серверов: это Kubernetes-чарт (S2, ADR-0118).
