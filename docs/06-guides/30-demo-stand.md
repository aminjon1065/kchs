# Стенд демонстрации

Стенд для показа «Портала КЧС» Комитету — на ноутбуке или арендованном VPS. Ставится одной
командой, работает на демо-данных: оргструктура Комитета, документы, поручения, предметный
пакет ЧС с лентами опасных явлений. Перед каждым показом стенд сбрасывается к исходному
состоянию. Рабочие данные на стенд не заносите: у демо-мира общие учётные записи для показа.

## Что понадобится

**Ноутбук** — macOS, Windows или Linux:
- Docker Desktop (или Docker Engine) 27+ с Compose v2;
- Docker должно быть выделено не меньше 8 ГБ памяти (машина с 16 ГБ): **Docker Desktop →
  Settings → Resources → Memory**;
- 30 ГБ свободного места;
- интернет — для первой сборки образов и для лент опасных явлений. Всё остальное работает без
  сети.

**VPS** — Ubuntu 24.04:
- 4 vCPU, 16 ГБ RAM, 80 ГБ SSD;
- доменное имя с записью A на адрес сервера, например `demo.example.org`;
- открытые порты 80, 443 и 9443 (9443 — файлы: браузер получает и загружает их напрямую из
  хранилища);
- Docker: `curl -fsSL https://get.docker.com | sh`, затем `sudo usermod -aG docker $USER` и
  перезайти.

## Установка

Ноутбук:

```bash
git clone https://github.com/aminjon1065/kchs.git && cd kchs
bash infra/scripts/demo-stand.sh up
```

VPS:

```bash
git clone https://github.com/aminjon1065/kchs.git && cd kchs
bash infra/scripts/demo-stand.sh up --domain demo.example.org --email you@example.org
```

Скрипт сделает всё сам:

1. Создаст `.env` со случайными секретами и своим паролем демо-сотрудников.
2. Соберёт образы: первый раз — 5–15 минут, дальше — из кэша.
3. Поднимет службы и заведёт первого администратора (`kchs init`).
4. Загрузит демо-данные с пакетом ЧС (`kchs seed --data small`) — 3–6 минут.
5. Загрузит подложку карты, если она собрана.

В конце скрипт напечатает адрес стенда и **временный пароль администратора — один раз**, сразу
после `kchs init`. Запишите его.

Адрес:
- на ноутбуке — `http://localhost:8080`; порт меняется так: `WEB_PORT=8081 bash
  infra/scripts/demo-stand.sh up`;
- на VPS — `https://demo.example.org`; сертификат Let's Encrypt Caddy получит сам в первые
  минуты.

### Подложка карты

Без подложки карты открываются на пустом фоне. Её собирают один раз на машине с интернетом:
нужен только Docker, около 6 минут и 620 МБ загрузок.

```bash
KCHS_BASEMAP_UPLOAD=0 bash infra/basemaps/build-pmtiles.sh
```

Результат ляжет в `seeds/.cache/basemaps/out`. Скрипт стенда найдёт его сам при `up` и
`reset`. На VPS подложку проще собрать прямо на сервере. Другой каталог указывается так:
`--basemap <каталог>`.

## Перед показом

- **Накануне сбросьте стенд:** `bash infra/scripts/demo-stand.sh reset`, 5–8 минут. Данные
  загрузятся заново, сроки поручений и сводки отсчитаются от дня показа. Окружение, пароли и
  сертификат при сбросе сохраняются.
- **Ленты** (USGS, EMSC, GDACS, FIRMS) подтянутся в первые 5–15 минут после сброса, если есть
  интернет. Без интернета ленты стоят, остальное работает.
- **Проверьте:**
  - вход администратора;
  - ситуационный экран (пространство «Оперативный штаб ЧС» → «Ситуационный экран»);
  - карту «Обстановка ЧС» с подложкой;
  - что во «Входящих» дежурного (`user010`) есть дела.
- **Большой экран:** на ситуационном экране кнопка **«TV»** — полноэкранный режим с
  автообновлением.
- Проверить стенд целиком: `bash infra/scripts/demo-stand.sh status`.

## Сценарий показа (30–40 минут)

Каждый шаг — под указанным сотрудником: удобно держать несколько окон браузера или окна
в режиме инкогнито.

1. **Вход и «Мой день»** (`user010`, дежурная смена).
   - Приветствие, счётчики «Входящие» и «Просрочено», дела на сегодня: приём-передача
     дежурства, приглашение на заседание штаба, резолюции.
   - Переключите язык в профиле на **«Тоҷикӣ»**, затем обратно.
2. **Ситуационный экран** (`user010`).
   - Происшествия, пострадавшие и погибшие за сегодня со сравнением со вчерашним днём.
   - Карта обстановки, происшествия за трое суток, дежурная смена, сводки по регионам.
   - Кнопка **«TV»** — режим для большого экрана.
3. **Карта «Обстановка ЧС»** (`user024`).
   - Слои: сообщения об опасных явлениях, происшествия, гидропосты, пункты временного
     размещения, защитные объекты.
   - Щелчок по объекту — его карточка. **«Хороплет»** — районы по показателю.
4. **Ленты опасных явлений** (`user010`).
   - Свежее землетрясение из USGS или EMSC приходит уведомлением дежурной смене, с районом
     и магнитудой.
   - Предупреждений населению система не выпускает.
5. **Суточная сводка региона** (`user038`, затем `user010`).
   - Специалист области открывает дело «Заполнить сводку» во «Входящих» и сдаёт итоги
     цифрами со списком происшествий.
   - Дежурный принимает сводку, цифры попадают в «За сутки по регионам».
6. **Документооборот** (`user031`, `user010`, исполнитель). Порядок действий на экранах —
   руководство [06](06-user-documents.md).
   1. Делопроизводитель регистрирует входящее письмо: номер вида «подразделение-дело/номер»
      виден до регистрации, дело номенклатуры подбирается само.
   2. Руководитель накладывает резолюцию (у `user010` во «Входящих» уже лежат дела
      «Резолюция по документу»), исполнитель получает поручение.
   3. Исполнитель готовит ответ («Ответить»), канцелярия регистрирует и отправляет его.
   4. У исполнителя в карточке поручения появляется **«Готовый отчёт»** — отправляется одной
      кнопкой.
   5. Автор резолюции принимает отчёт. Документ подшивается в дело.
7. **Поручения и контроль** (`user003`).
   - Экран контроля: просроченные и продлённые поручения, эскалации руководителю.
8. **Заседание штаба** (`user001`). Подробно — руководство [08](08-user-calendar-meetings.md).
   - Приглашение на заседание штаба уже во «Входящих» у членов штаба.
   - Встреча с повесткой, секретарь ведёт протокол.
   - Печатная форма протокола становится документом, поручения протокола — задачами.
9. **Данные и аналитика** (`user002`).
   - Датасеты пакета ЧС, дашборды, показатели с периодами «Сегодня» и «Последние 14 дней».
10. **База знаний** (любой сотрудник).
    - Регламенты штаба ЧС.
    - Пункт **«Справка»** на рейке — руководство на языке сотрудника.
11. **Администрирование** (`admin`, `user033`, `user037`).
    - Оргструктура, группы («Дежурная смена»), должности, перевод сотрудника.
    - Консоль у `user033` показывает только его разделы.
    - Журнал аудита у `user037`.

## Команды

```bash
bash infra/scripts/demo-stand.sh status          # адрес, учётки, состояние служб
bash infra/scripts/demo-stand.sh reset           # данные заново (накануне показа)
bash infra/scripts/demo-stand.sh logs api        # последние строки журналов службы
bash infra/scripts/demo-stand.sh kchs help       # команда kchs в контейнере api
bash infra/scripts/demo-stand.sh down            # остановить; данные остаются
bash infra/scripts/demo-stand.sh down --volumes --yes   # остановить и стереть всё
```

Обновить стенд до новой версии: `git pull`, затем `bash infra/scripts/demo-stand.sh reset
--build`. Без `--build` сброс берёт уже собранные образы.

## Частые вопросы

**Скрипт пишет «окружение стенда разработки».** В этой копии репозитория уже есть `.env`
для разработки. Стенд демонстрации ставьте в отдельной копии или укажите другой файл:
`KCHS_DEMO_ENV_FILE=~/demo.env bash infra/scripts/demo-stand.sh up`.

**Порт 8080 занят.** `WEB_PORT=8081 bash infra/scripts/demo-stand.sh up` — порт запомнится в
`.env`.

**На VPS страницы открываются, а файлы — нет.** Закрыт порт 9443: файлы браузер получает и
загружает напрямую из хранилища.

**Сколько раз можно сбрасывать стенд на VPS?** Сколько угодно: сертификат при сбросе
сохраняется. `down --volumes` стирает и его, а Let's Encrypt выдаёт не больше пяти
одинаковых сертификатов в неделю.

**Забыли временный пароль администратора.** Сбросьте стенд (`reset`) — администратор
заведётся заново с новым временным паролем.

## Чего пока нет

- Встреч с видео и записью: медиасервер (профиль `media`) скрипт не поднимает.
- Офисного редактора: сервер документов (профиль `office`) — отдельно,
  [20](20-admin-install.md).
- Почтового сервера: ответы и отправка писем уходят в mailpit стенда.
