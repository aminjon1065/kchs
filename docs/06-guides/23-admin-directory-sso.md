# Каталог LDAP и единый вход

## Каталог (LDAP/AD)

**«Администрирование» → «Каталог (LDAP/AD)»**. «Синхронизация сотрудников и
подразделений из LDAP или Active Directory и вход по паролю каталога. У записи
каталога локального пароля нет».

### Настройка подключения

Карточка **«Подключение к каталогу»**:

- **«Каталог подключён»** — «Пока выключено, синхронизация не идёт и вход по
  паролю каталога не работает»;
- **«Адрес каталога»** — «ldap:// или ldaps://; для ldaps:// проверяется
  сертификат сервера»;
- **«Учётная запись чтения (DN)»** и **«Пароль учётной записи чтения»**
  («Пустое значение — анонимное чтение каталога»). Сохранённый пароль наружу не
  отдаётся: при повторном открытии подсказка меняется на «Пароль задан. Пустое
  поле оставит прежний»;
- **«Корень поиска сотрудников»** и **«Фильтр сотрудников»** («Например,
  `(&(objectClass=user)(objectCategory=person))`»);
- **«Корень поиска подразделений»** — «Пусто — оргструктура не
  синхронизируется»;
- флажки **«Поднимать TLS на обычном соединении (StartTLS)»**, **«Проверять
  сертификат сервера»**, **«Разрешить вход по паролю каталога»**.

Карточка **«Соответствие полей»** — какие атрибуты записи каталога отвечают полям
карточки сотрудника: «Логин», «Почта», «Фамилия», «Имя», «Отчество»,
«Отображаемое имя», «Телефон», «Устойчивый идентификатор», «Признак отключения»,
«Подразделение», «Должность», «Группы».

Карточка **«Группы каталога и роли»**: «Сотрудник получает роли по группам
каталога. Не попавший ни в одно правило получает роли по умолчанию». Правила —
пары **«Группа каталога»** → **«Роль»**, добавляются кнопкой **«Добавить
правило»**.

Ниже: **«Если сотрудника нет в каталоге»** — **«Заблокировать учётную запись»**
или «Ничего не делать» («Уволенный в каталоге сотрудник теряет доступ при
следующей синхронизации»), и **«Интервал синхронизации, мин»** — «Не чаще раза в
15 минут; расписание проверяется каждый час».

### Порядок подключения

1. Включите **«Каталог подключён»**, заполните адрес, DN и пароль чтения, корень
   поиска → **«Сохранить»**. Сервер не даст включить каталог без адреса и корня
   поиска.
2. **«Проверить соединение»** — «Соединение установлено: сотрудников {N},
   подразделений {M}. Например: …» или «Соединение не установлено: {ошибка}».
3. **«Предпросмотр»** — покажет план **«Что изменится»**, ничего не записывая.
   Счётчики: прочитано, создано, изменено, заблокировано, подразделений, ошибок;
   у каждой строки — действие «создать», «изменить», «заблокировать»,
   «разблокировать», «пропустить».
4. Изучите план и нажмите **«Синхронизировать сейчас»** — «Синхронизация
   завершена: создано {N}, изменено {M}, заблокировано {K}».
5. Дальше синхронизация идёт по расписанию.

Карточка **«Журнал синхронизаций»** хранит разбор каждого прогона: статус
(«идёт», «успешно», «ошибка»), режим («предпросмотр», «вручную», «по
расписанию») и сводку «создано … · изменено … · заблокировано … · ошибок …».

### Что нужно знать

- Локальная учётная запись с тем же логином каталогу не отдаётся.
- Вход по паролю каталога выполняет привязку (bind) в том же механизме входа:
  блокировка после серии неудач, аудит и политика сессий действуют так же.
- Синхронизация **не переносит руководителей подразделений и территории** — поля
  «Руководитель» и «Территория» остаются за администратором оргструктуры.
- Поля **«роли по умолчанию»** в форме нет, хотя подсказка о нём есть: значение
  задаётся только запросом к API (по умолчанию — базовая роль сотрудника).

## Единый вход (OIDC)

**«Администрирование» → «Единый вход»**. «Вход через OpenID Connect: Keycloak,
ADFS, Entra ID. Обмен идёт по схеме Authorization Code с PKCE».

Карточка **«Корпоративный поставщик входа»**:

- **«Единый вход включён»** — «Пока выключено, кнопка на экране входа не
  показывается»;
- **«Адрес издателя»** — «По нему читается `/.well-known/openid-configuration`»;
- **«Идентификатор клиента»**;
- **«Секрет клиента»** — «Пусто — публичный клиент, только PKCE»; сохранённый
  наружу не отдаётся;
- **«Запрашиваемые области»**;
- **«Подпись кнопки на экране входа»** — «Например, „Войти через корпоративную
  учётную запись“»;
- **«Адрес возврата»** — только для чтения, считается сервером: «Пропишите его в
  настройке клиента у провайдера»;
- флажки **«Заводить сотрудника при первом входе»**, **«Завершать сессию
  провайдера при выходе»**, **«Разрешить издателя по http (только внутренний
  стенд)»**.

Карточка **«Соответствие claims»** — какие поля токена отвечают полям карточки
сотрудника, плюс **«Группы»**.

Карточка **«Группы провайдера и роли»** — правила «группа провайдера → роль»
платформы.

Кнопка **«Проверить соединение»** читает конфигурацию провайдера и показывает
адреса авторизации, токенов и завершения сессии.

### Порядок подключения

1. Заведите клиент у провайдера; адрес возврата возьмите из поля **«Адрес
   возврата»**.
2. Заполните издателя, идентификатор и при необходимости секрет клиента.
3. **«Проверить соединение»**.
4. Настройте соответствие claims и правила групп.
5. Включите **«Единый вход включён»** и **«Сохранить»** — на экране входа
   появится кнопка с вашей подписью.

## Ключи входа (passkeys)

Отдельного раздела в консоли нет: ключи заводит и отзывает **сам сотрудник** в
своём профиле, раздел **«Ключи входа»**. Администратор чужие ключи не видит и не
отзывает.

Кнопка **«Войти по ключу»** появляется на экране входа только тогда, когда в
установке зарегистрирован хотя бы один ключ. Ключ с подтверждением личности
входит сам и засчитывается как второй фактор; ключ без подтверждения годится
только вторым фактором.

## Открытые вопросы

- Нужно согласовать с заказчиком каталога, какой атрибут считать признаком
  отключения и какой — устойчивым идентификатором записи.
- Применяется ли требование второго фактора платформы ко входу через внешнего
  поставщика.
- Кто восстанавливает доступ сотруднику каталога или поставщика, потерявшему
  устройство: у такой учётной записи нет локального пароля.

Эти вопросы записаны в `docs/04-delivery/05-risks-and-open-questions.md`.

## Частые вопросы

**Синхронизация заблокировала не тех.** Всегда начинайте с **«Предпросмотр»** —
он строит тот же план, но ничего не пишет. Если план не тот, поправьте фильтр
сотрудников и корни поиска.

**После включения единого входа пароль перестал работать?** Нет: поле логина и
пароля остаётся всегда, отключить вход по паролю в продукте нельзя.

**Сотрудник вошёл через провайдера, но у него нет прав.** Проверьте правила
«Группы провайдера и роли»: не попавший ни в одно правило получает роли по
умолчанию.
