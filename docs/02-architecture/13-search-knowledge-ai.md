# Поиск, база знаний и интеллектуальные функции

Статус: **Решено** — единый индекс и палитра команд, ИИ через сменяемого провайдера с прозрачностью; **Рекомендовано** — детали базы знаний и RAG.

## 1. Единый поиск

- **Индекс** (Meilisearch): документы `object` (все типы, с `aclPrincipals`), `file_text` (чанки текста файлов), `message`, `row` (опционально — строки датасетов с семантикой `text`/`identifier`, по настройке датасета «искать строки глобально»), `page_chunk`.
- **Палитра команд** (`Cmd/Ctrl+K`): мгновенный поиск объектов (с превью, типом, пространством, «где был недавно» выше), команды («Создать документ», «Открыть карту…», «Перейти в Настройки», «Сменить тему»), навигация по модулям, недавние и избранное, префиксы (`>` команды, `#` теги, `@` люди, `/` типы: `/док паводок`), клавиатура целиком. Действия над результатом: открыть, открыть в разделении, скопировать ссылку, поделиться.
- **Страница поиска**: фасеты (тип, пространство, владелец, даты, теги, статус, территория), сортировка (релевантность/дата), сниппеты с подсветкой, поиск внутри файлов и сообщений, сохранение поискового запроса как представления.
- **Семантика** (`pgvector`, модель `bge-m3` в engine): гибридная выдача (BM25 + вектор) для страниц, документов, сообщений; «похожие объекты» в контекстной панели. База знаний подключает её портом (`modules/knowledge/domain/semantic-port.ts`, ADR-0095) и мягко деградирует: источника нет — выдача словесная.
- Реализовано (ADR-0095): `page_chunk` — отдельный индекс кусков страниц (кусок по абзацам блока, идентификатор `<pageId>_<blockId>_<n>`, права фильтром `aclPrincipals` плюс пост-проверка `authorize`); `file_text` отдельным индексом не делается — текст файла лежит в поле `body` документа объекта.
- Права: фильтр по принципалам в индексе + пост-проверка `authorize` для конфиденциальных типов; результаты никогда не раскрывают названия объектов без `view`.
- Русская/таджикская морфология: Meilisearch токенизирует кириллицу; для таджикского добавляются словарь синонимов/стоп-слов и нормализация (`ӣ→и`, `ӯ→у` как варианты) в конвейере индексации.

## 2. База знаний

- Страницы ★ в пространствах: дерево, совместное редактирование (Yjs), блоки (текст, таблицы, изображения, файлы, встроенные объекты: график, карта, датасет-таблица, показатель, задача-список), шаблоны (инструкция, регламент, справочник, FAQ, протокол, отчёт), версии с diff, статусы (черновик/опубликовано/на пересмотре), владельцы и срок пересмотра (напоминание), ознакомление под подпись, комментарии к фрагментам (обсуждение с якорем), теги, оглавление, печать/PDF.
- Разделы по умолчанию: «Регламенты и инструкции», «Справочники», «Обучение», «Часто задаваемые вопросы».
- Реализовано (ADR-0095): страница — объект реестра `page` в дереве пространства, тело — совместный документ Yjs на том же ядре блочных документов, что тетрадь (ADR-0071) и протокол (ADR-0093). Блок-ссылка на объект хранит только его идентификатор; список задач — открытые задачи проекта. Версии — снимки блоков (публикация, кнопка, перед откатом), сравнение по словам общим алгоритмом (`shared/text-diff.ts`), откат через совместный документ. Срок пересмотра ведёт задание `knowledge.review` (дело Входящих `review_page` владельцу страницы; владелец страницы — своё поле, отдельное от владельца объекта). Ознакомление — механизм ядра (ADR-0084), комментарии к фрагментам — обсуждение ядра с якорем на блок, печать — печатная форма реестра (ADR-0085; встроенные объекты в PDF заменяются ссылкой). Разделы по умолчанию — корневые страницы пространства «Общее» из сида.
- ИИ-ответы по базе знаний и документам: RAG с цитатами (ссылки на страницы/документы), только по доступным пользователю материалам; режим «Спросить» в палитре.

## 3. Интеллектуальные функции: принципы

1. **Сменяемый провайдер** (`modules/ai/providers`): Anthropic Claude (облако; модели: `claude-sonnet-5` для качества, `claude-haiku-4-5` для массовых дешёвых задач) или on-prem через OpenAI-совместимый эндпоинт (vLLM/Ollama). Эмбеддинги — локально (`bge-m3`), расшифровка — локально (`faster-whisper`), OCR — локально (tesseract). Выбор — настройка администратора с политикой «какие данные можно отправлять во внешний провайдер» (по грифу/пространству).
2. **Прозрачность**: сгенерированный запрос/график/текст показывается и редактируется; ничего не выполняется «втихую».
3. **Права**: ассистент работает от имени пользователя, инструменты ассистента вызывают те же API с тем же `authorize`.
4. **Аудит**: промпты/ответы логируются (с маскированием по политике), лимиты по пользователю.
5. **Человек подтверждает**: создание объектов и действий — только после подтверждения в UI (кроме автоматизаций, явно настроенных администратором).

## 4. Где ИИ действительно помогает

| Место | Функция |
|---|---|
| Регистрация документа | извлечение реквизитов из скана (корреспондент, номер, дата, суть, адресат), предложение типа и маршрута |
| Документ | краткое содержание, черновик ответа по шаблону, проверка полноты карточки, перевод ru↔tg↔en |
| Данные | «спросить данные» → QuerySpec; семантика полей при импорте; объяснение графика/аномалии; описание датасета; предложения визуализации; нарратив отчёта |
| Карта | «покажи объекты в радиусе 5 км от …», подбор стиля |
| Встречи | расшифровка, резюме, решения и поручения, перевод |
| Чаты | резюме треда, черновик ответа, перевод |
| Поиск | ответы с цитатами по базе знаний и документам |
| Задачи | разбиение на подзадачи, оценка сроков по истории, черновик отчёта об исполнении |
| Администрирование | объяснение аудита, подозрительная активность (фаза 5) |

## 5. Ассистент в контекстной панели

Вкладка «Ассистент» знает текущий объект (тип, поля, доступные действия), предлагает уместные действия (для документа — «резюме», «черновик ответа»; для датасета — «опиши», «спроси»), поддерживает диалог с историей на объект, инструменты: `search`, `query_dataset`, `get_object`, `create_task (draft)`, `create_document (draft)`, `summarize_file`, `translate`. Ответы с ссылками-чипами на объекты.

Реализовано для документов (ADR-0088): вкладка «Ассистент» контекстной панели — у объектов, чьё представление даёт `assistantSection`; для документа — краткое содержание (вставить в карточку) и черновик ответа на входящее по указаниям исполнителя. Текст документа уходит модели только при грифе не строже порога установки; в аудит — функция и объём, без текста.

## 6. Реализация

`modules/ai`: сервис вызова провайдера с очередью `ai` (engine для локальных моделей, api для облачных через SDK), кэш по хэшу промпта, лимиты и бюджеты, шаблоны промптов версионированы в коде (`prompts/*.md`) с тестами на фиксированных примерах (golden), структурированные ответы через JSON-схемы (zod), fallback на ручной режим при недоступности провайдера.
