# Календарь, уведомления, Входящие и «Мой день»

Статус: **Решено** — Входящие как отдельный механизм и «Мой день» как стартовый экран; **Рекомендовано** — детали календаря.

## 1. Календарь

- Календари: личный (авто), командный/подразделения (авто для `unit`-пространств), проектный, ресурсный (переговорные, техника), подписки (ICS).
- События: заголовок, время/весь день, повтор (RRULE + исключения), место/комната, участники с ответами (да/нет/возможно/предложить время), напоминания (в приложении/почта/Telegram), видимость (открыто/занято/личное), связанные объекты, встреча (LiveKit) одной кнопкой, цвет.
- **Проекции**: сроки задач/поручений, сроки документов на контроле, дедлайны форм сбора, дежурства (предметный пакет) показываются как виртуальные события (не хранятся), с переходом к объекту.
- Виды: день/неделя/месяц/повестка/таймлайн команды; поиск свободного времени по участникам и ресурсам; перетаскивание; быстрое создание из палитры (`Встреча завтра в 10 с Ивановым`).
- Интеграции: ICS-экспорт/подписка (с токеном), импорт ICS; CalDAV/Google/Microsoft — фаза 5 (Открыто).
- Рабочее время и отпуска пользователя (из HR или вручную) — учитываются в подборе времени и делегировании.

**Реализация (фаза 3, ADR-0081).** Календарь и событие — объекты реестра `calendar` и `event` (событие — дочерний объект календаря). Личный календарь создаётся при первом обращении, календарь подразделения — автоматически для пространств `unit`, проектный — один на проект, ресурс — без владельца в пространстве, подписка ICS хранит адрес зашифрованным. Видимость — права ядра: «открыто» наследует права календаря, «занято» и «личное» закрывают объект (участникам — `comment`; «занято» — ещё и редакторам календаря политикой типа), чужое закрытое событие везде приходит как «Занято» — в сетке, поиске, ICS и подборе времени. Повтор разворачивается в стенном времени пояса события и материализуется в `event_instances` на два года; правка «только это / это и следующие / вся серия». Приглашение — дело Входящих `respond_invite` с кнопками «Да / Возможно / Нет» (в том числе в Telegram), перенос времени переоткрывает его. Напоминания — очередь `event_reminders` с заданием раз в минуту (без повторов при перезапуске воркера), доставка — срочным уведомлением в выбранные каналы. Проекции — реестр поставщиков `registerCalendarProjection` в `modules/calendar/public.ts`: задачи регистрируют `tasks.due`, документы — `documents.control`; календарь модули-поставщики не импортирует. ICS: ссылка подписки с токеном (права выпустившего, отзыв), импорт `.ics`, подписка на внешний канал с защитой от SSRF (`CALENDAR_FEEDS_ALLOW_PRIVATE` — для каналов интранета). Подбор времени учитывает рабочие часы каждого участника в его поясе и рабочие дни производственного календаря; праздники и переносы правит администратор в разделе консоли «Производственный календарь». Реализованы виды день, неделя, месяц и повестка; таймлайн команды, встреча LiveKit и отпуска из HR — следующими фазами.

## 2. Уведомления

Категории (для настроек): `inbox.*` (действия), `tasks.*`, `documents.*`, `chat.*`, `meetings.*`, `calendar.*`, `data.*` (импорт завершён, алерт, качество), `system.*`. Каналы: приложение (центр + toast + счётчик на рейле), e-mail (мгновенно/дайджест утром), Telegram (мгновенно), push (PWA, ADR-0094: ключи VAPID установки, подписка на устройство, служебный поток показывает уведомление при закрытой вкладке). Правила по умолчанию: действия и упоминания — везде; изменения объектов, на которые подписан, — только в приложении; дайджест утром 08:00 по локальному времени. Тихие часы, «не беспокоить», режим «на встрече». Агрегация: несколько событий одного объекта за 5 минут — одно уведомление «3 изменения в Документ №…». Центр уведомлений: непрочитанные/все, группировка по объектам, «отметить всё», переход к объекту в новой вкладке.

## 3. Входящие

Элементы с состоянием (`inbox_items`): согласовать, подписать, наложить резолюцию, ознакомиться, принять поручение, отчитаться, принять результат, ответить на приглашение, проверить протокол, сдать форму, рассмотреть запрос доступа, разобрать алерт, обработать ошибку импорта, проверить правку объектов слоя (`review_edit`, ADR-0076), принять сводку формы (`review_form`, ADR-0103). Дело «Сдать сводку» (`submit_form`) открывается экраном формы, а не кнопкой в списке: у формы своя схема полей. Каждый элемент — карточка с контекстом (кто, что, срок, ссылка) и **действиями прямо в списке** (согласовать/отклонить с комментарием, принять, ознакомиться, ответить), группировка по типу/сроку, фильтры «мои/замещаемые», отложить до времени. Закрытие автоматическое по событию действия; ручное закрытие невозможно (кроме «отклонить» там, где это действие). Счётчик Входящих — главный индикатор на рейле.

## 4. «Мой день»

Стартовая вкладка (закреплена первой, `G H`). Настраиваемая сетка виджетов (как дашборд, с системными плитками):

| Виджет | Содержание |
|---|---|
| Входящие | топ элементов по срочности с действиями, ссылка на все |
| Сегодня | таймлайн встреч и событий с кнопкой «Присоединиться», сроки задач (реализован в фазе 3: прошедшие встречи приглушены, идущая отмечена, у ближайшей — «через N мин»; ADR-0081) |
| Мои задачи и поручения | сгруппированы: просрочено / сегодня / на неделе; быстрая отметка |
| Выданные мной | поручения на контроле по статусам (для руководителей) |
| Продолжить | вчерашние вкладки/рабочие пространства и недавние объекты |
| Закреплённое | избранные объекты и представления |
| Команда | нагрузка/просрочки отдела (руководителям), кто в отпуске/делегирует |
| Показатели | 2–4 показателя по выбору (например, «Происшествия за сутки») |
| Объявления | системные объявления и новые страницы для ознакомления |
| Активность | лента по подписанным объектам |

Роль определяет набор по умолчанию (руководитель: Входящие, Выданные, Показатели, Сегодня; аналитик: Продолжить, Данные (свежесть/качество), Закреплённое; делопроизводитель: Входящие, Журнал сегодня, Контроль). Пользователь настраивает. Мобильный вариант — одна колонка: Входящие → Сегодня → Задачи.

## 5. Восстановление контекста

Состояние рабочего пространства (вкладки, разделения, активные панели, состояние вкладок) сохраняется на сервере (`workspace_state` в `settings` пользователя) с дебаунсом; при входе предлагается «Продолжить» или «Начать с чистого». Именованные рабочие пространства («Паводок-2026»: карта + дашборд + чат штаба) — сохраняются и открываются одним действием, могут быть общими (объект `view` вида `workspace`).
