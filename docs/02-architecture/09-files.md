# Файлы

Статус: **Решено** для модели хранения и вложений; **Рекомендовано** для предпросмотра и офисного редактора.

## 1. Роль модуля

Файлы — общий ресурс всех модулей: вложения документов, задач, сообщений, страниц; версии документов; записи встреч; результаты экспорта и отчётов; исходники импорта. Модуль даёт хранение, версии, предпросмотр, извлечение текста, шаринг и файловый менеджер как самостоятельный экран.

## 2. Модель

- `file` ★ — объект реестра (права, связи, обсуждение, поиск); `folder` ★ — контейнер с наследованием прав. Файл всегда в пространстве; `folder_id` — папка внутри пространства (или корень пространства/раздела).
- Вложение = связь `attachment` от объекта к файлу; один файл может быть вложен в несколько объектов. Файлы, загруженные как вложения, лежат в скрытой системной папке пространства «Вложения» (видны в менеджере через фильтр «Вложения объектов»).
- Версии: `file_versions` с автором, заметкой, контрольной суммой; текущая версия указывается в `files.current_version_id`; восстановление старой создаёт новую версию.
- Хранение: S3-ключ `spaces/{spaceId}/files/{fileId}/{versionId}/{safeName}`; бакеты: `kchs-files` (версионирование на стороне S3 выключено — версии ведём сами), `kchs-previews`, `kchs-media`, `kchs-exports` (TTL 30 дней), `kchs-tiles`.
- Загрузка: клиент запрашивает `POST /files/upload-sessions` → подписанные URL для multipart → загружает прямо в S3 → `complete` → сервер проверяет размер/сумму, создаёт версию, ставит задания: антивирус (опц.), извлечение текста/OCR, превью, индексация. Докачка при обрыве.
- Ограничения: размер файла по политике (по умолчанию 5 ГБ), квоты по пространствам, запрещённые типы (исполняемые) по политике.

## 3. Предпросмотр

Engine формирует превью заданием `render`: изображения (thumbnail + web-версия), PDF (страницы как изображения по запросу + текст), офисные форматы (LibreOffice → PDF), видео/аудио (постер, транскодирование в веб-формат при необходимости — ffmpeg), таблицы (первые N строк → JSON), геоданные (мини-карта + предложение «Импортировать как слой»), архивы (список). Просмотрщик в UI — единый компонент `FilePreview` с навигацией по страницам, поиском в тексте, комментариями к файлу (обсуждение), скачиванием, «Открыть в …» (импорт в датасет, создать документ, прикрепить к задаче).

## 4. Текст и поиск

`file_texts`: извлечённый текст (tika-подобный подход: pdftotext/LibreOffice/OCR tesseract `rus+tgk+eng` при отсутствии текстового слоя). Индексируется в Meilisearch отдельным документом с `parentId=file` и правами файла. Семантические эмбеддинги — для PDF/DOCX/страниц (чанки).

## 5. Файловый менеджер

Экран: дерево папок пространств слева, `CollectionView` (таблица/сетка) справа: имя, тип, размер, автор, изменён, версия, теги, статус; предпросмотр в контекстной панели; drag-and-drop загрузка и перемещение; массовые операции; сортировка/фильтры/сохранённые представления; «Недавние», «Общие со мной», «Избранное», «Корзина». Клавиатурная навигация как в десктопных менеджерах.

## 6. Общий доступ

Обычный шаринг объекта + публичные ссылки (`file_shares`) с паролем, сроком, лимитом скачиваний, водяным знаком в предпросмотре и аудитом; отключаемо политикой. «Запросить доступ» из превью без прав.

## 7. Блокировка и офисное редактирование

Блокировка (`locked_by`) для ручного цикла «скачать → править → загрузить версию». Совместное редактирование DOCX/XLSX/PPTX (фаза 3): интеграция ONLYOFFICE Document Server (или Collabora) по протоколу редактора: API выдаёт токен с правами, сервер редактора запрашивает файл по подписанному URL и сохраняет обратно колбэком → новая версия. Права редактора = права объекта.

## 8. Жизненный цикл и обслуживание

Корзина 30 дней; физическое удаление заданием; сироты (файлы без объектов/вложений старше 7 дней) — отчёт и очистка; дедупликация по контрольной сумме внутри пространства (ссылка на существующий объект хранения); статистика хранения в администрировании; экспорт пространства целиком (zip) — задание.
