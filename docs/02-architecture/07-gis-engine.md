# GIS-движок: слои, карты, тайлы, редактирование, анализ, территории

Статус: **Решено** для модели (объект карты = строка датасета), тайлов, стилей и территорий; **Рекомендовано** для инструментов анализа, печати и растров.

## 1. Принципы

1. **GIS-объект — строка датасета с геометрией.** Нет отдельной «гео-базы»: атрибуты, права, история, обсуждения, связи с документами и поручениями работают как для любой строки.
2. **Слой — представление датасета**: стиль, подписи, всплывающие карточки, фильтр, диапазон зумов. У датасета может быть несколько слоёв.
3. **Карта — композиция**: базовая карта, слои с порядком/группами/прозрачностью, вид, виджеты, закладки, привязка к фильтрам дашборда.
4. **Территории — сквозной справочник**: измерение аналитики, фильтр доступа, ключ хороплетов, хаб объектов.
5. **Карта живёт рядом с таблицей и графиком** через связанные представления (ViewContext).

## 2. Хранение геометрий

- Столбец `geom geometry(Geometry, 4326)` в таблице датасета; тип геометрии (Point/LineString/Polygon/Multi*) фиксируется в `datasets.geometry`; смешанные типы допустимы только при явном флаге.
- Валидация при записи: `ST_IsValid` → `ST_MakeValid`, обрезка по мировым границам, ориентация полигонов (правило правой руки для GeoJSON).
- Индексы: GIST по `geom`; для полигональных/линейных слоёв > 100 тыс. вершин — генерализованные столбцы `geom_s1` (≈ z0–6), `geom_s2` (≈ z7–10) через `ST_SimplifyPreserveTopology`, заполняются при импорте/правке (триггер или задание).
- Расстояния/площади: `geography` в вычислениях (`ST_Distance(geom::geography, ...)`), площадь в км².
- Поддержка локальных систем координат (например, EPSG:32642/32643 UTM для Таджикистана, Пулково-1942) — только на импорте/экспорте и в отображении координат; хранение всегда 4326.

## 3. Векторные тайлы

Эндпоинт: `GET /api/v1/gis/layers/{layerId}/tiles/{z}/{x}/{y}.pbf?v={datasetVersion}&f={filterHash}&t={timeRange}`.

```sql
WITH bounds AS (SELECT ST_TileEnvelope($z,$x,$y) AS b),
src AS (SELECT _id, c_name, c_type, geom_for_zoom AS geom FROM ds.t_<sid>, bounds
        WHERE geom && ST_Transform(b, 4326) AND <row policy> AND <layer filter> AND _deleted_at IS NULL)
SELECT ST_AsMVT(q, 'layer', 4096, 'geom', '_id') FROM (
  SELECT _id, c_name, c_type, ST_AsMVTGeom(ST_Transform(geom, 3857), b, 4096, 64, true) AS geom FROM src, bounds) q;
```

Реализация (ADR-0064): строки тайла выбирает компилятор запросов с политиками смотрящего (геометрия как есть, `rowMeta`), охват тайла — его пространственное окно (`&&` рядом с политикой строк, по индексу GIST), сервис оборачивает запрос в `ST_AsMVT`.

- **Поля тайла** — поля стиля (рендерер, подписи, время) и `layer.tile_fields`, видимые смотрящему; остальное — по клику через `/features/{rowId}`.
- **Предпросмотр стиля** (ADR-0075): `&p=` — рабочая копия стиля из редактора (поля, фильтр слоя, кластеры, масштабы, время) вместо сохранённых; права и политики те же.
- **Кластеризация** точек на низких зумах (до `cluster.maxZoom`): сетка по ячейкам в радиус кластера, `count` в SQL с полем `point_count` для стиля кластеров.
- **Кэш**: Redis (ключ `tile:{layer}:{v}:{f}:{z}/{x}/{y}`, TTL 24 ч), `ETag`/`Cache-Control: private, max-age`; инвалидация — по версии датасета в ключе (старые ключи истекают). В S2 — HTTP-кэш перед API (nginx proxy_cache/Varnish) и/или Martin как тайл-сервер для «тяжёлых» статичных слоёв (ADR-0010).
- **Права**: тайлы проходят `authorize(view)` слоя и политики строк датасета (фильтр внутри SQL), поэтому пользователь никогда не получит геометрии чужих строк.
- **Ограничения**: тайм-аут 5 с, при превышении — ответ 204 и предложение включить генерализацию/кластеризацию.

Для мелких слоёв (≤ 5 000 объектов) и режима редактирования используется GeoJSON `GET /gis/layers/{id}/features?bbox=&f=&t=&limit=`.

## 4. Стили и легенда

`LayerStyle` (контракт `contracts/layer-style.md`) — декларативный, независимый от MapLibre:

- **Простой**: заливка/обводка/маркер/ширина/прозрачность/иконка из набора (Lucide + пользовательские SVG).
- **По категориям**: поле → карта значений (цвет/иконка/размер), «прочее».
- **Градуированный**: числовое поле → классы (методы: равные интервалы, квантили, естественные границы Дженкса, ручные, логарифм), палитры из дизайн-системы (последовательные, расходящиеся, color-blind safe), нормализация (на площадь/на население).
- **Размер по значению**, **тепловая карта** (радиус, вес, палитра), **кластеры** (стиль по `point_count`), **подписи** (поле/шаблон, шрифт, гало, приоритет, минимальный зум), **3D-экструзия** (фаза 3), **анимация времени**.
- **Всплывающая карточка**: шаблон (поля, форматирование, ссылки, кнопки «Открыть строку», «Документы», «Создать поручение»).
- Компилятор `packages/map-style` → массив слоёв MapLibre (`fill`, `line`, `circle`, `symbol`, `heatmap`, `fill-extrusion`) с выражениями; легенда генерируется из того же описания.
- Редактор стиля — панель с живым предпросмотром, «умные» пресеты по семантике поля.
- Реализация (ADR-0075): рабочая копия стиля подменяет стиль слоя в рендере и в тайлах (`p`); границы классов и диапазоны полей — `POST /gis/layers/{id}/stats` по всем строкам слоя с политиками смотрящего (квантили и естественные границы крупного слоя — по выборке 10 000), кэш по версии данных и отпечатку политик.

## 5. Базовые карты

- **Векторная самостоятельная**: PMTiles, генерируется из OSM `Planetiler` для нужного региона (страна + соседи на низких зумах), лежит в S3, отдаётся через API с поддержкой range-запросов (или напрямую из MinIO). Стили `light`/`dark`/`muted` на базе OpenMapTiles-схемы, цвета согласованы с токенами дизайн-системы, чтобы данные читались поверх.
- **Растровые**: XYZ/WMTS/WMS (спутник, гибрид, гос. слои) через прокси API (скрытие ключей, кэш).
- **Спутниковые снимки** собственного хранения — как COG через TiTiler (фаза 3).
- Администратор ведёт реестр `basemaps`, назначает по умолчанию; в оффлайн-контуре достаточно PMTiles.
- Обновление PMTiles — процедура в `15-admin-operations.md` §6. Реализация (сборка без морских полигонов, реестр `basemap`, стиль и прокси через API) — ADR-0066.

## 6. Карта-студия (клиент)

- MapLibre GL JS v5 (WebGL, глобус и 3D-местность опционально), `terra-draw` для рисования, `@turf/turf` для клиентских расчётов, `deck.gl` (overlay) для тяжёлых визуализаций (фаза 3).
- Панели: слева «Слои» (дерево групп, видимость, прозрачность, порядок, стиль, легенда), снизу «Атрибуты» (grid активного слоя, связанный с картой), справа контекст (объект/выделение/анализ/обсуждение), тулбар (выбор, прямоугольник/лассо, идентификация, измерение, рисование, закладки, время, печать), панель поиска (адрес/объект/координаты/территория), переключатель базовой карты, масштаб/координаты/компас.
- Инструменты (рамка, идентификация, измерение, закладки, поиск, координаты и масштаб), атрибутивная таблица и связь с соседними панелями — ADR-0073.
- Состояние карты (вид, видимость, фильтры) — часть состояния вкладки и URL (`#map=z/lat/lon&layers=...`), восстанавливается.
- Не более 3 живых WebGL-контекстов в скрытых вкладках; остальные восстанавливаются из состояния.
- Производительность: в одном датасете до ~1 млн точек через тайлы с кластерами; polygon-слои через генерализацию; слой сверх порога числа объектов рисует deck.gl по тем же тайлам (ADR-0110).

## 7. Редактирование объектов

- Инструменты: создать точку/линию/полигон, редактировать вершины, перемещать, разделить/объединить, привязка к вершинам/рёбрам других слоёв, ввод координат вручную, из GPS (мобильный веб), импорт из файла с сопоставлением.
- Форма атрибутов генерируется из схемы датасета (`SchemaForm`), валидация, справочники, авто-территория (`ST_Contains`).
- Конкурентность: оптимистичная блокировка по `_ver`; при конфликте — показать различия.
- История: `ds.h_*` + `feature_edits` для гео-правок; просмотр «как было», откат.
- **Модерация** (`layer.moderated`): правки не редакторов попадают в состояние `pending` (хранятся в `feature_edits`), процесс `feature-review` (движок процессов) назначает проверку владельцу слоя; принятие применяет правку. Простые слои — без модерации.

Реализация фазы 2 (ADR-0076): запись строки через слой (`/gis/layers/{id}/features`, геометрия GeoJSON, исправление PostGIS, версия строки, события `feature.*` в одной транзакции со строкой), права `edit_features` (edit) и `suggest_features` (comment), предложения в `feature_edits` с проверкой редакторами слоя и делом `review_edit` во Входящих владельца (до движка процессов — простой статус), авто-территория обратным геокодером в форме, рисование — terra-draw с привязкой к объектам видимых слоёв.
- Массовые операции: изменить поле у выделенных, удалить, экспортировать, создать поручение «по объектам».

## 8. Импорт и экспорт геоданных

Engine (GDAL/pyogrio): чтение SHP(zip)/GPKG/GeoJSON/KML/KMZ/GPX/CSV(lat,lon|WKT)/DXF (базово), определение и перепроецирование CRS (`.prj`, подсказка пользователю при отсутствии), кодировки атрибутов (cp1251 для старых SHP), валидация/исправление геометрий, предпросмотр на карте до коммита, режим обновления существующего слоя с **diff-предпросмотром** (добавлено/изменено/удалено по ключу). Экспорт: GeoJSON, GPKG, SHP, KML, CSV, XLSX (с WKT), с учётом политик строк/столбцов — задание с файлом-результатом.

Реализация импорта геоформатов, пересчёта систем координат, предпросмотра изменений и геоэкспорта — ADR-0068 (предпросмотр на карте и DXF — позже).

## 9. Геокодирование

- **Внутренний адресный индекс**: строится из территорий и справочников населённых пунктов/улиц (если есть) — поиск по названиям (Meilisearch) → центроид/геометрия. Достаточно для уровня населённого пункта.
- **Внешний/самостоятельный**: Photon или Nominatim на OSM-данных региона (docker), через порт `Geocoder`; обратное геокодирование → территория и ближайший адрес.
- Пакетное геокодирование в пайплайне (`geocode` шаг) с отчётом о качестве совпадения.
- Фаза 2 (ADR-0067): `GET /gis/geocode?q=` — справочник территорий в памяти процесса (коды, названия на трёх языках, таджикские буквы как русские, уточнение предком через запятую) и опечатки из Meilisearch; `GET /gis/geocode/reverse?lon=&lat=` — цепочка территорий, покрывающих точку, и ближайший населённый пункт (10 км).

## 10. Пространственный анализ

| Операция | Реализация | Результат |
|---|---|---|
| Буфер | `ST_Buffer(geography)` | новый датасет/виртуальный слой |
| Пересечение/объединение/разность/вырезание | `ST_Intersection`, `ST_Union`, `ST_Difference`, clip | датасет |
| Растворение (dissolve) по полю | `ST_Union` group by | датасет |
| Пространственное соединение | `ST_Intersects/Within/DWithin` + агрегаты («точек в полигоне», сумма поля) | шаг `spatial` QuerySpec или датасет |
| Ближайший / в радиусе / матрица расстояний | KNN `<->`, `ST_DWithin` | таблица |
| Центроиды, выпуклая оболочка, конверт | `ST_Centroid`, `ST_ConvexHull` | датасет |
| Сетка/гексагоны с агрегацией | `ST_HexagonGrid`/`ST_SquareGrid` | датасет/слой |
| Тепловая карта | клиент (MapLibre heatmap) / серверный KDE (фаза 3) | стиль |
| Присвоение территории | `ST_Contains` с `territories` | поле датасета |
| Измерения | клиент turf + сервер geography | UI |
| Изохроны/маршруты | Valhalla/OSRM (фаза 3) | слой |
| Профиль высот, зона видимости | ЦМР в COG + TiTiler (фаза 3) | UI |

Лёгкие операции (в пределах интерактивного тайм-аута) выполняются как шаг `spatial` внутри QuerySpec и дают **виртуальный слой** (без материализации). Тяжёлые — как объект `analysis` (параметры сохранены, воспроизводимо) заданием engine с материализацией в новый датасет; происхождение фиксируется. UI: мастер анализа в контекстной панели с предпросмотром на выборке.

## 11. Территории

- Иерархия: страна → область/город республиканского подчинения → район/город → джамоат → населённый пункт; коды по официальному классификатору (Открыто: подтвердить источник) + геометрии (официальные или открытые данные — лицензия!).
- Хранение: справочный датасет + зеркало `territories` (быстрые соединения, замыкание для «всё вложенное»).
- Использование: тип поля `territory` (пикер с деревом и картой), семантика `territory` у полей датасетов (авто-соединение с иерархией: агрегация по любому уровню), политики доступа (`user.territory_codes`), фильтр дашбордов, хороплет-мастер (датасет с территорией → агрегат → уровень → классификация → слой).
- **Паспорт территории** (`/o/territory/{id}`): заголовок с хлебными крошками иерархии, карта с границей и объектами, сетка показателей (настраиваемая администратором: какие показатели показывать для уровня), вкладки: Данные (строки датасетов с этой территорией), Документы, Поручения, Встречи, Обсуждение. Собирается ядром по связям `about_territory` и по полям `territory` датасетов.
- Границы фазы 2 (ADR-0067): районы — geoBoundaries/OpenStreetMap (ODbL, атрибуция обязательна), города без своего района в OSM и районы Душанбе — условные; регион и страна — объединение детей при загрузке. API: `GET /gis/territories/{id}/geometry?zoom=` (GeoJSON), `GET /gis/territories/tiles/{z}/{x}/{y}.pbf?level=&lang=` (MVT, слой на уровень, кэш по версии справочника).
- Хороплет-мастер и паспорт фазы 2 (ADR-0077): хороплет — анализ вида `choropleth` (запрос строит сервер по параметрам мастера, нормализация — население и площадь справочника), слой с градуированным стилем ставит клиент; паспорт — `GET /gis/territories/{id}/passport?period=` (показатели датасетов с полем территории, показатели со связью `about_territory`, поручения с территорией) и экран объекта-территории. Сетка показателей настраивается связями `about_territory`: показатель, привязанный к единице, виден в паспортах её и вложенных.

## 12. Время

Слои с временным полем: слайдер диапазона/момента, шаг, анимация (тайлы с параметром `t`, кэш по дискретным шагам), синхронизация с фильтром периода дашборда.

Реализация (ADR-0074): интервал, режим и шаг — в `MapSpec.time`; даты и местное время пояса пользователя, `t` — только слоям со временем; диапазон данных — агрегатом с политиками смотрящего; воспроизведение ждёт дорисовки кадра; период дашборда — условием `f` на поле времени слоя.

## 13. Печать и экспорт карт

Композитор печати: формат/ориентация, заголовок, легенда, масштабная линейка, стрелка севера, врезка-обзор, подпись/дата/автор → PNG/PDF (сервер: Playwright рендерит маршрут `/print/map/{snapshotId}` с теми же стилями; клиент — быстрый PNG через `canvas.toDataURL` с `preserveDrawingBuffer`). Снимок карты (`map snapshot`) как плитка отчёта/дашборда.

Реализация печати из студии (ADR-0074): кадр снимает вторая карта вне экрана с `preserveDrawingBuffer` размером кадра листа; лист A4/A3 или текущий вид, PNG или PDF собираются в браузере; атрибуция OpenStreetMap печатается всегда. Врезка-обзор — позже; сервер печати — для отчётов по расписанию. Карта как плитка дашборда и ячейка тетради — живая карта (`MapEmbed`) с условиями фильтров дашборда и параметров тетради.

## 14. Растры и полевой сбор (фаза 3+)

- COG в S3 + TiTiler (docker) для снимков, ЦМР, покрытий; палитры и диапазоны как часть `LayerStyle` (`raster`).
- Полевой сбор: мобильный веб с оффлайн-кэшем (Service Worker, IndexedDB), формы с геопривязкой/фото, синхронизация при появлении сети; конфликты по `_ver`.

## 15. Сценарии масштаба

| | S1 | S2 | S3 |
|---|---|---|---|
| Тайлы | из API + Redis | Martin для статичных слоёв + nginx-кэш | выделенные тайл-узлы, CDN внутренний |
| Базовые карты | PMTiles в MinIO | + растровые кэши | зеркала в регионах |
| Клиент | MapLibre | + deck.gl | + бинарные форматы (Arrow) |
| Анализ | PostGIS | + DuckDB spatial для больших | + пакетные задания |

**Реализовано (ADR-0110).** Слой с числом объектов сверх порога (настройка `gis.render`, по умолчанию 50 000) рисует deck.gl по тем же тайлам MVT: политики строк применяет сервер, стиль берётся из скомпилированного стиля MapLibre, выбор объекта идёт через тот же обработчик щелчка. Пакет грузится по требованию; без WebGL2 и при любой ошибке deck.gl слой рисует MapLibre.
