# API, события и realtime-протокол

Статус: **Решено** (ADR-0005).

## 1. Соглашения REST API

- База: `/api/v1`. JSON, UTF-8. Все маршруты типизированы zod-схемами в `packages/contracts`, из которых генерируются OpenAPI (`/api/openapi.json`) и типизированный клиент для внешних потребителей; веб-клиент использует те же zod-типы напрямую (ADR-0030).
- Ресурсы: множественное число, kebab-case: `/datasets/{id}/fields`, `/documents/{id}/versions`, `/gis/layers/{id}/tiles/{z}/{x}/{y}.pbf`. Универсальные: `/objects/{id}` (сводка, права, связи, активность), `/objects:batch-get`, `/search` (параметр `mode=hybrid|words` — со смыслом или только словами, ADR-0099), `/objects/{id}/similar` (похожие по смыслу), `/inbox`, `/notifications`, `/me`, `/me/workspace-state`.
- Действия, не укладывающиеся в CRUD: `POST /documents/{id}:submit`, `:approve`, `:register`, `POST /datasets/{id}:import`, `POST /queries:run`. Двоеточие — единый стиль для действий. Фактически модули используют подресурс действия (`POST /tasks/{id}/accept`, `POST /documents/{id}/register`, `POST /documents/{id}/cancel`) — так маршруты описываются схемой Fastify без экранирования двоеточия.
- Идентификаторы: UUID v7; строки датасетов — `bigint` в строке.
- Пагинация: курсорная (`?cursor=&limit=`), ответ `{items, nextCursor, total?}`; `total` — только по запросу `&count=true` (может быть приблизительным для датасетов, флаг `approx`).
- Фильтрация списков объектов: `?filter=<json>` в формате `FilterBuilder` (`contracts/field-types.md`), `?sort=field:asc,field2:desc`, `?fields=` (частичный ответ), `?include=owner,space` (расширение связей).
- Версии/конкурентность: ответы содержат `version`; изменяющие запросы принимают `If-Match: <version>` → `409` при конфликте.
- Идемпотентность: `Idempotency-Key` для `POST`, хранится 24 ч.
- Длительные операции: `202 Accepted` + `{jobId}`; статус `/jobs/{id}`; прогресс по WebSocket.
- Ошибки: `application/problem+json` (RFC 9457): `{type, title, status, detail, instance, code, errors?: [{path, message, code}]}`. Коды: `validation_failed`, `not_found`, `forbidden` (только если `view` есть, иначе `not_found`), `conflict`, `rate_limited`, `dependency_failed`, `query_timeout`, `policy_violation`.
- Локализация ошибок: `Accept-Language`; коды стабильны, тексты — по локали.
- Загрузка файлов: подписанные URL в S3 (не через API-тело, кроме мелких ≤ 5 МБ).
- Безопасность: cookie `kchs_session` (HttpOnly, Secure, SameSite=Lax) + CSRF-токен в заголовке для изменяющих запросов от браузера; Bearer-токены для интеграций; CORS только для доверенных origin.
- Гостевой доступ: `POST /share/{token}/open` (публичный, с паролем при необходимости) выдаёт токен доступа для заголовка `x-kchs-share-token`; действует только на один объект (ADR-0032).
- Действия «от имени» (замещение): заголовок `x-kchs-on-behalf-of: <userId>` принимается только в пределах активного делегирования; иначе `403` (ADR-0033).
- Push-уведомления (ADR-0094): `GET /me/push` (настроен ли на установке, ключ VAPID, число устройств), `POST /me/push/subscriptions` (подписать устройство), `DELETE /me/push/subscriptions` (отписать его).
- Встречи (ADR-0089): `GET /meetings` (мои, идущие, все), `POST /meetings` (звонок из беседы), `GET /meetings/{id}`, `POST /meetings/{id}/join|leave|end`, `GET /meetings/status` (настроен ли медиасервер).
- Календарь (ADR-0081): `/calendars` (мой список и доступные), `/calendars/{id}` (с `/feeds`, `/import`, `/sync`), `/events`, `/events/{id}` (`/cancel`, `/respond`, `/my-reminders`), `/calendar/range`, `/calendar/today`, `/calendar/free-busy`, `/calendar/find-time`, `/calendar/settings`, `/calendar/projections`; лента ICS — публичный `GET /calendar-feeds/{token}.ics` (токен вместо сессии, права выпустившего ссылку).
- Чаты (ADR-0090): `/chats` (список бесед с непрочитанным и создание личной беседы, группы, канала), `/chats/{id}` (карточка и переименование; `/members`, `/join`, `/leave`, `/invite`, `/members/{userId}`, `/settings` — закрепить и «без звука», `/pins`, `/draft`, `/call`), `/chats/search` (по беседе — Postgres, глобально — индекс `messages` Meilisearch), `/chats/drafts`, `/chats/forward`, `/chats/messages/{messageId}/task` и `/attach` (быстрые действия), `/me/presence` и `/presence` (статусы «в сети / отошёл / не беспокоить / на встрече», тихие часы).
- Встречи и звонки (ADR-0089, ADR-0091): `GET /meetings/status`, `GET|POST /meetings`, `GET /meetings/{id}`, `POST /meetings/{id}/join|leave|end|decline`, `POST /meetings/{id}/guest-link`, `GET /meetings/{id}/knocks`, `POST /meetings/{id}/knocks/{requestId}`; вход гостя без сессии — публичные `GET /meetings/guest/{token}` (название и состояние встречи) и `POST /meetings/guest/{token}/join` (заявка в комнату ожидания, затем токен комнаты) с ограничением частоты. Токен ссылки подписан мастер-ключом установки и живёт от 15 минут до суток; доступа к объектам гостю он не даёт.
- Страница печати (`/print/*` веба в Chromium движка): cookie `kchs_print` со служебным токеном одного запуска, выданным движку внутренним маршрутом; права — того, под кем строится документ, только чтение (GET и POST с признаком `readOnly`), личные маршруты закрыты (ADR-0078).
- Печать и шаблоны документов (ADR-0085): `GET /documents/print-forms?subjectId=` (формы объекта с причиной недоступности), `POST /documents/prints` (заказ формы), `GET /documents/renders?subjectId=`, `GET /documents/renders/{id}`, `POST /documents/watermarked` (копия файла с грифом под водяным знаком) и `GET /documents/renders/{id}/download`; шаблоны — `/document-templates` (`/{id}`, `/{id}/file`), `POST /documents/from-template`, `POST /documents/{id}/fill`; сравнение версий — `GET /documents/{id}/versions/compare?from&to`. Движок — `POST /internal/documents/renders/{id}/start|done` (сервисный токен). Файл с грифом от «конфиденциально»: `GET /files/{id}/download` вне режима администратора — `403` с `data.reason: watermark_required`; превью несут `watermark.lines`.
- Встречи (ADR-0089): `/meetings` (список и звонок), `/meetings/{id}`, `/meetings/{id}/join|leave|end`, `/meetings/status`. Запись и расшифровка (ADR-0092): `POST /meetings/{id}/recording/start`, `POST /recordings/{id}/stop`, `GET /meetings/{id}/recordings`, `GET /recordings/{id}`, `GET /recordings/{id}/transcript`; запись скачивается как обычный файл (`GET /files/{fileId}/download`, `inline=true` — для плеера). Медиасервер — `POST /meetings/webhooks/livekit` (тело `application/webhook+json`, подпись JWT ключом установки, проверяется до разбора); движок — `POST /internal/meetings/recordings/{id}/transcript` (сервисный токен).
- Версионирование: `v1` в пути; несовместимые изменения — `v2` с периодом сосуществования; добавления полей — совместимы.
- Публичный API токеном (ADR-0097): `Authorization: Bearer kchs_…` обрабатывается раньше cookie-сессии, CSRF для него не требуется. Область доступа выводится из тега маршрута (`read:<тег>` / `write:<тег>`, `POST` с `readOnly` — чтение); список закрыт по умолчанию, личные, входные и административные пути токенам недоступны. Документация — `/api/docs` (страница по текущему OpenAPI, без скриптов), спецификация — `/api/openapi.json`. Массовые операции: `POST /objects/batch-get`, `POST /datasets/{id}/rows/batch` (`202 + jobId` на большой пачке). Токены и интеграции: `GET|POST /me/api-tokens`, `DELETE /me/api-tokens/{id}`, `GET /admin/api-tokens` (`/{id}`, `/scopes`), `GET|POST /integrations` (`/{id}`, `/{id}/check`, `/{id}/inbound-secret`, `/{id}/syncs`, `/builtin/{key}/check`), `GET|POST /webhooks` (`/{id}`, `/{id}/secret`, `/{id}/deliveries`, `/{id}/deliveries/{deliveryId}/retry`), публичный `POST /hooks/{integrationId}/{secret}`, `GET /config/sections`, `POST /config/export|import/preview|import`.
- Ограничения: rate limit `429` с `Retry-After`; максимальный размер тела 10 МБ (кроме загрузок).

## 3. Realtime-протокол (Socket.IO)

- Подключение: `/ws` с cookie-сессией; при неудаче — переподключение с экспоненциальной задержкой; после переподключения клиент повторно подписывается и запрашивает `since=<lastEventId>` для пропущенных `object.updated` по открытым вкладкам.
- Клиент → сервер: `subscribe {rooms: ['object:…','space:…','conversation:…','job:…']}`, `unsubscribe`, `presence.view {objectId}` (видимая вкладка — раз в 30 с; отметка без подтверждения дольше 70 с считается ушедшей), `presence.leave {objectId}`, `typing {conversationId}`, `ping`.
- Сервер → клиент: `object.updated {id, type, version, changedFields, actorId}`, `object.removed {id}`, `message.posted {conversationId, message}`, `message.updated`, `notification.new {notification}`, `inbox.changed {counts}`, `job.progress {jobId, progress, message}`, `job.finished {jobId, status}`, `presence {objectId, users[]}`, `typing {...}`, `call.incoming {meetingId, title, caller, conversationId}` (приглашённому в комнату `user:{id}`, ADR-0091), `call.declined {meetingId, userId}` (звонящему), `meeting.changed {meetingId, change}` (состав и состояние комнаты — в комнату `object:{id}`), `meeting.knock {meetingId, requestId}` (гость просится в комнату — ведущему встречу), `acl.revoked {objectId}` (клиент закрывает вкладку с сообщением), `calendar.changed {}` (календарь пользователя изменился: приглашение, ответ, перенос — клиент перечитывает сетку и «Сегодня», ADR-0081).
- Комнаты объектов проверяются `authorize(view)` при подписке; изменение ACL → пересчёт членов комнаты.
- Совместное редактирование — `/collab` (Hocuspocus, Yjs, ADR-0070): процесс api, тот же порт, клиент подключается к `/collab/ws` одним сокетом на вкладку браузера. Имя документа = `objectId`; вход — cookie сессии и CSRF-токен в поле `token` протокола; права `edit`/`view` (без `edit` — только чтение); отказ — `unauthorized`, `setup_required`, `not_found`. Права перепроверяются раз в минуту и сразу по `acl.changed`/корзине/архиву; потеря права закрывает документ с причиной `access_changed`. Правки сохраняются в `yjs.documents` (через 2 с, не реже 10 с), JSON-снимок тела пишет модуль типа.

## 4. Внутренние контракты между модулями (`public.ts`)

Примеры (исполнитель фиксирует сигнатуры в коде):
- `tasks.public.createInstruction({source, authorId, assigneeId, coAssignees, dueAt|dueWorkingDays, controllerId, title, text})`, `tasks.public.getStatusSummary(sourceObjectId)`. Реализовано (ADR-0082): `Instructions.create(tx, ctx, {title, description?, source: {kind: 'resolution', objectId, resolutionId, label?} | {kind: 'object', objectId}, authorId?, assigneeId, coAssigneeIds?, controllerId?, due: {at} | {workingDays}, priority?, spaceId?, territoryId?}) → {id, key, parts}` в транзакции вызывающего, `Instructions.status(sourceObjectId) → {total, open, accepted, cancelled, allClosed, resolutionIds}`, `Instructions.bySource(ctx, sourceObjectId)`; закрытие последнего поручения источника — событие `task.source_closed`.
- `documents.public.createFromReport({reportRunId, typeId, subject, fileId})`, `documents.public.registerProtocol({protocolId, typeId})`. Реализовано (ADR-0093): вместо `registerProtocol` — общая точка `DocumentsPublic.create(tx, ctx, DocumentCreateInput)`; протокол зовёт её сам и связывает документ с собой. Реализовано (ADR-0080): `DocumentsPublic.applyTransition(tx, ctx, documentId, {to, cause, source?})` — единственная смена статуса по графу жизненного цикла; `DocumentsPublic.setParticipants(tx, ctx, documentId, source, entries)` — права участников одного источника (`route:<экземпляр>`, `resolution:<id>`); `DocumentsPublic.register(tx, ctx, documentId, {journalId?, reservationId?})`; `DocumentsPublic.brief(executor, documentId)` — реквизиты после проверки `view` вызывающим. Маршруты документов (ADR-0083): поставщик данных `document` движка процессов (реквизиты для назначений и условий, хуки статусов и заморозки версии), исполнитель шага `register`; для модулей ядро даёт `ProcessDefinitions.published/preview/ensure` и `ProcessView.active`. Ядро (ADR-0084): `Acknowledgments.request(tx, ctx, {objectId, source, userIds, unitIds, groupIds, dueAt, requireSecondFactor, note})` — запрос ознакомления в транзакции модуля (права получателей выдаёт модуль типа), `acknowledge`, `remind`, `list`, `usersOf`, `pendingFor`; `registerProcessObserver({name, stepTypes, stepChanged})` — наблюдатель шагов маршрутов в транзакции перехода. Задачи: `Instructions.create` принимает `confidentiality` источника, `Instructions.progress(ids)` — всего и открыто. Вторая волна (ADR-0086): `DocumentsSeed.ensureOfficeDashboard(tx, ctx, spaceId)` и `DocumentsSeed.seedDemoDocuments(people)` — сид; модуль «Данные» — `Dashboards.create(tx, ctx, input, {systemKey})`; модуль «Файлы» — `destroyFiles(tx, ctx, fileIds)` (уничтожение по акту; байты — заданием `maintenance:files.delete-stored`); ядро — `LinkService.edges(objectIds, kind)` (рёбра связей для обхода цепочек). HTTP: `POST /documents/{id}/reply`, `GET /documents/{id}/correspondence`, `GET|POST /documents/{id}/dispatches`, `GET /documents/{id}/cases`, `POST /documents/{id}/file`, `GET /documents/office`, `GET|POST /cases`, `GET|PATCH /cases/{id}`, `POST /cases/{id}/close|reopen|archive`, `POST /cases/close-year`, `GET|POST /cases/destruction-acts`; `GET /search?statuses=`.
- `data.public.runQuery(ctx, spec, opts)`, `data.public.getDatasetSchema(id)`, `data.public.upsertRows(ctx, datasetId, rows, opts)`, `data.public.evaluateMetric(ctx, metricId, dims, period)`.
- `gis.public.assignTerritory(points)`, `gis.public.getTerritoryTree()`, `gis.public.renderMapSnapshot(mapId, view)`.
- `files.public.createFromBuffer/Stream(...)`, `files.public.getSignedUrl(fileId, versionId?)`, `files.public.extractText(fileId)`.
- `comms.public.postSystemMessage(objectId, template, params)`, `meetings.public.createRoom(...)`.
- `calendar.public.registerCalendarProjection({key, labelKey, icon, list(ctx, {from, to, timezone})})` — реализовано (ADR-0081): модуль-поставщик регистрирует сроки своих объектов как виртуальные события календаря (`tasks.due`; `documents.control` — сроки документов на контроле); `list` возвращает только видимые смотрящему объекты, календарь поставщиков не импортирует.
- `ai.public.complete(task, input, schema)`, `ai.public.embed(texts)`. Реализовано (ADR-0061): `AiService.complete(ctx, {feature, system, prompt, schema, …}, accept)` — ответ проверяется схемой, `accept` модуля проверяет его по существу, аудит пишет исход целиком.
- Движок процессов (ядро, `kernel/process`, ADR-0079): `ProcessService.start(tx, ctx, {objectId, definitionKey|definitionId, variables, assignees})` в транзакции модуля, `ProcessService.completeStep(tx, ctx, {stepId, outcome, result})` — шаг `task`/`call` модуля выполнен, `ProcessService.running(tx, objectId)`; `registerProcessObjectProvider({objectType, load, setField?, canStart?, onStepActivated?, onDecision?, onStepCompleted?, onFinished?})`, `registerProcessStepHandler({type: register|task|call, objectType?, action?, execute, cancel?})`, `registerProcessWaitEvent(type)`, `withProcessParticipants(policy, {afterStep})` для политики типа.

HTTP API движка процессов (контракты — `@kchs/process`, ADR-0079):
- `GET|POST /process-definitions`, `GET /process-definitions/{key}`, `GET /process-definitions/{key}/versions/{version}`, `PUT|DELETE /process-definitions/{key}/draft`, `POST /process-definitions/{key}/publish`, `POST /process-definitions/validate`, `POST /process-definitions/preview` — способность `processes.manage`; ошибки проверки — 400 с `data.issues` (путь, код, сообщение, важность).
- Маршруты документа (ADR-0083): `GET /documents/{id}/routes` — опубликованные маршруты (маршрут типа первым), переменные, шаги с выбором инициатора, можно ли запустить сейчас и почему нет (`access`, `status`, `running`, `no_version`); `POST /documents/{id}/routes/preview` — «кто будет назначен» на этом документе; `POST /documents/{id}/routes` (`definitionKey`, `variables`, `assignees`) — запуск с проверками карточки, назначенных безусловных шагов и допуска к грифу; `GET /documents/{id}/route-versions` — версия, которую видел каждый шаг; `GET /documents/{id}/signatures` — подписи и их проверка по хэшу (`valid`, `pending`, `mismatch`). Карточка `GET /documents/{id}` отдаёт идущий маршрут (`route`: текущие шаги и ждущие) и право `can.startRoute`.
- `GET /documents/{id}/assist` — доступна ли помощь ИИ по документу и почему нет (`ai_disabled`, `confidentiality`, `no_file`, `text_pending`, `no_text`); `POST /documents/{id}/assist/extract` (право правки) — реквизиты из текста скана с уверенностью и цитатой и отправитель со сверкой по справочнику; `POST /documents/{id}/assist/summary`, `…/reply` (`instructions`) — краткое содержание и черновик ответа (право просмотра). Гриф строже `AI_DOCUMENTS_MAX_CONFIDENTIALITY` — 403 `policy_violation`; без ИИ — 503 (ADR-0088).
- Встречи (ADR-0089): `GET /meetings/status`, `GET|POST /meetings`, `GET /meetings/{id}`, `POST /meetings/{id}/join|leave|end`.
- Протокол встречи (ADR-0093): `GET|POST /meetings/{id}/protocol` — протокол встречи (null — не заведён) и его заведение (право `edit` на встрече); `GET /protocols/{id}`; `POST /protocols/{id}/blocks` — блоки в открытый документ (как ячейки тетради); `POST /protocols/{id}/draft` — черновик ИИ (право `edit`; 503 без ИИ, 403 по грифу, 409 без повестки и расшифровки); `POST /protocols/{id}/confirm` — поручения из блоков `instruction` (право `manage`; 409 со списком `blockIds` у неполного блока); `POST /protocols/{id}/register` (`typeId`) — документ по протоколу; `POST /protocols/{id}/acknowledgments` (`userIds`, `dueAt`) — ознакомление участников. Тело протокола правится через `/collab`.
- `GET /process-catalog` — справочник конструктора маршрутов (ADR-0087): типы объектов с поставщиком данных маршрута (поля для `field:` и `object.fields.*`, можно ли запускать общим API), события для шага `wait`, исполнители шагов модулей (`register`, `task`, `call` с действием); способность `processes.manage`. `GET /principals/describe?keys=` — названия людей, подразделений, групп и должностей по ключам `user:<id>`… (до 100; прочие ключи пропускаются), чтобы конструктор показывал назначенных именами.
- `POST /processes` — запуск, если поставщик типа объекта разрешает (`canStart`); `GET /processes?objectId=` — маршруты объекта; `GET /processes/{id}` — линия шагов (назначенные с решениями, сроки, просрочка, действия с комментариями и файлами), определение экземпляра, действия смотрящего (`myActions`), `canCancel`; `POST /processes/{id}/cancel`; `POST /processes/{id}/steps/{stepId}/act` (`action`, `comment`, `fileIds`, `code`), `…/assignees` (добавить согласующего), `…/delegate` (передать шаг), `…/reassign` (администратор маршрутов). Маршрут видит тот, кто видит объект; не участнику шага, не видящему объект, — 404.

Правило: публичный API принимает `ctx: UserCtx | SystemCtx`, не «доверяет» вызывающему и сам проверяет права.
