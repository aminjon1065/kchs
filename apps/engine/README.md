# kchs engine

Вычислительный движок: импорт данных и геоформатов (GDAL/pyogrio), преобразования
(pandas/DuckDB), рендеринг отчётов и карт (Playwright, docxtpl/LibreOffice),
извлечение текста и OCR (tesseract), расшифровка речи (faster-whisper),
эмбеддинги и обращения к LLM.

Движок **не содержит доменной логики и не принимает решений о правах**: задания
приходят с уже проверенным контекстом (02-architecture/01-overview.md).

## Запуск

```bash
uv sync --extra dev
uv run uvicorn kchs_engine.main:app --port 8000
uv run pytest
uv run ruff check .
```

## Импорт датасетов (ADR-0046)

- `POST /data/analyze` (сервисный токен `x-kchs-service-token`): тело
  `{bucket, key, fileName, options}` → `ImportAnalysis` контракта по голове файла
  (текстовые форматы — первые 8 МБ, Excel — книга целиком). Файл не читается — 422,
  причина по-русски в `detail`.
- Задание `imports:dataset.normalize`: весь файл потоком → нормализованный CSV (первый
  столбец — номер строки файла, дальше поля сопоставления, геометрия последней) и CSV
  ошибок `row,field,value,code` в хранилище; итог — `POST
  /api/v1/internal/data/imports/{importId}/normalized`. Нечитаемый файл — окончательный
  сбой задания без повторов.

Долгие и внешние проверки в CI не запускаются:

```bash
uv run pytest -m slow -s            # нормализация 1 млн строк CSV, 5 млн строк демо-данных
KCHS_TEST_S3=1 uv run pytest -m s3  # анализ и демо-данные в MinIO разработки (S3_* из .env)
```

## Демо-данные

Генератор демонстрационных данных фазы 1 (P1-E10, `04-verification.md` §7) — пакет
`kchs_engine/demo`. Он пишет **файлы**, а не строки в базу: сид загружает их через обычный
конвейер импорта (ADR-0046, ADR-0054) — файл в S3 → анализ → нормализация в движке →
загрузка воркером, — так демо-данные заодно проверяют импорт на 5 млн строк.

```bash
uv run python -m kchs_engine.demo --out seeds/.cache/demo --profile small
uv run python -m kchs_engine.demo --out s3://kchs-files/seed/demo --profile demo
docker compose exec engine python -m kchs_engine.demo --out s3://kchs-files/seed/demo
```

`--out` — каталог или `s3://бакет/префикс` (клиент `kchs_engine/storage.py`, переменные
`S3_*`; файл пишется во временный каталог и загружается частями, если он больше 8 МБ).
`--profile` — `small` или `demo` (по умолчанию), `--seed` — seed (по умолчанию 2026),
`--only incidents,territories` — только эти наборы, `--incidents N` — число строк
«Происшествий» вместо профиля (для замеров). Ход и замеры — в stderr.

Сид api (`pnpm db:seed --data=small|demo`, ADR-0063) запускает тот же генератор заданием
`transform:demo.generate` (`kchs_engine/jobs/demo.py`): файлы и манифест — в бакет файлов под
`demo/<профиль>-<seed>/`; если там уже лежит манифест того же профиля и seed, задание
завершается сразу, не генерируя файлы заново.

| Файл | Набор | Строк: small / demo | Ключ | Время | Территория | Геометрия |
|---|---|---|---|---|---|---|
| `territories.csv` | Территории (справочник) | 74 | `code` | — | — | центроид (широта/долгота) |
| `incident_types.csv` | Типы происшествий (справочник) | 22 | `code` | — | — | — |
| `hydro_posts.csv` | Гидропосты (справочник) | 46 | `code` | — | `territory_code` | точка |
| `incidents.csv` | Происшествия | 50 000 / 5 000 000 | `code` | `occurred_at` | `territory_code` | точка |
| `protected_objects.geojson` | Объекты защиты | 5 000 / 50 000 | `code` | — | `territory_code` | точка |
| `risk_zones.geojson` | Зоны риска | 311 | `code` | `assessed_on` | `territory_code` | полигон |
| `water_levels.csv` | Уровни воды (посты × сутки) | 13 152 / 50 416 | `observed_on`, `post_code` | `observed_on` | `territory_code` | — |

Период — 2024-01-01…2026-12-31, время без смещения — в поясе `Asia/Dushanbe`. CSV — UTF-8
без BOM, разделитель «,», десятичная точка, даты ISO, заголовок в первой строке; анализ
импорта распознаёт каждый файл без предупреждений (проверяется тестами), нормализация по
манифесту проходит без ошибок.

- **Территории**: страна `TJ`, 5 регионов (`TJ-DU`, `TJ-GB`, `TJ-KT`, `TJ-RA`, `TJ-SU`) и 68
  районов и городов (`TJ-SU-01`…): код, названия по-русски, по-таджикски и по-английски,
  уровень, вид, код родителя, приблизительный центроид, население (оценка).
- **Происшествия**: номер `INC-2024-0000001` (по порядку внутри года), дата и время, тип (код
  справочника), район, широта и долгота у одного из населённых пунктов района, ущерб в сомони
  (логнормальный, 10–20 % пусто), пострадавшие, погибшие (у ~6 % происшествий), описание.
  Строки идут по времени; сезонность — паводки и сели весной, природные пожары и происшествия
  на воде летом, лавины, пожары в домах и взрывы газа зимой; тип зависит от района (лавины — в
  горах, ДТП — где живут люди); число происшествий растёт от года к году на 4 %.
- **Объекты защиты** — точки: школы, детские сады, больницы, ПВР, мосты, дамбы, малые ГЭС,
  подстанции и др. с вместимостью, годом постройки, сейсмостойкостью и состоянием.
- **Зоны риска** — звёздные многоугольники вокруг населённых пунктов (подтопление, сели,
  оползни, лавины, камнепады) и районов (сейсмичность): уровень риска, сезонность, метод и дата
  оценки, площадь. Кольца замкнуты и ориентированы против часовой стрелки.
- **Уровни воды**: 46 постов на 16 реках; пик в мае у рек снегового питания и в июле — у
  ледниковых, влажные и сухие годы, паводковые волны; расход по кривой расходов; признак
  «выше опасного уровня» (≈ 3 % суток).

`manifest.json` (формат `kchs-demo/1`) — рядом с файлами, пишется последним: наборы в порядке
загрузки (справочники раньше таблиц). Для каждого набора — название, вид (`table` или
`reference`), описание, файл, формат, число строк, размер, SHA-256, ключ, поля времени и
территории, предлагаемые связи со справочниками (`lookups`) и `import` — это `ImportRunInput`
контракта без `fileId` и `target`: сиду остаётся зарегистрировать файл и указать датасет.

```json
{
  "format": "kchs-demo/1", "profile": "demo", "seed": 2026,
  "period": {"from": "2024-01-01", "to": "2026-12-31"}, "timezone": "Asia/Dushanbe",
  "datasets": [
    {
      "id": "incidents", "file": "incidents.csv", "name": "Происшествия", "kind": "table",
      "description": "Синтетический журнал происшествий 2024–2026 годов…",
      "format": "csv", "contentType": "text/csv; charset=utf-8",
      "rows": 5000000, "bytes": 1158037632, "sha256": "1e06c05b…",
      "key": ["code"], "timeField": "occurred_at", "territoryField": "territory_code",
      "geometryField": "geometry",
      "lookups": [
        {"field": "type_code", "dataset": "incident_types", "keyField": "code", "labelField": "name"},
        {"field": "territory_code", "dataset": "territories", "keyField": "code", "labelField": "name"}
      ],
      "import": {
        "options": {"format": "csv", "encoding": "utf-8", "delimiter": ",", "skipRows": 0,
                    "headerRows": 1, "decimal": ".", "thousands": "", "dateOrder": "ymd"},
        "mapping": [
          {"column": 0, "fieldKey": "code", "label": {"ru": "Номер", "en": "Number"},
           "type": "identifier", "semantic": "identifier", "required": true},
          {"column": 3, "fieldKey": "territory_code", "label": {"ru": "Территория", "en": "Territory"},
           "type": "text", "semantic": "territory", "required": true},
          {"column": 6, "fieldKey": "damage", "label": {"ru": "Ущерб, сомони", "en": "Damage, TJS"},
           "type": "money", "semantic": "measure",
           "format": {"precision": 2, "currency": "TJS", "thousands": true}, "required": false}
        ],
        "geometry": {"kind": "latlon", "lat": 4, "lon": 5}, "geometryField": "geometry",
        "key": ["code"], "onError": "stop"
      }
    }
  ]

```

(в примере сопоставление сокращено: в манифесте перечислены все столбцы файла.) Манифест
сознательно отличается от предложений анализа там, где анализ не может знать больше: код
района — семантика `territory`, ущерб — `money` в сомони, сейсмостойкость — измерение, а не мера.

**Детерминированность.** Один seed и одна версия генератора — побайтно те же файлы:
случайные числа берутся только из `random.random()`, последовательность которого Python
гарантирует между версиями; нормальное, логнормальное и прочие распределения построены поверх
него. У каждого набора свой поток, поэтому `--incidents` не меняет другие файлы. Хэши малого
профиля совпадают на macOS (arm64, Python 3.14) и Linux (arm64 и x86_64, Python 3.12) и
закреплены в `tests/test_demo.py` (`GOLDEN`): правка генератора, меняющая данные, — осознанная,
вместе с эталоном. Генератору хватает стандартной библиотеки (boto3 — только для `s3://`).

**Скорость** (Apple M4, Python 3.14, каталог на SSD): «Происшествия» профиля `demo` —
5 000 000 строк, 1 104 МБ за 15,1 с (≈ 330 тыс. строк/с); весь профиль `demo` — 15,4 с,
пик памяти процесса 94 МБ (из них ~50 МБ — импорты; в памяти только происшествия одного дня).
Профиль `small` — 0,2 с. Нормализация этого файла движком по манифесту — 52,9 с (≈ 94 тыс.
строк/с), ошибок нет (`pytest -m slow -s tests/test_demo.py`).

**Источники и лицензия.** Все значения синтетические, сторонних наборов данных генератор не
содержит. Настоящие только названия: регионы и районы — официальные названия административных
единиц Республики Таджикистан (общедоступные факты, авторским правом не охраняются), коды
регионов — ISO 3166-2:TJ, коды районов (`TJ-SU-01`…) — собственные устойчивые коды демо-данных,
не официальный классификатор (N5 в `05-risks-and-open-questions.md`). Центроиды районов
приблизительные (±20–30 км, заданы вручную), население — округлённая оценка для демонстрации,
не статистика; имена кишлаков — распространённые таджикские топонимы, приписанные районам
случайно. Границ территорий нет — они появятся в фазе 2 (`seeds/README.md`).
